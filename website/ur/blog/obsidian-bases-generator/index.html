Obsidian Bases جنریٹر: فلٹرز، ویوز اور فارمولے

اسکیما سیکھے بغیر Obsidian base کا YAML بنائیں: فلٹرز چنیں، ویوز شامل کریں، .base فائل یا کوڈ بلاک کاپی کریں، اور Obsidian کی اپنی دستاویزات کے لنکس کے ساتھ دیکھیں کہ ہر key کیا کرتی ہے۔

Cody Bontecou
تازہ کاری

درکار ہے
کوئی بھی جدید براؤزر، بشمول iPhone پر Safari۔ اختیاری: Bases بنیادی پلگ اِن کے ساتھ Obsidian، اور آواز یا متن سے نوٹس کیپچر کرنے کے لیے iPhone یا Mac کے لیے Vox.md۔
مختصر جواب

base آپ کے نوٹس پر ڈیٹا بیس طرز کا ویو ہے، جو YAML میں لکھا جاتا ہے اور جس میں زیادہ سے زیادہ پانچ بالائی سطح کی keys ہوتی ہیں: filters, formulas, properties, summaries اور views۔ YAML کو بطور محفوظ کریں .base فائل، یا اسے کسی نوٹ میں پیسٹ کریں اس کے اندر base کوڈ بلاک۔ جنریٹر نیچے آپ کے لیے لکھتا ہے۔ آپ کو Obsidian کا کون سا ورژن چاہیے، یہ ویو کی قسم پر منحصر ہے: ویوز کا صفحہ میں Table اور Cards 1.9 سے، List اور Map 1.10 سے، اور Kanban 1.14 سے درج ہیں۔

filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

آپ کا base

اسے کسی نوٹ میں ایمبیڈ کریں

جانچ

    کلپ بورڈ پر کاپی ہو گیا۔ کاپی ناکام رہی۔ متن منتخب کریں اور خود کاپی کریں۔ {file} ڈاؤن لوڈ ہو گئی۔ پری سیٹ لوڈ ہو گیا: {name}۔ ہٹائیں ویو ہٹائیں ویو {n} فلٹر کی قسم پراپرٹی کا موازنہ پراپرٹی آپریٹر ویلیو آرگومنٹ فارمولے کا نام ایکسپریشن پراپرٹی ڈسپلے نام قسم نام دکھانے کی پراپرٹیز (ترتیب سے)، ہر لائن میں ایک حد (اختیاری) پراپرٹی کے مطابق گروپ (اختیاری) سمت ویو کے فلٹرز، ہر لائن میں ایک ایکسپریشن (سب کا درست ہونا ضروری ہے) سمریز سمری پراپرٹی خلاصہ سمری شامل کریں ویو {n} کا کوئی نام نہیں۔ ہر ویو کو نام دیں۔ کم از کم ایک ویو شامل کریں، ورنہ base کچھ نہیں دکھائے گا۔ فارمولا {name} خود کا حوالہ دیتا ہے۔ Obsidian دائرہ دار حوالوں کی اجازت نہیں دیتا۔ فارمولے کے نام {name} کا آغاز حرف یا انڈرسکور سے ہونا چاہیے اور اس میں صرف حروف، ہندسے اور انڈرسکور ہوں۔ فارمولا {name} میں ایکسپریشن نہیں ہے، اس لیے اسے چھوڑ دیا گیا۔ دو فارمولوں کا نام {name} ہے۔ متن {value} میں اسپیس ہیں، اس لیے اسے کوٹ کی گئی اسٹرنگ کے طور پر لکھا گیا۔ متنی قدروں کو کوٹس چاہییں۔ ایک فلٹر قطار کی قدر خالی ہے، اس لیے اسے چھوڑ دیا گیا۔ groupBy پراپرٹی {name} ویو {n} کی order فہرست میں نہیں ہے۔ base پھر بھی کام کرتا ہے، لیکن کالم نہیں دکھایا جاتا۔ {name} دستاویزی سمری نہیں ہے۔ فہرست میں سے کوئی ایک چنیں۔ کوئی سورس فلٹر سیٹ نہیں، اس لیے اس base میں vault کا ہر نوٹ شامل ہے۔ اسے محدود کرنے کے لیے فولڈر یا ٹیگ فلٹر شامل کریں۔ map ویو کی قسم کے لیے Maps پلگ اِن درکار ہے۔ ویوز کے صفحے پر kanban ویو کی قسم Obsidian 1.14 سے دستیاب درج ہے۔ پراپرٹی کے نام {name} میں اسپیس ہیں۔ اس پر انحصار کرنے سے پہلے دیکھ لیں کہ Obsidian اس پراپرٹی کا نام کیسے رکھتا ہے۔ کوئی مسئلہ نہیں ملا۔

    2. Bases سنٹیکس ایک نظر میں

    یہ keys ہیں Obsidian کا سنٹیکس کا صفحہ بیان کرتا ہے۔ سیکھنے کے لیے کوئی اور اسکیما نہیں۔

    کلیدیہ کیا کرتا ہےمثال
    filtersہر ویو کے لیے نوٹس محدود کرتا ہے۔file.hasTag("project")
    formulasحساب شدہ پراپرٹیز متعین کرتا ہے، جو بطور استعمال ہوتی ہیں formula.name.total: 'price * qty'
    propertiesہر پراپرٹی کی سیٹنگز۔ displayName کالم کا ہیڈر مقرر کرتا ہے۔displayName: "Status"
    summariesاپنے سمری فارمولے متعین کرتا ہے، استعمال کرتے ہوئے values.حسبِ ضرورت، اختیاری
    viewsانہی نوٹس پر ویوز کی فہرست۔- type: table
    type (ویو)ویو کی ترتیب۔table, cards, list
    name (ویو)ویو کا نام۔name: "Projects"
    filters (ویو)صرف اس ویو کے لیے فلٹرز۔file.inFolder("Work")
    groupBy (ویو)قطاروں کو گروپ کرتا ہے ایک کے مطابق property میں ایک direction.direction: DESC
    order (ویو)دکھائی جانے والی پراپرٹیز، ترتیب سے۔- file.name
    limit (ویو)قطاروں کی تعداد محدود کرتا ہے۔limit: 10
    summaries (ویو)پراپرٹی کو سمری سے جوڑتا ہے۔price: Sum

    جنریٹر ہر دستاویزی key نہیں لکھتا۔ سنٹیکس کا صفحہ یہ بھی بیان کرتا ہے groupOrder، اور ویوز میں اضافی حالت بھی ہو سکتی ہے جیسے ترتیب کا کالم، جسے Obsidian خود سنبھالتا ہے۔ ضرورت ہو تو انہیں ہاتھ سے شامل کریں: YAML آپ کی اپنی ہے۔

    3. فلٹرز: and، or، not

    فلٹر ایک متنی اسٹیٹمنٹ ہے جو ہر نوٹ کے لیے درست یا غلط ہوتی ہے، یا ایک آبجیکٹ جس میں and, or یا not جس میں مزید فلٹرز کی فہرست ہو۔ گلوبل filters ہر ویو پر لاگو ہوتے ہیں۔ ویو کا اپنا filters صرف اسی ویو پر لاگو ہوتے ہیں، اور دونوں AND سے ملائے جاتے ہیں۔

    filters:
  or:
    - file.hasTag("meeting")
    - file.inFolder("Meetings")

    کوئی نہیں ہے from یا source key، جیسے SQL یا Dataview میں۔ فلٹر نہ ہو تو base میں vault کی ہر فائل شامل ہوتی ہے، اس لیے ہمیشہ ایک فلٹر لگائیں، جب تک آپ یہی نہ چاہتے ہوں۔

    اسٹیٹمنٹ کے اندر متنی قدروں کو کوٹس چاہییں، اس لیے YAML میں اندرونی کوٹس درکار ہیں: 'status == "done"'۔ جنریٹر یہ آپ کے لیے کرتا ہے۔ فنکشن فلٹرز جیسے file.hasTag(), file.inFolder() اور file.hasLink() اس پر ہیں فنکشنز کا صفحہ.

    4. فارمولے اور سمریز

    کے تحت ہر اندراج formulas ایسی پراپرٹی بن جاتا ہے جو ہر ویو میں استعمال ہو سکتی ہے بطور formula.name۔ ایک فارمولا دوسرے فارمولے کو استعمال کر سکتا ہے، لیکن دائرہ دار حوالے کی اجازت نہیں، اس لیے فارمولا خود کا حوالہ نہیں دے سکتا۔ نتیجہ YAML اسٹرنگ کے طور پر محفوظ ہوتا ہے، اسی لیے ایکسپریشن کوٹس کے اندر جاتا ہے۔

    formulas:
  formatted_price: 'if(price, price.toFixed(2) + " dollars")'

    ویو کا summaries پراپرٹی کو سمری سے جوڑتا ہے۔ سنٹیکس کا صفحہ یہ ڈیفالٹس بتاتا ہے:

    • عدد: Average, Min, Max, Sum, Range, Median, Stddev
    • تاریخ: Earliest, Latest, Range
    • بولین: Checked, Unchecked
    • کوئی بھی: Empty, Filled, Unique

    تاریخ کے حساب کے لیے سنٹیکس کا صفحہ کہتا ہے file.mtime > now() - "1 week" اس فائل کے لیے درست ہے جو پچھلے ہفتے میں تبدیل ہوئی ہو۔

    5. اس کا مطلب

    فلٹر یا فارمولے میں، this وہ فائل ہے جس میں base دکھایا جاتا ہے۔ سنٹیکس کے صفحے کے مطابق، جب base مرکزی مواد کے حصے میں کھلے تو یہ خود base فائل ہوتی ہے؛ جب base کسی نوٹ یا Canvas میں ایمبیڈ ہو تو ایمبیڈ کرنے والی فائل؛ اور جب base سائیڈ بار میں ہو تو مرکزی مواد کے حصے کی فعال فائل۔ صفحہ دیتا ہے file.hasLink(this.file) بیک لنکس پین کی نقل کرنے کے طریقے کے طور پر۔

    6. کاپی کے لیے مثالیں

    یہ جنریٹر کے پری سیٹس سادہ کوڈ کی صورت میں ہیں، اس لیے یہ JavaScript کے بغیر بھی کام کرتے ہیں۔ فولڈر، ٹیگ اور پراپرٹی کے نام اپنے نام سے بدل لیں۔ متن کو بطور .base فائل، یا اسے اس میں لپیٹیں base کوڈ بلاک۔ دیکھیں base بنائیں کمانڈز کے لیے، اور محفوظ فائل کو اس سے ایمبیڈ کریں ![[Name.base]] یا ![[Name.base#View]] ڈیفالٹ ویو چننے کے لیے۔

    مطالعہ فہرست

    filters:
  and:
    - file.inFolder("Reading")
    - 'status == "to read"'
properties:
  status:
    displayName: "Status"
views:
  - type: cards
    name: "Reading list"
    order:
      - file.name
      - status

    اسٹیٹس کے مطابق پراجیکٹس

    filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

    ٹیگ والے نوٹس، جو اس ہفتے تبدیل ہوئے

    filters:
  and:
    - file.hasTag("project")
    - 'file.mtime > now() - "1 week"'
views:
  - type: table
    name: "Modified this week"
    order:
      - file.name
      - file.mtime

    اس نوٹ کے بیک لنکس

    filters:
  and:
    - file.hasLink(this.file)
views:
  - type: table
    name: "Backlinks"
    order:
      - file.name
      - file.folder

    Vox.md سے کیپچر کیے گئے صوتی نوٹس

    filters:
  and:
    - file.inFolder("Vox")
    - file.hasTag("voice")
views:
  - type: table
    name: "Voice notes"
    order:
      - file.ctime
      - file.name
      - file.tags

    یہ order فہرست کالم چنتی ہے۔ ترتیب ویو کی سیٹنگ ہے جو آپ Obsidian کے ویو ٹول بار میں بدلتے ہیں، اس لیے مثالیں اسے نہیں لکھتیں۔

    7. اپنے کیپچرز کو base میں دکھائیں

    Vox.md آپ کے کیپچر کیے ہوئے مواد کو آپ کے vault کے ایک فولڈر میں Markdown نوٹس کے طور پر محفوظ کرتا ہے۔ اس کا میٹا ڈیٹا کی دستاویزات کہتا ہے کہ Route جامد میٹا ڈیٹا بطور شامل کر سکتا ہے key: value لائنیں، جیسے tags: [journal, idea]، اور وہ نوٹ کا ابتدائی میٹا ڈیٹا اسے دستاویز کی سطح پر لکھتا ہے۔ یہ اختیاری مقام کا میٹا ڈیٹا بھی بیان کرتا ہے۔ اس فولڈر یا ٹیگ پر فلٹر کیا گیا base، جیسے اوپر کی آخری مثال، پھر آپ کے کیپچرز کو ایک ٹیبل میں دکھاتا ہے۔ میٹا ڈیٹا بنائیں اس کے ذریعے پراپرٹیز جنریٹر، اور دیکھیں iPhone پر Obsidian میں صوتی نوٹس سیٹ اپ کے لیے۔

    متعلقہ ٹولز: روزانہ نوٹ ٹیمپلیٹ جنریٹر تاریخ والے نوٹس بنانے کے لیے، callout جنریٹر اور Markdown ٹیبل میکر نوٹ کے مواد کے لیے۔

    ایسے نوٹس چاہییں جنہیں کوئری کرنا فائدہ مند ہو؟

    Vox.md آپ کی آواز اور متن کو iPhone اور Mac پر براہِ راست آپ کے vault میں Markdown کی صورت میں کیپچر کرتا ہے، آپ کی منتخب کردہ پراپرٹیز کے ساتھ۔ ریکارڈنگ، Transcription اور Capture کے لیے Vox.md Unlimited درکار ہے؛ اہل اکاؤنٹس کو 7 دن کا Free trial ملتا ہے۔

    آواز سے نوٹس کیپچر کریں

    اوپر دیا گیا جنریٹر ایپ کے بغیر مکمل طور پر کام کرتا ہے۔

    8. مسائل کا حل

    • base تمام نوٹس دکھاتا ہے۔ کوئی سورس فلٹر سیٹ نہیں۔ base بطورِ ڈیفالٹ پورا vault شامل کرتا ہے، اس لیے شامل کریں file.inFolder() یا file.hasTag() فلٹر۔
    • پراپرٹی کا کالم خالی ہے۔ نام مماثل نہیں، بشمول بڑے چھوٹے حروف، یا نوٹ کے frontmatter میں وہ پراپرٹی موجود نہیں۔ نوٹ کی Properties اور کالم کا نام دیکھیں۔
    • YAML کی خرابی۔ انڈینٹیشن دیکھیں، جس میں اسپیس استعمال ہوتے ہیں، اور کوٹس بھی۔ متن رکھنے والے فلٹر کو اندرونی کوٹس چاہییں: 'status == "done"'.
    • map ویو خالی ہے۔ ویوز کے صفحے کے مطابق map لے آؤٹ کے لیے Maps پلگ اِن درکار ہے۔

    9. سوالات

    کیا Bases بنیادی پلگ اِن ہے؟

    جی ہاں۔ Obsidian مدد میں لکھا ہے: “Bases ایک بنیادی پلگ اِن ہے جو آپ کو اپنے نوٹس کے ڈیٹا بیس جیسے ویوز بنانے دیتا ہے۔”

    Bases یا Dataview؟

    یہ الگ ہیں۔ Dataview ایک کمیونٹی پلگ اِن ہے جس کی اپنی کوئری زبان ہے۔ base YAML ہے جسے Obsidian خود پڑھتا ہے، بغیر from key: آپ فلٹرز سے نوٹس محدود کرتے ہیں۔ یہ صفحہ ان کی خصوصیات کا مزید موازنہ نہیں کرتا۔

    کیا میں YAML ہاتھ سے ایڈٹ کر سکتا ہوں؟

    جی ہاں۔ ایک .base فائل YAML متن ہے، اور سنٹیکس کا صفحہ keys کی وضاحت کرتا ہے۔ تیار شدہ فائل کو کسی بھی ایڈیٹر میں کھولیں، یا کوڈ بلاک کو کسی نوٹ میں پیسٹ کر کے وہیں ایڈٹ کریں۔

    کیا جنریٹر میرا ڈیٹا اپ لوڈ کرتا ہے؟

    نہیں۔ اس صفحے کا اسکرپٹ YAML آپ کے ڈیوائس پر بناتا ہے، اور صفحہ کوئی نیٹ ورک درخواست نہیں کرتا۔ ری لوڈ کرنے سے سب کچھ صاف ہو جاتا ہے۔
