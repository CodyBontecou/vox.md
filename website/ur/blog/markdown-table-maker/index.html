1. اپنا ٹیبل بنائیں

    پیش منظر

    ٹیبل دیکھنے کے لیے اپنا ڈیٹا پیسٹ کریں۔

    کلپ بورڈ پر کاپی ہو گیا۔ کاپی ناکام رہی۔ متن منتخب کریں اور خود کاپی کریں۔ مثال لوڈ ہو گئی۔ صاف ہو گیا۔ ڈاؤن لوڈ شروع ہو گیا۔ آپ کا Markdown ٹیبل آپ کی CSV آپ کی TSV پہچانا گیا: {format}۔ {rows} قطاریں، {cols} کالمز۔ Markdown ٹیبل ٹیب سے الگ کیا ہوا کوما سے الگ کیا ہوا سیمی کولن سے الگ کیا ہوا پائپ سے الگ کیا ہوا ایک کالم \| کے طور پر ایسکیپ کیے گئے پائپس: {n}، جن میں سے {m} ویکی لنکس یا تصویری لنکس کے اندر ہیں۔ سطر {line}: ڈیلیمیٹر قطار غائب ہے، اس لیے ہیڈر کے بعد ایک ڈیلیمیٹر قطار شامل کی گئی۔ سطر {line}: ڈیلیمیٹر قطار میں {found} خانے ہیں مگر ہیڈر میں {expected} ہیں۔ GFM اسپیک اسے ٹیبل نہیں مانتی۔ آؤٹ پٹ {expected} استعمال کرتا ہے۔ سطر {line}: {found} خانے ہیں، جبکہ ہیڈر میں {expected} ہیں۔ خالی خانے شامل کیے گئے۔ سطر {line}: {found} خانے ہیں، جبکہ ہیڈر میں {expected} ہیں۔ ٹیبل کو {max} کالمز تک چوڑا کیا گیا۔ سطر {line} خالی ہے۔ ٹیبل پہلی خالی سطر پر ختم ہو جاتا ہے، اس لیے اس کے بعد کی قطاریں ٹیبل کا حصہ نہیں ہوں گی۔ اور {n} مزید قطاریں جن میں خانوں کی تعداد مختلف ہے۔ کالم {n}: {name} کوئی نہیں بائیں مرکز دائیں (کوئی ہیڈر نہیں)

    2. Markdown ٹیبل سنٹیکس

    | Name   | Qty | Price |
| :----- | :-: | ----: |
| Apple  |   3 |  1.20 |
| Pear   |  12 |  0.80 |

    یہ GitHub Flavored Markdown سپیک ٹیبل کی تعریف یوں کرتا ہے: ایک ہیڈر قطار، ایک ڈیلیمیٹر قطار جو ہیڈر کو ڈیٹا سے الگ کرتی ہے، اور صفر یا زیادہ ڈیٹا قطاریں۔ خانے پائپس سے الگ ہوتے ہیں۔

    • ڈیلیمیٹر قطار۔ اس کے خانوں میں صرف ہائفن ہوتے ہیں، اور بائیں، دائیں یا دونوں سروں پر اختیاری کولن ہوتا ہے جو بائیں، دائیں یا مرکز کی ترتیب طے کرتا ہے۔ Obsidian مدد کہتا ہے کہ متن کی ترتیب کے لیے ہیڈر قطار میں کولن لگائیں، اور یہ کہ ہیڈر قطار میں کم از کم دو ہائفن ہونے چاہییں۔
    • بیرونی پائپس۔ اسپیک میں دونوں طرف کے پائپس اختیاری ہیں۔ Obsidian Help کہتی ہے کہ پڑھنے میں آسانی کے لیے انہیں شامل کرنا بہتر ہے، اور میکر ہمیشہ انہیں لکھتا ہے۔
    • پیڈنگ۔ Obsidian Help کے مطابق خانوں کا بالکل برابر ہونا ضروری نہیں۔ میکر کا “Pad columns” لے آؤٹ سورس کو صرف پڑھنے میں آسان بنانے کے لیے سیدھا کرتا ہے؛ “Compact” اسے چھوڑ دیتا ہے۔
    • برابر تعداد۔ اسپیک کے مطابق ہیڈر قطار میں خانوں کی تعداد ڈیلیمیٹر قطار کے برابر ہونی چاہیے۔ ایسا نہ ہو تو یہ سطریں ٹیبل نہیں بنتیں اور ایک پیراگراف کے طور پر دکھائی دیتی ہیں۔ جس ڈیٹا قطار میں خانے کم ہوں اس میں خالی خانے شامل کر دیے جاتے ہیں، اور اضافی خانے نظر انداز ہو جاتے ہیں۔
    • خانے کے اندر۔ اسپیک ان لائن فارمیٹنگ کی اجازت دیتی ہے مگر بلاک سطح کا مواد نہیں، اس لیے فہرست یا عنوان خانے میں نہیں آ سکتا۔ Obsidian Help کہتی ہے کہ آپ ٹیبل میں مواد کو سجانے کے لیے اس کی بنیادی فارمیٹنگ سنٹیکس استعمال کر سکتے ہیں۔
    • ٹیبل کا اختتام۔ اسپیک کے مطابق ٹیبل پہلی خالی سطر پر، یا کسی دوسرے بلاک سطح کے ڈھانچے کے آغاز پر ٹوٹ جاتا ہے۔

    میکر ہر ڈیلیمیٹر خانے میں کم از کم تین ہائفن لکھتا ہے۔ یہ Obsidian کی کم از کم دو کی شرط پوری کرتا ہے، اور وہ تین بھی جن کی GitHub دستاویزات جو مانگتا ہے۔

    3. Obsidian میں ٹیبلز

    • Insert Table۔ Obsidian Help کے مطابق آپ Command Palette سے Insert Table کمانڈ کے ذریعے ٹیبل داخل کر سکتے ہیں۔ اپنے موجودہ ڈیٹا سے ٹیبل بنانے کے لیے اسے اوپر دیے گئے میکر میں پیسٹ کریں۔
    • عرف اور تصویر کے سائز۔ ویکی لنک کا عرف، جیسے [[Note|Alias]] اور تصویر کا سائز، جیسے ![[image.png|300]] دونوں میں عمودی بار ہے۔ Obsidian Help کہتی ہے کہ ٹیبل کے اندر آپ کو شامل کرنا ہوگا \ بار سے پہلے، اس لیے لکھیں [[Note\|Alias]] اور ![[image.png\|300]]۔ میکر یہ آپ کے لیے کر دیتا ہے؛ آپ کا پہلے سے لکھا ہوا ایسکیپ دوہرا نہیں ہوتا۔
    • کوئی بھی دوسرا پائپ۔ GFM اسپیک کہتی ہے کہ خانے کے اندر پائپ کو بیک سلیش سے ایسکیپ کرنا ضروری ہے، کوڈ اسپین کے اندر بھی۔ میکر ہر غیر ایسکیپ شدہ پائپ کو اس طرح ایسکیپ کرتا ہے \|.
    • سطر کی تبدیلیاں۔ قطار ایک سطر میں لکھی جاتی ہے، اس لیے خانے کے اندر سطر کی تبدیلی کو کسی اور چیز میں بدلنا پڑتا ہے۔ میکر ایک HTML لکھتا ہے <br> ٹیگ لگاتا ہے، یا اگر آپ چاہیں تو سطروں کو ایک خالی جگہ سے جوڑ دیتا ہے۔ نہ Obsidian Help کا Tables سیکشن اور نہ GitHub Docs خانوں کے اندر سطر کی تبدیلی بیان کرتے ہیں، اس لیے خود جانچ لیں کہ <br> آپ کے اپنے والٹ میں کیسا نظر آتا ہے، اور اگر آپ سورس میں ٹیگز نہیں چاہتے تو خالی جگہ والا آپشن چنیں۔
    • پلگ اِنز۔ ٹیبلز میں ترمیم میں مدد کرنے والے کمیونٹی پلگ اِنز موجود ہیں۔ یہ صفحہ ان میں سے کسی کا جائزہ یا تائید نہیں کرتا۔

    چیک لسٹس کے لیے دیکھیں Markdown چیک لسٹ میکر؛ نوٹ کے اوپر والی پراپرٹیز کے لیے، پراپرٹیز جنریٹر۔ فیصلوں اور ذمہ داروں کی فہرست کے لیے ٹیبل اچھا رہتا ہے، جیسے اس سے بنے نوٹ میں میٹنگ نوٹس ٹیمپلیٹ.

    4. Excel، Google Sheets یا CSV سے

    اپنی اسپریڈشیٹ میں خانے منتخب کریں، کاپی کریں، اور اوپر والے باکس میں پیسٹ کریں۔ اگر خانوں کے درمیان ٹیب پیسٹ ہوں تو میکر اسے پہچان لیتا ہے۔ یہ کوما، سیمی کولن اور پائپس بھی پہچانتا ہے، اور حوالہ جاتی CSV فیلڈز پڑھتا ہے، اس لیے "Lee, Sam" ایک ہی خانہ رہتا ہے اور "" اگر اقتباس کے اندر ہو تو ایک اقتباسی نشان بن جاتا ہے۔ اگر اندازہ غلط ہو تو Separator مینو استعمال کریں۔ “The first row is the header” کو ٹک یا ان ٹک کریں تاکہ طے ہو کہ پہلی قطار ہیڈر بنے یا نہیں؛ اس کے بغیر ایک خالی ہیڈر قطار شامل کی جاتی ہے، کیونکہ Markdown ٹیبل کو اس کی ضرورت ہوتی ہے۔

    • ملائے ہوئے خانے۔ اسپیک اور دونوں ہیلپ صفحات قطار کو پائپس سے الگ کیے گئے خانوں کی فہرست بتاتے ہیں، اور کوئی بھی خانے ملانے کا طریقہ بیان نہیں کرتا۔ کاپی کرنے سے پہلے ہر اس خانے میں قدر ڈالیں جسے ملانے میں شامل کیا گیا تھا۔
    • فارمولے۔ میکر صرف وہ متن پڑھتا ہے جو آپ پیسٹ کرتے ہیں۔ اگر پیسٹ کیے گئے خانوں میں نتائج کے بجائے فارمولے نظر آئیں تو اپنی اسپریڈشیٹ ایپ میں ویلیوز کاپی کریں اور دوبارہ پیسٹ کریں۔
    • غیر برابر قطاریں۔ اگر کسی قطار میں ہیڈر سے مختلف تعداد میں خانے ہوں تو میکر اس قطار کی سطر کا نمبر بتا کر خبردار کرتا ہے اور ٹیبل کو خالی خانوں سے بھر دیتا ہے۔ جس قطار میں ہیڈر سے زیادہ خانے ہوں وہ ڈیٹا گرانے کے بجائے ٹیبل کو چوڑا کر دیتی ہے۔
    • الٹنا اور درست کرنا۔ موجودہ Markdown ٹیبل کو دوبارہ سیدھا کرنے کے لیے پیسٹ کریں، یا اسے برآمد کرنے کے لیے Output as کو CSV یا TSV پر سیٹ کریں۔ میکر سطر کے نمبر کے ساتھ خبردار کرتا ہے جب ڈیلیمیٹر قطار غائب ہو، اس کے خانوں کی تعداد ہیڈر سے مختلف ہو، یا کوئی خالی سطر ٹیبل کو ختم کر دے۔

    پیسٹ کیے گئے Markdown ٹیبل کے ترتیبی کولن برقرار رہتے ہیں، اور آپ Column alignment مینوز سے ہر کالم بدل سکتے ہیں۔

    5. GitHub اور Obsidian کے فرق

    Obsidian Help اور GitHub Docs دونوں ہیڈر قطار، ہائفنز اور اختیاری ترتیبی کولنز والے پائپ ٹیبلز بیان کرتے ہیں۔ صفحات میں بیان کردہ فرق چھوٹے ہیں:

    موضوعObsidian مددGitHub Docs اور GFM اسپیک
    ہائفنہیڈر قطار میں کم از کم دو ہائفن ہونے چاہییںGitHub Docs: ہر ہیڈر کالم میں کم از کم تین ہائفن
    ٹیبل سے پہلے خالی سطرTables سیکشن میں اس کا ذکر نہیں ہےGitHub Docs: ٹیبل سے پہلے ایک خالی سطر لازمی ہے
    خانے میں لفظی پائپشامل کریں \ عرف اور تصویر کے سائز میں بار سے پہلےاسے اس طرح ایسکیپ کریں \|، کوڈ اسپین کے اندر بھی
    بیرونی پائپساختیاری، پڑھنے میں آسانی کے لیے تجویز کردہاختیاری

    دونوں جگہ محفوظ رہنے کے لیے تین یا زیادہ ہائفن لکھیں، ٹیبل سے اوپر ایک خالی سطر چھوڑیں، اور ہر پائپ کو ایسکیپ کریں۔ میکر یہی کرتا ہے۔ ویکی لنک کا عرف Obsidian کی سنٹیکس ہے؛ GitHub پر یہ پائپ والا عام متن ہے۔ چیک لسٹ میکر کی گائیڈ اس کا احاطہ کرتی ہے ٹاسک لسٹ کے فرق اسی طرح۔

    کسی ٹیبل یا اس کے بارے میں نوٹ کو نمایاں کرنے کے لیے اسے callout میں لپیٹیں: Obsidian callout جنریٹر شامل کرتا ہے > سابقے آپ کے لیے۔
