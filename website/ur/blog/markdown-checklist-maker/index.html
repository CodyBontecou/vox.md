- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

2. Markdown چیک لسٹ سنٹیکس

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

ہر ٹاسک ایک لسٹ آئٹم ہے: ایک ہائفن اور ایک اسپیس، پھر [ ] لکھیں، قوسین کے درمیان ایک اسپیس کے ساتھ، پھر متن۔ Obsidian Help صفحہ اور GitHub Docs صفحہ دونوں اسے ہائفن اور اسپیس کے بعد یوں بیان کرتے ہیں [ ]۔ ٹاسک کو مکمل نشان زد کرنے کے لیے GitHub Docs کہتا ہے کہ استعمال کریں [x].

اسپیسز اہم ہیں۔ GitHub Flavored Markdown سپیک چیک باکس مارکر کو بایاں بریکٹ، ایک وائٹ اسپیس حرف یا حرف xاور دایاں بریکٹ قرار دیتا ہے، اور اس کے بعد والے متن سے پہلے خالی جگہ ضروری ہے۔ لہٰذا [] جس کے اندر کچھ نہ ہو، یا - [ ]text بریکٹ کے بعد اسپیس کے بغیر، تعریف سے میل نہیں کھاتا۔ ہائفن اور اس کی اسپیس ہی لائن کو لسٹ آئٹم بناتے ہیں۔

ٹاسک لسٹیں بنیادی Markdown کا حصہ نہیں ہیں۔ وہی سپیک انہیں CommonMark کی توسیع قرار دیتا ہے، اور اس کے تعارف میں لکھا ہے کہ جو خصوصیات اصل CommonMark سپیک میں نہیں ہیں انہیں توسیع کے طور پر نشان زد کیا گیا ہے۔ جو رینڈرر توسیع نافذ نہیں کرتا وہ قوسین جوں کی توں دکھاتا ہے، اور صفحے پر چیک باکس کے اس طرح نظر آنے کی عام وجہ یہی ہے [ ] صفحے پر۔

3. Obsidian میں چیک لسٹیں

Obsidian Help کا بنیادی فارمیٹنگ سنٹیکس صفحہ ٹاسک لسٹوں کا احاطہ کرتا ہے:

  • ٹاسک ہائفن اور اسپیس سے شروع ہوتا ہے، اس کے بعد [ ].
  • ٹاسک کو مکمل نشان زد کرنے کے لیے آپ قوسین کے اندر کوئی بھی حرف استعمال کر سکتے ہیں، لہٰذا [x], [-] اور [?] سب شمار ہوتے ہیں۔
  • آپ لسٹ آئٹمز کو انڈینٹ کر کے ٹاسک لسٹ نیسٹ کرتے ہیں۔ استعمال کریں Tab یا Shift+Tab منتخب آئٹمز کو انڈینٹ یا ان انڈینٹ کرنے کے لیے۔
  • Reading view میں آپ کسی ٹاسک کا چیک باکس منتخب کر کے اسے ٹوگل کر سکتے ہیں۔

Help صفحہ بتاتا ہے کہ کوئی بھی حرف ٹاسک کو مکمل کر دیتا ہے۔ وہ ہر حرف کے لیے الگ ظاہری شکل بیان نہیں کرتا۔ اگر [-] یا [?] اس سے مختلف نظر آتا ہے [x] آپ کے والٹ میں مختلف نظر آتا ہے، تو یہ آپ کی انسٹال کردہ تھیم یا CSS سنیپٹ سے ہے، خود Markdown سے نہیں۔

میکر کی پیش رفت والی لائن بھی اسی طرح گنتی ہے: قوسین کے اندر اسپیس کے سوا کوئی بھی حرف مکمل ہے، لہٰذا [x], [X], [-] اور [?] مکمل ہیں اور [ ] کھلا ہے۔ جو لائنیں “done:” یا “x ” سے شروع ہوتی ہیں وہ عام متن ہیں؛ ٹول یہ اندازہ نہیں لگاتا کہ ان کا مطلب مکمل ٹاسک ہے۔

4. مقررہ تاریخیں: Tasks بمقابلہ Dataview بمقابلہ Reminder

Obsidian کی ٹاسک لسٹ سنٹیکس میں اپنی کوئی مقررہ تاریخ نہیں ہے: Help صفحہ ایسی کوئی چیز بیان نہیں کرتا۔ تین پلگ اِن ٹاسک کے متن میں لکھی تاریخ پڑھتے ہیں، ہر ایک اپنے فارمیٹ میں۔ میکر تاریخ کو ISO YYYY-MM-DD میں لکھتا ہے۔ پلگ اِن کے بغیر تاریخ محض متن ہے۔

ریمائنڈر: (@YYYY-MM-DD) یا (@YYYY-MM-DD HH:mm)obsidian-reminder پلگ اِن، جس کی README دکھاتی ہے (@2021-08-14) اور (@2021-08-14 09:37) غیر چیک شدہ ٹاسکس پر- [ ] send invoice (@2026-11-25 09:30)

جو ایک پلگ اِن آپ استعمال کرتے ہیں اسے چنیں۔ Dataview کا صفحہ تاریخوں کے لیے اپنے ایموجی شارٹ ہینڈ بھی بتاتا ہے اور کہتا ہے کہ وہ صرف انہی کو سپورٹ کرتا ہے؛ میکر اس کے بجائے Dataview کی بریکٹ والی شکل لکھتا ہے۔ Reminder README کہتا ہے کہ جن ٹاسکس پر آپ پہلے ہی نشان لگا چکے ہیں ان کے ریمائنڈرز کی اطلاع آپ کو نہیں ملتی۔

5. GitHub اور Obsidian کے فرق

GitHub Docs بیان کرتا ہے [ ] کھلے ٹاسک کے لیے اور [x] مکمل نشان زد کرنے کے لیے۔ GFM سپیک مارکر کو وائٹ اسپیس یا حرف قرار دیتا ہے x قوسین کے درمیان۔ Obsidian کوئی بھی حرف قبول کرتا ہے۔ لہٰذا ایسا ٹاسک جیسے - [-] skipped یا - [?] unsure Obsidian میں مکمل شمار ہوتا ہے، لیکن یہ سپیک کی مارکر تعریف سے باہر ہے، اور سپیک کی پیروی کرنے والا رینڈرر اسے سادہ متن کے طور پر دکھا سکتا ہے۔ اگر فائل GitHub پر بھی پڑھی جاتی ہے تو استعمال کریں [ ] اور [x] صرف۔

GitHub Docs ایک اور اصول شامل کرتا ہے: اگر ٹاسک کی تفصیل قوسین سے شروع ہو تو اس سے پہلے بیک سلیش لگائیں، جیسے - [ ] \(Optional) Open a followup issue۔ میکر آپ کے لیے بیک سلیش شامل نہیں کرتا؛ جب ٹاسک قوسین سے شروع ہو تو یہ خبردار کرتا ہے۔

6. iPhone اور Mac پر Vox.md کے ساتھ آواز یا متن سے ٹاسک کیپچر کریں

Vox.md کا Todo Checklist پروسیسنگ موڈ کیپچر سے Markdown - [ ] ٹاسک آئٹمز بناتا ہے، اور اس کا متبادل ایک متعین چیک لسٹ فارمیٹر ہے۔ آواز آپ کے آلے پر ٹرانسکرائب ہوتی ہے۔ Capture Bar میں، چیکنگ یہ پریفکس لگاتا ہے - [ ] پریفکس، اور دو تاریخوں کا داخل کرتا ہے (@yyyy-MM-dd) یا وقت والی شکل۔ دیکھیں فوری پکڑنے اور Routes اور پروسیسنگ موڈز دستاویزات۔

Route آئٹمز کو آپ کے ڈیلی نوٹ میں کسی عنوان کے نیچے شامل کر سکتا ہے، جیسے ## Tasks; Obsidian روزانہ نوٹ میں اضافہ کریں سیٹ اپ کی تفصیل بتاتا ہے، اور روزانہ نوٹ ٹیمپلیٹ جنریٹر نوٹ کا ڈھانچہ لکھتا ہے۔ میٹنگ کے ایکشن آئٹمز کے لیے دیکھیں میٹنگ نوٹس ٹیمپلیٹ؛ ٹاسک لسٹ پریفکس کی ترکیب کے لیے دیکھیں کیپچر ٹیمپلیٹس.

Vox.md یہ شکل لکھتا ہے (@yyyy-MM-dd) شکل جو اس کی دستاویزات میں دکھائی گئی ہے۔ یہ Tasks پلگ اِن کی ایموجی تاریخیں یا Dataview فیلڈز نہیں لکھتا۔ اگر آپ ان میں سے کوئی استعمال کرتے ہیں تو کیپچر کیے گئے ٹاسکس اوپر والے میکر میں پیسٹ کر کے وہ فارمیٹ چنیں، یا بعد میں تاریخ خود ایڈٹ کریں۔ نوٹ کے اوپر کی پراپرٹیز بنانے کے لیے استعمال کریں پراپرٹیز جنریٹر.

iPhone، iPad یا Mac پر آواز سے ٹاسک کیپچر کریں۔

Vox.md آپ کی کہی بات کو ڈیوائس پر ہی Markdown چیک لسٹ میں بدل کر آپ کے Obsidian نوٹ میں شامل کرتا ہے۔ ریکارڈنگ، نقل نویسی اور Capture کے لیے Vox.md Unlimited درکار ہے: اہل اکاؤنٹس کے لیے 7 دن کے مفت ٹرائل کے ساتھ ہفتہ وار یا سالانہ سبسکرپشن، یا ایک بار کی تاحیات خریداری۔ App Store آپ کی مقامی قیمت دکھاتا ہے۔

7۔ سوالات

میرا چیک باکس [ ] متن کی صورت میں کیوں نظر آتا ہے؟

رینڈرر ٹاسک لسٹیں نہیں بنا رہا۔ ٹاسک لسٹیں CommonMark کی ایک توسیع ہیں، اس لیے اس کے بغیر رینڈرر قوسین جوں کی توں دکھاتا ہے۔ جانچیں کہ لائن ہائفن اور اسپیس سے شروع ہو، قوسین کے درمیان اسپیس یا x ہو، اور بند قوسین کے بعد ایک اسپیس ہو۔ Obsidian میں کوڈ بلاک یا ٹیبل سیل میں موجود ٹاسک فہرست کی آئٹم کی طرح چیک باکس کے طور پر نظر نہ آئے، ایسا ممکن ہے۔

ٹاسکس کو نیسٹ کیسے کروں؟

چائلڈ ٹاسک کو انڈینٹ کریں۔ Obsidian میں دبائیں Tab منتخب آئٹمز کو انڈینٹ کرنے کے لیے اور Shift+Tab انڈینٹ ہٹانے کے لیے۔ میکر آپ کی فہرست کی 2 یا 4 اسپیسز کو فی سطح ایک ٹیب میں بدلتا ہے، یا اگر آپ چاہیں تو 2 یا 4 اسپیسز میں۔

x کے علاوہ کسی اور حرف سے باکس کیسے چیک کروں؟

Obsidian Help کہتا ہے کہ قوسین کے اندر کوئی بھی حرف ٹاسک کو مکمل نشان زد کرتا ہے، لہٰذا - [-] task اور - [?] task مکمل ہیں۔ جب تک آپ فہرست ری سیٹ نہ کریں، میکر وہی حرف رکھتا ہے جو آپ نے پیسٹ کیا۔ جن فائلوں کو GitHub پر بھی پڑھا جاتا ہے ان کے لیے استعمال کریں [x].
