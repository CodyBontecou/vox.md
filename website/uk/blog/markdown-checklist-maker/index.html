Генератор чеклістів у Markdown: перетворіть будь-який список на завдання з датами завершення

Вставте прості рядки, маркери, нумеровані пункти або наявний список завдань і скопіюйте коректні завдання - [ ] зі збереженою вкладеністю, необов’язковою датою завершення та кількістю виконаних.

Оновлено
24 листопада 2026 р.
Потребує
Будь-який сучасний браузер, зокрема Safari на iPhone. За бажанням: Obsidian для чеклістів і Vox.md для iPhone або Mac, щоб захоплювати завдання голосом.
Коротка відповідь

Завдання Markdown — це дефіс, пробіл, дужки, пробіл і текст. Пишіть - [ ] task для відкритого завдання і - [x] done для виконаного. Щоб перетворити весь список на завдання, вставте його в генератор чеклістів нижче.

- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

Генератор прибирає наявні маркери, номери й прапорці, щоб нічого не дублювалося, зберігає відступи як вкладеність і може додати дату завершення у форматі, який читає ваш плагін Obsidian. Він працює цілком на цій сторінці: список ніколи не вивантажується, а сторінка не робить мережевих запитів.

1. Створіть свій чекліст

Генератор чеклістів потребує JavaScript. Без нього синтаксис нижче все одно працює як довідка.

Попередній перегляд

Вставте список, щоб побачити результат. виконано {done} з {total} У цьому списку немає завдань. Скопійовано в буфер обміну. Не вдалося скопіювати. Виділіть текст і скопіюйте самостійно. Приклад завантажено. Очищено. Ваш чекліст Ваш список без прапорців Виберіть коректну дату, щоб додати дати завершення. Дату не додано. Введіть час, наприклад 09:30. Дату додано без часу. Завдання, які вже мають таку дату, залишено без змін. На GitHub опис завдання, що починається з дужки, потребує зворотної скісної риски перед нею.

2. Синтаксис чекліста в Markdown

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

Кожне завдання — це елемент списку: дефіс і пробіл, а потім [ ] із пробілом між дужками, а потім текст. Obsidian Help сторінка і GitHub Docs сторінка обидві описують це як дефіс і пробіл, за якими йде [ ]. Щоб позначити завдання виконаним, GitHub Docs радить використовувати [x].

Пробіли важливі. специфікація GitHub Flavored Markdown визначає маркер прапорця як ліву дужку, пробільний символ або літеру xта праву квадратну дужку, і потрібен пробіл перед текстом після неї. Отже [] з порожнім вмістом, або - [ ]text без пробілу після дужки, не відповідає визначенню. Саме дефіс із пробілом роблять рядок елементом списку.

Списки завдань не входять до базового Markdown. Та сама специфікація позначає їх як розширення CommonMark, а у вступі сказано, що можливості, яких немає в оригінальній специфікації CommonMark, позначені як розширення. Рендерер, який не реалізує розширення, показує дужки як звичайний текст, і це зазвичай причина, чому прапорець на сторінці виглядає як [ ] на сторінці.

3. Чекліст в Obsidian

Сторінка Obsidian Help базовий синтаксис форматування розповідає про списки завдань:

  • Завдання починається з дефіса і пробілу, за якими йде [ ].
  • Щоб позначити завдання виконаним, можна використати будь-який символ між дужками, тож [x], [-] і [?] усі враховуються.
  • Список завдань робиться вкладеним відступами елементів списку. Використовуйте Tab або Shift+Tab щоб збільшити або зменшити відступ вибраних елементів.
  • У режимі читання завдання можна перемикати, вибравши його прапорець.

На сторінці Help сказано, що будь-який символ завершує завдання. Про окремий вигляд для кожного символу там не йдеться. Якщо [-] або [?] виглядає інакше, ніж [x] у вашому сховищі виглядає інакше, це зумовлено темою або фрагментом CSS, які ви встановили, а не самим Markdown.

Рядок прогресу в генераторі рахує так само: будь-який символ між дужками, окрім пробілу, означає виконане, тож [x], [X], [-] і [?] виконані, а [ ] відкрите. Рядки, що починаються з «done:» або «x », — звичайний текст; інструмент не вгадує, що вони означають виконане завдання.

4. Дати завершення: Tasks, Dataview і Reminder

Синтаксис списків завдань Obsidian не має власної дати завершення: сторінка Help такої не описує. Три плагіни читають дату, записану в тексті завдання, кожен у своєму форматі. Генератор записує дату в ISO-форматі YYYY-MM-DD в усіх них. Без плагіна дата — просто текст.

ФорматЧитаєПриклад рядка
Завершення: 📅 YYYY-MM-DDплагіна спільноти Tasks, де сказано, що дата має бути у форматі YYYY-MM-DD формат- [ ] send invoice 📅 2026-11-25
Заплановано: ⏳ YYYY-MM-DDплагіна спільноти Tasks- [ ] send invoice ⏳ 2026-11-25
Початок: 🛫 YYYY-MM-DDплагіна спільноти Tasks- [ ] send invoice 🛫 2026-11-25
Вбудоване поле: [due:: YYYY-MM-DD]Dataview документація, який читає поля, записані в завданні, наприклад [completion:: 2021-08-15]- [ ] send invoice [due:: 2026-11-25]
Нагадування: (@YYYY-MM-DD) або (@YYYY-MM-DD HH:mm)obsidian-reminder плагін, у README якого показано (@2021-08-14) і (@2021-08-14 09:37) у невиконаних завданнях- [ ] send invoice (@2026-11-25 09:30)

Оберіть один плагін, яким ви користуєтесь. На сторінці Dataview також перелічено власні емодзі-скорочення для дат, і сказано, що лише їх він підтримує; генератор натомість записує дужковий формат Dataview. У README Reminder сказано, що ви не отримуєте сповіщень про нагадування для завдань, які вже позначено виконаними.

5. Відмінності GitHub і Obsidian

GitHub Docs описує [ ] для відкритого завдання і [x] , щоб позначити виконаним. Специфікація GFM визначає маркер як пробіл або літеру x між дужками. Obsidian приймає будь-який символ. Тож завдання на кшталт - [-] skipped або - [?] unsure в Obsidian вважається виконаним, але виходить за визначення маркера в специфікації, і рендерер, що дотримується специфікації, може показати його як звичайний текст. Якщо файл читають і на GitHub, використовуйте [ ] і [x] лише.

GitHub Docs додає одне правило: якщо опис завдання починається з дужки, екрануйте її зворотною скісною рискою, як у - [ ] \(Optional) Open a followup issue. Генератор не додає зворотну скісну риску за вас; він попереджає, коли завдання починається з дужки.

Таблиці — ще один синтаксис, де важливі відмінності між Obsidian і GitHub. Щоб перетворити клітинки з електронної таблиці або CSV на таблицю, яка працює в Obsidian і на GitHub, скористайтеся Конструктор таблиць Markdown.

Виділіть підсумок або попередження над списком завдань за допомогою callout: Генератор callout для Obsidian створює > [!type] Markdown, зокрема й ті, що згортаються.

6. Захоплюйте завдання голосом або текстом на iPhone і Mac з Vox.md

Режим обробки Todo Checklist у Vox.md створює з захоплення елементи завдань Markdown - [ ] із захоплення, а резервний варіант — детермінований форматувальник чеклістів. Голос транскрибується на вашому пристрої. У Capture Bar Чеклист застосовує префікс - [ ] префікс, і Дві дати вставляє (@yyyy-MM-dd) або форму з часом. Дивіться Швидкий захоплення і Routes і режими обробки документація.

Route може додавати пункти до вашої щоденної нотатки під заголовком, наприклад ## Tasks; Додавайте записи до щоденної нотатки Obsidian покроково описує налаштування, а генератор шаблонів щоденної нотатки записує структуру нотатки. Про завдання з наради дивіться шаблон нотаток про зустрічі; рецепт префікса для списку завдань дивіться в шаблони захоплення.

Vox.md записує форму (@yyyy-MM-dd) формату, показану в його документації. Він не записує емодзі-дати Tasks або поля Dataview. Якщо ви користуєтесь одним із них, вставте захоплені завдання в генератор вище й оберіть цей формат або відредагуйте дату згодом. Щоб створити властивості на початку нотатки, скористайтеся генератор властивостей.

Захоплюйте завдання голосом на iPhone, iPad або Mac.

7. Запитання

Чому мій прапорець показано як текст [ ]?

Рендерер не малює списки завдань. Списки завдань — це розширення CommonMark, тому рендерер без нього показує дужки. Перевірте, що рядок починається з дефіса і пробілу, що між дужками є пробіл або x між дужками і що після закривної дужки стоїть пробіл. В Obsidian завдання в блоці коду або в клітинці таблиці може не відображатися як прапорець, на відміну від елемента списку.

Як зробити вкладені завдання?

Зробіть відступ для дочірнього завдання. В Obsidian натисніть Tab щоб збільшити відступ вибраних елементів, і Shift+Tab щоб зменшити відступ. Генератор перетворює 2 або 4 пробіли у вашому списку на одну табуляцію на рівень або, за бажанням, на 2 чи 4 пробіли.

Як позначити прапорець іншим символом, ніж x?

Obsidian Help каже, що будь-який символ між дужками позначає завдання виконаним, тож - [-] task і - [?] task виконані. Генератор залишає той символ, який ви вставили, доки ви не скинете список. Для файлів, які читають і на GitHub, використовуйте [x].

Як додати дату завершення, яку читає плагін Tasks?

Додайте 📅 і YYYY-MM-DD дату в кінці завдання, наприклад - [ ] send invoice 📅 2026-11-25. Оберіть вище «Плагін Tasks: завершення», щоб додати її до кожного завдання. Використовуйте ⏳ для запланованої дати та 🛫 для дати початку.

Чи вивантажує генератор мій список?

Ні. Список перетворює скрипт на цій сторінці, на вашому пристрої, і сторінка не робить жодних мережевих запитів. Вона не зберігає ваш список: закриття або перезавантаження сторінки очищає його.
