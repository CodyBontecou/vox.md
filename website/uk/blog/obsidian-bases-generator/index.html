Генератор Obsidian Bases: фільтри, подання та формули

Створіть YAML для base в Obsidian, не вивчаючи спершу схему: виберіть фільтри, додайте подання, скопіюйте файл .base чи блок коду та дізнайтеся, що робить кожен ключ, за посиланнями на власну документацію Obsidian.

Автор:
Cody Bontecou
Оновлено
28 листопада 2026 р.
Потребує
Будь-який сучасний браузер, зокрема Safari на iPhone. Необов’язково: Obsidian з базовим плагіном Bases і Vox.md для iPhone чи Mac, щоб захоплювати нотатки голосом або текстом.
Коротка відповідь

Base — це подання ваших нотаток у стилі бази даних, записане як YAML щонайбільше з п’ятьма ключами верхнього рівня: filters, formulas, properties, summaries і views. Збережіть YAML як .base файл або вставте його в нотатку всередині base блок коду. Параметр генератор нижче запише його за вас. Яка версія Obsidian потрібна, залежить від типу подання: сторінці подань перелічує Table і Cards з версії 1.9, List і Map з 1.10, а Kanban з 1.14.

filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

Генератор працює повністю на цій сторінці. Нічого з того, що ви вводите, не завантажується, а сторінка не надсилає мережевих запитів.

1. Створіть свій base

Генератор потребує JavaScript. Без нього таблиця синтаксису та готові до копіювання приклади нижче все одно працюють.

Перевірки

    Скопійовано в буфер обміну. Не вдалося скопіювати. Виділіть текст і скопіюйте самостійно. Завантажено {file}. Шаблон завантажено: {name}. Видалити Видалити подання Подання {n} Тип фільтра Порівняння властивостей Властивість Оператор Значення Аргумент Назва формули Вираз Властивість Відображувана назва Тип Назва Властивості для показу (порядок), по одній на рядок Ліміт (необов’язково) Групувати за властивістю (необов’язково) Напрямок Фільтри подання, один вираз на рядок (усі мають бути істинними) Підсумки Властивість підсумку Підсумок Додати підсумок Подання {n} не має назви. Дайте назву кожному поданню. Додайте щонайменше одне подання, інакше base нічого не показуватиме. Формула {name} посилається сама на себе. Obsidian не дозволяє циклічних посилань. Назва формули {name} має починатися з літери або підкреслення та містити лише літери, цифри й підкреслення. Формула {name} не має виразу, тому її пропущено. Дві формули мають назву {name}. Текст {value} містить пробіли, тому його записано як рядок у лапках. Текстові значення потребують лапок. Рядок фільтра має порожнє значення, тому його пропущено. Властивості groupBy {name} немає в списку order подання {n}. Base усе одно працює, але стовпець не показано. {name} не є задокументованим підсумком. Виберіть один зі списку. Фільтр джерела не задано, тому цей base включає всі нотатки у vault. Додайте фільтр за текою чи тегом, щоб звузити його. Тип подання map потребує плагіна Maps. Тип подання kanban на сторінці подань указано як доступний в Obsidian від версії 1.14. Назва властивості {name} містить пробіли. Перевірте, як Obsidian називає цю властивість, перш ніж на неї покладатися. Проблем не знайдено.

    2. Синтаксис Bases коротко

    Це ключі, які сторінка синтаксису Obsidian документує. Іншої схеми вивчати не потрібно.

    КлючЩо робитьПриклад
    filtersЗвужує нотатки для кожного подання.file.hasTag("project")
    formulasВизначає обчислювані властивості, що використовуються як formula.name.total: 'price * qty'
    propertiesПараметри для окремих властивостей. displayName задає заголовок стовпця.displayName: "Status"
    summariesВизначає власні формули підсумків, використовуючи values.Власний, необов’язково
    viewsСписок подань тих самих нотаток.- type: table
    type (подання)Макет подання.table, cards, list
    name (подання)Назва подання.name: "Projects"
    filters (подання)Фільтри лише для цього подання.file.inFolder("Work")
    groupBy (подання)Групує рядки за property у direction.direction: DESC
    order (подання)Показані властивості в заданому порядку.- file.name
    limit (подання)Обмежує кількість рядків.limit: 10
    summaries (подання)Зіставляє властивість із підсумком.price: Sum

    Генератор записує не всі задокументовані ключі. Сторінка синтаксису також описує groupOrder, а подання можуть містити додатковий стан, як-от стовпець сортування, яким Obsidian керує сам. Додайте їх вручну, якщо потрібно: YAML ваш, його можна редагувати.

    3. Фільтри: and, or, not

    Фільтр — це текстовий вираз, який для кожної нотатки істинний або хибний, або об’єкт із and, or або not зі списком додаткових фільтрів. Глобальні filters застосовуються до кожного подання. Власні filters застосовуються лише до цього подання, а обидва поєднуються через AND.

    filters:
  or:
    - file.hasTag("meeting")
    - file.inFolder("Meetings")

    Немає from або source ключа, як у SQL чи Dataview. Без фільтра base включає кожен файл у vault, тож завжди задавайте фільтр, якщо цього не хочете.

    Текстові значення потребують лапок усередині виразу, тому YAML потребує вкладених лапок: 'status == "done"'. Генератор робить це за вас. Функційні фільтри, як-от file.hasTag(), file.inFolder() і file.hasLink() є на сторінці функцій.

    4. Формули та підсумки

    Кожен запис у formulas стає властивістю, яку можна використовувати в кожному поданні як formula.name. Формула може використовувати іншу формулу, але циклічні посилання заборонені, тому формула не може посилатися на себе. Результат зберігається як рядок YAML, тому вираз беруть у лапки.

    formulas:
  formatted_price: 'if(price, price.toFixed(2) + " dollars")'

    Ключ подання summaries зіставляє властивість із підсумком. Сторінка синтаксису наводить такі типові значення:

    • Число: Average, Min, Max, Sum, Range, Median, Stddev
    • Дата: Earliest, Latest, Range
    • Логічне: Checked, Unchecked
    • Будь-яке: Empty, Filled, Unique

    Для обчислень із датами сторінка синтаксису каже: file.mtime > now() - "1 week" істинне для файлу, зміненого за останній тиждень.

    5. Що це означає

    У фільтрі чи формулі this — це файл, у якому показано base. За сторінкою синтаксису, це сам файл base, коли він відкритий в основній області вмісту; файл, що вбудовує base, коли його вбудовано в нотатку або Canvas; і активний файл в основній області вмісту, коли base розміщено в бічній панелі. Сторінка наводить file.hasLink(this.file) як спосіб відтворити панель зворотних посилань.

    6. Приклади, які можна скопіювати

    Це готові налаштування генератора у вигляді звичайного коду, тож вони працюють без JavaScript. Замініть назви тек, тегів і властивостей на свої. Збережіть текст як .base файл або візьміть його в base блок коду. Див. Створити base щоб дізнатися про команди, і вбудуйте збережений файл через ![[Name.base]] або ![[Name.base#View]] щоб вибрати типове подання.

    Список читання

    filters:
  and:
    - file.inFolder("Reading")
    - 'status == "to read"'
properties:
  status:
    displayName: "Status"
views:
  - type: cards
    name: "Reading list"
    order:
      - file.name
      - status

    Проєкти за статусом

    filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

    Нотатки з тегом, змінені цього тижня

    filters:
  and:
    - file.hasTag("project")
    - 'file.mtime > now() - "1 week"'
views:
  - type: table
    name: "Modified this week"
    order:
      - file.name
      - file.mtime

    Зворотні посилання цієї нотатки

    filters:
  and:
    - file.hasLink(this.file)
views:
  - type: table
    name: "Backlinks"
    order:
      - file.name
      - file.folder

    Голосові нотатки, захоплені через Vox.md

    filters:
  and:
    - file.inFolder("Vox")
    - file.hasTag("voice")
views:
  - type: table
    name: "Voice notes"
    order:
      - file.ctime
      - file.name
      - file.tags

    Також order вибирає стовпці. Порядок сортування — це параметр подання, який ви змінюєте на панелі інструментів подання в Obsidian, тому приклади його не записують.

    7. Показуйте свої захоплення в base

    Vox.md зберігає те, що ви захоплюєте, як нотатки Markdown у теці у вашому vault. Її Документація з метаданих каже, що Route може додавати статичні метадані як key: value рядки, наприклад tags: [journal, idea], і що Frontmatter нотатки записує його на рівні документа. Також описано необов’язкові метадані розташування. Base, відфільтрований за цією текою чи тегом, як в останньому прикладі вище, показує ваші захоплення в одній таблиці. Створіть метадані за допомогою генератор властивостей, а також див. голосові нотатки в Obsidian на iPhone щоб дізнатися про налаштування.

    Пов’язані інструменти: генератор шаблонів щоденної нотатки для створення нотаток із датами, генератор callout і Конструктор таблиць Markdown для вмісту нотатки.

    Хочете нотатки, які варто запитувати?

    Vox.md захоплює голос і текст на iPhone та Mac прямо у ваш vault як Markdown із вибраними вами властивостями. Запис, транскрибування та Capture потребують Vox.md Unlimited; відповідні облікові записи отримують 7-денну безкоштовну пробну версію.

    Генератор вище повністю працює й без застосунку.

    8. Усунення несправностей

    • Base показує всі нотатки. Фільтр джерела не задано. За замовчуванням base включає весь vault, тож додайте file.inFolder() або file.hasTag() фільтр.
    • Стовпець властивості порожній. Назва не збігається (з урахуванням регістру) або нотатка не має цієї властивості у frontmatter. Перевірте властивості нотатки та назву стовпця.
    • Помилка YAML. Перевірте відступи (це пробіли) і лапки. Фільтр із текстом потребує вкладених лапок: 'status == "done"'.
    • Подання map порожнє. За сторінкою подань, макет map потребує плагіна Maps.

    9. Запитання

    Чи Bases — базовий плагін?

    Так. Довідка Obsidian каже: «Bases — це базовий плагін, що дає змогу створювати подання ваших нотаток, схожі на бази даних».

    Bases чи Dataview?

    Вони окремі. Dataview — це плагін спільноти з власною мовою запитів. Base — це YAML, який Obsidian читає сам, без ключа from ключа: нотатки звужуються фільтрами. Ця сторінка не порівнює їхні можливості докладніше.

    Чи можна редагувати YAML вручну?

    Так. .base — це текст YAML, а ключі описано на сторінці синтаксису. Відкрийте створений файл у будь-якому редакторі або вставте блок коду в нотатку й редагуйте його там.

    Чи завантажує генератор мої дані?

    Ні. Скрипт на цій сторінці створює YAML на вашому пристрої, а сторінка не надсилає мережевих запитів. Перезавантаження все очищає.
