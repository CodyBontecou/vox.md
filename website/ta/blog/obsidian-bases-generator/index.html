சரிபார்ப்புகள்

    கிளிப்போர்டுக்குப் பிரதியெடுக்கப்பட்டது. பிரதியெடுக்க இயலவில்லை. உரையைத் தேர்ந்தெடுத்து நீங்களே பிரதியெடுக்கவும். {file} பதிவிறக்கப்பட்டது. முன்னமைவு ஏற்றப்பட்டது: {name}. நீக்கு காட்சியை நீக்கு காட்சி {n} வடிகட்டி வகை பண்பு ஒப்பீடு பண்பு செயல்குறி மதிப்பு வாதம் சூத்திரப் பெயர் கோவை பண்பு காட்சிப் பெயர் வகை பெயர் காட்ட வேண்டிய பண்புகள் (வரிசை), ஒரு வரிக்கு ஒன்று வரம்பு (விருப்பத்திற்குரியது) பண்பின்படி குழுவாக்கு (விருப்பத்திற்குரியது) திசை காட்சி வடிகட்டிகள், ஒரு வரிக்கு ஒரு கோவை (அனைத்தும் உண்மையாக இருக்க வேண்டும்) சுருக்கங்கள் சுருக்கப் பண்பு சுருக்கம் சுருக்கம் சேர் காட்சி {n}-க்குப் பெயர் இல்லை. ஒவ்வொரு காட்சிக்கும் பெயர் கொடுங்கள். குறைந்தது ஒரு காட்சியைச் சேருங்கள், இல்லையெனில் base எதையும் காட்டாது. சூத்திரம் {name} தன்னையே குறிப்பிடுகிறது. Obsidian சுழற்சிக் குறிப்புகளை அனுமதிப்பதில்லை. சூத்திரப் பெயர் {name} ஒரு எழுத்து அல்லது அடிக்கோட்டுடன் தொடங்க வேண்டும்; எழுத்துகள், இலக்கங்கள், அடிக்கோடுகள் மட்டுமே பயன்படுத்த வேண்டும். சூத்திரம் {name}-இல் கோவை இல்லை, எனவே அது தவிர்க்கப்பட்டது. இரண்டு சூத்திரங்களுக்கு {name} என்று பெயரிடப்பட்டுள்ளது. உரை {value}-இல் இடைவெளிகள் உள்ளன, எனவே அது மேற்கோளிட்ட சரமாக எழுதப்பட்டது. உரை மதிப்புகளுக்கு மேற்கோள்கள் தேவை. ஒரு வடிகட்டி வரிசையில் மதிப்பு காலியாக உள்ளது, எனவே அது தவிர்க்கப்பட்டது. groupBy பண்பு {name} காட்சி {n}-இன் order பட்டியலில் இல்லை. base தொடர்ந்து செயல்படும், ஆனால் அந்த நெடுவரிசை காட்டப்படாது. {name} என்பது ஆவணப்படுத்தப்பட்ட சுருக்கம் அல்ல. பட்டியலிலிருந்து ஒன்றைத் தேர்ந்தெடுங்கள். மூல வடிகட்டி அமைக்கப்படவில்லை, எனவே இந்த base vault-இல் உள்ள எல்லா குறிப்புகளையும் சேர்க்கும். குறுக்க ஒரு கோப்புறை அல்லது tag வடிகட்டியைச் சேர்க்கவும். map காட்சி வகைக்கு Maps plugin தேவை. kanban காட்சி வகை Obsidian 1.14 முதல் கிடைக்கும் என்று காட்சிகள் பக்கத்தில் பட்டியலிடப்பட்டுள்ளது. பண்புப் பெயர் {name}-இல் இடைவெளிகள் உள்ளன. அந்தப் பண்பை நம்புவதற்கு முன் Obsidian அதற்கு எப்படிப் பெயரிடுகிறது என்று சரிபாருங்கள். சிக்கல்கள் எதுவும் இல்லை.

    2. Bases syntax ஒரு பார்வையில்

    இவை விசைகள் Obsidian-இன் syntax பக்கம் விவரிக்கிறது. கற்க வேறு schema எதுவும் இல்லை.

    விசைஇது என்ன செய்கிறதுஎடுத்துக்காட்டு
    filtersஎல்லா காட்சிகளுக்கும் குறிப்புகளைக் குறுக்குகிறது.file.hasTag("project")
    formulasகணக்கிடப்பட்ட பண்புகளை வரையறுக்கிறது; இவ்வாறு பயன்படுத்தப்படும் formula.name.total: 'price * qty'
    propertiesஒவ்வொரு பண்புக்கான அமைப்புகள். displayName நெடுவரிசைத் தலைப்பை அமைக்கிறது.displayName: "Status"
    summariesஉங்கள் சொந்த சுருக்கச் சூத்திரங்களை வரையறுக்கிறது, இதைப் பயன்படுத்தி values.தனிப்பயன், விருப்பத்திற்குரியது
    viewsஒரே குறிப்புகள் மீதான காட்சிகளின் பட்டியல்.- type: table
    type (காட்சி)காட்சியின் தளவமைப்பு.table, cards, list
    name (காட்சி)காட்சியின் பெயர்.name: "Projects"
    filters (காட்சி)இந்தக் காட்சிக்கு மட்டுமான வடிகட்டிகள்.file.inFolder("Work")
    groupBy (காட்சி)வரிசைகளைக் குழுவாக்குகிறது, இதன் மூலம் property இதில் direction.direction: DESC
    order (காட்சி)காட்டப்படும் பண்புகள், வரிசைப்படி.- file.name
    limit (காட்சி)வரிசைகளின் எண்ணிக்கையை வரம்பிடுகிறது.limit: 10
    summaries (காட்சி)ஒரு பண்பை ஒரு சுருக்கத்துடன் இணைக்கிறது.price: Sum

    உருவாக்கி ஆவணப்படுத்தப்பட்ட ஒவ்வொரு விசையையும் எழுதுவதில்லை. syntax பக்கம் இவற்றையும் விவரிக்கிறது: groupOrder, மேலும் காட்சிகள் வரிசைப்படுத்தும் நெடுவரிசை போன்ற கூடுதல் நிலையையும் கொண்டிருக்கலாம்; அதை Obsidian தானே நிர்வகிக்கிறது. தேவைப்பட்டால் அவற்றைக் கையால் சேர்க்கலாம்: YAML உங்கள் திருத்தத்திற்கே.

    3. வடிகட்டிகள்: and, or, not

    வடிகட்டி என்பது ஒவ்வொரு குறிப்புக்கும் உண்மை அல்லது பொய்யாகும் ஒரு உரை அறிக்கை, அல்லது இதைக் கொண்ட ஒரு பொருள்: and, or அல்லது not மேலும் பல வடிகட்டிகளைக் கொண்ட பட்டியல். பொது filters எல்லா காட்சிகளுக்கும் பொருந்தும். காட்சியின் சொந்த filters அந்தக் காட்சிக்கு மட்டும் பொருந்தும்; இரண்டும் AND மூலம் இணைக்கப்படும்.

    filters:
  or:
    - file.hasTag("meeting")
    - file.inFolder("Meetings")

    இல்லை from அல்லது source விசை SQL அல்லது Dataview போல இல்லை. வடிகட்டி இல்லையெனில், base vault-இல் உள்ள எல்லா கோப்புகளையும் சேர்க்கும்; அது வேண்டாமெனில் எப்போதும் ஒரு வடிகட்டியை அமையுங்கள்.

    அறிக்கைக்குள் உரை மதிப்புகளுக்கு மேற்கோள்கள் தேவை, எனவே YAML-இல் உள்ளமை மேற்கோள்கள் வேண்டும்: 'status == "done"'. உருவாக்கி இதை உங்களுக்காகச் செய்கிறது. இது போன்ற செயல்பாட்டு வடிகட்டிகள் file.hasTag(), file.inFolder() மற்றும் file.hasLink() உள்ளன செயல்பாடுகள் பக்கம்.

    4. சூத்திரங்களும் சுருக்கங்களும்

    இதன் கீழ் ஒவ்வொரு உள்ளீடும் formulas என்பது எல்லா காட்சிகளிலும் இவ்வாறு பயன்படுத்தக்கூடிய பண்பாகிறது formula.name. ஒரு சூத்திரம் மற்றொரு சூத்திரத்தைப் பயன்படுத்தலாம், ஆனால் சுழற்சிக் குறிப்புகள் அனுமதிக்கப்படாது; ஆகவே ஒரு சூத்திரம் தன்னையே குறிப்பிட முடியாது. முடிவு YAML சரமாகச் சேமிக்கப்படுகிறது, அதனால்தான் கோவை மேற்கோள்களுக்குள் இருக்கிறது.

    formulas:
  formatted_price: 'if(price, price.toFixed(2) + " dollars")'

    காட்சியின் summaries ஒரு பண்பை ஒரு சுருக்கத்துடன் இணைக்கிறது. syntax பக்கம் இந்த இயல்புநிலைகளைப் பட்டியலிடுகிறது:

    • எண்: Average, Min, Max, Sum, Range, Median, Stddev
    • தேதி: Earliest, Latest, Range
    • பூலியன்: Checked, Unchecked
    • ஏதேனும்: Empty, Filled, Unique

    தேதிக் கணக்கீட்டுக்கு, syntax பக்கம் கூறுவது file.mtime > now() - "1 week" கடந்த வாரத்தில் மாற்றப்பட்ட கோப்புக்கு உண்மையாகும்.

    5. இதன் பொருள்

    ஒரு வடிகட்டியில் அல்லது சூத்திரத்தில், this என்பது base காட்டப்படும் கோப்பு. base முதன்மை உள்ளடக்கப் பகுதியில் திறக்கும்போது அது base கோப்பே என்றும், ஒரு குறிப்பிலோ Canvas-இலோ உட்பொதிக்கப்படும்போது உட்பொதிக்கும் கோப்பு என்றும், பக்கப்பட்டியில் இருக்கும்போது முதன்மை உள்ளடக்கப் பகுதியில் செயலில் உள்ள கோப்பு என்றும் syntax பக்கம் கூறுகிறது. அந்தப் பக்கம் தருவது file.hasLink(this.file) backlinks பலகத்தைப் போலவே செய்வதற்கான வழியாக.

    6. நகலெடுக்கக்கூடிய எடுத்துக்காட்டுகள்

    இவை உருவாக்கியின் முன்னமைவுகள் எளிய குறியீடாக, அதனால் JavaScript இல்லாமலும் செயல்படும். கோப்புறை, tag, பண்புப் பெயர்களை உங்களுடையவற்றால் மாற்றுங்கள். உரையை இவ்வாறு சேமியுங்கள்: .base கோப்பு, அல்லது அதைச் சுற்றி வையுங்கள் base குறியீட்டுத் தொகுதி. பாருங்கள் base உருவாக்குங்கள் கட்டளைகளுக்கு, மற்றும் சேமித்த கோப்பை இதனுடன் உட்பொதியுங்கள் ![[Name.base]] அல்லது ![[Name.base#View]] இயல்புநிலைக் காட்சியைத் தேர்ந்தெடுக்க.

    வாசிப்புப் பட்டியல்

    filters:
  and:
    - file.inFolder("Reading")
    - 'status == "to read"'
properties:
  status:
    displayName: "Status"
views:
  - type: cards
    name: "Reading list"
    order:
      - file.name
      - status

    நிலைப்படி திட்டங்கள்

    filters:

    - file.hasTag("project")
properties:
  status:
    displayName: "Status"

    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

    ஒரு tag உள்ள, இந்த வாரம் மாற்றப்பட்ட குறிப்புகள்

    filters:
  and:
    - file.hasTag("project")
    - 'file.mtime > now() - "1 week"'
views:
  - type: table
    name: "Modified this week"
    order:
      - file.name
      - file.mtime

    இந்தக் குறிப்பின் backlinks

    Vox.md மூலம் பதிவுசெய்த குரல் குறிப்புகள்

    filters:
  and:

    - file.hasTag("voice")
views:

    name: "Voice notes"
    order:
      - file.ctime
      - file.name
      - file.tags

    இந்த order பட்டியல் நெடுவரிசைகளைத் தேர்ந்தெடுக்கிறது. வரிசை முறை என்பது Obsidian-இன் காட்சிக் கருவிப்பட்டியில் மாற்றும் காட்சி அமைப்பு, எனவே எடுத்துக்காட்டுகள் அதை எழுதுவதில்லை.

    7. உங்கள் பதிவுகளை base-இல் தெரியச் செய்யுங்கள்

    Vox.md நீங்கள் பதிவுசெய்வதை உங்கள் vault-இல் உள்ள ஒரு கோப்புறையில் Markdown குறிப்புகளாகச் சேமிக்கிறது. அதன் மெட்டாடேட்டா ஆவணம் ஒரு Route நிலையான மெட்டாடேட்டாவை இவ்வாறு சேர்க்கலாம் என்று கூறுகிறது key: value வரிகள், எடுத்துக்காட்டாக tags: [journal, idea], மற்றும் அந்த குறிப்பின் முன்தரவு அதை ஆவண அளவில் எழுதுகிறது. இது விருப்பத்திற்குரிய இருப்பிட மெட்டாடேட்டாவையும் விவரிக்கிறது. மேலே உள்ள கடைசி எடுத்துக்காட்டு போல அந்தக் கோப்புறை அல்லது tag மூலம் வடிகட்டிய base உங்கள் பதிவுகளை ஒரே table-இல் பட்டியலிடும். மெட்டாடேட்டாவை இதைக் கொண்டு உருவாக்குங்கள்: பண்புகள் உருவாக்கி, மேலும் பாருங்கள் iPhone-இல் Obsidian-க்கான குரல் குறிப்புகள் அமைப்புக்கு.

    தொடர்புடைய கருவிகள்: தினசரிக் குறிப்பு வார்ப்புரு உருவாக்கி தேதியிட்ட குறிப்புகளை உருவாக்க, callout உருவாக்கி மேலும் Markdown அட்டவணை உருவாக்கி குறிப்பின் உள்ளடக்கத்திற்கு.

    வினவத் தகுந்த குறிப்புகள் வேண்டுமா?

    Vox.md iPhone மற்றும் Mac-இல் குரலையும் உரையையும் நீங்கள் தேர்ந்தெடுக்கும் பண்புகளுடன் நேரடியாக உங்கள் vault-இல் Markdown ஆகப் பதிவுசெய்கிறது. பதிவு, Transcription மற்றும் Capture-க்கு Vox.md Unlimited தேவை; தகுதியுள்ள கணக்குகளுக்கு 7 நாள் Free trial கிடைக்கும்.

    குரலால் குறிப்புகளைப் பதிவுசெய்யுங்கள்

    மேலே உள்ள உருவாக்கி செயலி இல்லாமலும் முழுமையாகச் செயல்படும்.

    8. சிக்கல் தீர்வு

    • base எல்லா குறிப்புகளையும் காட்டுகிறது. மூல வடிகட்டி அமைக்கப்படவில்லை. base இயல்பாக முழு vault-ஐயும் சேர்க்கும், எனவே ஒன்றைச் சேர்க்கவும் file.inFolder() அல்லது file.hasTag() வடிகட்டி.
    • ஒரு பண்பு நெடுவரிசை காலியாக உள்ளது. பெயர் (எழுத்துவடிவம் உட்பட) பொருந்தவில்லை, அல்லது குறிப்பின் frontmatter-இல் அந்தப் பண்பு இல்லை. குறிப்பின் Properties-ஐயும் நெடுவரிசைப் பெயரையும் சரிபாருங்கள்.
    • YAML பிழை. இடைவெளிகளால் ஆன உள்தள்ளலையும் மேற்கோள்களையும் சரிபாருங்கள். உரையைக் கொண்ட வடிகட்டிக்கு உள்ளமை மேற்கோள்கள் தேவை: 'status == "done"'.
    • map காட்சி காலியாக உள்ளது. காட்சிகள் பக்கத்தின்படி, map தளவமைப்புக்கு Maps plugin தேவை.

    9. கேள்விகள்

    Bases ஒரு core plugin-ஆ?

    ஆம். Obsidian Help ஆவணம் இவ்வாறு கூறுகிறது: “Bases என்பது உங்கள் குறிப்புகளின் தரவுத்தள வகைக் காட்சிகளை உருவாக்க உதவும் ஒரு core plugin.”

    Bases அல்லது Dataview?

    அவை தனித்தனியானவை. Dataview என்பது தனக்கே உரிய வினவல் மொழியுடைய ஒரு community plugin. base என்பது Obsidian தானே படிக்கும் YAML; அதில் இல்லை from விசை: நீங்கள் வடிகட்டிகளால் குறிப்புகளைக் குறுக்குகிறீர்கள். இந்தப் பக்கம் அவற்றின் அம்சங்களை மேலும் ஒப்பிடுவதில்லை.

    YAML-ஐக் கையால் திருத்தலாமா?

    ஆம். ஒரு .base கோப்பு YAML உரை, அதன் விசைகளை syntax பக்கம் விவரிக்கிறது. உருவாக்கிய கோப்பை எந்த எடிட்டரிலும் திறக்கலாம், அல்லது குறியீட்டுத் தொகுதியை ஒரு குறிப்பில் ஒட்டி அங்கே திருத்தலாம்.

    உருவாக்கி என் தரவைப் பதிவேற்றுகிறதா?

    இல்லை. இந்தப் பக்கத்தில் உள்ள ஒரு script உங்கள் சாதனத்திலேயே YAML-ஐ உருவாக்குகிறது; பக்கம் எந்த நெட்வொர்க் கோரிக்கையும் அனுப்புவதில்லை. மீண்டும் ஏற்றினால் அனைத்தும் அழியும்.
