Markdown சரிபார்ப்புப் பட்டியல் உருவாக்கி: எந்தப் பட்டியலையும் நிறைவு தேதிகளுடன் பணிகளாக மாற்றுங்கள்

எளிய வரிகள், புள்ளிகள், எண்ணிட்ட உருப்படிகள் அல்லது ஏற்கெனவே உள்ள பணிப் பட்டியலை ஒட்டி, உள்ளமைவு பாதுகாக்கப்பட்ட, விருப்பமான நிறைவு தேதியுடன், முடிந்தவற்றின் எண்ணிக்கையுடன் கூடிய சரியான - [ ] பணிகளை நகலெடுங்கள்.

Markdown பணி என்பது ஒரு ஹைபன், ஓர் இடைவெளி, அடைப்புக்குறிகள், ஓர் இடைவெளி, உரை. திறந்த பணிக்கு - [ ] task திறந்த பணிக்கும் - [x] done என்று எழுதவும். முழுப் பட்டியலையும் பணிகளாக மாற்ற, அதை ஒட்டவும்: சரிபார்ப்புப் பட்டியல் உருவாக்கி கீழே.

- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

இருக்கும் புள்ளிகள், எண்கள், தேர்வுப்பெட்டிகளை உருவாக்கி நீக்குகிறது, இதனால் எதுவும் இரட்டிப்பாகாது; உள்தள்ளலை உள்ளமைவாக வைத்திருக்கிறது; உங்கள் Obsidian plugin படிக்கும் வடிவத்தில் நிறைவு தேதியையும் சேர்க்க முடியும். இது முழுவதும் இந்தப் பக்கத்திலேயே இயங்குகிறது: பட்டியல் ஒருபோதும் பதிவேற்றப்படாது, பக்கம் எந்த நெட்வொர்க் கோரிக்கையும் அனுப்பாது.

1. உங்கள் சரிபார்ப்புப் பட்டியலை உருவாக்குங்கள்

சரிபார்ப்புப் பட்டியல் உருவாக்கிக்கு JavaScript தேவை. அது இல்லாவிட்டாலும், கீழே உள்ள தொடரியல் குறிப்பாகப் பயன்படும்.

உங்கள் பட்டியலில் உள்ள ஒரு tab எப்போதும் ஒரு நிலையாகக் கணக்கிடப்படும். தலைப்புகள் தலைப்புகளாகவே இருக்கும்.

முன்னோட்டம்

முடிவைப் பார்க்க ஒரு பட்டியலை ஒட்டவும். {total}-இல் {done} முடிந்தன இந்தப் பட்டியலில் பணிகள் இல்லை. கிளிப்போர்டுக்குப் பிரதியெடுக்கப்பட்டது. பிரதியெடுக்க இயலவில்லை. உரையைத் தேர்ந்தெடுத்து நீங்களே பிரதியெடுக்கவும். எடுத்துக்காட்டு ஏற்றப்பட்டது. அழிக்கப்பட்டது. உங்கள் சரிபார்ப்புப் பட்டியல் தேர்வுப்பெட்டிகள் இல்லாத உங்கள் பட்டியல் நிறைவு தேதிகளைச் சேர்க்க சரியான தேதியைத் தேர்ந்தெடுக்கவும். தேதி எதுவும் சேர்க்கப்படவில்லை. 09:30 போன்ற நேரத்தை உள்ளிடவும். தேதி நேரம் இல்லாமல் சேர்க்கப்பட்டது. ஏற்கெனவே இந்த வகை தேதி உள்ள பணிகள் அப்படியே விடப்பட்டன. GitHub-இல், அடைப்புக்குறியுடன் தொடங்கும் பணி விளக்கத்துக்கு முன் பின்சாய்வுக் கோடு தேவை.

2. Markdown சரிபார்ப்புப் பட்டியல் தொடரியல்

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

ஒவ்வொரு பணியும் ஒரு பட்டியல் உருப்படி: ஒரு ஹைபனும் இடைவெளியும், பின்னர் [ ] அடைப்புக்குறிகளுக்கு இடையில் ஓர் இடைவெளியுடன், பின்னர் உரையுடன். Obsidian Help பக்கம் மற்றும் GitHub Docs பக்கம் இரண்டும் இதை ஒரு ஹைபனும் இடைவெளியும் அதைத் தொடர்ந்து என்று விவரிக்கின்றன: [ ]. ஒரு பணியை முடிந்ததாகக் குறிக்க, GitHub Docs இதைப் பயன்படுத்தச் சொல்கிறது: [x].

இடைவெளிகள் முக்கியம். GitHub Flavored Markdown விவரக்குறிப்பு தேர்வுப்பெட்டிக் குறியீட்டை இடது அடைப்புக்குறி, ஒரு வெற்றிட எழுத்து அல்லது எழுத்து இவற்றில் ஒன்றாக வரையறுக்கிறது: x, ஒரு வலது அடைப்புக்குறி ஆகியவை; அதன் பின் வரும் உரைக்கு முன் வெற்றிடமும் தேவை. எனவே [] உள்ளே எதுவும் இல்லாதது, அல்லது - [ ]text அடைப்புக்குறிக்குப் பின் இடைவெளி இல்லாதது, வரையறைக்குப் பொருந்தாது. ஹைபனும் அதன் இடைவெளியும்தான் வரியைப் பட்டியல் உருப்படியாக்குகின்றன.

பணிப் பட்டியல்கள் அடிப்படை Markdown-இன் பகுதி அல்ல. அதே விவரக்குறிப்பு அவற்றை CommonMark-இன் நீட்டிப்பாகக் குறிக்கிறது; அசல் CommonMark விவரக்குறிப்பில் இல்லாத அம்சங்கள் நீட்டிப்புகளாகக் குறிக்கப்படுகின்றன என்று அதன் அறிமுகம் கூறுகிறது. நீட்டிப்பைச் செயல்படுத்தாத ரெண்டரர் அடைப்புக்குறிகளை சாதாரண உரையாகக் காட்டும்; தேர்வுப்பெட்டி இவ்வாறு தெரிவதற்கு இதுவே வழக்கமான காரணம்: [ ] பக்கத்தில்.

3. Obsidian-இல் சரிபார்ப்புப் பட்டியல்கள்

Obsidian உதவியின் அடிப்படை வடிவமைப்புத் தொடரியல் பக்கம் பணிப் பட்டியல்களை விளக்குகிறது:

  • ஒரு பணி ஹைபனும் இடைவெளியும் அதைத் தொடர்ந்து [ ].
  • பணியை முடிந்ததாகக் குறிக்க அடைப்புக்குறிகளுக்குள் எந்த எழுத்தையும் பயன்படுத்தலாம், எனவே [x], [-] மற்றும் [?] அனைத்தும் முடிந்ததாகக் கணக்கிடப்படும்.
  • பட்டியல் உருப்படிகளை உள்தள்ளுவதன் மூலம் பணிப் பட்டியலை உள்ளமைக்கிறீர்கள். பயன்படுத்தவும்: Tab அல்லது Shift+Tab தேர்ந்தெடுத்த உருப்படிகளை உள்தள்ள அல்லது உள்தள்ளலை நீக்க.
  • வாசிப்புக் காட்சியில் பணியின் தேர்வுப்பெட்டியைத் தேர்ந்தெடுப்பதன் மூலம் அதை மாற்றலாம்.

எந்த எழுத்தும் பணியை முடிக்கும் என்று உதவிப் பக்கம் கூறுகிறது. ஒவ்வொரு எழுத்துக்கும் வெவ்வேறு தோற்றத்தை அது விவரிக்கவில்லை. உங்கள் vault-இல் [-] அல்லது [?] இதிலிருந்து வேறுபடுகிறது: [x] உங்கள் vault-இல் வேறுபாடாகத் தெரிந்தால், அது நீங்கள் நிறுவிய theme அல்லது CSS snippet-இலிருந்து வருகிறது, Markdown-இலிருந்து அல்ல.

உருவாக்கியில் உள்ள முன்னேற்ற வரியும் இதே முறையில் எண்ணுகிறது: அடைப்புக்குறிகளுக்குள் இடைவெளி தவிர்த்த எந்த எழுத்தும் முடிந்ததைக் குறிக்கும், எனவே [x], [X], [-] மற்றும் [?] முடிந்தவை, மேலும் [ ] திறந்த நிலையில் உள்ளது. “done:” அல்லது “x ” என்று தொடங்கும் வரிகள் சாதாரண உரை; அவை முடிந்த பணியைக் குறிக்கின்றன என்று கருவி ஊகிக்காது.

4. நிறைவு தேதிகள்: Tasks, Dataview மற்றும் Reminder

Obsidian-இன் பணிப் பட்டியல் தொடரியலுக்கு சொந்த நிறைவு தேதி இல்லை: உதவிப் பக்கம் எதையும் குறிப்பிடவில்லை. மூன்று plugin-கள் பணி உரையில் எழுதப்பட்ட தேதியைப் படிக்கின்றன, ஒவ்வொன்றும் தனது வடிவத்தில். உருவாக்கி தேதியை ISO YYYY-MM-DD அனைத்திலும். plugin இல்லாவிட்டால், தேதி வெறும் உரைதான்.

Dataview பக்கம் தேதிகளுக்கான தனது சொந்த emoji சுருக்கங்களையும் பட்டியலிட்டு, அவை மட்டுமே தான் ஆதரிக்கும் சுருக்கங்கள் என்கிறது; உருவாக்கி அதற்குப் பதிலாக Dataview-இன் அடைப்புக்குறி வடிவத்தை எழுதுகிறது. ஏற்கெனவே தேர்வுசெய்த பணிகளின் நினைவூட்டல்களுக்கு அறிவிப்பு வராது என்று Reminder README கூறுகிறது.

5. GitHub மற்றும் Obsidian வேறுபாடுகள்

GitHub Docs விவரிப்பது: [ ] திறந்த பணிக்கும் [x] என்று பயன்படுத்தவும். GFM விவரக்குறிப்பு குறியீட்டை வெற்றிட எழுத்து அல்லது எழுத்து இவ்வாறு வரையறுக்கிறது: x அடைப்புக்குறிகளுக்கு இடையில். Obsidian எந்த எழுத்தையும் ஏற்கிறது. எனவே இது போன்ற பணி: - [-] skipped அல்லது - [?] unsure Obsidian-இல் முடிந்ததாகும், ஆனால் இது விவரக்குறிப்பின் குறியீட்டு வரையறைக்கு வெளியே உள்ளது, விவரக்குறிப்பைப் பின்பற்றும் ரெண்டரர் இதை சாதாரண உரையாகக் காட்டலாம். கோப்பு GitHub-இலும் படிக்கப்பட்டால், பயன்படுத்தவும் [ ] மற்றும் [x] மட்டும்.

GitHub Docs ஒரு விதியைச் சேர்க்கிறது: பணி விளக்கம் அடைப்புக்குறியுடன் தொடங்கினால், அதற்கு முன் பின்சாய்வுக் கோடு இடவும், உதாரணமாக - [ ] \(Optional) Open a followup issue. பின்சாய்வுக் கோட்டை உருவாக்கி உங்களுக்காகச் சேர்க்காது; பணி அடைப்புக்குறியுடன் தொடங்கினால் எச்சரிக்கும்.

அட்டவணைகளில் Obsidian மற்றும் GitHub விவரங்கள் முக்கியமாகும் மற்றொரு தொடரியல் ஆகும். விரிதாள் கலங்களை அல்லது CSV-ஐ Obsidian-லும் GitHub-லும் வேலை செய்யும் அட்டவணையாக மாற்ற, இதைப் பயன்படுத்துங்கள்: Markdown அட்டவணை உருவாக்கி.

பணிப் பட்டியலுக்கு மேலே சுருக்கத்தையோ எச்சரிக்கையையோ callout மூலம் முன்னிலைப்படுத்துங்கள்: Obsidian callout உருவாக்கி இதற்கான > [!type] Markdown-ஐ (மடிக்கக்கூடியவை உட்பட) உருவாக்குகிறது.

6. iPhone மற்றும் Mac-இல் Vox.md மூலம் குரலில் அல்லது உரையில் பணிகளைப் பதிவு செய்யுங்கள்

Vox.md-இன் Todo Checklist செயலாக்க முறை Markdown வடிவில் உருவாக்குகிறது: - [ ] பதிவிலிருந்து பணி உருப்படிகளை; அதன் மாற்று வழி ஒரு தீர்மானகரமான சரிபார்ப்புப் பட்டியல் வடிவமைப்பி. குரல் உங்கள் சாதனத்திலேயே உரையாக மாற்றப்படுகிறது. Capture Bar-இல், Checklist செய்திகள் முன்னொட்டைப் பயன்படுத்துகிறது - [ ] முன்னொட்டையும், மேலும் 2 நாட்களுக்கு என்பதைச் செருகுகிறது (@yyyy-MM-dd) அல்லது நேரத்துடன் கூடிய வடிவம். பார்க்கவும்: விரைவான Capture மற்றும் Routes மற்றும் செயலாக்க முறைகள் ஆவணங்களில்.

ஒரு Route, உருப்படிகளை உங்கள் தினசரிக் குறிப்பில் இது போன்ற தலைப்பின் கீழ் சேர்க்கலாம்: ## Tasks; Obsidian தினக்குறிப்பில் சேர்க்கவும் அமைப்பை விளக்குகிறது, மேலும் தினசரிக் குறிப்பு வார்ப்புரு உருவாக்கி குறிப்பின் அமைப்பை எழுதுகிறது. ஒரு கூட்டத்தின் செயல் உருப்படிகளுக்கு, பார்க்கவும் கூட்டக் குறிப்புகள் வார்ப்புரு; பணிப் பட்டியல் முன்னொட்டுச் செய்முறைக்கு, பார்க்கவும் capture வார்ப்புருக்கள்.

Vox.md இந்த வடிவத்தை எழுதுகிறது: (@yyyy-MM-dd) வடிவம், அதன் ஆவணங்களில் காட்டப்பட்டுள்ளது. இது Tasks plugin emoji தேதிகளையோ Dataview புலங்களையோ எழுதாது. அவற்றில் ஒன்றைப் பயன்படுத்தினால், பதிவு செய்த பணிகளை மேலே உள்ள உருவாக்கியில் ஒட்டி அந்த வடிவத்தைத் தேர்ந்தெடுக்கவும், அல்லது பின்னர் தேதியைத் திருத்தவும். குறிப்பின் மேலே உள்ள பண்புகளை உருவாக்க, இதைப் பயன்படுத்தவும்: பண்புகள் உருவாக்கி.

iPhone, iPad அல்லது Mac-இல் குரலில் பணிகளைப் பதிவு செய்யுங்கள்.

நீங்கள் சொல்வதை Vox.md சாதனத்திலேயே Markdown சரிபார்ப்புப் பட்டியலாக மாற்றி உங்கள் Obsidian குறிப்பில் சேர்க்கிறது. பதிவு, உரைமாற்றம், Capture ஆகியவற்றுக்கு Vox.md Unlimited தேவை: தகுதியான கணக்குகளுக்கு 7 நாள் இலவசச் சோதனையுடன் வாராந்திர அல்லது ஆண்டு சந்தா, அல்லது ஒருமுறை வாழ்நாள் கொள்முதல். உங்கள் உள்ளூர் விலையை App Store காட்டும்.

குரலில் பணிகளைப் பதிவு செய்யுங்கள்

மேலே உள்ள சரிபார்ப்புப் பட்டியல் உருவாக்கி செயலி இல்லாமலும் முழுமையாக வேலை செய்யும்.

7. கேள்விகள்

என் தேர்வுப்பெட்டி ஏன் [ ] உரையாகத் தெரிகிறது?

ரெண்டரர் பணிப் பட்டியல்களை வரையவில்லை. பணிப் பட்டியல்கள் CommonMark-இன் நீட்டிப்பு, எனவே அது இல்லாத ரெண்டரர் அடைப்புக்குறிகளை அப்படியே காட்டும். வரி ஹைபன் மற்றும் இடைவெளியுடன் தொடங்குகிறதா, ஓர் இடைவெளி அல்லது x அடைப்புக்குறிகளுக்கு இடையில் உள்ளதா, மூடும் அடைப்புக்குறிக்குப் பின் ஓர் இடைவெளி உள்ளதா என்றும் சரிபார்க்கவும். Obsidian-இல், குறியீட்டுத் தொகுதியிலோ அட்டவணைக் கலத்திலோ உள்ள பணி, பட்டியல் உருப்படியைப் போல தேர்வுப்பெட்டியாகக் காட்டப்படாமல் போகலாம்.

பணிகளை எப்படி உள்ளமைப்பது?

துணைப் பணியை உள்தள்ளவும். Obsidian-இல் அழுத்தவும்: Tab தேர்ந்தெடுத்த உருப்படிகளை உள்தள்ள, மேலும் Shift+Tab என்பதை அழுத்தி உள்தள்ளலை நீக்கவும். உங்கள் பட்டியலில் உள்ள 2 அல்லது 4 இடைவெளிகளை உருவாக்கி ஒரு நிலைக்கு ஒரு tab ஆக மாற்றும்; விரும்பினால் 2 அல்லது 4 இடைவெளிகளாகவும் மாற்றலாம்.

x அல்லாத வேறு எழுத்தால் பெட்டியை எப்படித் தேர்வு செய்வது?

அடைப்புக்குறிகளுக்குள் எந்த எழுத்தும் பணியை முடிந்ததாகக் குறிக்கும் என்று Obsidian உதவி கூறுகிறது, எனவே - [-] task மற்றும் - [?] task முடிந்தவை. நீங்கள் பட்டியலை மீட்டமைக்காத வரை, ஒட்டிய எழுத்தை உருவாக்கி அப்படியே வைத்திருக்கும். GitHub-இலும் படிக்கப்படும் கோப்புகளுக்கு, பயன்படுத்தவும் [x].

Tasks plugin படிக்கும் நிறைவு தேதியை எப்படிச் சேர்ப்பது?

இடுங்கள்: 📅 மற்றும் ஒரு தேதி: YYYY-MM-DD என்ற தேதியைப் பணியின் இறுதியில், உதாரணமாக - [ ] send invoice 📅 2026-11-25. அதை ஒவ்வொரு பணிக்கும் சேர்க்க மேலே “Tasks plugin: நிறைவு” என்பதைத் தேர்ந்தெடுக்கவும். பயன்படுத்தவும்: ⏳ திட்டமிட்ட தேதிக்கும், 🛫 தொடக்கத் தேதிக்கு.

உருவாக்கி என் பட்டியலைப் பதிவேற்றுகிறதா?

இல்லை. பட்டியல் இந்தப் பக்கத்தில் உள்ள ஸ்கிரிப்ட் மூலம் உங்கள் சாதனத்திலேயே மாற்றப்படுகிறது; பக்கம் எந்த நெட்வொர்க் கோரிக்கையும் அனுப்பாது. அது உங்கள் பட்டியலைச் சேமிக்காது: பக்கத்தை மூடினாலோ மீண்டும் ஏற்றினாலோ அது அழிந்துவிடும்.
