Generador de Obsidian Bases: filtros, vistas y fórmulas

Crea el YAML de una base de Obsidian sin aprender antes el esquema: elige filtros, añade vistas, copia un archivo .base o un bloque de código, y descubre qué hace cada clave con enlaces a la documentación de Obsidian.

Por
Cody Bontecou
Actualizado
28 de noviembre de 2026
Requiere
Cualquier navegador moderno, incluido Safari en iPhone. Opcional: Obsidian con el complemento básico Bases, y Vox.md para iPhone o Mac para capturar notas por voz o texto.
La respuesta breve

Una base es una vista de tus notas al estilo de una base de datos, escrita como YAML con hasta cinco claves de nivel superior: filters, formulas, properties, summaries y views. Guarda el YAML como un .base archivo, o pégalo en una nota dentro de un base bloque de código. El generador de abajo lo escribe por ti. La versión de Obsidian que necesitas depende del tipo de vista: la página de vistas enumera Table y Cards desde la 1.9, List y Map desde la 1.10 y Kanban desde la 1.14.

filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

El generador se ejecuta por completo en esta página. Nada de lo que escribes se sube, y la página no hace solicitudes de red.

    2. La sintaxis de Bases de un vistazo

    Estas son las claves página de sintaxis de Obsidian documenta. No hay ningún otro esquema que aprender.

    ClaveQué haceEjemplo
    filtersAcota las notas para todas las vistas.file.hasTag("project")
    formulasDefine propiedades calculadas, que se usan como formula.name.total: 'price * qty'
    propertiesAjustes por propiedad. displayName establece el encabezado de la columna.displayName: "Status"
    summariesDefine tus propias fórmulas de resumen, usando values.Personalizado, opcional
    viewsUna lista de vistas sobre las mismas notas.- type: table
    type (vista)El diseño de la vista.table, cards, list
    name (vista)El nombre de la vista.name: "Projects"
    filters (vista)Filtros solo para esta vista.file.inFolder("Work")
    groupBy (vista)Agrupa las filas por una property en un direction.direction: DESC
    order (vista)Las propiedades mostradas, en orden.- file.name
    limit (vista)Limita el número de filas.limit: 10
    summaries (vista)Asigna un resumen a una propiedad.price: Sum

    El generador no escribe todas las claves documentadas. La página de sintaxis también describe groupOrderopcional, y las vistas pueden guardar estado adicional, como la columna de ordenación, que Obsidian gestiona por sí mismo. Añádelos a mano si los necesitas: el YAML es tuyo para editarlo.

    3. Filtros: and, or, not

    Un filtro es una sentencia de texto que es verdadera o falsa para cada nota, o un objeto con and, or o not que contiene una lista de más filtros. Los globales filters se aplican a todas las vistas. El filters se aplican solo a esa vista, y ambos se combinan con AND.

    filters:
  or:
    - file.hasTag("meeting")
    - file.inFolder("Meetings")

    No existe ningún from o source como en SQL o Dataview. Sin filtro, una base incluye todos los archivos del vault, así que define siempre uno salvo que quieras eso.

    Los valores de texto necesitan comillas dentro de la sentencia, así que el YAML necesita comillas anidadas: 'status == "done"'. El generador lo hace por ti. Los filtros de función como file.hasTag(), file.inFolder() y file.hasLink() están en la página de funciones.

    4. Fórmulas y resúmenes

    Cada entrada de formulas se convierte en una propiedad que puedes usar en todas las vistas como formula.name. Una fórmula puede usar otra fórmula, pero no se permiten referencias circulares, así que una fórmula no puede referirse a sí misma. El resultado se guarda como cadena YAML, por eso la expresión va entre comillas.

    formulas:
  formatted_price: 'if(price, price.toFixed(2) + " dollars")'

    El summaries asigna un resumen a una propiedad. La página de sintaxis enumera estos valores predeterminados:

    • Número: Average, Min, Max, Sum, Range, Median, Stddev
    • Fecha: Earliest, Latest, Range
    • Booleano: Checked, Unchecked
    • Cualquiera: Empty, Filled, Unique

    Para cálculos con fechas, la página de sintaxis dice file.mtime > now() - "1 week" es verdadero para un archivo modificado en la última semana.

    5. Qué significa esto

    En un filtro o una fórmula, this es el archivo en el que se muestra la base. Según la página de sintaxis, es el propio archivo de la base cuando esta se abre en el área de contenido principal, el archivo que la incrusta cuando la base está incrustada en una nota o un Canvas, y el archivo activo del área de contenido principal cuando la base está en la barra lateral. La página ofrece file.hasLink(this.file) como forma de replicar el panel de retroenlaces.

    6. Ejemplos que puedes copiar

    Estos son los ajustes predefinidos del generador como código simple, así que funcionan sin JavaScript. Sustituye los nombres de carpeta, etiqueta y propiedad por los tuyos. Guarda el texto como .base archivo, o envuélvelo en un base bloque de código. Consulta Crear una base para los comandos, e incrusta un archivo guardado con ![[Name.base]] o ![[Name.base#View]] para elegir la vista predeterminada.

    Lista de lectura

    filters:
  and:
    - file.inFolder("Reading")
    - 'status == "to read"'
properties:
  status:
    displayName: "Status"
views:
  - type: cards
    name: "Reading list"
    order:
      - file.name
      - status

    Notas con una etiqueta, modificadas esta semana

    filters:
  and:
    - file.hasTag("project")
    - 'file.mtime > now() - "1 week"'
views:
  - type: table
    name: "Modified this week"
    order:
      - file.name
      - file.mtime

    Retroenlaces de esta nota

    filters:
  and:
    - file.hasLink(this.file)
views:
  - type: table
    name: "Backlinks"
    order:
      - file.name
      - file.folder

    Notas de voz capturadas con Vox.md

    filters:
  and:
    - file.inFolder("Vox")
    - file.hasTag("voice")
views:
  - type: table
    name: "Voice notes"
    order:
      - file.ctime
      - file.name
      - file.tags

    La order list elige las columnas. El orden es un ajuste de la vista que cambias en la barra de herramientas de vistas de Obsidian, así que los ejemplos no escriben ninguno.

    7. Haz que tus capturas aparezcan en una base

    Vox.md guarda lo que capturas como notas Markdown en una carpeta de tu vault. Su Documentación de metadatos dice que una ruta puede añadir metadatos estáticos como key: value líneas, como tags: [journal, idea], y que Metadatos iniciales de la nota lo escribe a nivel de documento. También describe metadatos de ubicación opcionales. Una base filtrada por esa carpeta o etiqueta, como el último ejemplo de arriba, lista entonces tus capturas en una sola tabla. Crea los metadatos con el generador de propiedades, y consulta notas de voz en Obsidian en el iPhone para la configuración.

    Herramientas relacionadas: el generador de plantillas de nota diaria para crear notas con fecha, el generador de callouts y la Creador de tablas Markdown para el contenido de la nota.

    8. Solución de problemas

    • La base muestra todas las notas. No hay filtro de origen. Una base incluye todo el vault por defecto, así que añade un file.inFolder() o file.hasTag() filtro.
    • Una columna de propiedad está en blanco. El nombre no coincide, mayúsculas y minúsculas incluidas, o la nota no tiene esa propiedad en su frontmatter. Revisa las propiedades de la nota y el nombre de la columna.
    • Error de YAML. Revisa la sangría, que usa espacios, y las comillas. Un filtro que contiene texto necesita comillas anidadas: 'status == "done"'.
    • Una vista map está vacía. El diseño map necesita el complemento Maps, según la página de vistas.

    9. Preguntas

    ¿Bases es un complemento básico?

    Sí. Ayuda de Obsidian dice: «Bases es un complemento básico que te permite crear vistas de tus notas similares a una base de datos».

    ¿Bases o Dataview?

    Son distintos. Dataview es un complemento de la comunidad con su propio lenguaje de consultas. Una base es YAML que Obsidian lee por sí mismo, sin from clave: las notas se acotan con filtros. Esta página no compara más sus funciones.

    ¿Puedo editar el YAML a mano?

    Sí. Un .base es texto YAML, y la página de sintaxis documenta las claves. Abre el archivo generado en cualquier editor, o pega el bloque de código en una nota y edítalo allí.

    ¿El generador sube mis datos?

    No. Un script de esta página crea el YAML en tu dispositivo, y la página no hace solicitudes de red. Al recargar se borra todo.
