Generador de listas de verificación en Markdown: convierte cualquier lista en tareas, con fechas de vencimiento

Pega líneas simples, viñetas, elementos numerados o una lista de tareas existente y copia tareas - [ ] válidas, con la anidación conservada, una fecha de vencimiento opcional y un recuento de lo que está hecho.

Por
Cody Bontecou
Actualizado
24 de noviembre de 2026
Requiere
Cualquier navegador moderno, incluido Safari en iPhone. Opcional: Obsidian para las listas de verificación y Vox.md para iPhone o Mac para capturar tareas por voz.
La respuesta breve

Una tarea en Markdown es un guion, un espacio, corchetes, un espacio y el texto. Escribe - [ ] task para una tarea abierta y - [x] done para una terminada. Para convertir una lista entera en tareas, pégala en el generador de listas de verificación de abajo.

- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

El generador quita las viñetas, los números y las casillas existentes para que nada se duplique, conserva la sangría como anidación y puede añadir una fecha de vencimiento en el formato que lee tu plugin de Obsidian. Funciona por completo en esta página: la lista nunca se sube y la página no hace ninguna solicitud de red.

2. Sintaxis de listas de verificación en Markdown

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

Cada tarea es un elemento de lista: un guion y un espacio, y luego [ ] con un espacio entre los corchetes y después el texto. Obsidian Help página y GitHub Docs página lo describen como un guion y un espacio seguidos de [ ]. Para marcar una tarea como completada, GitHub Docs indica usar [x].

Los espacios importan. La especificación de GitHub Flavored Markdown define el marcador de la casilla como un corchete izquierdo, un carácter de espacio en blanco o la letra x, y un corchete derecho, y necesita un espacio en blanco antes del texto que sigue. Por tanto, [] sin nada dentro, o - [ ]text sin espacio después del corchete, no cumple la definición. El guion y su espacio son lo que convierte la línea en un elemento de lista.

Las listas de tareas no forman parte del Markdown básico. La misma especificación las marca como una extensión de CommonMark, y su introducción dice que las funciones que no están en la especificación original de CommonMark se marcan como extensiones. Un renderizador que no implementa la extensión muestra los corchetes como texto literal, que es el motivo habitual por el que una casilla aparece como [ ] en la página.

3. Listas de verificación en Obsidian

En Obsidian Help, la página sintaxis básica de formato trata las listas de tareas:

  • Una tarea empieza con un guion y un espacio seguidos de [ ].
  • Puedes usar cualquier carácter entre los corchetes para marcar la tarea como completada, así que [x], [-] y [?] cuentan.
  • Anidas una lista de tareas aplicando sangría a sus elementos. Usa Tab o Shift+Tab para aplicar o quitar la sangría de los elementos seleccionados.
  • Puedes marcar o desmarcar una tarea en la vista de lectura seleccionando su casilla.

La página de ayuda documenta que cualquier carácter completa una tarea. No describe un aspecto distinto para cada carácter. Si [-] o [?] se ve distinto de [x] en tu vault, eso viene de un tema o de un fragmento de CSS que has instalado, no del propio Markdown.

La línea de progreso del generador cuenta igual: cualquier carácter entre los corchetes que no sea un espacio se considera hecho, así que [x], [X], [-] y [?] están hechas y [ ] está abierta. Las líneas que empiezan con «done:» o «x » son texto normal; la herramienta no supone que signifiquen una tarea terminada.

4. Fechas de vencimiento: Tasks, Dataview y Reminder

La sintaxis de listas de tareas de Obsidian no tiene fecha de vencimiento propia: la página de ayuda no documenta ninguna. Tres plugins leen una fecha escrita en el texto de la tarea, cada uno con su propio formato. El generador escribe la fecha como ISO YYYY-MM-DD en los tres. Sin el plugin, la fecha es solo texto.

Elige el único plugin que uses. La página de Dataview también enumera sus propios atajos con emoji para las fechas y dice que son los únicos atajos que admite; el generador escribe en su lugar la forma con corchetes de Dataview. El README de Reminder dice que no recibes avisos de los recordatorios de tareas que ya has marcado.

5. Diferencias entre GitHub y Obsidian

GitHub Docs describe [ ] para una tarea abierta y [x] para marcar una como completada. La especificación GFM define el marcador como un espacio en blanco o la letra x entre los corchetes. Obsidian acepta cualquier carácter. Así, una tarea como - [-] skipped o - [?] unsure está completa en Obsidian, pero queda fuera de la definición de marcador de la especificación, y un renderizador que la siga puede mostrarla como texto literal. Si el archivo también se lee en GitHub, usa [ ] y [x] únicamente.

GitHub Docs añade una regla: si la descripción de una tarea empieza con un paréntesis, escápalo con una barra invertida, como en - [ ] \(Optional) Open a followup issue. El generador no añade la barra invertida por ti; avisa cuando una tarea empieza con un paréntesis.

7. Preguntas

¿Por qué mi casilla aparece como texto [ ]?

El renderizador no está mostrando listas de tareas. Las listas de tareas son una extensión de CommonMark, así que un renderizador sin ella muestra los corchetes. Comprueba que la línea empieza con un guion y un espacio, que hay un espacio o una x entre los corchetes y que un espacio sigue al corchete de cierre. En Obsidian, una tarea dentro de un bloque de código o de una celda de tabla puede no mostrarse como casilla, como sí ocurre con un elemento de lista.

¿Cómo anido tareas?

Aplica sangría a la tarea hija. En Obsidian, pulsa Tab para aplicar sangría a los elementos seleccionados y Shift+Tab para quitar la sangría. El generador convierte 2 o 4 espacios de tu lista en un tabulador por nivel, o en 2 o 4 espacios si lo prefieres.

¿Cómo marco una casilla con un carácter distinto de x?

Obsidian Help dice que cualquier carácter entre los corchetes marca la tarea como completada, así que - [-] task y - [?] task están hechas. El generador conserva el carácter que pegaste a menos que restablezcas la lista. Para archivos que también se leen en GitHub, usa [x].

¿Cómo añado una fecha de vencimiento que lea el plugin Tasks?

Pon 📅 y una fecha YYYY-MM-DD al final de la tarea, por ejemplo - [ ] send invoice 📅 2026-11-25. Elige «Plugin Tasks: vencimiento» arriba para añadirla a cada tarea. Usa ⏳ para una fecha programada y 🛫 para una fecha de inicio.

¿El generador sube mi lista?

No. La lista la convierte un script de esta página, en tu dispositivo, y la página no hace ninguna solicitud de red. No guarda tu lista: al cerrar o recargar la página se borra.
