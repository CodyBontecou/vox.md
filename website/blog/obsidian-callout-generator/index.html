Obsidian callout generator: every type, alias and folding option

Pick a type, add a title and body, choose folding and nesting, and copy a valid > [!type] callout, with the full list of types and aliases and how collapsible callouts work.

By
Cody Bontecou
Updated

Requires
Any modern browser, including Safari on iPhone. Optional: Obsidian for the callouts, and Vox.md for iPhone or Mac to capture notes by voice or text.
The short answer

A callout is a blockquote whose first line is > [!type] Optional title. Every following line starts with > . Add + or - right after the brackets to make it foldable. To build one without typing the prefixes, use the callout generator below.

> [!warning]- Back up first
> Copy the vault before you change the plugin settings.
>
> Then restart Obsidian.

The generator adds the > prefix to every line (repeated for nesting), keeps blank lines inside the callout, and does not double a > you pasted. It runs entirely in this page: your text is never uploaded, and the page makes no network requests.

2. Callout syntax

> [!type] Title
> Body line one.
> Body line two.
  • Type. The first line of a blockquote starts with the type in brackets after an exclamation mark: > [!info]. Obsidian Help says the type identifier is case-insensitive, and that an unsupported type falls back to note.
  • Title. Text after the brackets replaces the title. Without it, Obsidian shows the type identifier in title case, so > [!tip] shows “Tip”.
  • Body. Each following line begins with > . The body can hold Markdown, wikilinks and embeds.
  • Title-only. You can leave out the body: > [!tip] Remember to save is a complete callout.

4. Collapsible callouts: + vs -

Add a plus or a minus directly after the closing bracket:

> [!faq]+ Open by default
> This callout is foldable and starts expanded.

> [!faq]- Closed by default
> This callout is foldable and starts collapsed.

Obsidian Help describes + as foldable and expanded by default, and - as foldable and collapsed by default. With neither, the callout is not foldable. The + or - is part of the Markdown, so it stays in the file.

5. Nested callouts, lists, code and embeds

For a nested callout, add another > for each level:

> [!question] Can callouts be nested?
> > [!example] Yes
> > Add one more > for each level.

The generator’s “Nest inside another callout” setting writes the extra > on every line, up to three levels. Paste the result inside the outer callout’s body.

Lists, code and other Markdown go inside the body, with the > prefix on every line. Obsidian Help says the body can contain Markdown, wikilinks and embeds, and that you can wrap existing content, lists and code blocks included, by selecting it and running the Insert callout command. Paste a list or code block into the generator’s body field and it adds the prefixes for you:

6. Custom callout types with a CSS snippet

A type you invent renders with the note style. Obsidian Help says custom callouts are defined in a CSS snippet or a community plugin. Its example:

.callout[data-callout="custom-question-type"] {
  --callout-color: #000000;
  --callout-icon: lucide-alert-circle;
}

Per the Help page, --callout-color accepts any valid CSS colour, and --callout-icon takes an icon ID from lucide.dev or an SVG element. Then write > [!custom-question-type] in a note. Type the same name into the generator’s custom type field.

7. GitHub alerts vs Obsidian callouts

GitHub has a similar feature called alerts. GitHub Docs lists five: NOTE, TIP, IMPORTANT, WARNING and CAUTION.

> [!NOTE]
> Useful information that users should know, even when skimming content.

That page documents no folding and no custom title, and no custom types; Obsidian callouts have all three. The first line looks the same, so a basic > [!note] or > [!warning] often works in both, but an Obsidian-only type such as [!bug], a +/- fold or a title is outside what GitHub documents. If a file is read on both, stay with the five GitHub types and no extras.

9. Questions

Why isn’t my callout rendering?

Check three things. The first line must start with > and then [!type], with the exclamation mark and no space inside the brackets. Every body line needs its own >. A blank line with no > ends the blockquote, so the lines after it are ordinary text; write it as >. If it still shows as a plain blockquote, check for a space or a typo between > and [!.

Can a callout have no title?

Not quite: leave the title out and Obsidian shows the type identifier in title case instead. To hide the title you need CSS; Obsidian Help says further styling, such as hiding the title, can use standard CSS selectors. The generator leaves the title empty when you do, so you get the default.

Admonition plugin or native callouts?

Native callouts need no plugin and use the > [!type] syntax on this page. The Admonition plugin is a separate community plugin with its own syntax, which this page does not cover. Obsidian Help says custom callout types can also come from a community plugin.

Do callouts work on Obsidian mobile and in Publish?

Obsidian Help says callouts are supported natively on Obsidian Publish. Its callouts page does not mention mobile either way, so this page makes no claim about it.

Does the generator upload my text?

No. A script in this page builds the callout on your device, and the page makes no network requests. It does not save anything: reloading the page clears it.
