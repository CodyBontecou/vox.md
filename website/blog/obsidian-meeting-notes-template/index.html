2. Add the template to Obsidian

Core Templates plugin. Turn on Templates in Settings → Core plugins, then set Template folder location, for example Templates. Save the template there as a .md file. In a new note, run Templates: Insert template from the command palette and pick it. Obsidian replaces {{title}}, {{date}} and {{time}} when you insert the template. A format after a colon, such as {{date:YYYY-MM-DD}}, uses Moment.js tokens. See the Templates plugin help and the Moment.js format tokens.

Templater plugin. Install Templater from Community plugins and set its Template folder location. Insert the template with Templater: Open insert template modal. To give every new note in Meetings/ this template, turn on Trigger Templater on new file creation, set Template matching mode to folder templates, and map the Meetings folder to the file. The Templater settings documentation explains folder templates, and the date module documents tp.date.now.

Properties. The frontmatter between the --- lines becomes note properties. A link in a property must be in quotes, which is why the project field is written "[[Project name]]". See Properties in Obsidian Help. To check frontmatter you already have, use the properties generator and checker.

3. One note per meeting

Keep meetings in one folder, such as Meetings/, and put the date and the start time in the file name: Meetings/2026-11-19 1430 Design review.md. Names in this order sort by date, and two meetings on the same day never share a file.

Turn on Link to the daily note in the generator to add a Daily note: line that links to that day’s note. The link uses YYYY-MM-DD; if your daily notes use a different date format, change it to match; the daily note template generator previews the file name a format produces. To list the day’s meetings in the daily note too, link them from there; append to an Obsidian daily note shows how Vox.md can add entries to it.

4. Action items and follow-up

Write each action item as an Obsidian task, - [ ] Send the release notes, and tick it off as - [x] when it is done; see Basic formatting syntax. Put the owner first so each line reads as who does what.

The optional style adds a due date in the format of the community Tasks plugin: 📅 followed by YYYY-MM-DD. The generator fills in the meeting date; change it to the real due date. Without the Tasks plugin, the emoji and date are plain text and the task still works.

To collect open items from every meeting in one place, add a Tasks query to a note:

```tasks
not done
path includes Meetings
```

The query lists unfinished tasks from notes whose path contains Meetings. Dataview can build similar lists if you already use it.

5. Fill the note from a recording

A template gives you the headings. Vox.md can write the note itself: it records the meeting, transcribes it on your device and saves a Markdown file to your vault through a Route.

  1. Record. On a Mac, Vox.md can record one call app and your microphone as separate tracks; follow transcribe Mac meetings locally into Obsidian. For a meeting in the room, record with the microphone on iPhone or iPad; see save iPhone voice notes to Obsidian.
  2. Choose the destination. In the Route, pick your vault, choose New Note, and enter a path such as Meetings/{date}-{hour}{minute}.md. {date} is written as 2026-11-19 and {hour}{minute} as 1430. These are Vox.md tokens, not Moment.js formats. See Obsidian capture templates for more path recipes.
  3. Choose the mode. Set the Route’s processing mode to Meeting Notes. It produces a ## Notes section and, when the transcript contains action items, a ## Action Items checklist. It uses Apple Intelligence on compatible hardware with macOS 26 or iOS 26; otherwise a deterministic formatter builds the structure.

Meeting Notes does not fill in an agenda, attendees or decisions for you. If you want those headings above the notes, choose Plain Markdown in the generator, untick Notes and Action Items, and save the result in your vault. Then select that file as the Route’s vault template. Vox.md fills its single-brace tokens in the template and writes the processed transcript below it. Check the first note before you rely on the layout; the Routes documentation covers destinations and templates.

Tell everyone in the meeting that you are recording and transcribing, and get their consent first. Rules differ by place and workplace; see tell people you are recording.

6. Questions

Should I use Core Templates or Templater?

Core Templates ships with Obsidian and covers the title, date and time. Templater is a community plugin that adds scripting, date offsets and folder templates, so a new note in Meetings/ can get the template automatically. If you only need the fields on this page, Core Templates is enough.

Why doesn’t {{date}} change later?

Obsidian replaces template variables once, when you insert the template. The note then holds plain text, such as 2026-11-19, and keeps it. That is what you want for a meeting record.

Can Vox.md use my Obsidian template?

Partly. A Route can use a Markdown file from your vault as its template. Vox.md fills its own single-brace tokens, such as {date}, and the Templater date commands tp.date.now and tp.file.creation_date. It does not run other Templater commands, such as tp.file.title, and it does not expand core Templates variables such as {{title}}, so keep those out of a Route’s template. Use the Plain Markdown output for a Vox.md Route.

Does the generator send my choices anywhere?

No. The template is built by a script in this page. It saves your last choices in your browser’s local storage, so they are still there next time, and Reset clears them.
