Obsidian note properties (YAML frontmatter) generator and checker

Generate properties in the format Obsidian expects, or check frontmatter you already have and see why a property does not show as the type you meant.

By
Cody Bontecou
Updated
November 22, 2026
Requires
Obsidian (any platform). Optional: Vox.md for iPhone, Apple Watch or Mac to add properties to captured notes.
The short answer

Obsidian note properties are YAML at the very top of a note, between two --- lines. Each property is a name: value pair, a list has one - value line per item, and an internal link must be in quotes. This example is valid:

---
tags:
  - journal
  - idea
aliases:
  - Weekly review
date: 2026-11-21
project: "[[Vox.md launch]]"
published: true
---

Need other properties, or want to know why one is not showing as the type you meant? The generator below writes the YAML, and the checker lists line-numbered problems with a fix. Both run entirely in this page: nothing you type is sent anywhere. The rules come from Obsidian Help, Properties and Tags.

    2. Check frontmatter you already have

    Paste the top of a note, including the --- lines. The checker reads the block line by line and lists each problem with the line number and a fix. It uses a fixed set of line rules, not a full YAML parser, so it can miss an error that a parser would find, and it only checks the rules listed here.

    The checker looks for: tabs used for indentation, a missing opening or closing ---, internal links without quotes, tags with spaces, a # prefix, other characters tags cannot contain or only numbers, the deprecated names tag, alias and cssclass, nested objects, Markdown formatting in values, duplicate names, and a few values YAML itself reads differently from what you meant. Template tokens such as {{date}} and <% %> are skipped.

    3. Property types and how each is written

    Obsidian supports seven property types. Each is written in the YAML like this:

    Obsidian also has three default properties: tags, aliases and cssclasses. The generator has a button for each.

    4. The rules that break properties most often

    • Put internal links in quotes. project: "[[Vox.md launch]]", not project: [[Vox.md launch]]. This applies to text properties and to items in a list.
    • One list item per line. Each item starts with a hyphen and a space, indented under the property name. Use spaces to indent, not tabs.
    • Tags have their own rules. No # in the YAML, no spaces, and at least one non-numeric character: 1984 is not a valid tag but y1984 is. Use / for nested tags such as inbox/to-read. See Tags in Obsidian Help.
    • Write dates in the stored format. 2026-11-21 for a date and 2026-11-21T10:30:00 for a date and time.
    • Use the current names. tag, alias and cssclass were deprecated in Obsidian 1.4 in favor of tags, aliases and cssclasses, and support for them as default properties was dropped in Obsidian 1.9.
    • Do not nest. Properties do not support nested objects. Obsidian suggests source mode to view nested properties, so flatten them into top-level names such as project_status.
    • Do not use Markdown. Bold, links and other formatting are not rendered in properties. Obsidian describes this as intentional, because properties are meant for small, atomic bits of information.

    5. Using properties in templates

    Turn on Template plugin tokens in the generator to write date fields as a token instead of a fixed date. The core Templates plugin uses {{date:YYYY-MM-DD}}; the Templater community plugin uses <% tp.date.now("YYYY-MM-DD") %> (see the Templater documentation). Date & time fields use YYYY-MM-DD[T]HH:mm:ss in the token, with the T in square brackets so it is written as a letter.

    Links need care here. Obsidian adds the quotes for a link you type in the Properties UI, but a template plugin writes text into the file as it is, so write the quotes yourself in the template: project: "[[Vox.md launch]]".

    For whole templates that use these properties, see the daily note template generator and the meeting notes template generator.

    6. Add properties to notes you capture

    In a Vox.md Route, the Metadata field takes one key: value pair per line, such as tags: [journal, idea]. Note Frontmatter writes the metadata at document scope. Inline Entry Fields writes key:: value fields beside each entry in a rolling note. See Metadata in the Routes reference.

    The generator’s Copy as Vox.md Route metadata button writes your properties in that shape, with lists as [a, b] and one property per line. Vox.md’s documentation describes the field as key: value lines; this page does not test how each property type is written, so open the first captured note in Obsidian and check it. Routes for a daily note and an inbox are covered in Append to an Obsidian daily note, capture templates and iPhone voice notes to Obsidian.

    7. Questions

    Why does Obsidian not show my property as the type I meant?

    Obsidian reads properties as YAML, and a value that does not follow the rules for its type is not shown as that type. The usual causes are an unquoted link, a list not written one item per line, a date not in YYYY-MM-DD, and tags with spaces. Paste the block into the checker above to find the line.

    Do tags need a # in properties?

    No. In the YAML, tags are written as plain words, such as - recipe. The # is for tags in the body of a note.

    Can I nest properties?

    No. Properties do not support nested objects. Use flat names, or nested tags with / inside the tags list.

    Can I write properties as JSON?

    Obsidian can read a JSON block, but it reads and saves it as YAML. The checker above only applies its line rules to YAML.
