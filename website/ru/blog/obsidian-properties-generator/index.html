Генератор и проверка свойств заметок Obsidian (frontmatter YAML)

Создайте свойства в формате, который ожидает Obsidian, или проверьте уже имеющийся frontmatter и узнайте, почему свойство показывается не с тем типом.

Короткий ответ

Свойства заметки в Obsidian — это YAML в самом начале заметки, между двумя строками --- строк. Каждое свойство — это name: value пара, а у списка по одной - value строка на элемент, а внутренняя ссылка должна быть в кавычках. Этот пример корректен:

---
tags:
  - journal
  - idea
aliases:
  - Weekly review
date: 2026-11-21
project: "[[Vox.md launch]]"
published: true
---

Нужны другие свойства или хотите узнать, почему свойство показывается не с тем типом? Генератор ниже записывает YAML, а проверка перечисляет проблемы с номерами строк и исправлением. Оба работают целиком на этой странице: ничего из введённого не отправляется. Правила взяты из справки Obsidian, Свойства и Теги.

    2. Проверка frontmatter, который у вас уже есть

    Вставьте начало заметки, включая строки --- строк. Проверка читает блок построчно и перечисляет каждую проблему с номером строки и исправлением. Она использует фиксированный набор правил для строк, а не полноценный парсер YAML, поэтому может пропустить ошибку, которую нашёл бы парсер, и проверяет только перечисленные здесь правила.

    Проверка ищет: табуляцию в отступах, отсутствующую открывающую или закрывающую ---, внутренние ссылки без кавычек, теги с пробелами, # префикс, другие недопустимые в тегах символы или одни цифры, устаревшие имена tag, alias и cssclass, вложенные объекты, форматирование Markdown в значениях, повторяющиеся имена и несколько значений, которые сам YAML читает иначе, чем вы задумали. Токены шаблонов, такие как {{date}} и <% %> пропускаются.

Свойство без имени пропускается. {name} встречается более одного раза. Оставьте одну строку для каждого свойства. {name} не является числом, поэтому поле оставлено пустым. Тег «{from}» записан как {to}, потому что теги не могут содержать пробелы и префикс # и должны включать нецифровой символ. Тег, который не удалось сделать допустимым, пропущен: {from} Для {name} нужны и дата, и время, поэтому поле оставлено пустым. Проблем не найдено. Вставьте frontmatter для проверки. Это похоже на JSON. Obsidian читает его и сохраняет как YAML. Правила для строк здесь относятся к YAML, поэтому для проверки вставьте версию в YAML. Найдено проблем: {n} Строка {line} Исправление: Блок не начинается со строки ---. Свойства находятся между двумя строками --- в начале заметки. Добавьте --- отдельной строкой перед первым свойством. После свойств нет закрывающей строки ---. Добавьте --- отдельной строкой после последнего свойства. Эта строка начинается с отступа-табуляции. YAML не допускает табуляцию в отступах. Замените каждую ведущую табуляцию пробелами, например двумя. Эта строка не является парой имя: значение. Запишите как имя: значение, с пробелом после двоеточия. Свойство {key} уже задано в строке {first}. Оставьте одну строку {key} и объедините значения в ней. {key} — устаревшее имя свойства. Оно признано устаревшим в Obsidian 1.4, а поддержка в качестве свойства по умолчанию удалена в 1.9. Переименуйте в {fixed}. Внутреннюю ссылку в свойстве нужно заключать в кавычки. Запишите как {fixed} Теги в свойствах записываются без префикса #. Запишите {fixed} Тег {tag} содержит пробел. Теги не могут содержать пробелы. Используйте дефис, например {fixed}, или поставьте каждый тег на отдельную строку. В теге {tag} нет нецифровых символов. Тег должен содержать хотя бы один. Добавьте букву, например {fixed} Тег {tag} содержит недопустимый символ. В тегах можно использовать буквы, цифры, подчёркивание, дефис и / для вложенности. Удалите или замените, например {fixed} {key} содержит вложенный объект. Свойства не поддерживают вложенные объекты. Разверните в отдельные свойства верхнего уровня или отредактируйте в режиме исходного кода. Значение содержит форматирование Markdown ({sample}). Свойства не отображают Markdown — так задумано. Удалите символы форматирования и оставьте простой текст. Это значение без кавычек содержит двоеточие и пробел после него, и YAML воспринимает их как начало другого имени. Заключите значение в кавычки: {fixed} Это значение без кавычек начинается с {char}, а YAML обрабатывает этот символ особым образом. Заключите значение в кавычки: {fixed} В этой строке кавычка открыта, но не закрыта. Добавьте закрывающую кавычку. В YAML пробел, за которым следует #, начинает комментарий, поэтому остаток строки не входит в значение. Если # входит в значение, заключите значение в кавычки: {fixed} Пример с ошибками загружен.

    3. Типы свойств и как записывается каждый

    Obsidian поддерживает семь типов свойств. В YAML каждый записывается так:

    ТипПример YAMLПодвох
    Текстtitle: Weekly reviewЗаключайте в кавычки значение, которое YAML поймёт неверно, например такое, где есть : в нём, или значение, которое начинается с #. Внутренние ссылки должны быть в кавычках.
    Списокtopics:
      - sleep
      - focus    		Каждое значение на отдельной строке, перед ним дефис и пробел.
    Числоrating: 4Запишите число без кавычек.
    Флажокpublished: trueЗначение — true или false.
    Датаdate: 2026-11-21Формат такой: YYYY-MM-DD.

    В Obsidian также есть три свойства по умолчанию: tags, aliases и cssclasses. В генераторе для каждого есть кнопка.

    4. Правила, которые чаще всего ломают свойства

    • Заключайте внутренние ссылки в кавычки. project: "[[Vox.md launch]]", а не project: [[Vox.md launch]]. Это относится к текстовым свойствам и к элементам списка.
    • Один элемент списка на строку. Каждый элемент начинается с дефиса и пробела и имеет отступ под именем свойства. Для отступа используйте пробелы, не табуляцию.
    • У тегов свои правила. Нет # в YAML, без пробелов и хотя бы с одним нецифровым символом: 1984 не является допустимым тегом, а y1984 — так. Используйте / для вложенных тегов, таких как inbox/to-read. См. Теги в справке Obsidian.
    • Записывайте даты в хранимом формате. 2026-11-21 для даты и 2026-11-21T10:30:00 для даты и времени.
    • Используйте текущие имена. tag, alias и cssclass были признаны устаревшими в Obsidian 1.4 в пользу tags, aliases и cssclasses, а поддержка их в качестве свойств по умолчанию удалена в Obsidian 1.9.
    • Не вкладывайте. Свойства не поддерживают вложенные объекты. Obsidian советует смотреть вложенные свойства в режиме исходного кода, поэтому разверните их в имена верхнего уровня, например project_status.
    • Не используйте Markdown. Жирный текст, ссылки и другое форматирование в свойствах не отображаются. В Obsidian говорят, что так задумано: свойства предназначены для небольших атомарных фрагментов информации.

    5. Свойства в шаблонах

    Включите Токены плагинов шаблонов в генераторе, чтобы записывать поля дат как токен, а не фиксированную дату. Основной плагин «Шаблоны» использует {{date:YYYY-MM-DD}}; плагин сообщества Templater использует <% tp.date.now("YYYY-MM-DD") %> (см. Templater документация). Поля «Дата и время» используют YYYY-MM-DD[T]HH:mm:ss в токене, с T в квадратных скобках, чтобы оно записывалось как буква.

    Со ссылками нужна осторожность. Obsidian сам добавляет кавычки к ссылке, введённой в интерфейсе свойств, но плагин шаблонов записывает текст в файл как есть, поэтому кавычки в шаблоне нужно поставить самому: project: "[[Vox.md launch]]".

    Готовые шаблоны, использующие эти свойства, смотрите в генератор шаблона ежедневной заметки и генератор шаблона заметок о встрече.

    6. Добавляйте свойства в захваченные заметки

    В Route в Vox.md поле «Метаданные» принимает один key: value пару в каждой строке, например tags: [journal, idea]. Frontmatter заметки записывает метаданные на уровне документа. Встроенные поля записи записывает key:: value поля рядом с каждой записью в сквозной заметке. См. Метаданные в справочнике по Route.

    Кнопка генератора Копировать как метаданные Route в Vox.md записывает ваши свойства в таком виде, а списки как [a, b] и по одному свойству на строку. В документации Vox.md это поле описано как key: value строк; эта страница не проверяет, как записывается каждый тип свойства, поэтому откройте первую захваченную заметку в Obsidian и проверьте её. Route для ежедневной заметки и для входящих описаны в Добавляйте записи в ежедневную заметку Obsidian, шаблоны захвата и Голосовые заметки с iPhone в Obsidian.

    Добавлять эти свойства в каждую захваченную заметку.

    7. Вопросы

    Почему Obsidian показывает свойство не с тем типом, который я имел в виду?

    Obsidian читает свойства как YAML, а значение, не соответствующее правилам своего типа, не показывается как этот тип. Обычные причины: ссылка без кавычек, список не по одному элементу на строку, дата не в формате YYYY-MM-DD, а также теги с пробелами. Вставьте блок в проверку выше, чтобы найти нужную строку.

    Нужен ли # у тегов в свойствах?

    Нет. В YAML теги записываются обычными словами, например - recipe. # предназначен для тегов в тексте заметки.

    Можно ли вкладывать свойства?

    Нет. Свойства не поддерживают вложенные объекты. Используйте плоские имена или вложенные теги с / внутри tags списка.

    Можно ли записывать свойства в JSON?

    Obsidian может прочитать блок JSON, но читает и сохраняет его как YAML. Проверка выше применяет свои правила для строк только к YAML.
