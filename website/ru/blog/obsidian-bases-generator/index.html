Генератор Obsidian Bases: фильтры, представления и формулы

Создайте YAML для базы Obsidian, не изучая схему заранее: выберите фильтры, добавьте представления, скопируйте файл .base или блок кода и узнайте, что делает каждый ключ, по ссылкам на документацию Obsidian.

Автор:
Cody Bontecou
Обновлено
28 ноября 2026 г.
Требуется
Любой современный браузер, включая Safari на iPhone. По желанию: Obsidian с базовым плагином Bases и Vox.md для iPhone или Mac, чтобы записывать заметки голосом или текстом.
Короткий ответ

База — это представление ваших заметок в стиле базы данных, написанное на YAML и содержащее до пяти ключей верхнего уровня: filters, formulas, properties, summaries и views. Сохраните YAML как .base файл или вставьте его в заметку внутри base блок кода. Блок генератор ниже создаст его для вас. Нужная версия Obsidian зависит от типа представления: страница представлений указывает Table и Cards начиная с 1.9, List и Map с 1.10 и Kanban с 1.14.

filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

Генератор работает целиком на этой странице. Ничто из введённого не загружается, и страница не делает сетевых запросов.

Дайте название каждому представлению. Добавьте хотя бы одно представление, иначе база ничего не покажет. Формула {name} ссылается на саму себя. Obsidian не допускает циклических ссылок. Название формулы {name} должно начинаться с буквы или подчёркивания и содержать только буквы, цифры и подчёркивания. У формулы {name} нет выражения, поэтому она пропущена. Две формулы называются {name}. Текст {value} содержит пробелы, поэтому записан как строка в кавычках. Текстовым значениям нужны кавычки. В строке фильтра пустое значение, поэтому она пропущена. Свойство groupBy {name} отсутствует в списке order представления {n}. База работает, но столбец не отображается. {name} не входит в документированные итоги. Выберите один из списка. Фильтр источника не задан, поэтому база включает все заметки хранилища. Добавьте фильтр по папке или тегу, чтобы сузить выборку. Для типа представления map нужен плагин Maps. На странице представлений тип представления kanban указан как доступный начиная с Obsidian 1.14. Название свойства {name} содержит пробелы. Проверьте, как Obsidian называет это свойство, прежде чем на него полагаться. Проблем не найдено.

    2. Синтаксис Bases вкратце

    Вот ключи, которые страница синтаксиса Obsidian описывает. Других схем изучать не нужно.

    КлючЧто делаетПример
    filtersСужает набор заметок для всех представлений.file.hasTag("project")
    formulasОпределяет вычисляемые свойства, используемые как formula.name.total: 'price * qty'
    propertiesНастройки для отдельных свойств. displayName задаёт заголовок столбца.displayName: "Status"
    summariesОпределяет собственные формулы итогов с помощью values.Свой вариант, необязательно
    viewsСписок представлений одних и тех же заметок.- type: table
    type (представление)Макет представления.table, cards, list
    name (представление)Название представления.name: "Projects"
    filters (представление)Фильтры только для этого представления.file.inFolder("Work")
    groupBy (представление)Группирует строки по property в direction.direction: DESC
    order (представление)Отображаемые свойства по порядку.- file.name
    limit (представление)Ограничивает число строк.limit: 10
    summaries (представление)Сопоставляет свойство с итогом.price: Sum

    Генератор записывает не все документированные ключи. На странице синтаксиса также описаны groupOrder, а представления могут хранить дополнительное состояние, например столбец сортировки, которым управляет сам Obsidian. Добавляйте их вручную при необходимости: YAML можно свободно править.

    3. Фильтры: and, or, not

    Фильтр — это текстовое выражение, истинное или ложное для каждой заметки, либо объект с and, or или not со списком дополнительных фильтров. Глобальные filters действуют для всех представлений. Собственный filters действуют только для этого представления, а два набора объединяются через AND.

    filters:
  or:
    - file.hasTag("meeting")
    - file.inFolder("Meetings")

    Нет from или source ключа, как в SQL или Dataview. Без фильтра база включает все файлы хранилища, поэтому всегда задавайте его, если только это не нужно.

    Текстовые значения внутри выражения нужны в кавычках, поэтому в YAML нужны вложенные кавычки: 'status == "done"'. Генератор делает это за вас. Функциональные фильтры, такие как file.hasTag(), file.inFolder() и file.hasLink() находятся на страница функций.

    4. Формулы и итоги

    Каждая запись в formulas становится свойством, которое можно использовать во всех представлениях как formula.name. Формула может использовать другую формулу, но циклические ссылки запрещены, поэтому формула не может ссылаться на саму себя. Результат хранится как строка YAML, поэтому выражение пишется в кавычках.

    formulas:
  formatted_price: 'if(price, price.toFixed(2) + " dollars")'

    Ключ summaries сопоставляет свойство с итогом. На странице синтаксиса перечислены такие значения по умолчанию:

    • Число: Average, Min, Max, Sum, Range, Median, Stddev
    • Дата: Earliest, Latest, Range
    • Логическое: Checked, Unchecked
    • Любое: Empty, Filled, Unique

    Для вычислений с датами на странице синтаксиса сказано: file.mtime > now() - "1 week" истинно для файла, изменённого за последнюю неделю.

    5. Что это значит

    В фильтре или формуле this — это файл, в котором показана база. На странице синтаксиса сказано, что это сам файл базы, если она открыта в основной области содержимого; файл, в который база встроена, если она встроена в заметку или Canvas; и активный файл основной области, если база находится в боковой панели. На странице приведён file.hasLink(this.file) как способ воспроизвести панель обратных ссылок.

    6. Примеры для копирования

    Это шаблоны генератора в виде обычного кода, поэтому они работают без JavaScript. Замените названия папок, тегов и свойств своими. Сохраните текст как .base файл или оберните его в base блок кода. См. Создать базу с описанием команд, а сохранённый файл встраивайте с помощью ![[Name.base]] или ![[Name.base#View]] чтобы выбрать представление по умолчанию.

    Список чтения

    filters:
  and:
    - file.inFolder("Reading")
    - 'status == "to read"'
properties:
  status:
    displayName: "Status"
views:
  - type: cards
    name: "Reading list"
    order:
      - file.name
      - status

    Проекты по статусу

    filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

    Заметки с тегом, изменённые на этой неделе

    filters:
  and:
    - file.hasTag("project")
    - 'file.mtime > now() - "1 week"'
views:
  - type: table
    name: "Modified this week"
    order:
      - file.name
      - file.mtime

    Обратные ссылки этой заметки

    filters:
  and:
    - file.hasLink(this.file)
views:
  - type: table
    name: "Backlinks"
    order:
      - file.name
      - file.folder

    Голосовые заметки, записанные в Vox.md

    filters:
  and:
    - file.inFolder("Vox")
    - file.hasTag("voice")
views:
  - type: table
    name: "Voice notes"
    order:
      - file.ctime
      - file.name
      - file.tags

    Эта order list выбирает столбцы. Порядок сортировки — настройка представления, которую вы меняете на панели инструментов Obsidian, поэтому в примерах она не задана.

    7. Сделайте так, чтобы ваши записи Capture появлялись в базе

    Vox.md сохраняет всё, что вы записываете, как заметки Markdown в папке вашего хранилища. Его Документация по метаданным сказано, что Route может добавлять статические метаданные как key: value строки, например tags: [journal, idea]и что Frontmatter заметки записывает его на уровне документа. Также описаны необязательные метаданные местоположения. База, отфильтрованная по этой папке или тегу, как в последнем примере выше, покажет ваши записи Capture в одной таблице. Соберите метаданные с помощью генератор свойстви см. голосовые заметки в Obsidian на iPhone с описанием настройки.

    Связанные инструменты: генератор шаблона ежедневной заметки для создания заметок с датой, генератор выносок и Конструктор таблиц Markdown для содержимого заметки.

    Хотите заметки, по которым удобно делать запросы?

    Vox.md записывает голос и текст на iPhone и Mac прямо в ваше хранилище в формате Markdown с выбранными вами свойствами. Для записи, транскрипции и Capture нужен Vox.md Unlimited; подходящим аккаунтам доступен бесплатный пробный период 7 дней.

    8. Устранение неполадок

    • База показывает все заметки. Фильтр источника не задан. По умолчанию база включает всё хранилище, поэтому добавьте file.inFolder() или file.hasTag() фильтр.
    • Столбец свойства пуст. Название не совпадает (с учётом регистра) или у заметки нет этого свойства во frontmatter. Проверьте свойства заметки и название столбца.
    • Ошибка YAML. Проверьте отступы (они делаются пробелами) и кавычки. Фильтр с текстом требует вложенных кавычек: 'status == "done"'.
    • Представление map пусто. Согласно странице представлений, для макета map нужен плагин Maps.

    9. Вопросы

    Bases — это базовый плагин?

    Да. Справка Obsidian сказано: «Bases — это базовый плагин, который позволяет создавать представления ваших заметок, похожие на базы данных».

    Bases или Dataview?

    Это разные вещи. Dataview — плагин сообщества со своим языком запросов. База — это YAML, который Obsidian читает сам, без from ключ: заметки сужаются фильтрами. Эта страница не сравнивает их возможности подробнее.

    Можно ли править YAML вручную?

    Да. .base — это текст YAML, а ключи описаны на странице синтаксиса. Откройте созданный файл в любом редакторе или вставьте блок кода в заметку и правьте там.

    Загружает ли генератор мои данные?

    Нет. Скрипт на этой странице создаёт YAML на вашем устройстве, а сама страница не делает сетевых запросов. При перезагрузке всё очищается.
