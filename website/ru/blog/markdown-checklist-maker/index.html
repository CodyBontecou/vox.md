Генератор чек-листов в Markdown: превратите любой список в задачи со сроками

Вставьте простые строки, маркеры, нумерованные пункты или готовый список задач и скопируйте корректные задачи - [ ] с сохранённой вложенностью, необязательным сроком и подсчётом выполненного.

Любой современный браузер, включая Safari на iPhone. Дополнительно: Obsidian для чек-листов и Vox.md для iPhone или Mac, чтобы захватывать задачи голосом.
Короткий ответ

Задача в Markdown — это дефис, пробел, скобки, пробел и текст. Напишите - [ ] task для открытой задачи и - [x] done для выполненной. Чтобы превратить весь список в задачи, вставьте его в генератор чек-листов ниже.

- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

Генератор убирает существующие маркеры, номера и чекбоксы, чтобы ничего не дублировалось, сохраняет отступы как вложенность и может добавить срок в формате, который читает ваш плагин Obsidian. Он работает целиком на этой странице: список никогда не загружается, а страница не делает сетевых запросов.

2. Синтаксис чек-листов в Markdown

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

Каждая задача — элемент списка: дефис и пробел, затем [ ] с пробелом между скобками, затем текст. Obsidian Help страница и GitHub Docs страница оба описывают его как дефис и пробел, за которыми следует [ ]. Чтобы отметить задачу выполненной, GitHub Docs советует использовать [x].

Пробелы важны. спецификация GitHub Flavored Markdown определяет маркер чекбокса как левую скобку, пробельный символ или букву x, и закрывающей скобки, а перед текстом после неё нужен пробельный символ. Поэтому [] без содержимого или - [ ]text без пробела после скобки, не соответствует определению. Именно дефис и пробел после него делают строку элементом списка.

Списки задач не входят в базовый Markdown. Та же спецификация помечает их как расширение CommonMark, а во введении сказано, что возможности, которых нет в исходной спецификации CommonMark, помечены как расширения. Средство отображения без этого расширения показывает скобки как обычный текст — это обычная причина, по которой чекбокс выглядит как [ ] на странице.

3. Чек-листы в Obsidian

Страница Справки Obsidian базовому синтаксису форматирования посвящена спискам задач:

  • Задача начинается с дефиса и пробела, за которыми следует [ ].
  • Внутри скобок можно использовать любой символ, чтобы отметить задачу выполненной, поэтому [x], [-] и [?] — всё это считается выполненным.
  • Вложенный список задач делается отступами у элементов списка. Используйте Tab или Shift+Tab чтобы добавить или убрать отступ у выбранных пунктов.
  • Переключать задачу в режиме чтения можно, выбрав её чекбокс.

В справке описано, что любой символ отмечает задачу выполненной. Отдельный вид для каждого символа не описан. Если [-] или [?] выглядит иначе, чем [x] в вашем хранилище, это заслуга установленной вами темы или CSS-сниппета, а не самого Markdown.

Строка прогресса в генераторе считает так же: любой символ внутри скобок, кроме пробела, означает выполненную задачу, поэтому [x], [X], [-] и [?] выполнены, а [ ] — открытая. Строки, начинающиеся с «done:» или «x », — обычный текст; инструмент не считает, что они означают выполненную задачу.

4. Сроки: Tasks, Dataview и Reminder

В синтаксисе списков задач Obsidian нет собственной даты выполнения: страница справки её не описывает. Три плагина читают дату, записанную в тексте задачи, каждый в своём формате. Генератор записывает дату в формате ISO YYYY-MM-DD во всех. Без плагина дата — просто текст.

ФорматЧитаетПример строки
Срок: 📅 YYYY-MM-DDплагина сообщества Tasks, где сказано, что дата должна быть записана как YYYY-MM-DD (формат ISO)- [ ] send invoice 📅 2026-11-25
Запланировано: ⏳ YYYY-MM-DDплагина сообщества Tasks- [ ] send invoice ⏳ 2026-11-25
Начало: 🛫 YYYY-MM-DDплагина сообщества Tasks- [ ] send invoice 🛫 2026-11-25
Встроенное поле: [due:: YYYY-MM-DD]Dataview документация, который читает поля, записанные в задаче, например [completion:: 2021-08-15]- [ ] send invoice [due:: 2026-11-25]
Напоминание: (@YYYY-MM-DD) или (@YYYY-MM-DD HH:mm)obsidian-reminder плагин, в README которого показано (@2021-08-14) и (@2021-08-14 09:37) для неотмеченных задач- [ ] send invoice (@2026-11-25 09:30)

Выберите тот плагин, которым вы пользуетесь. На странице Dataview также перечислены его собственные эмодзи-сокращения для дат, и сказано, что других сокращений он не поддерживает; генератор вместо этого пишет форму Dataview со скобками. В README Reminder сказано, что уведомления о напоминаниях для уже отмеченных задач вы не получаете.

5. Различия между GitHub и Obsidian

GitHub Docs описывает [ ] для открытой задачи и [x] чтобы отметить задачу выполненной. Спецификация GFM определяет маркер как пробельный символ или букву x между скобками. Obsidian принимает любой символ. Поэтому задача вроде - [-] skipped или - [?] unsure в Obsidian считается выполненной, но выходит за определение маркера в спецификации, и средство отображения, следующее спецификации, может показать её как обычный текст. Если файл читают и на GitHub, используйте [ ] и [x] и только их.

GitHub Docs добавляет одно правило: если описание задачи начинается со скобки, поставьте перед ней обратную косую черту, как в - [ ] \(Optional) Open a followup issue. Генератор не добавляет обратную косую черту за вас; он предупреждает, если задача начинается со скобки.

Таблицы — ещё один синтаксис, где важны различия между Obsidian и GitHub. Чтобы превратить ячейки из электронной таблицы или CSV в таблицу, которая работает и в Obsidian, и на GitHub, используйте Конструктор таблиц Markdown.

Выделите итог или предупреждение над списком задач с помощью выноски: Генератор выносок Obsidian собирает > [!type] Markdown, включая сворачиваемые.

Голос расшифровывается на вашем устройстве. В Capture Bar Чеклист добавляет префикс - [ ] , а Настройте две даты вставляет (@yyyy-MM-dd) или форму со временем. Подробнее — Быстрый захват и Routes и режимы обработки в документации.

Route может добавлять пункты в вашу ежедневную заметку под заголовком, например ## Tasks; Добавляйте записи в ежедневную заметку Obsidian описывает настройку, а генератор шаблона ежедневной заметки записывает структуру заметки. О пунктах действий со встречи читайте в шаблон заметок о встрече; о рецепте префикса для списка задач читайте в шаблоны захвата.

Vox.md записывает форму (@yyyy-MM-dd) из своей документации. Он не записывает даты эмодзи плагина Tasks и поля Dataview. Если вы пользуетесь одним из них, вставьте захваченные задачи в генератор выше и выберите этот формат или отредактируйте дату позже. 7. Вопросы

Почему мой чекбокс отображается как текст [ ]?

Средство отображения не показывает списки задач. Списки задач — расширение CommonMark, поэтому без него показываются скобки. Проверьте, что строка начинается с дефиса и пробела, что между скобками есть пробел или x между скобками и что после закрывающей скобки идёт пробел. В Obsidian задача в блоке кода или в ячейке таблицы может не отображаться как чекбокс, в отличие от элемента списка.

Как сделать вложенные задачи?

Сделайте отступ у дочерней задачи. В Obsidian нажмите Tab чтобы сделать отступ у выбранных пунктов, и Shift+Tab чтобы убрать отступ. Генератор превращает 2 или 4 пробела в вашем списке в одну табуляцию на уровень или, по желанию, в 2 или 4 пробела.

Как отметить чекбокс символом, отличным от x?

Справка Obsidian сообщает, что любой символ внутри скобок отмечает задачу выполненной, поэтому - [-] task и - [?] task выполнены. Генератор сохраняет вставленный вами символ, если вы не сбросите список. Для файлов, которые читают и на GitHub, используйте [x].

Как добавить срок, который читает плагин Tasks?

Поставьте 📅 и дату в формате YYYY-MM-DD в конце задачи, например - [ ] send invoice 📅 2026-11-25. Выберите выше «Плагин Tasks: срок», чтобы добавить её к каждой задаче. Используйте ⏳ для запланированной даты и 🛫 для даты начала.

Загружает ли генератор мой список?

Нет. Список преобразуется скриптом на этой странице, на вашем устройстве, а сама страница не делает сетевых запросов. Список не сохраняется: при закрытии или перезагрузке страницы он очищается.
