Obsidian용 Markdown 표 만들기: Excel, Sheets, CSV에서 붙여넣기

Excel, Google Sheets, Numbers, CSV 또는 TSV의 행을 붙여넣고 유효한 파이프 표를 복사하세요. [[Note|Alias]]와 ![[image.png|300]]의 세로 막대는 이스케이프되고, 줄바꿈은 처리되며, 열마다 정렬을 지정할 수 있습니다.

    2. Markdown 표 문법

    | Name   | Qty | Price |
| :----- | :-: | ----: |
| Apple  |   3 |  1.20 |
| Pear   |  12 |  0.80 |

    해당 GitHub Flavored Markdown 사양 은(는) 표를 헤더 행 하나, 헤더와 데이터를 구분하는 구분선 행, 그리고 0개 이상의 데이터 행으로 정의합니다. 셀은 파이프로 구분합니다.

    • 구분선 행. 셀에는 하이픈만 들어가며, 왼쪽, 오른쪽 또는 양쪽 끝에 콜론을 선택적으로 붙여 왼쪽, 오른쪽, 가운데 정렬을 지정합니다. Obsidian Help 문서 에 따르면 헤더 행에 콜론을 추가해 텍스트를 정렬하며, 헤더 행에는 하이픈이 최소 두 개 있어야 합니다.
    • 바깥쪽 파이프. 양쪽 끝의 파이프는 사양상 선택 사항입니다. Obsidian Help는 가독성을 위해 넣기를 권장하며, 이 도구는 항상 파이프를 씁니다.
    • 패딩. Obsidian Help에 따르면 셀이 완벽하게 정렬될 필요는 없습니다. 이 도구의 “Pad columns” 레이아웃은 소스를 읽기 쉽게 정렬할 뿐이며, “Compact”는 정렬하지 않습니다.
    • 셀 개수 일치. 사양에 따르면 헤더 행은 구분선 행과 셀 개수가 같아야 합니다. 같지 않으면 해당 줄은 표가 아니며 문단으로 렌더링됩니다. 셀이 부족한 데이터 행에는 빈 셀이 추가되고, 넘치는 셀은 무시됩니다.
    • 셀 안에서. 사양은 인라인 서식은 허용하지만 블록 수준 콘텐츠는 허용하지 않으므로 목록이나 제목은 셀에 넣을 수 없습니다. Obsidian Help에 따르면 기본 서식 문법으로 표 안의 내용을 꾸밀 수 있습니다.
    • 표의 끝. 사양에 따르면 표는 첫 번째 빈 줄이나 다른 블록 수준 구조가 시작되는 곳에서 끊어집니다.

    이 도구는 모든 구분선 셀에 하이픈을 세 개 이상 씁니다. Obsidian의 최소 두 개와 다음에서 요구하는 세 개를 모두 충족합니다: GitHub Docs 문서 에서 요구하는 대로입니다.

    3. Obsidian의 표

    • Insert Table 명령. Obsidian Help에 따르면 Command Palette의 Insert Table 명령으로 표를 삽입할 수 있습니다. 이미 가진 데이터로 표를 만들려면 위의 도구에 붙여넣으세요.
    • 별칭과 이미지 크기. 위키링크 별칭, 예를 들어 [[Note|Alias]] 그리고 다음과 같은 이미지 크기 ![[image.png|300]] 에는 모두 세로 막대가 들어 있습니다. Obsidian Help에 따르면 표 안에서는 다음을 추가해야 합니다: \ 세로 막대 앞에 붙이므로 다음과 같이 쓰세요: [[Note\|Alias]] 및 ![[image.png\|300]]. 도구가 대신 처리해 주며, 이미 직접 쓴 이스케이프는 중복되지 않습니다.
    • 그 밖의 파이프. GFM 사양에 따르면 셀 안의 파이프는 코드 스팬 안에서도 백슬래시로 이스케이프해야 합니다. 이 도구는 이스케이프되지 않은 모든 파이프를 다음으로 바꿉니다: \|.
    • 줄바꿈. 행은 한 줄로 쓰기 때문에 셀 안의 줄바꿈은 다른 것으로 바뀌어야 합니다. 이 도구는 HTML을 씁니다: <br> 태그를 쓰거나, 원하면 줄을 공백으로 연결합니다. Obsidian Help의 Tables 섹션과 GitHub Docs 어디에도 셀 안의 줄바꿈에 대한 설명이 없으니 직접 확인하세요: <br> 가 내 볼트에서 어떻게 렌더링되는지 확인하세요. 소스에 태그를 넣고 싶지 않다면 공백 옵션을 고르세요.
    • 플러그인. 표 편집을 돕는 커뮤니티 플러그인이 있습니다. 이 페이지는 그중 어느 것도 평가하거나 추천하지 않습니다.

    체크리스트는 다음을 참고하세요: Markdown 체크리스트 메이커. 노트 상단의 속성에는 속성 생성기. 결정 사항과 담당자 목록은 다음에서 만든 노트에서 표로 정리하면 좋습니다: 회의 노트 템플릿.

    4. Excel, Google Sheets 또는 CSV에서

    스프레드시트에서 셀을 선택해 복사한 다음 위의 입력란에 붙여넣으세요. 셀 사이에 탭이 붙여넣어지면 도구가 이를 감지합니다. 쉼표, 세미콜론, 파이프도 감지하며 따옴표로 묶인 CSV 필드도 읽으므로 "Lee, Sam" 는 한 셀로 유지되고, "" 는 따옴표 안에서 따옴표 하나가 됩니다. 추측이 틀리면 Separator 메뉴를 사용하세요. “The first row is the header”를 선택하거나 해제해서 첫 행을 헤더 행으로 쓸지 정하세요. 해제하면 Markdown 표에는 헤더가 필요하므로 빈 헤더 행이 추가됩니다.

    • 셀 병합. 사양과 두 도움말 페이지 모두 행을 파이프로 구분된 셀의 목록으로 설명하며, 셀을 병합하는 방법은 설명하지 않습니다. 복사하기 전에 병합된 모든 셀에 같은 값을 넣으세요.
    • 수식. 이 도구는 붙여넣은 텍스트만 읽습니다. 붙여넣은 셀에 결과 대신 수식이 보이면 스프레드시트 앱에서 값을 복사한 뒤 다시 붙여넣으세요.
    • 행 길이 불일치. 행의 셀 개수가 헤더와 다르면 도구가 해당 행의 줄 번호와 함께 경고하고 표를 빈 셀로 채웁니다. 헤더보다 셀이 많은 행은 데이터를 버리지 않고 표를 넓힙니다.
    • 되돌리기와 복구. 기존 Markdown 표를 붙여넣어 다시 정렬하거나, Output as를 CSV 또는 TSV로 설정해 내보내세요. 구분선 행이 없을 때, 셀 개수가 헤더와 맞지 않을 때, 빈 줄 때문에 표가 끝날 때 줄 번호와 함께 경고합니다.

    붙여넣은 Markdown 표의 정렬 콜론은 유지되며, Column alignment 메뉴에서 열마다 바꿀 수 있습니다.

    5. GitHub와 Obsidian의 차이

    Obsidian Help와 GitHub Docs는 모두 헤더 행, 하이픈, 선택적 정렬 콜론으로 이루어진 파이프 표를 설명합니다. 두 페이지에 명시된 차이는 작습니다:

    주제Obsidian Help 문서GitHub Docs 및 GFM 사양
    하이픈헤더 행에는 하이픈이 최소 두 개 있어야 합니다GitHub Docs: 각 헤더 열에 하이픈 최소 세 개
    표 앞의 빈 줄Tables 섹션에는 언급이 없습니다GitHub Docs: 표 앞에 빈 줄을 넣어야 합니다
    셀 안의 파이프 문자추가: \ 별칭과 이미지 크기에서 세로 막대 앞에다음과 같이 이스케이프하세요: \|, 코드 스팬 안에서도
    바깥쪽 파이프선택 사항이지만 가독성을 위해 권장선택 사항

    두 환경 모두에서 안전하려면 하이픈을 세 개 이상 쓰고, 표 위에 빈 줄을 두고, 모든 파이프를 이스케이프하세요. 이 도구가 하는 일이 바로 그것입니다. 위키링크 별칭은 Obsidian 문법이며, GitHub에서는 파이프가 들어 있는 평범한 텍스트일 뿐입니다. 체크리스트 도구 가이드에서 다음을 다룹니다: 작업 목록의 차이점 같은 방식으로.

    6. Vox.md로 표와 노트를 볼트에 담기

    Vox.md는 표를 직접 만들지 않으며, 위의 도구는 앱 없이도 작동합니다. Vox.md가 하는 일은 텍스트를 Obsidian에 캡처하는 것입니다. Quick Capture로 기존 텍스트를 붙여넣고, Route가 이를 Markdown 대상에 전달합니다. 다음을 참고하세요: 빠른 캡처 및 루트 문서를 참고하세요.

    1. 위에서 표를 만들고 Copy를 누르세요.
    2. iPhone, iPad 또는 Mac의 Vox.md에서 Quick Capture를 열고 텍스트 편집기에 표를 붙여넣으세요.
    3. 원본 텍스트를 유지하는 Route로 보내세요. 문서에는 다음이 나와 있습니다: 원본 유지 를 AI 재작성 없이 캡처한 텍스트를 보존하는 처리 모드로 소개하며, 다음이 꺼져 있으면 캡처한 텍스트가 그대로 전달된다고 설명합니다: Apple Intelligence 사용 가 꺼져 있을 때입니다. 이것이 기본값입니다. 입력한 텍스트 처리는 각 Route에서 직접 켜는 설정입니다.
    4. Route의 대상에 따라 도착 위치가 정해집니다. 새 노트, 데일리 노트 같은 롤링 노트, 또는 기존 노트의 맨 아래, 맨 위, 선택한 제목 아래 중에서 고를 수 있습니다.

    대상에 이미 위쪽에 텍스트가 있다면 붙여넣은 표 위에 빈 줄을 두세요. Route 레시피는 다음을 참고하세요: 캡처 템플릿. Zoom, Teams, YouTube 자막 파일을 먼저 전사 노트로 바꾸려면 다음을 참고하세요: SRT 및 VTT를 Markdown으로.

    Vox.md로 iPhone, iPad, Mac에서 Obsidian에 캡처하기

    7. 자주 묻는 질문

    Obsidian에서 표가 렌더링되지 않는 이유는 무엇인가요?

    세 가지를 확인하세요. 헤더 바로 아래에 하이픈으로 된 구분선 행이 있어야 하고, 헤더와 구분선 행의 셀 개수가 같아야 합니다. 그렇지 않으면 사양에 따라 해당 줄이 문단으로 렌더링됩니다. Obsidian Help에 따르면 헤더 행에는 하이픈이 최소 두 개 있어야 합니다. 그리고 표 앞에 빈 줄을 두세요. GitHub Docs에서는 필수이고 Obsidian에서는 손해가 없습니다. 표를 도구에 붙여넣으면 구분선 행이 없거나 셀 개수가 다를 때 줄 번호와 함께 경고합니다.

    셀 안에서 줄바꿈하려면 어떻게 하나요?

    행을 한 줄로 유지하고 HTML을 사용하세요: <br> 를 셀 안에 넣는 것이며, 여러 줄 셀에 이 도구가 쓰는 방식입니다. 인용한 페이지에는 셀 안의 줄바꿈 설명이 없으니 내 볼트에서 직접 테스트하세요. 다른 방법은 줄을 공백으로 연결하는 것입니다.

    셀에 파이프나 위키링크 별칭을 넣으려면 어떻게 하나요?

    파이프 앞에 백슬래시를 붙이세요: [[Note\|Alias]], ![[image.png\|300]] 또는 a \| b. Obsidian Help는 표 안의 별칭과 이미지 크기 조정에 이것을 요구하며, GFM 사양은 셀 안의 모든 파이프에 이것을 요구합니다.

    셀을 병합할 수 있나요?

    사양과 Obsidian Help 어디에도 이를 위한 문법이 없습니다. 대신 각 셀에 같은 값을 반복해서 넣으세요.

    표는 얼마나 넓을 수 있나요?

    인용한 어떤 페이지에도 열이나 행의 최대 개수가 나와 있지 않으며, 이 도구도 제한을 두지 않습니다. 매우 넓은 표는 소스에서 읽기 어려우니 Compact 레이아웃을 쓰거나 표를 둘로 나누세요.

    내 데이터가 업로드되나요?

    아니요. 표는 이 페이지의 스크립트가 내 기기에서 만들며, 페이지는 네트워크 요청을 보내지 않습니다. 데이터를 저장하지도 않아서 페이지를 닫거나 새로고침하면 지워집니다. Download 버튼은 페이지의 파일을 내 기기에 저장합니다.
