Obsidian Bases 생성기: 필터, 보기, 수식

스키마를 먼저 익히지 않고도 Obsidian base용 YAML을 만들어 보세요. 필터를 고르고 보기를 추가한 뒤 .base 파일이나 코드 블록을 복사하고, 각 키의 역할은 Obsidian 공식 문서 링크와 함께 확인할 수 있습니다.

작성자
Cody Bontecou
업데이트
2026년 11월 28일
필요 조건
최신 브라우저라면 iPhone의 Safari를 포함해 모두 사용할 수 있습니다. 선택 사항: Bases 코어 플러그인을 켠 Obsidian, 그리고 음성이나 텍스트로 노트를 캡처하는 iPhone 또는 Mac용 Vox.md.
짧은 답변

base는 노트에 대한 데이터베이스 형식의 보기이며, 최상위 키가 최대 5개인 YAML로 작성합니다: filters, formulas, properties, summaries 및 views. YAML을 다음 이름으로 저장하세요: .base 파일로 만들거나 노트 안의 다음 블록에 붙여넣으세요: base 코드 블록. 해당 생성기 이(가) 대신 작성해 줍니다. 필요한 Obsidian 버전은 보기 유형에 따라 다릅니다: 보기 페이지 에는 1.9부터 Table과 Cards, 1.10부터 List와 Map, 1.14부터 Kanban이 나와 있습니다.

filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

생성기는 이 페이지 안에서만 실행됩니다. 입력한 내용은 업로드되지 않으며, 페이지는 네트워크 요청을 하지 않습니다.

    2. Bases 구문 한눈에 보기

    다음이 키입니다: Obsidian 구문 페이지 이(가) 설명합니다. 따로 익혀야 할 스키마는 없습니다.

    키동작예시
    filters모든 보기의 노트를 좁힙니다.file.hasTag("project")
    formulas계산된 속성을 정의하며, 다음과 같이 사용합니다: formula.name.total: 'price * qty'
    properties속성별 설정입니다. displayName 은(는) 열 머리글을 설정합니다.displayName: "Status"
    summaries직접 만든 요약 수식을 정의하며, 다음을 사용합니다: values.사용자 지정, 선택
    views같은 노트에 대한 보기 목록입니다.- type: table
    type (보기)보기의 레이아웃입니다.table, cards, list
    name (보기)보기의 이름입니다.name: "Projects"
    filters (보기)이 보기에만 적용되는 필터입니다.file.inFolder("Work")
    groupBy (보기)행을 그룹으로 묶습니다. 기준: property (다음 안에): direction.direction: DESC
    order (보기)표시할 속성을 순서대로 지정합니다.- file.name
    limit (보기)행 수의 상한을 지정합니다.limit: 10
    summaries (보기)속성을 요약에 연결합니다.price: Sum

    생성기가 문서에 있는 모든 키를 작성하지는 않습니다. 구문 페이지에는 다음도 설명되어 있습니다: groupOrder, 그리고 보기에는 정렬 열처럼 Obsidian이 직접 관리하는 추가 상태가 있을 수 있습니다. 필요하면 직접 추가하세요. YAML은 자유롭게 편집할 수 있습니다.

    3. 필터: and, or, not

    필터는 노트마다 true 또는 false가 되는 텍스트 구문이거나, 다음을 가진 객체입니다: and, or 또는 not (더 많은 필터의 목록을 담음). 전역 filters 은(는) 모든 보기에 적용됩니다. 보기 자체의 filters 은(는) 해당 보기에만 적용되며, 둘은 AND로 결합됩니다.

    filters:
  or:
    - file.hasTag("meeting")
    - file.inFolder("Meetings")

    다음이 없습니다: from 또는 source 키는 SQL이나 Dataview와 다릅니다. 필터가 없으면 base에 vault의 모든 파일이 포함되므로, 의도한 경우가 아니라면 항상 필터를 설정하세요.

    텍스트 값은 구문 안에서 따옴표가 필요하므로 YAML에서는 따옴표를 중첩해야 합니다: 'status == "done"'. 생성기가 이를 자동으로 처리합니다. 함수 필터(예: file.hasTag(), file.inFolder() 및 file.hasLink() 은(는) 다음에 있습니다: 함수 페이지.

    4. 수식과 요약

    다음 아래의 각 항목: formulas 은(는) 모든 보기에서 다음과 같이 쓸 수 있는 속성이 됩니다: formula.name. 수식은 다른 수식을 사용할 수 있지만 순환 참조는 허용되지 않으므로 수식이 자기 자신을 참조할 수 없습니다. 결과는 YAML 문자열로 저장되므로 식을 따옴표로 감쌉니다.

    formulas:
  formatted_price: 'if(price, price.toFixed(2) + " dollars")'

    보기의 summaries 은(는) 속성을 요약에 연결합니다. 구문 페이지에는 다음 기본값이 나와 있습니다:

    • 숫자: Average, Min, Max, Sum, Range, Median, Stddev
    • 날짜: Earliest, Latest, Range
    • 불리언: Checked, Unchecked
    • 하나라도: Empty, Filled, Unique

    날짜 계산에 대해 구문 페이지에는 다음과 같이 나와 있습니다: file.mtime > now() - "1 week" 은(는) 최근 1주일 안에 수정된 파일에서 true입니다.

    5. 이 도구로 할 수 있는 일

    필터나 수식에서 this 은(는) base가 표시되는 파일입니다. 구문 페이지에 따르면 base가 메인 콘텐츠 영역에서 열리면 base 파일 자체, 노트나 Canvas에 포함되면 포함하는 파일, 사이드바에 있으면 메인 콘텐츠 영역의 활성 파일을 가리킵니다. 이 페이지에는 다음 예가 있습니다: file.hasLink(this.file) (백링크 창을 재현하는 방법으로).

    6. 복사해서 쓸 수 있는 예제

    생성기의 프리셋을 일반 코드로 옮긴 것이라 JavaScript 없이도 사용할 수 있습니다. 폴더, 태그, 속성 이름을 본인 것으로 바꾸세요. 텍스트를 다음 이름으로 저장하세요: .base 파일로 만들거나 다음으로 감싸세요: base 코드 블록. 참고: base 만들기 (명령어 설명). 저장한 파일은 다음으로 포함할 수 있습니다: ![[Name.base]] 또는 ![[Name.base#View]] (기본 보기를 선택).

    읽기 목록

    filters:
  and:
    - file.inFolder("Reading")
    - 'status == "to read"'
properties:
  status:
    displayName: "Status"
views:
  - type: cards
    name: "Reading list"
    order:
      - file.name
      - status

    상태별 프로젝트

    filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

    태그가 있고 이번 주에 수정한 노트

    filters:
  and:
    - file.hasTag("project")
    - 'file.mtime > now() - "1 week"'
views:
  - type: table
    name: "Modified this week"
    order:
      - file.name
      - file.mtime

    이 노트의 백링크

    filters:
  and:
    - file.hasLink(this.file)
views:
  - type: table
    name: "Backlinks"
    order:
      - file.name
      - file.folder

    Vox.md로 캡처한 음성 노트

    filters:
  and:
    - file.inFolder("Vox")
    - file.hasTag("voice")
views:
  - type: table
    name: "Voice notes"
    order:
      - file.ctime
      - file.name
      - file.tags

    해당 order list로 열을 고릅니다. 정렬 순서는 Obsidian의 보기 도구 모음에서 바꾸는 보기 설정이라 예제에는 포함하지 않았습니다.

    7. 캡처한 내용을 base에 표시하기

    Vox.md는 캡처한 내용을 vault의 폴더에 Markdown 노트로 저장합니다. 해당 메타데이터 문서 에는 Route가 정적 메타데이터를 다음과 같이 추가할 수 있다고 나와 있습니다: key: value 줄(예: tags: [journal, idea], 그리고 그 노트 프런트매터 은(는) 이를 문서 범위에 기록합니다. 선택 사항인 위치 메타데이터도 설명되어 있습니다. 위의 마지막 예처럼 해당 폴더나 태그로 필터링한 base는 캡처한 내용을 하나의 표에 나열합니다. 메타데이터는 다음으로 만드세요: 속성 생성기. 다음도 참고하세요: iPhone에서 Obsidian으로 음성 노트 보내기 (설정 방법).

    관련 도구: 일일 노트 템플릿 생성기 날짜가 붙은 노트를 만드는 콜아웃 생성기 및 다음을 Markdown 표 만들기 (노트 내용용).

    조회할 만한 노트가 필요하신가요?

    Vox.md는 iPhone과 Mac에서 음성과 텍스트를 선택한 속성과 함께 Markdown으로 vault에 바로 캡처합니다. 녹음, 받아쓰기(Transcription), Capture에는 Vox.md Unlimited가 필요하며, 대상 계정에는 7일 무료 체험이 제공됩니다.

    8. 문제 해결

    • base에 모든 노트가 표시됩니다. 소스 필터가 설정되지 않았습니다. base는 기본적으로 vault 전체를 포함하므로 다음을 추가하세요: file.inFolder() 또는 file.hasTag() 필터.
    • 속성 열이 비어 있습니다. 대소문자를 포함해 이름이 일치하지 않거나, 노트의 프런트매터에 해당 속성이 없습니다. 노트의 속성과 열 이름을 확인하세요.
    • YAML 오류. 공백으로 된 들여쓰기와 따옴표를 확인하세요. 텍스트가 들어간 필터에는 중첩 따옴표가 필요합니다: 'status == "done"'.
    • map 보기가 비어 있습니다. 보기 페이지에 따르면 map 레이아웃에는 Maps 플러그인이 필요합니다.

    9. 자주 묻는 질문

    Bases는 코어 플러그인인가요?

    예. Obsidian Help 문서 에는 다음과 같이 나와 있습니다. “Bases는 노트를 데이터베이스처럼 볼 수 있는 보기를 만들어 주는 코어 플러그인입니다.”

    Bases와 Dataview 중 무엇을 쓸까요?

    서로 별개입니다. Dataview는 자체 쿼리 언어를 가진 커뮤니티 플러그인입니다. base는 Obsidian이 직접 읽는 YAML이며 다음이 필요 없습니다: from 키: 필터로 노트를 좁힙니다. 이 페이지에서는 기능을 더 자세히 비교하지 않습니다.

    YAML을 직접 편집할 수 있나요?

    예. .base 파일은 YAML 텍스트이며, 각 키는 구문 페이지에 설명되어 있습니다. 생성된 파일을 아무 편집기에서 열거나 코드 블록을 노트에 붙여넣어 편집하세요.

    생성기가 내 데이터를 업로드하나요?

    아니요. 이 페이지의 스크립트가 기기에서 YAML을 만들며, 페이지는 네트워크 요청을 하지 않습니다. 새로고침하면 모두 지워집니다.
