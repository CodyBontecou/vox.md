Obsidian 콜아웃 생성기: 모든 유형, 별칭, 접기 옵션

유형, 제목, 본문을 고르고 접기와 중첩을 설정해 올바른 > [!type] 콜아웃을 복사하세요. 모든 유형과 별칭, 접을 수 있는 콜아웃의 작동 방식도 확인할 수 있습니다.

작성자
Cody Bontecou
업데이트
2026년 11월 27일
필요 조건
iPhone의 Safari를 포함해 최신 브라우저라면 모두 사용할 수 있습니다. 선택 사항: 콜아웃을 쓰는 Obsidian, 음성이나 텍스트로 노트를 캡처하는 iPhone 또는 Mac용 Vox.md.
짧은 답변

콜아웃은 첫 줄이 다음과 같은 인용 블록입니다: > [!type] Optional title. 이후의 모든 줄은 다음으로 시작합니다: > . 다음을 추가하세요: + 또는 - 를 대괄호 바로 뒤에 붙이면 접을 수 있게 됩니다. 접두사를 직접 입력하지 않고 만들려면 다음을 사용하세요: 콜아웃 생성기 아래를 참고하세요.

> [!warning]- Back up first
> Copy the vault before you change the plugin settings.
>
> Then restart Obsidian.

생성기는 다음을 추가합니다: > 접두사를 모든 줄에 붙이고(중첩 시 반복), 콜아웃 안의 빈 줄을 유지하며, 붙여넣은 > 를 중복해서 붙이지 않습니다. 모든 처리는 이 페이지 안에서 이루어지며, 텍스트는 업로드되지 않고 페이지는 네트워크 요청을 하지 않습니다.

1. 콜아웃 만들기

콜아웃 생성기는 JavaScript가 필요합니다. 없어도 아래의 구문과 유형 표는 참고용으로 사용할 수 있습니다.

유형

내용

접기
레이아웃

완전히 빈 줄은 콜아웃을 끝내므로 남겨 둔 빈 줄은 >로 기록됩니다. 끄면 빈 줄이 제거됩니다.

내 콜아웃

이것을 중첩하려는 바깥 콜아웃의 본문 안에 붙여넣으세요.

미리보기(대략)

미리보기는 대략적인 모습입니다. 실제 색상, 아이콘, 간격은 테마가 정합니다.

유형 갤러리

유형을 선택하면 위에 불러옵니다.

클립보드에 복사했습니다. 복사하지 못했습니다. 텍스트를 선택해 직접 복사하세요. 예시를 불러왔습니다. 지웠습니다. 비어 있을 때의 기본 제목: {title} 내장 유형이 아닙니다. CSS 스니펫으로 정의하지 않으면 Obsidian은 note 스타일로 표시합니다. 유형을 불러왔습니다.

2. 콜아웃 구문

> [!type] Title
> Body line one.
> Body line two.
  • 유형. 인용 블록의 첫 줄은 느낌표 뒤에 대괄호로 묶은 유형으로 시작합니다: > [!info]. Obsidian Help 문서 의 유형 식별자는 대소문자를 구분하지 않으며, 지원되지 않는 유형은 다음으로 대체됩니다: note.
  • 제목. 대괄호 뒤의 텍스트가 제목을 대체합니다. 없으면 Obsidian은 유형 식별자를 제목 형식(첫 글자 대문자)으로 표시합니다. 예를 들어 > [!tip] 는 “Tip”으로 표시됩니다.
  • 본문. 이후의 각 줄은 다음으로 시작합니다: > . 본문에는 Markdown, 위키링크, 임베드를 넣을 수 있습니다.
  • 제목만. 본문은 생략할 수 있습니다: > [!tip] Remember to save 는 완전한 콜아웃입니다.

3. 모든 콜아웃 유형과 별칭

Obsidian 도움말에 나온 내장 유형입니다. 각 별칭은 해당하는 유형과 함께 표시합니다. 예: tldr 에 abstract.

유형별칭일반적인 용도
note없음일반적인 메모입니다. 알 수 없는 유형이 대체되는 스타일이기도 합니다.
abstractsummary, tldr노트 맨 위의 요약입니다.
info없음배경 정보입니다.
todo없음아직 해야 할 일입니다.
tiphint, important조언이나 핵심 요점입니다.
successcheck, done완료한 단계나 좋은 결과입니다.
questionhelp, faq열린 질문이나 자주 묻는 질문입니다.
warningcaution, attention조심해야 할 점입니다.
failurefail, missing무엇이 잘못되었는지, 또는 무엇이 빠졌는지입니다.
dangererror심각한 위험이나 오류 메시지입니다.
bug없음알려진 버그입니다.
example없음작동 예시입니다.
quotecite출처가 있는 인용문입니다.

유형과 별칭은 Obsidian 도움말을 따릅니다. “일반적인 용도” 열은 제안일 뿐 Obsidian이 정한 것이 아닙니다. 기본 모양에서는 유형마다 색상과 아이콘이 다르며, 테마에서 둘 다 바꿀 수 있습니다.

4. 접을 수 있는 콜아웃: + 와 -

닫는 대괄호 바로 뒤에 플러스 또는 마이너스를 붙입니다:

> [!faq]+ Open by default
> This callout is foldable and starts expanded.

> [!faq]- Closed by default
> This callout is foldable and starts collapsed.

Obsidian 도움말은 + 는 접을 수 있고 기본적으로 펼쳐진 상태로, - 는 접을 수 있고 기본적으로 접힌 상태입니다. 둘 다 없으면 콜아웃은 접을 수 없습니다. + 또는 - 는 Markdown의 일부이므로 파일에 그대로 남습니다.

5. 중첩 콜아웃, 목록, 코드, 임베드

중첩 콜아웃은 단계마다 다음을 하나씩 더 추가합니다: > 를 단계마다 추가합니다:

> [!question] Can callouts be nested?
> > [!example] Yes
> > Add one more > for each level.

생성기의 “다른 콜아웃 안에 중첩” 설정은 추가 > 를 모든 줄에 붙이며 최대 3단계까지 지원합니다. 결과를 바깥 콜아웃의 본문 안에 붙여넣으세요.

목록, 코드 등 다른 Markdown은 본문 안에 넣고 모든 줄에 다음 접두사를 붙입니다: > 접두사를 모든 줄에 붙입니다. Obsidian 도움말에 따르면 본문에는 Markdown, 위키링크, 임베드를 넣을 수 있고, 목록과 코드 블록을 포함한 기존 콘텐츠도 선택한 뒤 다음 콜아웃 삽입 명령을 실행하세요. 목록이나 코드 블록을 생성기의 본문 필드에 붙여넣으면 접두사가 자동으로 추가됩니다:

> [!info] Checklist
> - [ ] first
> - [ ] second
>
> ```
> code line
> ```

6. CSS 스니펫으로 사용자 지정 콜아웃 유형 만들기

직접 만든 유형은 note 스타일로 표시됩니다. Obsidian 도움말에 따르면 사용자 지정 콜아웃은 CSS 스니펫이나 커뮤니티 플러그인에서 정의합니다. 예시:

.callout[data-callout="custom-question-type"] {
  --callout-color: #000000;
  --callout-icon: lucide-alert-circle;
}

도움말 페이지에 따르면 --callout-color 는 유효한 CSS 색상이면 무엇이든 받으며, --callout-icon 는 lucide.dev의 아이콘 ID 또는 SVG 요소를 받습니다. 그런 다음 다음을 쓰세요: > [!custom-question-type] 를 노트에 쓰세요. 같은 이름을 생성기의 사용자 지정 유형 필드에도 입력하세요.

7. GitHub 알림과 Obsidian 콜아웃

GitHub에도 알림(alerts)이라는 비슷한 기능이 있습니다. GitHub Docs 문서 는 다섯 가지를 나열합니다: NOTE, TIP, IMPORTANT, WARNING 및 CAUTION.

> [!NOTE]
> Useful information that users should know, even when skimming content.

그 페이지에는 접기, 사용자 지정 제목, 사용자 지정 유형이 모두 문서화되어 있지 않지만 Obsidian 콜아웃에는 세 가지가 모두 있습니다. 첫 줄은 모양이 같으므로 기본적인 > [!note] 또는 > [!warning] 는 대개 양쪽 모두에서 작동하지만, 다음과 같은 Obsidian 전용 유형은 [!bug], +/- 접기나 제목은 GitHub 문서에 없는 기능입니다. 두 곳에서 모두 읽는 파일이라면 GitHub의 다섯 가지 유형만 쓰고 다른 기능은 넣지 마세요.

8. Vox.md로 음성이나 텍스트를 Obsidian에 캡처

Vox.md는 캡처한 내용을 Obsidian 보관함 폴더에 Markdown 노트로 저장합니다. 캡처 앱이며, 콜아웃을 대신 작성해 준다고 주장하지 않습니다. 이 페이지의 생성기로 만들어 붙여넣거나 위의 구문을 직접 입력해 나중에 추가하세요. 받아쓰기 내용을 본문으로 쓰려면 텍스트를 생성기에 붙여넣으면 접두사가 추가됩니다.

관련 도구와 가이드: Markdown 체크리스트 메이커 및 Markdown 표 만들기 는 콜아웃 안에 넣을 내용에, 속성 생성기, 데일리 노트 템플릿 및 회의 노트 템플릿 는 노트 구조에, 캡처 템플릿 는 접두사와 경로에, iPhone에서 Obsidian으로 음성 노트 보내기.

Vox.md로 음성이나 텍스트 노트를 보관함에 캡처

Vox.md는 기기에서 받아쓰기를 하고 Markdown을 Obsidian 보관함에 저장합니다. 녹음, 받아쓰기, 캡처에는 Vox.md Unlimited가 필요합니다. 대상 계정은 7일 무료 체험이 포함된 주간 또는 연간 구독이거나, 한 번만 결제하는 평생 구매입니다. App Store에는 현지 가격이 표시됩니다.

음성으로 노트 캡처

위의 콜아웃 생성기는 앱 없이도 완전히 작동합니다.

9. 자주 묻는 질문

콜아웃이 표시되지 않는 이유는 무엇인가요?

세 가지를 확인하세요. 첫 줄은 다음으로 시작해야 합니다: > 그리고 [!type]로 시작해야 하며, 느낌표가 있어야 하고 대괄호 안에 공백이 없어야 합니다. 본문의 모든 줄에는 각각 다음이 필요합니다: >. 다음이 없는 빈 줄은 > 는 인용 블록을 끝내므로 그 뒤의 줄은 일반 텍스트가 됩니다. 다음과 같이 쓰세요: >. 그래도 일반 인용 블록으로 보이면 다음 사이에 공백이나 오타가 없는지 확인하세요: > 및 [!.

콜아웃에 제목이 없어도 되나요?

꼭 그렇지는 않습니다. 제목을 생략하면 Obsidian은 대신 유형 식별자를 제목 형식으로 표시합니다. 제목을 숨기려면 CSS가 필요합니다. Obsidian 도움말에 따르면 제목 숨기기 같은 추가 스타일은 표준 CSS 선택자로 지정할 수 있습니다. 제목을 비워 두면 생성기는 제목을 비운 채로 두므로 기본 제목이 표시됩니다.

Admonition 플러그인과 기본 콜아웃 중 무엇을 쓸까요?

기본 콜아웃은 플러그인이 필요 없으며, 이 페이지의 > [!type] 구문을 사용합니다. Admonition 플러그인은 자체 구문을 가진 별도의 커뮤니티 플러그인이며, 이 페이지에서는 다루지 않습니다. Obsidian 도움말에 따르면 사용자 지정 콜아웃 유형은 커뮤니티 플러그인에서도 제공될 수 있습니다.

콜아웃은 Obsidian 모바일과 Publish에서도 작동하나요?

Obsidian 도움말에 따르면 콜아웃은 Obsidian Publish에서 기본으로 지원됩니다. 콜아웃 페이지에는 모바일에 대한 언급이 없으므로 이 페이지에서는 모바일 지원 여부를 단정하지 않습니다.

생성기가 내 텍스트를 업로드하나요?

아니요. 이 페이지의 스크립트가 사용자의 기기에서 콜아웃을 만들며, 페이지는 네트워크 요청을 하지 않습니다. 아무것도 저장하지 않으므로 페이지를 새로 고치면 내용이 지워집니다.
