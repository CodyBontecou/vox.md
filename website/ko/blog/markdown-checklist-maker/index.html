Markdown 체크리스트 메이커: 어떤 목록이든 마감일이 있는 작업으로

일반 줄, 글머리 기호, 번호 항목 또는 기존 작업 목록을 붙여넣고, 중첩을 유지한 올바른 - [ ] 작업을 선택적 마감일과 완료 개수와 함께 복사하세요.

작성자
Cody Bontecou
업데이트
2026년 11월 24일
필요 조건
iPhone의 Safari를 포함한 최신 브라우저면 됩니다. 선택 사항: 체크리스트용 Obsidian, 음성으로 작업을 캡처하기 위한 iPhone 또는 Mac용 Vox.md.
짧은 답변

Markdown 작업은 하이픈, 공백, 대괄호, 공백, 텍스트 순서입니다. 다음과 같이 쓰세요: - [ ] task 은(는) 미완료 작업, - [x] done 은(는) 완료된 작업입니다. 목록 전체를 작업으로 바꾸려면 다음에 붙여넣으세요: 체크리스트 메이커 아래를 참고하세요.

- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

메이커는 기존 글머리 기호, 번호, 체크박스를 제거해 중복되지 않게 하고, 들여쓰기를 중첩으로 유지하며, 사용하는 Obsidian 플러그인이 읽는 형식으로 마감일을 추가할 수 있습니다. 모든 처리는 이 페이지 안에서만 이루어지며 목록은 업로드되지 않고 페이지는 네트워크 요청도 하지 않습니다.

1. 체크리스트 만들기

체크리스트 메이커는 JavaScript가 필요합니다. JavaScript가 없어도 아래 문법은 참고용으로 그대로 사용할 수 있습니다.

내 목록
할 작업
중첩

목록의 탭은 항상 한 단계로 셉니다. 제목은 제목 그대로 둡니다.

모든 작업의 마감일

내 체크리스트

미리보기

목록을 붙여넣으면 결과가 표시됩니다. {total}개 중 {done}개 완료 이 목록에는 작업이 없습니다. 클립보드에 복사했습니다. 복사하지 못했습니다. 텍스트를 선택해 직접 복사하세요. 예시를 불러왔습니다. 지웠습니다. 내 체크리스트 체크박스 없는 내 목록 마감일을 추가하려면 유효한 날짜를 선택하세요. 날짜가 추가되지 않았습니다. 09:30 같은 시간을 입력하세요. 날짜는 시간 없이 추가되었습니다. 이미 이런 날짜가 있는 작업은 그대로 두었습니다. GitHub에서는 괄호로 시작하는 작업 설명 앞에 백슬래시가 필요합니다.

2. Markdown 체크리스트 문법

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

각 작업은 목록 항목입니다. 하이픈과 공백 뒤에 [ ] 을(를) 쓰는데, 대괄호 사이에 공백을 넣고 그다음 텍스트를 씁니다. Obsidian Help 페이지 및 GitHub Docs 페이지 둘 다 하이픈과 공백 뒤에 다음이 온다고 설명합니다: [ ]. 작업을 완료로 표시하려면 GitHub Docs는 다음을 사용하라고 합니다: [x].

공백이 중요합니다. GitHub Flavored Markdown 사양 은(는) 체크박스 마커를 다음처럼 정의합니다. 여는 대괄호, 공백 문자 또는 문자 x, 닫는 대괄호로 이루어지며 그 뒤 텍스트 앞에는 공백이 필요합니다. 따라서 [] 처럼 안이 비어 있는 것이나 - [ ]text 처럼 대괄호 뒤에 공백이 없으면 정의에 맞지 않습니다. 하이픈과 그 뒤의 공백이 있어야 비로소 그 줄이 목록 항목이 됩니다.

작업 목록은 기본 Markdown에 포함되지 않습니다. 같은 사양이 이를 CommonMark의 확장으로 표시하며, 소개에서도 원래 CommonMark 사양에 없는 기능은 확장으로 표시한다고 설명합니다. 이 확장을 구현하지 않은 렌더러는 대괄호를 그대로 텍스트로 보여 주며, 이것이 체크박스가 [ ] 라고 표시되는 가장 흔한 이유입니다.

3. Obsidian의 체크리스트

Obsidian 도움말의 기본 서식 문법 페이지에 작업 목록 설명이 있습니다:

  • 작업은 하이픈과 공백 뒤에 [ ].
  • 대괄호 안에 어떤 문자를 넣어도 작업을 완료로 표시할 수 있으므로 [x], [-] 및 [?] 모두 완료로 셉니다.
  • 목록 항목을 들여써서 작업 목록을 중첩합니다. Tab 또는 Shift+Tab 을(를) 눌러 선택한 항목을 들여쓰거나 내어쓰세요.
  • 읽기 보기에서는 체크박스를 선택해 작업을 전환할 수 있습니다.

도움말 페이지에는 어떤 문자든 작업을 완료로 만든다고 되어 있습니다. 문자마다 다른 모양을 설명하지는 않습니다. 만약 [-] 또는 [?] 이(가) [x] 과(와) 다르게 보인다면, 그것은 Markdown 자체가 아니라 설치한 테마나 CSS 스니펫 때문입니다.

메이커의 진행 표시줄도 같은 방식으로 셉니다. 대괄호 안에 공백이 아닌 문자가 있으면 완료로 보므로 [x], [X], [-] 및 [?] 은(는) 완료이고 [ ] 은(는) 미완료입니다. “done:”이나 “x ”로 시작하는 줄은 일반 텍스트이며, 도구가 그것을 완료된 작업이라고 추측하지 않습니다.

4. 마감일: Tasks, Dataview, Reminder 비교

Obsidian의 작업 목록 문법에는 자체 마감일 표기가 없으며, 도움말 페이지에도 관련 설명이 없습니다. 플러그인 세 가지가 작업 텍스트에 적힌 날짜를 각자의 형식으로 읽습니다. 메이커는 모든 플러그인에서 날짜를 ISO 형식인 YYYY-MM-DD 로 모든 플러그인에 씁니다. 플러그인이 없으면 날짜는 그냥 텍스트입니다.

형식읽는 플러그인예시 줄
마감일: 📅 YYYY-MM-DDTasks 플러그인이(가) 읽으며, 날짜는 다음 YYYY-MM-DD 형식이어야 한다고 설명합니다- [ ] send invoice 📅 2026-11-25
예정일: ⏳ YYYY-MM-DDTasks 플러그인- [ ] send invoice ⏳ 2026-11-25
시작일: 🛫 YYYY-MM-DDTasks 플러그인- [ ] send invoice 🛫 2026-11-25
인라인 필드: [due:: YYYY-MM-DD]Dataview 문서. 작업에 적힌 필드를 읽습니다. 예: [completion:: 2021-08-15]- [ ] send invoice [due:: 2026-11-25]
Reminder 플러그인: (@YYYY-MM-DD) 또는 (@YYYY-MM-DD HH:mm)obsidian-reminder 플러그인. README에는 다음이 나옵니다: (@2021-08-14) 및 (@2021-08-14 09:37) 이(가) 미완료 작업에 있는 예가 나옵니다- [ ] send invoice (@2026-11-25 09:30)

사용하는 플러그인 하나만 고르세요. Dataview 페이지에는 날짜용 이모지 단축 표기도 나와 있고 지원하는 단축 표기는 그것뿐이라고 하지만, 메이커는 대신 Dataview의 대괄호 형식으로 씁니다. Reminder README에 따르면 이미 체크한 작업의 미리 알림은 알림이 오지 않습니다.

5. GitHub와 Obsidian의 차이

GitHub Docs는 [ ] 은(는) 미완료 작업, [x] 은(는) 완료 표시라고 설명합니다. GFM 사양은 마커를 대괄호 사이의 공백 또는 문자 x 로 정의합니다. Obsidian은 모든 문자를 받아들입니다. 따라서 다음과 같은 작업은 - [-] skipped 또는 - [?] unsure 은(는) Obsidian에서는 완료이지만 사양의 마커 정의에서 벗어나므로, 사양을 따르는 렌더러는 그대로 텍스트로 보여 줄 수 있습니다. 파일을 GitHub에서도 읽는다면 [ ] 및 [x] 만 사용하세요.

GitHub Docs에는 규칙이 하나 더 있습니다. 작업 설명이 괄호로 시작하면 백슬래시로 이스케이프하세요. 예: - [ ] \(Optional) Open a followup issue. 메이커는 백슬래시를 대신 추가하지 않으며, 작업이 괄호로 시작하면 경고합니다.

6. Vox.md로 iPhone과 Mac에서 음성이나 텍스트로 작업 캡처하기

Vox.md의 할 일 체크리스트 처리 모드는 캡처에서 Markdown - [ ] 할 일 항목을 만들며, 대체 수단은 정해진 규칙의 체크리스트 포매터입니다. 음성은 기기에서 전사됩니다. 캡처 바에서 체크리스트 이(가) - [ ] 접두사를 적용하고, 두번째 날짜를 설정 은(는) (@yyyy-MM-dd) 또는 시간 형식을 삽입합니다. 다음을 참고하세요: 빠른 캡처 및 Route와 처리 모드 문서를 참고하세요.

Route를 사용하면 다음과 같은 제목 아래에서 데일리 노트에 항목을 추가할 수 있습니다: ## Tasks; Obsidian 일일 노트에 추가 에서 설정 방법을 안내하며, 일일 노트 템플릿 생성기 이(가) 노트의 구조를 작성합니다. 회의의 할 일 항목은 다음을 참고하세요: 회의 노트 템플릿. 작업 목록 접두사 레시피는 다음을 참고하세요: 캡처 템플릿.

Vox.md는 다음 (@yyyy-MM-dd) 형식을 씁니다. Tasks 플러그인의 이모지 날짜나 Dataview 필드는 쓰지 않습니다. 그런 형식을 쓴다면 캡처한 작업을 위의 메이커에 붙여넣고 해당 형식을 고르거나 나중에 날짜를 직접 수정하세요. 노트 맨 위의 속성을 만들려면 다음을 사용하세요: 속성 생성기.

iPhone, iPad 또는 Mac에서 음성으로 작업을 캡처하세요.

Vox.md는 말한 내용을 기기에서 Markdown 체크리스트로 만들어 Obsidian 노트에 추가합니다. 녹음, 전사, Capture에는 Vox.md Unlimited가 필요합니다. 대상 계정에 7일 무료 체험이 제공되는 주간 또는 연간 구독, 또는 한 번 구매하는 평생 이용권 중에서 고를 수 있습니다. 지역 가격은 App Store에 표시됩니다.

7. 자주 묻는 질문

체크박스가 [ ] 텍스트로 보이는 이유는 무엇인가요?

렌더러가 작업 목록을 그리지 않고 있습니다. 작업 목록은 CommonMark의 확장 기능이므로 이를 지원하지 않는 렌더러는 대괄호를 그대로 보여 줍니다. 줄이 하이픈과 공백으로 시작하는지, 대괄호 사이에 공백이나 x 이(가) 있는지, 닫는 대괄호 뒤에 공백이 오는지 확인하세요. Obsidian에서는 코드 블록이나 표 셀 안의 작업이 목록 항목처럼 체크박스로 표시되지 않을 수 있습니다.

작업은 어떻게 중첩하나요?

하위 작업을 들여씁니다. Obsidian에서는 Tab 로 선택한 항목을 들여쓰고 Shift+Tab 으로 내어쓰기합니다. 메이커는 목록의 공백 2칸 또는 4칸을 단계마다 탭 하나로 바꾸며, 원하면 공백 2칸 또는 4칸으로도 바꿉니다.

x가 아닌 다른 문자로 체크하려면 어떻게 하나요?

Obsidian 도움말에 따르면 대괄호 안의 어떤 문자든 작업을 완료로 표시하므로 - [-] task 및 - [?] task 은(는) 완료입니다. 목록을 초기화하지 않는 한 메이커는 붙여넣은 문자를 그대로 유지합니다. GitHub에서도 읽는 파일에는 다음을 사용하세요: [x].

Tasks 플러그인이 읽는 마감일은 어떻게 추가하나요?

작업 끝에 📅 과(와) YYYY-MM-DD 날짜를 붙입니다. 예: - [ ] send invoice 📅 2026-11-25. 모든 작업에 추가하려면 위에서 “Tasks 플러그인: 마감일”을 고르세요. 예정일에는 ⏳ 을(를), 시작일에는 🛫 을(를) 사용하세요.

메이커가 내 목록을 업로드하나요?

아니요. 목록은 이 페이지의 스크립트가 기기에서 변환하며, 페이지는 네트워크 요청을 하지 않습니다. 목록을 저장하지 않으므로 페이지를 닫거나 새로고침하면 지워집니다.
