Obsidian 노트 속성(YAML 프런트매터) 생성기 및 검사기

Obsidian이 기대하는 형식으로 속성을 만들거나, 가지고 있는 프런트매터를 검사해 속성이 의도한 유형으로 표시되지 않는 이유를 확인하세요.

Obsidian 노트 속성은 노트 맨 위에 있는 YAML이며, 다음 두 줄 사이에 위치합니다: --- 줄. 각 속성은 다음과 같습니다: name: value 쌍이며, 목록에는 다음이 있습니다: - value 줄에 항목 하나씩 쓰며, 내부 링크는 따옴표 안에 있어야 합니다. 다음 예시는 올바릅니다:

  - idea
aliases:
  - Weekly review

    2. 가지고 있는 프런트매터 검사

    노트의 맨 위 부분을 붙여넣으세요. 다음을 포함해서: --- 줄. 검사기는 블록을 한 줄씩 읽어 각 문제를 줄 번호와 수정안과 함께 나열합니다. 완전한 YAML 파서가 아니라 고정된 줄 규칙을 사용하므로, 파서라면 찾았을 오류를 놓칠 수 있고 여기에 나열된 규칙만 검사합니다.

    검사기가 확인하는 항목: 들여쓰기에 탭 사용, 여는 또는 닫는 항목 누락, ---, 따옴표 없는 내부 링크, 공백이 있는 태그, # 접두사, 태그에 쓸 수 없는 다른 문자나 숫자만 있는 태그, 더 이상 사용되지 않는 이름 tag, alias 및 cssclass, 중첩된 객체, 값 안의 Markdown 서식, 중복된 이름, 그리고 YAML 자체가 의도와 다르게 해석하는 일부 값. 다음과 같은 템플릿 토큰은 {{date}} 및 <% %> 는 건너뜁니다.

    속성 이름 유형 값 삭제 속성 {name} 삭제 한 줄에 값 하나 한 줄에 태그 하나(# 포함 여부는 자유) 체크됨 템플릿 플러그인이 채움 텍스트 목록 숫자 체크박스 날짜 날짜 및 시간 태그 클립보드에 복사했습니다. 복사했습니다. 루트의 메타데이터 필드에 붙여넣으세요. 복사하지 못했습니다. 텍스트를 선택해 직접 복사하세요. properties.md 파일을 다운로드했습니다. {name}을(를) 추가했습니다. {name}은(는) 이미 목록에 있습니다. 이름이 없는 속성은 제외됩니다. {name}이(가) 두 번 이상 나타납니다. 속성마다 한 행만 남기세요. {name}은(는) 숫자가 아니므로 비워 두었습니다. 태그 “{from}”은(는) {to}(으)로 작성되었습니다. 태그에는 공백이나 # 접두사를 쓸 수 없고, 숫자가 아닌 문자가 필요하기 때문입니다. 올바르게 만들 수 없는 태그는 제외되었습니다: {from} {name}에는 날짜와 시간이 모두 필요하므로 비워 두었습니다. 문제가 발견되지 않았습니다. 검사할 프런트매터를 붙여넣으세요. JSON처럼 보입니다. Obsidian은 이를 읽어 YAML로 저장합니다. 여기의 줄 규칙은 YAML에 적용되므로, 검사하려면 YAML 버전을 붙여넣으세요. 발견된 문제: {n} {line}번째 줄 수정: 블록이 --- 줄로 시작하지 않습니다. 속성은 노트 맨 위의 두 --- 줄 사이에 위치합니다. 첫 번째 속성 앞에 --- 만 있는 줄을 추가하세요. 속성 뒤에 닫는 --- 줄이 없습니다. 마지막 속성 뒤에 --- 만 있는 줄을 추가하세요. 이 줄은 탭으로 들여쓰기되어 있습니다. YAML은 들여쓰기에 탭을 허용하지 않습니다. 줄 앞의 탭을 공백(예: 두 칸)으로 바꾸세요. 이 줄은 name: value 형식이 아닙니다. name: value 형식으로, 콜론 뒤에 공백을 넣어 작성하세요. 속성 {key}은(는) 이미 {first}번째 줄에서 설정되었습니다. {key} 줄은 하나만 남기고 값을 그 줄에 합치세요. {key}는 더 이상 사용되지 않는 속성 이름입니다. Obsidian 1.4에서 사용 중단되었으며, 기본 속성으로서의 지원은 1.9에서 제거되었습니다. {fixed}로 이름을 바꾸세요. 속성 안의 내부 링크는 따옴표로 감싸야 합니다. {fixed}로 작성하세요 속성의 태그는 # 접두사 없이 작성합니다. {fixed}로 작성하세요 태그 {tag}에 공백이 있습니다. 태그에는 공백을 사용할 수 없습니다. 하이픈을 사용하세요. 예: {fixed}. 또는 태그를 한 줄에 하나씩 쓰세요. 태그 {tag}에는 숫자가 아닌 문자가 없습니다. 태그에는 하나 이상 있어야 합니다. 문자를 추가하세요. 예: {fixed} 태그 {tag}에 태그에 쓸 수 없는 문자가 있습니다. 태그에는 문자, 숫자, 밑줄, 하이픈, 중첩용 / 기호를 사용할 수 있습니다. 삭제하거나 바꾸세요. 예: {fixed} {key}에 중첩된 객체가 있습니다. 속성은 중첩된 객체를 지원하지 않습니다. 별도의 최상위 속성으로 평평하게 펼치거나, 소스 모드에서 편집하세요. 값에 Markdown 서식({sample})이 들어 있습니다. 속성은 설계상 Markdown을 렌더링하지 않습니다. 서식 문자를 제거하고 일반 텍스트로 두세요. 따옴표 없는 이 값에는 콜론과 공백이 들어 있어, YAML은 이를 다른 이름의 시작으로 해석합니다. 값을 따옴표로 감싸세요: {fixed} 따옴표 없는 이 값은 {char}(으)로 시작하며, YAML은 이를 특별하게 취급합니다. 값을 따옴표로 감싸세요: {fixed} 이 줄에서 따옴표가 열렸지만 닫히지 않았습니다. 닫는 따옴표를 추가하세요. YAML에서는 공백 뒤의 #가 주석을 시작하므로, 그 줄의 나머지는 값에 포함되지 않습니다. #가 값의 일부라면 값을 따옴표로 감싸세요: {fixed} 잘못된 예시를 불러왔습니다.

    3. 속성 유형과 작성 방법

    Obsidian은 일곱 가지 속성 유형을 지원합니다. YAML에서는 각각 다음과 같이 작성합니다:

    유형YAML 예시주의할 점
    텍스트title: Weekly reviewYAML이 잘못 해석할 값은 따옴표로 감싸세요. 예를 들어 다음이 들어 있는 값: : 가 들어 있는 값, 또는 다음으로 시작하는 값: #. 내부 링크는 따옴표 안에 있어야 합니다.
    목록topics:
      - sleep
      - focus    		각 값은 한 줄에 하나씩이며, 앞에 하이픈과 공백이 붙습니다.
    숫자rating: 4숫자는 따옴표 없이 작성하세요.
    체크박스published: true값은 다음과 같습니다: true 또는 false.
    날짜date: 2026-11-21형식은 다음과 같습니다: YYYY-MM-DD.
    날짜 및 시간time: 2026-11-21T10:30:00형식은 다음과 같습니다: YYYY-MM-DDTHH:MM:SS.
    태그tags:
      - recipe
      - cooking    		다음 없이 작성: #. 공백 없이, 숫자가 아닌 문자가 하나 이상 있어야 합니다.

    Obsidian에는 기본 속성도 세 가지 있습니다: tags, aliases 및 cssclasses. 생성기에는 각각을 위한 버튼이 있습니다.

    4. 속성이 가장 자주 깨지는 규칙

    • 내부 링크는 따옴표로 감싸세요. project: "[[Vox.md launch]]", 다음이 아님: project: [[Vox.md launch]]. 텍스트 속성과 목록의 항목에 적용됩니다.
    • 목록 항목은 한 줄에 하나씩. 각 항목은 속성 이름 아래에 들여쓰기하여 하이픈과 공백으로 시작합니다. 들여쓰기는 탭이 아닌 공백을 사용하세요.
    • 태그에는 별도의 규칙이 있습니다. 아니요 # YAML에서 공백 없이, 숫자가 아닌 문자를 하나 이상 포함해야 합니다: 1984 는 올바른 태그가 아니지만 다음은 올바릅니다: y1984 입니다. 대신 다음을 사용하세요: / . 다음과 같은 중첩 태그용: inbox/to-read. 참조: 태그 (Obsidian 도움말)
    • 날짜는 저장 형식으로 작성하세요. 2026-11-21 (날짜용) 및 2026-11-21T10:30:00 (날짜와 시간용).
    • 현재 이름을 사용하세요. tag, alias 및 cssclass 는 Obsidian 1.4에서 더 이상 사용되지 않게 되었으며, 다음으로 대체되었습니다: tags, aliases 및 cssclasses. 기본 속성으로서의 지원은 Obsidian 1.9에서 제거되었습니다.
    • 중첩하지 마세요. 속성은 중첩된 객체를 지원하지 않습니다. Obsidian은 중첩된 속성을 보려면 소스 모드를 쓰도록 안내하므로, 다음과 같은 최상위 이름으로 평평하게 펼치세요: project_status.
    • Markdown을 사용하지 마세요. 굵게, 링크 등의 서식은 속성에서 렌더링되지 않습니다. Obsidian은 속성이 작고 독립된 정보를 위한 것이므로 이는 의도된 동작이라고 설명합니다.

    5. 템플릿에서 속성 사용하기

    켜세요: 템플릿 플러그인 토큰 를 생성기에서 사용하면 날짜 필드를 고정된 날짜 대신 토큰으로 작성합니다. 코어 Templates 플러그인은 다음을 사용합니다: {{date:YYYY-MM-DD}}; Templater 커뮤니티 플러그인은 다음을 사용합니다: <% tp.date.now("YYYY-MM-DD") %> (다음의 Templater 참고: 문서). 날짜 및 시간 필드는 다음을 사용합니다: YYYY-MM-DD[T]HH:mm:ss 를 토큰에 지정하고 다음과 함께 사용합니다: T 를 대괄호로 감싸면 문자로 작성됩니다.

    링크는 주의가 필요합니다. Obsidian은 속성 UI에서 입력한 링크에는 따옴표를 붙여 주지만, 템플릿 플러그인은 텍스트를 그대로 파일에 쓰므로 템플릿에서는 직접 따옴표를 쓰세요: project: "[[Vox.md launch]]".

    이 속성을 사용하는 전체 템플릿은 다음을 참고하세요: 일일 노트 템플릿 생성기 및 다음을 회의 메모 템플릿 생성기.

    노트 본문에는 Markdown 표 만들기 는 스프레드시트 셀이나 CSV를 속성 블록 아래에 붙여넣을 수 있는 표로 바꿔 줍니다.

    6. 캡처하는 노트에 속성 추가

    Vox.md 루트에서 메타데이터 필드는 다음을 하나 받습니다: key: value 쌍을 한 줄에 하나씩 입력하세요. 예: tags: [journal, idea]. 노트 프런트매터 는 메타데이터를 문서 범위로 작성합니다. 인라인 항목 필드 기록합니다: key:: value 롤링 노트에서 각 항목 옆에 있는 필드. 다음을 참고하세요: 루트 참조 문서의 메타데이터.

    생성기의 Vox.md 루트 메타데이터로 복사 버튼은 목록을 다음 형태로 하여 속성을 그 형식으로 작성합니다: [a, b] 그리고 한 줄에 속성 하나씩으로 이루어집니다. Vox.md 문서에서는 이 필드를 다음과 같이 설명합니다: key: value 줄. 이 페이지는 각 속성 유형이 어떻게 작성되는지 테스트하지 않으므로, 처음 캡처한 노트를 Obsidian에서 열어 확인하세요. 데일리 노트와 받은편지함용 루트는 다음에서 다룹니다: Obsidian 일일 노트에 추가, 캡처 템플릿 및 iPhone 음성 노트를 Obsidian으로.

    캡처하는 모든 노트에 이 속성을 넣습니다.

    iPhone, Apple Watch 또는 Mac에서 기록하는 모든 노트에 이 속성을 넣고 싶나요? Vox.md 루트의 메타데이터에 붙여 넣고 노트 프런트매터를 선택하세요. 대상 계정은 7일 무료 체험을 받을 수 있습니다.

    7. 자주 묻는 질문

    Obsidian이 내 속성을 의도한 유형으로 표시하지 않는 이유는 무엇인가요?

    Obsidian은 속성을 YAML로 읽으며, 해당 유형의 규칙을 따르지 않는 값은 그 유형으로 표시되지 않습니다. 흔한 원인은 따옴표 없는 링크, 한 줄에 항목 하나로 쓰지 않은 목록, 다음 형식이 아닌 날짜입니다: YYYY-MM-DD, 공백이 있는 태그. 블록을 위의 검사기에 붙여넣으면 해당 줄을 찾을 수 있습니다.

    속성의 태그에 #가 필요한가요?

    아니요. YAML에서 태그는 다음과 같이 일반 단어로 작성합니다: - recipe. 해당 # 는 노트 본문의 태그용입니다.

    속성을 중첩할 수 있나요?

    아니요. 속성은 중첩된 객체를 지원하지 않습니다. 평평한 이름을 쓰거나, 다음과 같은 중첩 태그를 사용하세요: / 안의 tags 목록.

    속성을 JSON으로 작성할 수 있나요?

    Obsidian은 JSON 블록을 읽을 수 있지만 YAML로 읽고 저장합니다. 위의 검사기는 줄 규칙을 YAML에만 적용합니다.
