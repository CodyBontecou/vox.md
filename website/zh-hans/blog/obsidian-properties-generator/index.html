Obsidian 笔记属性（YAML frontmatter）生成器和检查器

按 Obsidian 期望的格式生成属性，或检查你已有的 frontmatter，查看某个属性为何没有显示为你想要的类型。

需要
Obsidian（任意平台）。可选：用于 iPhone、Apple Watch 或 Mac 的 Vox.md，可为捕获的笔记添加属性。
简短回答

Obsidian 笔记属性是位于笔记最顶部的 YAML，夹在两条 --- 行。每个属性是一个 name: value 对，列表则有一个 - value 行，每项一行，内部链接必须加引号。以下示例是有效的：

---
tags:
  - journal
  - idea
aliases:
  - Weekly review
date: 2026-11-21
project: "[[Vox.md launch]]"
published: true
---

需要其他属性，或想知道为什么某个属性没有显示为你想要的类型？下面的生成器会写出 YAML，检查器会列出带行号的问题及修复方法。两者都完全在本页面中运行：你输入的任何内容都不会被发送到别处。规则来自 Obsidian 帮助， 属性 和 标签.

    3. 属性类型及各自的写法

    Obsidian 支持七种属性类型。每种在 YAML 中的写法如下：

    类型YAML 示例注意事项
    文本title: Weekly review请为 YAML 可能误读的值加引号，例如包含 : ，或以如下内容开头的值： #。内部链接必须加引号。
    列表topics:
      - sleep
      - focus    		每个值各占一行，前面是连字符和空格。
    数字rating: 4数字不要加引号。
    复选框published: true该值是 true 或 false.
    日期date: 2026-11-21格式为 YYYY-MM-DD.
    日期和时间time: 2026-11-21T10:30:00格式为 YYYY-MM-DDTHH:MM:SS.
    标签tags:
      - recipe
      - cooking    		写成不带 #。不含空格，且至少包含一个非数字字符。

    Obsidian 还有三个默认属性： tags, aliases 和 cssclasses。生成器为每一种都提供了按钮。

    4. 最容易让属性出错的规则

    • 请给内部链接加引号。 project: "[[Vox.md launch]]"，而不是 project: [[Vox.md launch]]。这适用于文本属性以及列表中的各项。
    • 每个列表项占一行。 每一项以连字符和空格开头，并在属性名称下缩进。请用空格缩进，不要用制表符。
    • 标签有自己的规则。 否 # 写在 YAML 中，不含空格，且至少包含一个非数字字符： 1984 不是有效的标签，而 y1984 。请使用 / 用于嵌套标签，例如 inbox/to-read。参阅 标签 （Obsidian 帮助）
    • 请用存储的格式写日期。 2026-11-21 表示日期， 2026-11-21T10:30:00 表示日期和时间。
    • 请使用当前的名称。 tag, alias 和 cssclass 在 Obsidian 1.4 中已弃用，改用 tags, aliases 和 cssclasses，并且在 Obsidian 1.9 中不再支持将它们作为默认属性。
    • 不要嵌套。 属性不支持嵌套对象。Obsidian 建议使用源码模式查看嵌套属性，因此请把它们展平为顶层名称，例如 project_status.
    • 不要使用 Markdown。 粗体、链接和其他格式不会在属性中渲染。Obsidian 称这是有意为之，因为属性是用来存放小而原子化的信息的。

    5. 在模板中使用属性

    开启 模板插件令牌 ，可在生成器中把日期字段写成令牌，而不是固定日期。核心模板插件使用 {{date:YYYY-MM-DD}}；Templater 社区插件使用 <% tp.date.now("YYYY-MM-DD") %> （见 Templater 文档）。日期和时间字段使用 YYYY-MM-DD[T]HH:mm:ss ，在令牌中配合 T 放在方括号中，使其被写成字母。

    链接需要留意。你在属性界面中输入链接时，Obsidian 会自动加上引号，但模板插件会原样把文本写入文件，所以请在模板中自己写上引号： project: "[[Vox.md launch]]".

    如需使用这些属性的完整模板，请参阅 每日笔记模板生成器 以及 会议记录模板生成器.

    6. 为你捕获的笔记添加属性

    在 Vox.md 路线中，元数据字段接受一个 key: value 键值对，每行一对，例如 tags: [journal, idea]. 笔记 frontmatter 会在文档范围写入元数据。 行内条目字段 写入 key:: value 字段，位于滚动笔记中每个条目旁边。参见 路线参考中的元数据.

    生成器的 复制为 Vox.md 路线元数据 按钮会以这种形式写入你的属性，列表写为 [a, b] ，每行一个属性。Vox.md 的文档将该字段描述为 key: value 行；本页面不会测试每种属性类型的写法，因此请在 Obsidian 中打开第一条捕获的笔记并确认。每日笔记和收件箱的路线见 追加到 Obsidian 每日笔记, 捕捉模板 和 将 iPhone 语音笔记存入 Obsidian.

    7. 常见问题

    为什么 Obsidian 没有把我的属性显示为我想要的类型？

    Obsidian 将属性读取为 YAML，不符合其类型规则的值不会显示为该类型。常见原因有：没有加引号的链接、没有按每行一项写的列表、日期不是 YYYY-MM-DD，以及带空格的标签。把该代码块粘贴到上面的检查器中即可找到所在行。

    属性中的标签需要 # 吗？

    不需要。在 YAML 中，标签写成普通文字，例如 - recipe。该 # 用于笔记正文中的标签。

    可以嵌套属性吗？

    不可以。属性不支持嵌套对象。请使用扁平的名称，或使用嵌套标签： / 在 tags 列表。

    可以把属性写成 JSON 吗？

    Obsidian 可以读取 JSON 代码块，但会按 YAML 读取并保存。上面的检查器只对 YAML 应用其行规则。
