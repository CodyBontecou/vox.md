Obsidian 标注生成器：所有类型、别名和折叠选项

选择类型，添加标题和正文，选择折叠与嵌套方式，然后复制有效的 > [!type] 标注，并附有完整的类型和别名列表以及可折叠标注的使用方法。

作者：
Cody Bontecou
更新于
2026年11月27日
需要
任何现代浏览器，包括 iPhone 上的 Safari。可选：用于显示标注的 Obsidian，以及用于通过语音或文字捕捉笔记的 iPhone 或 Mac 版 Vox.md。
简短回答

标注是一个引用块，其第一行为 > [!type] Optional title。之后的每一行都以 > 。添加 + 或 - 紧跟在方括号之后即可使其可折叠。如果不想手动输入前缀，请使用 标注生成器 如下。

> [!warning]- Back up first
> Copy the vault before you change the plugin settings.
>
> Then restart Obsidian.

生成器会添加 > 前缀（嵌套时重复），保留标注内的空行，并且不会重复 > 你粘贴的内容。它完全在本页中运行：你的文本不会被上传，页面也不会发出任何网络请求。

2. 标注语法

> [!type] Title
> Body line one.
> Body line two.
  • 类型。 引用块的第一行以感叹号后括号中的类型开头： > [!info]. Obsidian 帮助 说明类型标识符不区分大小写，且不受支持的类型会回退为 note.
  • 标题。 括号后的文字会替换标题。没有它时，Obsidian 会以首字母大写形式显示类型标识符，所以 > [!tip] 显示为“Tip”。
  • 正文。 后面的每一行都以 > 。正文可以包含 Markdown、wikilink 和嵌入内容。
  • 仅标题。 正文可以省略： > [!tip] Remember to save 就是一个完整的标注。

3. 所有标注类型与别名

Obsidian 帮助列出了这些内置类型。每个别名都列在其所属类型之下，例如 tldr 配合 abstract.

类型别名典型用途
note无一般性备注。也是未知类型回退到的样式。
abstractsummary, tldr笔记顶部的摘要。
info无背景信息。
todo无仍待完成的事项。
tiphint, important建议或要点。
successcheck, done已完成的步骤或良好的结果。
questionhelp, faq未解决的问题或常见问题。
warningcaution, attention需要小心的事项。
failurefail, missing哪里出了问题，或缺少什么。
dangererror严重风险或错误信息。
bug无一个已知的 bug。
example无一个完整示例。
quotecite带出处的引文。

类型和别名来自 Obsidian 帮助。“典型用途”一列只是建议，并非 Obsidian 的定义。在默认外观中，每种类型都有自己的颜色和图标；主题可以更改这两者。

4. 可折叠标注：+ 与 -

在右括号后直接加一个加号或减号：

> [!faq]+ Open by default
> This callout is foldable and starts expanded.

> [!faq]- Closed by default
> This callout is foldable and starts collapsed.

Obsidian 帮助描述了 + 为默认展开的可折叠标注，而 - 为默认折叠的可折叠标注。两者都不加时，标注不可折叠。 + 或 - 属于 Markdown 的一部分，因此会保留在文件中。

5. 嵌套标注、列表、代码和嵌入

嵌套标注时，再添加一个 > 每一级的写法：

> [!question] Can callouts be nested?
> > [!example] Yes
> > Add one more > for each level.

生成器的“嵌套在另一个标注中”设置会写入额外的 > 每行都加上，最多三级。把结果粘贴到外层标注的正文中。

列表、代码和其他 Markdown 放在正文中，使用 > 前缀。Obsidian 帮助指出，正文可以包含 Markdown、wikilink 和嵌入内容，并且可以选中现有内容（包括列表和代码块）后运行 插入标注 命令。把列表或代码块粘贴到生成器的正文字段中，它会替你加上前缀：

> [!info] Checklist
> - [ ] first
> - [ ] second
>

> ```

6. 使用 CSS 代码片段自定义标注类型

你自创的类型会以 note 样式显示。Obsidian 帮助指出，自定义标注需在 CSS 代码片段或社区插件中定义。其示例如下：

.callout[data-callout="custom-question-type"] {
  --callout-color: #000000;
  --callout-icon: lucide-alert-circle;
}

根据帮助页面， --callout-color 接受任何有效的 CSS 颜色，而 --callout-icon 接受来自 lucide.dev 的图标 ID 或 SVG 元素。然后写入 > [!custom-question-type] 写在笔记里。在生成器的自定义类型字段中输入相同的名称。

7. GitHub alerts 与 Obsidian 标注

GitHub 也有类似的功能，称为 alerts。 GitHub 文档 列出了五个： NOTE, TIP, IMPORTANT, WARNING 和 CAUTION.

> [!NOTE]
> Useful information that users should know, even when skimming content.

该页面没有记录折叠、自定义标题和自定义类型；而 Obsidian 标注三者都有。第一行看起来相同，所以基本的 > [!note] 或 > [!warning] 通常在两者中都有效，但仅限 Obsidian 的类型，例如 [!bug]， +/- 折叠或标题超出了 GitHub 文档的范围。如果文件要在两处阅读，请只使用五种 GitHub 类型，不要加额外内容。

9. 常见问题

为什么我的标注没有渲染？

检查三件事。第一行必须以 > 然后 [!type]，感叹号紧跟其后，括号内不留空格。正文的每一行都需要自己的 >。不带 > 会结束引用块，所以它后面的行就是普通文本；请写成 >。如果它仍显示为普通引用块，请检查以下两者之间是否有空格或拼写错误： > 和 [!.

标注可以没有标题吗？

不完全是：省略标题后，Obsidian 会改为以首字母大写形式显示类型标识符。要隐藏标题需要用 CSS；Obsidian 帮助指出，隐藏标题等进一步样式可以使用标准 CSS 选择器。你这样做时，生成器会让标题留空，因此会得到默认标题。

Admonition 插件还是原生标注？

原生标注无需插件，使用 > [!type] 语法。Admonition 插件是独立的社区插件，有自己的语法，本页不涉及。Obsidian 帮助指出，自定义标注类型也可以来自社区插件。

标注能在 Obsidian 移动端和 Publish 中使用吗？

Obsidian 帮助指出，Obsidian Publish 原生支持标注。其标注页面未提及移动端，因此本页对此不作任何说明。

生成器会上传我的文本吗？

不会。本页中的脚本在你的设备上生成标注，页面不会发出任何网络请求。它也不会保存任何内容：刷新页面即会清空。
