免费工具

适用于 Obsidian 的 Markdown 表格生成器：可从 Excel、Sheets 或 CSV 粘贴

粘贴来自 Excel、Google Sheets、Numbers、CSV 或 TSV 的行，即可复制有效的竖线表格；[[Note|Alias]] 和 ![[image.png|300]] 中的竖线会被转义，换行会被处理，并可按列设置对齐。

需要
任何现代浏览器均可，包括 iPhone 上的 Safari。可选：用 Obsidian 使用表格，用 iPhone 或 Mac 版 Vox.md 将文本捕获到笔记中。
简短回答

Markdown 表格由一行表头、一行由连字符组成的分隔行，以及每行一条的数据行构成，单元格之间用 |。将你的单元格粘贴到 表格生成器 在下方获取表格，或从这个示例开始。

| Name | Owner | Status |
| --- | --- | --- |
| Draft | Ana | Done |
| Review | Lee | Open |

生成器还会处理通用生成器在 Obsidian 中忽略的问题：它会转义以下内容中的竖线 [[Note|Alias]] 和 ![[image.png|300]] 写成 \|，并将单元格内的换行转换为 <br> 或空格。它完全在此页面中运行：你的数据绝不会被上传，页面也不发出任何网络请求。

    2. Markdown 表格语法

    | Name   | Qty | Price |
| :----- | :-: | ----: |
| Apple  |   3 |  1.20 |
| Pear   |  12 |  0.80 |

    该 GitHub Flavored Markdown 规范 将表格定义为一行表头、一行分隔表头与数据的分隔行，以及零行或多行数据。单元格之间用竖线分隔。

    • 分隔行。 其单元格只包含连字符，可在左侧、右侧或两端加冒号，分别表示左对齐、右对齐或居中对齐。 Obsidian 帮助 指出可在表头行中添加冒号来对齐文本，并且表头行必须至少包含两个连字符。
    • 外侧竖线。 规范中两侧的竖线是可选的。Obsidian Help 建议加上以提高可读性，生成器始终会写出它们。
    • 填充。 根据 Obsidian Help，单元格不需要完美对齐。生成器的“填充列”布局只是为了让源码更易读而将其对齐；“紧凑”则跳过这一步。
    • 数量一致。 规范要求表头行的单元格数必须与分隔行相同。否则这些行不是表格，会渲染为普通段落。数据行单元格较少时会补上空单元格，多出的单元格会被忽略。
    • 单元格内部。 规范允许行内格式，但不允许块级内容，因此列表或标题不能放入单元格。Obsidian Help 指出你可以使用其基本格式语法来设置表格内容的样式。
    • 表格的结束。 规范指出，表格在第一个空行处，或另一个块级结构开始处中断。

    生成器在每个分隔单元格中至少写入三个连字符。这既满足 Obsidian 的最少两个，也满足以下所要求的三个： GitHub 文档 所要求的。

    3. Obsidian 中的表格

    • Insert Table。 Obsidian Help 说明你可以通过 Command Palette 中的 Insert Table 命令插入表格。若要用现有数据构建表格，请将其粘贴到上方的生成器中。
    • 别名和图片尺寸。 Wikilink 别名，例如 [[Note|Alias]] 以及图片尺寸，例如 ![[image.png|300]] 都包含一个竖直线。Obsidian Help 指出，在表格内部你需要添加一个 \ 在竖线之前，因此请写成 [[Note\|Alias]] 和 ![[image.png\|300]]。生成器会替你完成这一步；你已写好的转义不会被重复添加。
    • 其他竖线。 GFM 规范指出，单元格内的竖线必须用反斜杠转义，即使在代码片段中也是如此。生成器会将每个未转义的竖线转义为 \|.
    • 换行。 一行写在一行内，因此单元格内的换行必须换成别的形式。生成器会写入 HTML <br> 标签，或者在你选择时用空格连接各行。Obsidian Help 的 Tables 部分和 GitHub Docs 都没有描述单元格内的换行，因此请检查 <br> 在你自己的库中的渲染效果，如果不想在源码中出现标签，请选择空格选项。
    • 插件。 存在可帮助编辑表格的社区插件。本页面不评价也不推荐其中任何一个。

    关于清单，请参阅 Markdown 清单生成器；对于笔记顶部的属性，请使用 属性生成器。对于笔记中的决策和负责人列表，表格很合适，可用于 会议记录模板.

    4. 来自 Excel、Google Sheets 或 CSV

    在电子表格中选中单元格，复制，然后粘贴到上方的框中。如果粘贴的单元格之间带有制表符，生成器会自动识别。它也能识别逗号、分号和竖线，并能读取带引号的 CSV 字段，因此 "Lee, Sam" 仍为一个单元格，而 "" 在引号内会变成一个引号。如果猜测有误，请使用 Separator 菜单。勾选或取消勾选“第一行是表头”，以决定第一行是否成为表头行；不勾选时会添加一个空表头行，因为 Markdown 表格必须有表头。

    • 合并单元格。 规范和两个帮助页面都将一行描述为由竖线分隔的单元格列表，且都没有描述合并单元格的方法。复制之前，请在合并所覆盖的每个单元格中填入该值。
    • 公式。 生成器只读取你粘贴的文本。如果粘贴的单元格显示的是公式而不是结果，请在电子表格应用中复制数值后再粘贴。
    • 行长短不一。 如果某一行的单元格数与表头不同，生成器会提示该行的行号，并用空单元格补齐表格。单元格比表头多的行会让表格变宽，而不是丢弃数据。
    • 反向转换与修复。 粘贴现有的 Markdown 表格即可重新对齐，或将 Output as 设为 CSV 或 TSV 以导出。当分隔行缺失、其单元格数与表头不一致，或空行会使表格中断时，生成器会提示并给出行号。

    粘贴的 Markdown 表格中的对齐冒号会被保留，你也可以通过 Column alignment 菜单更改每一列。

    5. GitHub 与 Obsidian 的差异

    Obsidian Help 和 GitHub Docs 都介绍了带有表头行、连字符和可选对齐冒号的竖线表格。这些页面所述的差异很小：

    主题Obsidian 帮助GitHub Docs 和 GFM 规范
    连字符表头行必须至少包含两个连字符GitHub Docs：每个表头列至少三个连字符
    表格前的空行Tables 部分没有提到这一点GitHub Docs：表格前必须有一个空行
    单元格中的字面竖线添加一个 \ 别名和图片尺寸中竖线之前的转义将其转义为 \|，即使在代码片段中也是如此
    外侧竖线可选，建议使用以提高可读性可选

    为了在两处都能正常工作，请写三个或更多连字符，在表格上方留一个空行，并转义每一个竖线。生成器正是这样做的。Wikilink 别名是 Obsidian 语法；在 GitHub 上它只是带有一个竖线的文本。清单生成器指南介绍了 任务列表的差异 ，方式相同。

    若要突出显示表格或有关它的备注，请用标注包裹它： Obsidian 标注生成器 添加 > 前缀。

    6. 用 Vox.md 将表格和笔记送入你的库

    Vox.md 本身不生成表格，上方的生成器无需应用即可使用。Vox.md 的作用是将文本捕获到 Obsidian：Quick Capture 可让你粘贴现有文本，Route 则将其送达某个 Markdown 目标位置。请参阅 快速捕捉 和 路线 文档。

    1. 在上方制作你的表格，然后点击 Copy。
    2. 在 iPhone、iPad 或 Mac 上的 Vox.md 中，打开 Quick Capture，并将表格粘贴到文本编辑器中。
    3. 通过保留原始文本的 Route 发送。文档中列出了 保留原文 作为不经 AI 改写而保留所捕获文本的处理模式，并说明在以下情况下所捕获的文本将原样送达： 使用 Apple Intelligence 处于关闭状态，这是它的默认值。处理键入的文本是每个 Route 上的可选设置。
    4. Route 的目标位置决定内容写入何处：新笔记、滚动笔记（如每日笔记），或现有笔记的末尾、开头或所选标题之下。

    如果目标位置上方已有文本，请在粘贴的表格上方留一个空行。有关 Route 的配方，请参阅 捕捉模板；若要先把 Zoom、Teams 或 YouTube 的字幕文件转成转写笔记，请参阅 SRT 和 VTT 转 Markdown.

    7. 常见问题

    为什么我的表格在 Obsidian 中不渲染？

    请检查三件事。表头正下方必须有一行由连字符组成的分隔行，且表头行与分隔行的单元格数必须相同，否则按规范这些行会被渲染为段落。Obsidian Help 指出表头行必须至少包含两个连字符。此外，请在表格前留一个空行，GitHub Docs 要求如此，而这在 Obsidian 中没有任何代价。将表格粘贴到生成器中：当分隔行缺失或数量不一致时，它会提示并给出行号。

    如何在单元格中添加换行？

    让该行保持在一行内，并使用 HTML <br> 放入单元格内，这正是生成器为多行单元格写出的内容。所引用的页面没有描述单元格内的换行，因此请在你的库中测试。另一种选择是用空格连接各行。

    如何在单元格中放入竖线或 wikilink 别名？

    在竖线前加一个反斜杠： [[Note\|Alias]], ![[image.png\|300]] 或 a \| b。Obsidian Help 要求别名和表格内图片缩放这样做，GFM 规范则要求单元格中的任何竖线都这样做。

    可以合并单元格吗？

    规范和 Obsidian Help 中都没有相应的语法。请改为在每个单元格中重复该值。

    表格最宽可以多宽？

    所引用的页面都没有给出列数或行数的上限，生成器也不设限制。过宽的表格在源码中难以阅读，因此请使用紧凑布局，或将其拆分为两个表格。

    生成器会上传我的数据吗？

    不会。表格由此页面中的脚本在你的设备上构建，页面不发出任何网络请求。它不会保存你的数据：关闭或重新加载页面即会清除。Download 按钮会将页面中的文件保存到你的设备。
