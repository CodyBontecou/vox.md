Markdown 清单生成器:把任意列表变成带截止日期的任务

粘贴普通行、项目符号、编号条目或现有任务列表,即可复制有效的 - [ ] 任务,保留嵌套层级,可选添加截止日期,并显示已完成数量。

作者：
Cody Bontecou
更新于
2026年11月24日
需要
任何现代浏览器,包括 iPhone 上的 Safari。可选:用于清单的 Obsidian,以及用于语音捕获任务的 iPhone 或 Mac 版 Vox.md。
简短回答

Markdown 任务由一个连字符、一个空格、方括号、一个空格和文本组成。写作 - [ ] task 表示未完成的任务, - [x] done 表示已完成的任务。要把整个列表转换为任务,请粘贴到 清单生成器 如下。

- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

生成器会移除已有的项目符号、编号和复选框以免重复,把缩进保留为嵌套层级,并能按你的 Obsidian 插件可读取的格式添加截止日期。它完全在本页中运行:列表不会被上传,页面也不会发出任何网络请求。

2. Markdown 清单语法

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

每个任务都是一个列表项:一个连字符和一个空格,然后是 [ ] 方括号之间有一个空格,然后是文本。 Obsidian Help页面 和 GitHub Docs页面 都将其描述为连字符和空格,后面跟着 [ ]。要将任务标记为完成,GitHub Docs 说明应使用 [x].

空格很重要。 GitHub Flavored Markdown 规范 将复选框标记定义为一个左方括号、一个空白字符或字母 x,以及一个右方括号,并且其后的文本之前需要有空白字符。因此 [] (里面什么都没有),或 - [ ]text (括号后没有空格)不符合定义。连字符及其后的空格才是让这一行成为列表项的关键。

任务列表不属于核心 Markdown。同一规范将其标记为 CommonMark 的扩展,其引言也说明,原始 CommonMark 规范中没有的功能会被标记为扩展。未实现该扩展的渲染器会把方括号显示为纯文本,这通常就是复选框显示为 [ ] 页面上。

3. Obsidian 中的清单

Obsidian 帮助中的 基本格式语法 页面介绍了任务列表:

  • 任务以连字符和空格开头,后面跟着 [ ].
  • 你可以在方括号内使用任何字符来把任务标记为完成,因此 [x], [-] 和 [?] 都算。
  • 通过缩进列表项来嵌套任务列表。使用 Tab 或 Shift+Tab 来缩进或取消缩进所选条目。
  • 在阅读视图中,选中复选框即可切换任务状态。

帮助页面说明任何字符都能完成任务,但并未描述每个字符对应的不同外观。如果 [-] 或 [?] 看起来不同于 [x] 在你的库中,这来自你安装的主题或 CSS 代码片段,而不是 Markdown 本身。

生成器中的进度行也按同样方式计数:方括号内除空格以外的任何字符都视为已完成,因此 [x], [X], [-] 和 [?] 均为已完成,而 [ ] 表示未完成。以“done:”或“x ”开头的行是普通文本;该工具不会猜测它们表示已完成的任务。

4. 截止日期:Tasks、Dataview 与 Reminder 的对比

Obsidian 的任务列表语法本身没有截止日期:帮助页面中没有相关说明。有三个插件会读取写在任务文本中的日期,各自使用不同的格式。生成器会把日期写成 ISO YYYY-MM-DD 在这三个插件中都是如此。没有插件时,日期只是文本。

格式读取者示例行
截止: 📅 YYYY-MM-DDTasks 插件,其中说明日期必须采用 YYYY-MM-DD 格式- [ ] send invoice 📅 2026-11-25
计划日期: ⏳ YYYY-MM-DDTasks 插件- [ ] send invoice ⏳ 2026-11-25
开始: 🛫 YYYY-MM-DDTasks 插件- [ ] send invoice 🛫 2026-11-25
行内字段: [due:: YYYY-MM-DD]Dataview文档,它会读取写在任务上的字段,例如 [completion:: 2021-08-15]- [ ] send invoice [due:: 2026-11-25]
提醒: (@YYYY-MM-DD) 或 (@YYYY-MM-DD HH:mm)obsidian-reminder 插件,其 README 展示了 (@2021-08-14) 和 (@2021-08-14 09:37) 于未勾选的任务- [ ] send invoice (@2026-11-25 09:30)

请选择你使用的那一个插件。Dataview 的页面还列出了它自己的日期 emoji 简写,并说明只支持这些简写;生成器改用 Dataview 的方括号形式。Reminder 的 README 指出,已勾选的任务不会再发出提醒通知。

5. GitHub 与 Obsidian 的差异

GitHub Docs 将其描述为 [ ] 表示未完成的任务, [x] 来标记完成。GFM 规范将该标记定义为空白字符或字母 x 之间。Obsidian 接受任何字符。因此像这样的任务 - [-] skipped 或 - [?] unsure 在 Obsidian 中算作已完成,但它不在规范的标记定义之内,遵循规范的渲染器可能会将其显示为纯文本。如果该文件也会在 GitHub 上阅读,请使用 [ ] 和 [x] 。

GitHub Docs 补充了一条规则:如果任务描述以圆括号开头,需要用反斜杠转义,例如 - [ ] \(Optional) Open a followup issue。生成器不会为你添加反斜杠;当任务以圆括号开头时,它会给出警告。

表格是另一处 Obsidian 与 GitHub 细节有差异的语法。若要把电子表格单元格或 CSV 转成在 Obsidian 和 GitHub 上都能用的表格，请使用 Markdown 表格生成器.

在任务清单上方用标注突出显示摘要或警告： Obsidian 标注生成器 会生成 > [!type] Markdown，包括可折叠的标注。

6. 在 iPhone 和 Mac 上用 Vox.md 语音或文字捕获任务

Vox.md 的 Todo Checklist 处理模式会生成 Markdown - [ ] 会从捕获内容中提取任务项,其后备方案是确定性的清单格式化器。语音在你的设备上转写。在 Capture Bar 中, 检查名单 应用 - [ ] 前缀,以及 两日期设置 插入 (@yyyy-MM-dd) 或带时间的形式。请参阅 快速捕捉 和 Routes 与处理模式 文档。

Route 可以把这些条目添加到你的每日笔记中某个标题之下,例如 ## Tasks; 追加到 Obsidian 每日笔记 介绍了设置方法,而 每日笔记模板生成器 负责编写笔记的结构。如果是会议中的待办事项,请参阅 会议记录模板;关于任务列表前缀的做法,请参阅 捕捉模板.

Vox.md 会写入 (@yyyy-MM-dd) 形式。它不会写入 Tasks 插件的 emoji 日期或 Dataview 字段。如果你使用其中之一,请把捕获的任务粘贴到上方的生成器中并选择该格式,或之后再编辑日期。要构建笔记顶部的属性,请使用 属性生成器.

7. 常见问题

为什么我的复选框显示为 [ ] 文本?

渲染器没有绘制任务列表。任务列表是 CommonMark 的扩展,不支持该扩展的渲染器会直接显示方括号。请检查该行是否以连字符和空格开头,方括号之间是否有一个空格或 x 方括号之间,右括号后面还要有一个空格。在 Obsidian 中,代码块或表格单元格里的任务,可能不会像列表项那样显示为复选框。

如何嵌套任务?

缩进子任务。在 Obsidian 中,按 Tab 缩进所选条目, Shift+Tab 来取消缩进。生成器会把你列表中的 2 个或 4 个空格转换为每级一个制表符,你也可以选择转换为 2 个或 4 个空格。

如何用 x 以外的字符勾选复选框?

Obsidian 帮助指出,方括号内的任何字符都会把任务标记为完成,因此 - [-] task 和 - [?] task 均为已完成。除非你重置列表,否则生成器会保留你粘贴的字符。对于也会在 GitHub 上阅读的文件,请使用 [x].

如何添加 Tasks 插件能读取的截止日期?

把 📅 以及一个 YYYY-MM-DD 日期放在任务末尾,例如 - [ ] send invoice 📅 2026-11-25。在上方选择“Tasks 插件:截止”即可为每个任务添加。使用 ⏳ 表示计划日期, 🛫 表示开始日期。

生成器会上传我的列表吗?

不会。列表由本页中的脚本在你的设备上转换,页面不会发出任何网络请求。它也不会保存你的列表:关闭或重新加载页面后内容即被清除。
