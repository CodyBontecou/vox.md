    文档 · 路由

    目前位置、 {location}，以及元数据

    在条目格式中使用一次发起时位置，不自动添加 YAML 或行内字段。每个路由中，获取位置和输出元数据都是分开、明确的选择。

    更新于 2026 年 8 月 21 日 一次性获取 不在后台跟踪 完整功能指南
    01 / 概览

    获取位置不等于输出元数据

    每个路由有两项独立的位置控件。 使用当前位置 决定路由是否请求一次采集发起时的位置。 写入位置元数据 决定是否将获取的快照也写入 frontmatter 或行内字段。

    控件含义它不意味着什么
    系统位置权限允许 Vox.md 在使用应用或受支持的采集界面时请求位置。它不会为任何路由启用位置。
    使用当前位置为此路由请求一次位置，并供以下内容使用： {location}.它不会自动写入 YAML 或行内元数据。
    写入位置元数据根据获取的快照写入所选结构化字段或经验证的高级 YAML。它不控制是否 {location} 可以渲染。
    路由才是意图信号，不是权限

    授予使用期间权限仅打开操作系统的门槛。Vox.md 仍仅为独立的采集栏目前位置操作，或已开启使用当前位置的路由请求位置。

    02 / 设置

    为单个路由设置目前位置

    1. 打开路由。在 iPhone 或 iPad 上打开设置 → 路由。在 Mac 上打开设置并选择路由。
    2. 编辑路由。选择应使用发起位置的路由。该设置仅属于该路由，不影响其他路由。
    3. 打开位置。开启 使用当前位置。保持 写入位置元数据 关闭，以使用仅令牌行为。
    4. 选择精度。选择准确可使用原始定位结果；选择城市则将坐标四舍五入到小数点后两位，且不显示兴趣点名称。
    5. 选择不可用时的行为。询问、不带位置发送或取消采集，决定无法获取原始定位结果时的行为。
    6. 添加 {location} 如有需要。将令牌放入条目模板、自定义条目前后缀，或仓库 Markdown 模板。

    首次使用可能显示操作系统位置权限提示。如果此前拒绝权限，请在 iOS、iPadOS 或 macOS 系统设置中为 Vox.md 启用位置访问。

    03 / 常用配置

    选择满足需求的最少位置内容

    所需结果使用当前位置写入位置元数据寺庙
    无路由位置关闭关闭请勿使用 {location}，否则会渲染为空。
    仅可点击链接开关闭添加 {location}。不写入位置字段。
    仅元数据开开省略 {location}。仅写入已配置的字段。
    链接与元数据开开添加 {location} 并配置元数据字段。

    关闭使用当前位置，会同时阻止该路由的令牌渲染和元数据输出，即使仍保留之前配置的元数据格式供以后使用。

    04 / 模板令牌

    使用 {location} 不更改笔记元数据

    开启使用当前位置且原始快照可用时， {location} 渲染经过验证的 Google Maps Markdown 链接：

    [Location](https://www.google.com/maps/search/?api=1&query=45.501235%2C-73.567890)

    令牌可用于可复用条目模板、自定义条目前后缀和仓库 Markdown 模板。它使用路由所选的同一组准确或城市坐标。

    仅令牌示例

    对于这样的后缀：

    Captured from {location}

    Vox.md 可生成：

    Captured from [Location](https://www.google.com/maps/search/?api=1&query=45.501235%2C-73.567890)

    关闭写入位置元数据时，该链接是路由添加的唯一位置内容。不会添加 locations: 集合，也没有 location.*:: 字段被写入。

    编辑器一键修复

    如果实际生效的条目前缀、后缀或可复用条目模板使用 {location} 而所选路由关闭了目前位置时，编辑器会说明令牌将渲染为空，并提供 为 [Route] 使用当前位置。该操作为路由开启目前位置，同时有意保持写入位置元数据关闭，让下一次发送可解析令牌而不更改笔记元数据。实时仓库模板文件仅在投递时读取，因此其内容无法触发编辑器提示；仓库模板使用该令牌时，请手动启用目前位置。

    令牌为空时

    {location} 在目前位置关闭、位置不可用或采集选择不带位置继续时变为空字符串。设计可选模板行时，请注意周围标点和标签。

    独立采集栏操作

    快速捕捉 目前位置 操作直接在当前草稿中插入一次性 Google Maps 链接。它独立于路由，不更改使用当前位置或写入位置元数据设置。

    05 / 元数据输出

    仅在你选择时写入结构化字段

    笔记需要接收机器可读位置字段，以补充或替代以下内容时，请开启写入位置元数据： {location} 链接。

    笔记 frontmatter

    将每个位置追加到名为以下内容的集合： locations 默认以采集 ID 为键。现有的无关 frontmatter 会保留。

    行内条目字段

    写入 Dataview 风格的 location.key:: value 行放在采集条目旁边。不会添加 frontmatter 集合。

    结构化字段

    选择并重命名坐标、纬度、经度、地点、城市、地区、国家、提供商链接、geo URI、精度、时间戳、来源和 ID。

    高级 YAML

    为笔记 frontmatter 使用经过验证且有边界限制的 YAML 模板。高级 YAML 不适用于行内条目字段。

    结构化 frontmatter 示例

    ---
title: Field Notes
locations:
  - id: "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee"
    coordinates: [45.501235, -73.567890]
    place: "Café & Main"
    appleMapsURL: "https://maps.apple.com/?ll=45.501235%2C-73.567890&q=Caf%C3%A9%20%26%20Main"
    timestamp: "2023-11-14T22:13:20.000Z"
    source: "app"
---

    滚动笔记可在集合中保留多次采集。位置合并内置重试保护：同一采集 ID 的重试无法重复追加同一位置。如果所选集合键已有不兼容的用户编写值，Vox.md 会停止，而不会覆盖。

    行内条目示例

    location.id:: aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee
location.coordinates:: [45.501235, -73.567890]
location.place:: "Café & Main"

Captured text

    高级 YAML 占位符

    高级模板可使用占位符，例如 {{coordinates}}, {{latitude}}, {{longitude}}, {{place}}, {{city}}, {{region}}, {{country}}, {{appleMapsURL}}, {{googleMapsURL}}, {{openStreetMapURL}}, {{geoURI}}, {{accuracy}}, {{timestamp}}, {{source}}，以及 {{id}}。保存前请在路由设置中预览配置。

    06 / 精度与标签

    准确与城市使用同一份一致快照

    精度坐标标签链接与字段
    准确保留原始定位结果，显示到小数点后六位。所选元数据字段需要时，可包含兴趣点名称。所有派生值都使用准确坐标。
    城市在保留快照前，将经纬度四舍五入到小数点后两位。移除兴趣点名称；城市、地区和国家可保留。所有提供商 URL、geo URI、令牌和字段都使用舍入后的坐标。

    仅在开启写入位置元数据，且所选结构化字段或高级占位符需要地点、城市、地区或国家时，才使用 Apple 系统反向地理编码器。仅令牌路由会跳过反向地理编码。标签查询失败时，基于坐标的输出仍可用。

    07 / 采集来源

    快照属于采集发起位置

    目前位置在采集发起的边界时刻确定。重试和恢复会复用这一持久保存的结果，而不会悄悄获取更新的位置。

    采集来源获取边界
    iPhone 和 iPad 快速捕捉发送
    共享表单在共享扩展中发送
    直接入队的文本、链接和文件意图意图调用
    打开快速捕捉的快捷指令、小组件、控件和深层链接在编辑器中发送
    快捷指令、小组件、控件、即时语音和键盘驱动路由录音录音停止时
    Apple Watch 普通采集投递以手表停止录音时为准；iPhone 不会替换为自身的位置
    Mac 采集发送时，或即时语音投递的录音停止时

    手表仅录音 将原始 M4A 音频导出到文件，没有 Markdown 内容，因此即使路由其他情况下使用目前位置，也不会请求位置。

    08 / 不可用与恢复

    选择各路由如何处理不可用的定位结果

    • 询问： 交互式采集可重试、取消、仅本次不带位置发送，或为该路由选择始终不带位置发送。
    • 不带位置发送： 不带令牌值或元数据输出继续投递。
    • 取消采集： 会停止投递，而不会创建缺少所请求发起位置的笔记。
    • 重置已保存选择： 使用路由位置设置中的重置位置不可用选择。

    无人值守的询问请求保存发起时位置不可用的结果，以供稍后检查。重试排队或失败的采集绝不会替换为稍后位置。待处理工作仅保留本地恢复所需的、按隐私设置调整后的快照或不可用结果。

    09 / 现有路由

    升级保留原有元数据行为

    将获取和输出分开可保证迁移安全：

    • 新路由： 使用当前位置和写入位置元数据初始均关闭。
    • 以前启用位置的路由： 升级后两项控件均保持开启，保留这些路由原有元数据输出。
    • 此前停用位置的路由： 两项控件都保持关闭；升级不会引入新的元数据输出。

    要将现有写入元数据的路由改为仅令牌行为，保持使用当前位置开启，关闭写入位置元数据。现有 Markdown 不会被重写或移除。

    10 / 隐私与保留

    一次明确的位置快照，绝不后台跟踪

    • Vox.md 不会持续监测位置或运行后台位置跟踪。
    • 位置不会发送至 Vox.md 服务器、分析系统、广告系统或第三方 AI 服务。
    • 令牌和提供商 URL 在本地格式化。只有打开链接时，Apple Maps、Google Maps 或 OpenStreetMap 才会收到坐标。
    • 仅当所选元数据需要地点名称时，Apple 系统反向地理编码器才可能发起网络请求。仅令牌位置会跳过此查询。
    • 投递成功后，可恢复请求会精简为不含内容的回执，已完成采集历史不保留坐标、标签、提供商 URL 或位置模板。
    • 位置元数据或令牌链接写入 Markdown 后，便成为所选文件的一部分。文件同步提供商可能按其自身条款处理该文件。
    权限可保持开启，路由仍保持私密

    可以保持系统权限可用于独立的目前位置操作，同时关闭所有路由的使用当前位置设置。

    请参阅 隐私政策 了解完整的数据处理和保留详情。

    11 / 故障排查

    修复常见位置和模板问题

    {location} 渲染为空

    确认实际生效的条目模板、前缀、后缀或仓库模板使用了完全一致的小写令牌 {location}。然后为执行投递的路由开启使用当前位置。编辑器的一键修复可针对检测到的行内条目格式执行此操作，而不启用元数据；实时仓库模板文件需手动设置路由。如果权限被拒绝或定位结果不可用，请检查路由的不可用行为及系统位置设置。

    链接有效，但未出现元数据

    仅令牌配置下，这是预期行为。打开路由的位置设置，开启写入位置元数据，再选择笔记 frontmatter 或行内条目字段，并选择所需字段。

    出现元数据，但条目中没有链接

    元数据输出不会自动插入链接。请添加 {location} 到实际生效的条目格式或仓库 Markdown 模板中。

    缺少地点或城市

    确认已选择标签字段。坐标仍可用时，Apple 反向地理编码器仍可能失败。城市精度会按设计移除兴趣点名称。

    frontmatter 投递报告冲突

    配置的集合键， locations 默认情况下必须是兼容的位置列表。在路由设置中重命名集合，或调整现有用户编写的 frontmatter。Vox.md 不会覆盖不兼容的值。

    重试时的位置较旧或不可用

    这是有意设计。请求保留发起时结果，避免稍后重试悄悄声称另一个采集位置。需要新快照时请新建采集。

    已允许位置权限，但路由未请求位置

    系统权限只是门槛。编辑该路由并开启使用当前位置。仅授予权限绝不会自动为路由启用位置。
