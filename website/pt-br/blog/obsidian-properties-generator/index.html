Gerador e verificador de propriedades de nota do Obsidian (frontmatter YAML)

Gere propriedades no formato que o Obsidian espera, ou verifique um frontmatter que você já tem e veja por que uma propriedade não aparece com o tipo que você queria.

Por
Cody Bontecou
Atualizado
22 de novembro de 2026
Requer
Obsidian (qualquer plataforma). Opcional: Vox.md para iPhone, Apple Watch ou Mac, para adicionar propriedades às notas capturadas.
Resposta curta

As propriedades de nota do Obsidian são YAML no topo da nota, entre duas linhas --- linhas. Cada propriedade é um name: value par, uma lista tem uma - value linha por item, e um link interno deve estar entre aspas. Este exemplo é válido:

---
tags:
  - journal
  - idea
aliases:
  - Weekly review
date: 2026-11-21
project: "[[Vox.md launch]]"
published: true
---

Precisa de outras propriedades ou quer saber por que uma não aparece com o tipo que você queria? O gerador abaixo escreve o YAML e o verificador lista os problemas com número de linha e uma correção. Ambos rodam inteiramente nesta página: nada do que você digita é enviado a lugar nenhum. As regras vêm da Ajuda do Obsidian, Propriedades e Etiquetas.

    2. Verifique o frontmatter que você já tem

    Cole o início de uma nota, incluindo as linhas --- linhas. O verificador lê o bloco linha por linha e lista cada problema com o número da linha e uma correção. Ele usa um conjunto fixo de regras de linha, não um analisador YAML completo, então pode deixar passar um erro que um analisador encontraria, e só verifica as regras listadas aqui.

    O verificador procura: tabulações usadas como indentação, ausência de ---, links internos sem aspas, tags com espaços, uma # prefixo, outros caracteres que tags não podem conter ou apenas números, os nomes descontinuados tag, alias e cssclass, objetos aninhados, formatação Markdown nos valores, nomes duplicados e alguns valores que o próprio YAML lê de forma diferente do que você quis dizer. Tokens de modelo como {{date}} e <% %> são ignoradas.

    3. Tipos de propriedade e como cada um é escrito

    O Obsidian aceita sete tipos de propriedade. Cada um é escrito no YAML assim:

    TipoExemplo de YAMLPegadinha
    Textotitle: Weekly reviewColoque entre aspas um valor que o YAML leria errado, como um com : nele, ou um que começa com #. Links internos devem estar entre aspas.
    Listatopics:
      - sleep
      - focus    		Cada valor fica em sua própria linha, precedido por um hífen e um espaço.
    Númerorating: 4Escreva o número sem aspas.
    Caixa de seleçãopublished: trueO valor é true ou false.
    Datadate: 2026-11-21O formato é YYYY-MM-DD.
    Data e horatime: 2026-11-21T10:30:00O formato é YYYY-MM-DDTHH:MM:SS.
    Etiquetastags:
      - recipe
      - cooking    		Escrito sem #. Sem espaços e com pelo menos um caractere não numérico.

    O Obsidian também tem três propriedades padrão: tags, aliases e cssclasses. O gerador tem um botão para cada um.

    4. As regras que mais quebram propriedades

    • Coloque links internos entre aspas. project: "[[Vox.md launch]]", não project: [[Vox.md launch]]. Isso vale para propriedades de texto e para itens de uma lista.
    • Um item de lista por linha. Cada item começa com um hífen e um espaço, indentado sob o nome da propriedade. Use espaços para indentar, não tabulações.
    • Tags têm regras próprias. Não # no YAML, sem espaços e com pelo menos um caractere não numérico: 1984 não é uma tag válida, mas y1984 é. Use / para tags aninhadas como inbox/to-read. Veja Etiquetas na Ajuda do Obsidian.
    • Escreva as datas no formato armazenado. 2026-11-21 para uma data e 2026-11-21T10:30:00 para data e hora.
    • Use os nomes atuais. tag, alias e cssclass foram descontinuados no Obsidian 1.4 em favor de tags, aliases e cssclasses, e o suporte a eles como propriedades padrão foi removido no Obsidian 1.9.
    • Não aninhe. As propriedades não aceitam objetos aninhados. O Obsidian sugere o modo de código-fonte para ver propriedades aninhadas, então transforme-as em nomes de nível superior como project_status.
    • Não use Markdown. Negrito, links e outras formatações não são renderizados nas propriedades. O Obsidian diz que isso é intencional, porque as propriedades servem para pequenas informações atômicas.

    5. Usar propriedades em modelos

    Ative Tokens de plugins de modelos no gerador para gravar campos de data como um token em vez de uma data fixa. O plugin principal Modelos usa {{date:YYYY-MM-DD}}; o plugin da comunidade Templater usa <% tp.date.now("YYYY-MM-DD") %> (veja o Templater documentação). Campos de data e hora usam YYYY-MM-DD[T]HH:mm:ss no token, com o T entre colchetes para que seja gravado como uma letra.

    Links exigem cuidado aqui. O Obsidian adiciona as aspas a um link digitado na interface de Propriedades, mas um plugin de modelos grava o texto no arquivo como está, então escreva as aspas você mesmo no modelo: project: "[[Vox.md launch]]".

    Para modelos completos que usam estas propriedades, veja os gerador de modelo de nota diária e o gerador de modelo de notas de reunião.

    6. Adicione propriedades às notas que você captura

    Em uma Rota do Vox.md, o campo Metadados aceita um key: value por linha, como tags: [journal, idea]. Metadados iniciais da nota grava os metadados no escopo do documento. Campos de entrada inline grava key:: value campos ao lado de cada entrada em uma nota contínua. Veja Metadados na referência de Rotas.

    O botão do gerador Copiar como metadados de Rota do Vox.md grava suas propriedades nesse formato, com listas como [a, b] e uma propriedade por linha. A documentação do Vox.md descreve o campo como key: value linhas; esta página não testa como cada tipo de propriedade é escrito, então abra a primeira nota capturada no Obsidian e confira. Rotas para uma nota diária e uma caixa de entrada estão em Adicionar a uma nota diária do Obsidian, modelos de captura e Notas de voz do iPhone para Obsidian.

    7. Perguntas

    Por que o Obsidian não mostra minha propriedade com o tipo que eu queria?

    O Obsidian lê propriedades como YAML, e um valor que não segue as regras do seu tipo não é mostrado como esse tipo. As causas comuns são um link sem aspas, uma lista que não está escrita com um item por linha, uma data que não está em YYYY-MM-DD, e tags com espaços. Cole o bloco no verificador acima para encontrar a linha.

    As tags precisam de # nas propriedades?

    Não. No YAML, as tags são escritas como palavras simples, como - recipe. O # serve para tags no corpo de uma nota.

    Posso aninhar propriedades?

    Não. As propriedades não aceitam objetos aninhados. Use nomes simples ou tags aninhadas com / dentro do tags lista.

    Posso escrever propriedades como JSON?

    O Obsidian consegue ler um bloco JSON, mas o lê e salva como YAML. O verificador acima só aplica suas regras de linha a YAML.
