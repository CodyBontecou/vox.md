Criador de tabelas Markdown para Obsidian: cole do Excel, Sheets ou CSV

Cole linhas do Excel, Google Sheets, Numbers, CSV ou TSV e copie uma tabela com barras verticais válida, com a barra em [[Note|Alias]] e ![[image.png|300]] escapada, quebras de linha tratadas e alinhamento por coluna.

Por
Cody Bontecou
Atualizado
26 de novembro de 2026
Requer
Qualquer navegador moderno, incluindo o Safari no iPhone. Opcional: Obsidian para as tabelas e Vox.md para iPhone ou Mac para capturar o texto em uma nota.
Resposta curta

Uma tabela Markdown é uma linha de cabeçalho, uma linha delimitadora de hifens e depois uma linha por registro, com células separadas por |. Cole suas células no criador de tabelas abaixo para obter uma, ou comece a partir deste exemplo.

| Name | Owner | Status |
| --- | --- | --- |
| Draft | Ana | Done |
| Review | Lee | Open |

O criador também corrige o que geradores genéricos ignoram no Obsidian: ele escapa a barra vertical dentro de [[Note|Alias]] e ![[image.png|300]] como \|, e transforma uma quebra de linha dentro de uma célula em <br> ou um espaço. Ele roda inteiramente nesta página: seus dados nunca são enviados, e a página não faz nenhuma requisição de rede.

    2. Sintaxe de tabelas Markdown

    | Name   | Qty | Price |
| :----- | :-: | ----: |
| Apple  |   3 |  1.20 |
| Pear   |  12 |  0.80 |

    O especificação GitHub Flavored Markdown define uma tabela como uma linha de cabeçalho, uma linha delimitadora que separa o cabeçalho dos dados e zero ou mais linhas de dados. As células são separadas por barras verticais.

    • Linha delimitadora. Suas células contêm apenas hifens, com dois-pontos opcionais à esquerda, à direita ou em ambas as extremidades para definir alinhamento à esquerda, à direita ou centralizado. Ajuda do Obsidian diz que você adiciona dois-pontos à linha de cabeçalho para alinhar o texto, e que a linha de cabeçalho deve conter pelo menos dois hifens.
    • Barras externas. As barras verticais nas extremidades são opcionais na especificação. A Obsidian Help diz que incluí-las é recomendado para facilitar a leitura, e o criador sempre as escreve.
    • Preenchimento. As células não precisam de alinhamento perfeito, segundo a Obsidian Help. O layout “Pad columns” do criador alinha o código-fonte apenas para facilitar a leitura; “Compact” dispensa isso.
    • Contagens iguais. A especificação diz que a linha de cabeçalho deve ter o mesmo número de células que a linha delimitadora. Se não tiver, as linhas não formam uma tabela e são exibidas como um parágrafo. Uma linha de dados com menos células recebe células vazias, e as células extras são ignoradas.
    • Dentro de uma célula. A especificação permite formatação em linha, mas não conteúdo de nível de bloco, então uma lista ou um título não pode ficar em uma célula. A Obsidian Help diz que você pode usar a sintaxe básica de formatação dela para estilizar o conteúdo em uma tabela.
    • O fim de uma tabela. A especificação diz que a tabela é interrompida na primeira linha vazia ou no início de outra estrutura de nível de bloco.

    O criador escreve pelo menos três hifens em cada célula delimitadora. Isso atende ao mínimo de dois do Obsidian e aos três que o Documentação do GitHub pede.

    3. Tabelas no Obsidian

    • Insert Table (inserir tabela). A Obsidian Help diz que você pode inserir uma tabela com o comando Insert Table na Command Palette. Para criar uma a partir de dados que você já tem, cole-os no criador acima.
    • Aliases e tamanhos de imagem. Um alias de wikilink como [[Note|Alias]] e um tamanho de imagem como ![[image.png|300]] contêm uma barra vertical. A Obsidian Help diz que, dentro de uma tabela, você precisa adicionar uma \ antes da barra, então escreva [[Note\|Alias]] e ![[image.png\|300]]. O criador faz isso por você; um escape que você já escreveu não é duplicado.
    • Qualquer outra barra vertical. A especificação GFM diz que uma barra vertical dentro de uma célula deve ser escapada com uma barra invertida, mesmo dentro de um trecho de código. O criador escapa toda barra vertical não escapada como \|.
    • Quebras de linha. Uma linha é escrita em uma só linha, então uma quebra de linha dentro de uma célula precisa virar outra coisa. O criador escreve um HTML <br> ou une as linhas com um espaço, se você escolher essa opção. Nem a seção Tables da Obsidian Help nem o GitHub Docs descrevem quebras de linha em células, então verifique como o <br> é exibido no seu próprio cofre, e escolha a opção de espaço se não quiser tags no código-fonte.
    • Complementos. Existem plugins da comunidade que ajudam a editar tabelas. Esta página não avalia nem recomenda nenhum deles.

    Para listas de tarefas, veja o Gerador de checklist em Markdown; para as propriedades no topo de uma nota, o gerador de propriedades. Uma tabela funciona bem para uma lista de decisões e responsáveis em uma nota da modelo de notas de reunião.

    4. Do Excel, Google Sheets ou CSV

    Selecione as células na sua planilha, copie e cole na caixa acima. Se as células forem coladas com tabulações entre elas, o criador detecta isso. Ele também detecta vírgulas, pontos e vírgulas e barras verticais, e lê campos CSV entre aspas, então "Lee, Sam" continua sendo uma célula e "" entre aspas vira uma aspa. Use o menu Separator se o palpite estiver errado. Marque ou desmarque “The first row is the header” para decidir se a primeira linha vira a linha de cabeçalho; sem isso, uma linha de cabeçalho vazia é adicionada, porque uma tabela Markdown precisa de uma.

    • Células mescladas. A especificação e as duas páginas de ajuda descrevem uma linha como uma lista de células separadas por barras verticais, e nenhuma descreve uma forma de mesclar células. Coloque o valor em todas as células que a mesclagem cobriria antes de copiar.
    • Fórmulas. O criador lê apenas o texto que você cola. Se as células coladas mostrarem fórmulas em vez dos resultados, copie os valores no app da planilha e cole novamente.
    • Linhas irregulares. Se uma linha tiver um número de células diferente do cabeçalho, o criador avisa com o número da linha e completa a tabela com células vazias. Uma linha com mais células que o cabeçalho amplia a tabela em vez de descartar dados.
    • Inverter e reparar. Cole uma tabela Markdown existente para realinhá-la, ou defina Output as como CSV ou TSV para exportá-la. O criador avisa, com o número da linha, quando a linha delimitadora está ausente, quando o número de células dela não corresponde ao cabeçalho ou quando uma linha em branco encerraria a tabela.

    Os dois-pontos de alinhamento de uma tabela Markdown colada são mantidos, e você pode alterar cada coluna com os menus Column alignment.

    5. Diferenças entre GitHub e Obsidian

    A Obsidian Help e o GitHub Docs descrevem tabelas com barras verticais, com linha de cabeçalho, hifens e dois-pontos de alinhamento opcionais. As diferenças que as páginas indicam são pequenas:

    TópicoAjuda do ObsidianGitHub Docs e especificação GFM
    HifensA linha de cabeçalho deve conter pelo menos dois hifensGitHub Docs: pelo menos três hifens em cada coluna do cabeçalho
    Linha em branco antes da tabelaA seção Tables não menciona nenhumGitHub Docs: você deve incluir uma linha em branco antes da tabela
    Barra vertical literal em uma célulaAdicione uma \ antes da barra em aliases e tamanhos de imagemEscape-a como \|, mesmo dentro de um trecho de código
    Barras externasOpcional, recomendado para facilitar a leituraOpcional

    Para funcionar bem nos dois lugares, escreva três ou mais hifens, deixe uma linha em branco acima da tabela e escape todas as barras verticais. É isso que o criador faz. Um alias de wikilink é sintaxe do Obsidian; no GitHub é apenas texto com uma barra vertical. O guia do criador de checklists cobre as diferenças das listas de tarefas da mesma forma.

    6. Leve tabelas e notas para o seu cofre com o Vox.md

    O Vox.md não cria tabelas por conta própria, e o criador acima funciona sem o app. O que o Vox.md faz é capturar texto no Obsidian: o Quick Capture permite colar texto existente, e uma Route o entrega em um destino Markdown. Veja o Rápida captura e Rotas na documentação.

    1. Crie sua tabela acima e pressione Copy.
    2. No Vox.md no iPhone, iPad ou Mac, abra o Quick Capture e cole a tabela no editor de texto.
    3. Envie com uma Route que mantém o texto original. A documentação lista Manter original como o modo de processamento que preserva o texto capturado sem reescrita por IA, e dizem que o texto capturado é entregue sem alterações quando Usar Apple Intelligence está desativado, que é o padrão. Processar texto digitado é uma configuração opcional em cada Route.
    4. O destino da Route decide onde o texto vai parar: uma nota nova, uma nota contínua como a sua nota diária, ou uma nota existente, no final, no início ou abaixo de um título escolhido.

    Deixe uma linha em branco acima da tabela colada se o destino já tiver texto acima. Para uma receita de Route, veja modelos de captura, e para transformar um arquivo de legendas do Zoom, Teams ou YouTube em uma nota de transcrição primeiro, veja SRT e VTT para Markdown.

    Capture no Obsidian a partir do iPhone, iPad ou Mac com o Vox.md

    O Vox.md captura voz e texto nas suas notas do Obsidian. Gravação, transcrição e Capture exigem o Vox.md Unlimited: uma assinatura semanal ou anual com 7 dias de teste grátis para contas elegíveis, ou uma compra única vitalícia. A App Store mostra o preço local.

    7. Perguntas

    Por que minha tabela não é exibida no Obsidian?

    Verifique três coisas. Deve haver uma linha delimitadora de hifens logo abaixo do cabeçalho, e as linhas de cabeçalho e delimitadora devem ter o mesmo número de células; caso contrário, a especificação exibe as linhas como um parágrafo. A Obsidian Help diz que a linha de cabeçalho deve conter pelo menos dois hifens. E deixe uma linha em branco antes da tabela, o que o GitHub Docs exige e não custa nada no Obsidian. Cole a tabela no criador: ele avisa, com o número da linha, quando a linha delimitadora está ausente ou as contagens diferem.

    Como adiciono uma quebra de linha em uma célula?

    Mantenha a linha em uma só linha e use um HTML <br> dentro da célula, que é o que o criador escreve para uma célula de várias linhas. As páginas citadas não descrevem quebras de linha em células, então teste no seu cofre. A outra opção é unir as linhas com um espaço.

    Como coloco uma barra vertical ou um alias de wikilink em uma célula?

    Coloque uma barra invertida antes da barra vertical: [[Note\|Alias]], ![[image.png\|300]] ou a \| b. A Obsidian Help exige isso para aliases e redimensionamento de imagens dentro de tabelas, e a especificação GFM exige para qualquer barra vertical em uma célula.

    Posso mesclar células?

    Nenhuma sintaxe para isso aparece na especificação nem na Obsidian Help. Repita o valor em cada célula.

    Qual pode ser a largura de uma tabela?

    Nenhuma das páginas citadas indica um número máximo de colunas ou linhas, e o criador não define limite. Uma tabela muito larga é difícil de ler no código-fonte; use o layout Compact ou divida-a em duas tabelas.

    O criador envia meus dados?

    Não. A tabela é criada por um script nesta página, no seu dispositivo, e a página não faz nenhuma requisição de rede. Ela não salva seus dados: fechar ou recarregar a página os apaga. O botão Download salva um arquivo da página no seu dispositivo.
