Gerador de Obsidian Bases: filtros, visualizações e fórmulas

Crie o YAML de uma base do Obsidian sem aprender o esquema antes: escolha filtros, adicione visualizações, copie um arquivo .base ou um bloco de código e veja o que cada chave faz, com links para a documentação do próprio Obsidian.

Por
Cody Bontecou
Atualizado
28 de novembro de 2026
Requer
Qualquer navegador moderno, incluindo o Safari no iPhone. Opcional: Obsidian com o plugin essencial Bases e o Vox.md para iPhone ou Mac para capturar notas por voz ou texto.
Resposta curta

Uma base é uma visualização das suas notas no estilo de banco de dados, escrita em YAML com até cinco chaves de nível superior: filters, formulas, properties, summaries e views. Salve o YAML como um .base arquivo, ou cole-o em uma nota dentro de um base bloco de código. O gerador abaixo o escreve para você. A versão do Obsidian necessária depende do tipo de visualização: a página de visualizações lista Table e Cards a partir da 1.9, List e Map a partir da 1.10 e Kanban a partir da 1.14.

filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

O gerador roda inteiramente nesta página. Nada do que você digita é enviado, e a página não faz requisições de rede.

    2. Sintaxe do Bases em resumo

    Estas são as chaves que página de sintaxe do Obsidian documenta. Não há nenhum outro esquema para aprender.

    ChaveO que fazExemplo
    filtersRestringe as notas para todas as visualizações.file.hasTag("project")
    formulasDefine propriedades calculadas, usadas como formula.name.total: 'price * qty'
    propertiesConfigurações por propriedade. displayName define o cabeçalho da coluna.displayName: "Status"
    summariesDefine suas próprias fórmulas de resumo, usando values.Personalizado, opcional
    viewsUma lista de visualizações sobre as mesmas notas.- type: table
    type (visualização)O layout da visualização.table, cards, list
    name (visualização)O nome da visualização.name: "Projects"
    filters (visualização)Filtros somente para esta visualização.file.inFolder("Work")
    groupBy (visualização)Agrupa as linhas por uma property em um direction.direction: DESC
    order (visualização)As propriedades exibidas, em ordem.- file.name
    limit (visualização)Limita o número de linhas.limit: 10
    summaries (visualização)Associa uma propriedade a um resumo.price: Sum

    O gerador não escreve todas as chaves documentadas. A página de sintaxe também descreve groupOrder, e as visualizações podem guardar estados extras, como a coluna de ordenação, que o próprio Obsidian gerencia. Adicione-os à mão se precisar: o YAML é seu para editar.

    3. Filtros: and, or, not

    Um filtro é uma instrução de texto que é verdadeira ou falsa para cada nota, ou um objeto com and, or ou not contendo uma lista de mais filtros. Os filtros globais filters valem para todas as visualizações. O filters valem só para essa visualização, e os dois são combinados com AND.

    filters:
  or:
    - file.hasTag("meeting")
    - file.inFolder("Meetings")

    Não existe from ou source chave como em SQL ou Dataview. Sem filtro, uma base inclui todos os arquivos do vault, então sempre defina um, a menos que queira isso.

    Valores de texto precisam de aspas dentro da instrução, então o YAML precisa de aspas aninhadas: 'status == "done"'. O gerador faz isso por você. Filtros de função como file.hasTag(), file.inFolder() e file.hasLink() estão na página de funções.

    4. Fórmulas e resumos

    Cada entrada em formulas vira uma propriedade que você pode usar em todas as visualizações como formula.name. Uma fórmula pode usar outra fórmula, mas referências circulares não são permitidas, então uma fórmula não pode se referir a si mesma. O resultado é armazenado como uma string YAML, por isso a expressão fica entre aspas.

    formulas:
  formatted_price: 'if(price, price.toFixed(2) + " dollars")'

    O summaries associa uma propriedade a um resumo. A página de sintaxe lista estes padrões:

    • Número: Average, Min, Max, Sum, Range, Median, Stddev
    • Data: Earliest, Latest, Range
    • Booleano: Checked, Unchecked
    • Qualquer: Empty, Filled, Unique

    Para cálculos com datas, a página de sintaxe diz file.mtime > now() - "1 week" é verdadeiro para um arquivo modificado na última semana.

    5. O que isso significa

    Em um filtro ou fórmula, this é o arquivo em que a base é exibida. A página de sintaxe diz que é o próprio arquivo da base quando ela abre na área de conteúdo principal, o arquivo que a incorpora quando a base está incorporada em uma nota ou no Canvas, e o arquivo ativo da área de conteúdo principal quando a base está na barra lateral. A página fornece file.hasLink(this.file) como forma de replicar o painel de backlinks.

    6. Exemplos para copiar

    Estes são os modelos do gerador como código simples, então funcionam sem JavaScript. Substitua os nomes de pasta, tag e propriedade pelos seus. Salve o texto como um .base arquivo, ou coloque-o em um base bloco de código. Veja Criar uma base para os comandos, e incorpore um arquivo salvo com ![[Name.base]] ou ![[Name.base#View]] para escolher a visualização padrão.

    Lista de leitura

    filters:
  and:
    - file.inFolder("Reading")
    - 'status == "to read"'
properties:
  status:
    displayName: "Status"
views:
  - type: cards
    name: "Reading list"
    order:
      - file.name
      - status

    Projetos por status

    filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

    Notas com uma tag, modificadas esta semana

    filters:
  and:
    - file.hasTag("project")
    - 'file.mtime > now() - "1 week"'
views:
  - type: table
    name: "Modified this week"
    order:
      - file.name
      - file.mtime

    Backlinks desta nota

    filters:
  and:
    - file.hasLink(this.file)
views:
  - type: table
    name: "Backlinks"
    order:
      - file.name
      - file.folder

    Notas de voz capturadas com o Vox.md

    filters:
  and:
    - file.inFolder("Vox")
    - file.hasTag("voice")
views:
  - type: table
    name: "Voice notes"
    order:
      - file.ctime
      - file.name
      - file.tags

    O order list escolhe as colunas. A ordenação é uma configuração da visualização que você altera na barra de ferramentas do Obsidian, então os exemplos não definem nenhuma.

    7. Faça suas capturas aparecerem em uma base

    O Vox.md salva o que você captura como notas em Markdown em uma pasta do seu vault. O Documentação de metadados diz que uma Route pode adicionar metadados estáticos como key: value linhas, como tags: [journal, idea], e que Metadados iniciais da nota o escreve no escopo do documento. Ele também descreve metadados de localização opcionais. Uma base filtrada por essa pasta ou tag, como o último exemplo acima, lista então suas capturas em uma única tabela. Monte os metadados com o gerador de propriedades, e veja notas de voz para o Obsidian no iPhone para a configuração.

    8. Solução de problemas

    • A base mostra todas as notas. Nenhum filtro de origem definido. Por padrão, uma base inclui o vault inteiro, então adicione um file.inFolder() ou file.hasTag() filtro.
    • Uma coluna de propriedade está em branco. O nome não corresponde, incluindo maiúsculas e minúsculas, ou a nota não tem essa propriedade no frontmatter. Verifique as Propriedades da nota e o nome da coluna.
    • Erro de YAML. Verifique a indentação, que usa espaços, e as aspas. Um filtro com texto precisa de aspas aninhadas: 'status == "done"'.
    • Uma visualização map está vazia. O layout map exige o plugin Maps, segundo a página de visualizações.

    9. Perguntas

    O Bases é um plugin essencial?

    Sim. Ajuda do Obsidian diz: “Bases é um plugin essencial que permite criar visualizações de suas notas semelhantes a um banco de dados.”

    Bases ou Dataview?

    São coisas separadas. Dataview é um plugin da comunidade com sua própria linguagem de consulta. Uma base é YAML que o próprio Obsidian lê, sem from chave: você restringe as notas com filtros. Esta página não compara os recursos em mais detalhes.

    Posso editar o YAML à mão?

    Sim. Um .base é um texto YAML, e a página de sintaxe documenta as chaves. Abra o arquivo gerado em qualquer editor ou cole o bloco de código em uma nota e edite lá.

    O gerador envia meus dados?

    Não. Um script nesta página cria o YAML no seu dispositivo, e a página não faz nenhuma requisição de rede. Recarregar apaga tudo.
