    目前位置、 {location}，以及後設資料

    在條目格式中使用一次發起時位置，不自動添加 YAML 或行內欄位。每個路線中，獲取位置和輸出後設資料都是分開、明確的選擇。

    更新於 2026 年 8 月 21 日 一次性獲取 不在後台跟蹤 完整功能指南
    01 / 概覽

    獲取位置不等於輸出後設資料

    每個路線有兩項獨立的位置控制項。 使用目前位置 決定路線是否請求一次擷取發起時的位置。 寫入位置後設資料 決定是否將獲取的快照也寫入 frontmatter 或行內欄位。

    控制項含義它不意味著什麼
    系統位置權限允許 Vox.md 在使用App或受支援的擷取界面時請求位置。它不會為任何路線啟用位置。
    使用目前位置為此路線請求一次位置，並供以下內容使用： {location}.它不會自動寫入 YAML 或行內後設資料。
    寫入位置後設資料根據獲取的快照寫入所選結構化欄位或經驗證的進階 YAML。它不控制是否 {location} 可以渲染。
    路線才是意圖信號，不是權限

    授予使用期間權限僅打開作業系統的門檻。Vox.md 仍僅為獨立的擷取列目前位置操作，或已開啟使用目前位置的路線請求位置。

    02 / 設定

    為單個路線設定目前位置

    1. 打開路線。在 iPhone 或 iPad 上打開設定 → 路線。在 Mac 上打開設定並選擇路線。
    2. 編輯路線。選擇應使用發起位置的路線。該設定僅屬於該路線，不影響其他路線。
    3. 打開位置。開啟 使用目前位置。保持 寫入位置後設資料 關閉，以使用僅令牌行為。
    4. 選擇精度。選擇準確可使用原始定位結果；選擇城市則將座標四捨五入到小數點後兩位，且不顯示興趣點名稱。
    5. 選擇不可用時的行為。詢問、不帶位置傳送或取消擷取，決定無法獲取原始定位結果時的行為。
    6. 添加 {location} 如有需要。將令牌放入條目模板、自訂條目前後綴，或儲存庫 Markdown 模板。

    首次使用可能顯示作業系統位置權限提示。如果此前拒絕權限，請在 iOS、iPadOS 或 macOS 系統設定中為 Vox.md 啟用位置取用。

    03 / 常用配置

    選擇滿足需求的最少位置內容

    所需結果使用目前位置寫入位置後設資料寺廟
    無路線位置關閉關閉請勿使用 {location}，否則會渲染為空。
    僅可點擊連結開啟關閉添加 {location}。不寫入位置欄位。
    僅後設資料開啟開啟省略 {location}。僅寫入已配置的欄位。
    連結與後設資料開啟開啟添加 {location} 並配置後設資料欄位。

    關閉使用目前位置，會同時阻止該路線的令牌渲染和後設資料輸出，即使仍保留之前配置的後設資料格式供以後使用。

    04 / 模板令牌

    使用 {location} 不更改筆記後設資料

    開啟使用目前位置且原始快照可用時， {location} 渲染經過驗證的 Google Maps Markdown 連結：

    [Location](https://www.google.com/maps/search/?api=1&query=45.501235%2C-73.567890)

    令牌可用於可重複使用條目模板、自訂條目前後綴和儲存庫 Markdown 模板。它使用路線所選的同一組準確或城市座標。

    僅令牌範例

    對於這樣的後綴：

    Captured from {location}

    Vox.md 可生成：

    Captured from [Location](https://www.google.com/maps/search/?api=1&query=45.501235%2C-73.567890)

    關閉寫入位置後設資料時，該連結是路線添加的唯一位置內容。不會添加 locations: 集合，也沒有 location.*:: 欄位被寫入。

    編輯器一鍵修復

    如果實際生效的條目前綴、後綴或可重複使用條目模板使用 {location} 而所選路線關閉了目前位置時，編輯器會說明令牌將渲染為空，並提供 為 [Route] 使用目前位置。該操作為路線開啟目前位置，同時有意保持寫入位置後設資料關閉，讓下一次傳送可解析令牌而不更改筆記後設資料。即時儲存庫模板檔案僅在傳送時讀取，因此其內容無法觸發編輯器提示；儲存庫模板使用該令牌時，請手動啟用目前位置。

    令牌為空時

    {location} 在目前位置關閉、位置不可用或擷取選擇不帶位置繼續時變為空字符串。設計可選模板行時，請注意周圍標點和標籤。

    獨立擷取列操作

    快速捕捉 目前位置 操作直接在目前草稿中插入一次性 Google Maps 連結。它獨立於路線，不更改使用目前位置或寫入位置後設資料設定。

    05 / 後設資料輸出

    僅在你選擇時寫入結構化欄位

    筆記需要接收機器可讀位置欄位，以補充或替代以下內容時，請開啟寫入位置後設資料： {location} 連結。

    筆記 frontmatter

    將每個位置追加到名為以下內容的集合： locations 預設以擷取 ID 為鍵。現有的無關 frontmatter 會保留。

    行內條目欄位

    寫入 Dataview 風格的 location.key:: value 行放在擷取條目旁邊。不會添加 frontmatter 集合。

    結構化字段

    選擇並重命名座標、緯度、經度、地點、城市、地區、國家、提供商連結、geo URI、精度、時間戳、來源和 ID。

    進階 YAML

    為筆記 frontmatter 使用經過驗證且有邊界限制的 YAML 模板。進階 YAML 不適用於行內條目欄位。

    結構化 frontmatter 範例

    ---
title: Field Notes
locations:
  - id: "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee"
    coordinates: [45.501235, -73.567890]
    place: "Café & Main"
    appleMapsURL: "https://maps.apple.com/?ll=45.501235%2C-73.567890&q=Caf%C3%A9%20%26%20Main"
    timestamp: "2023-11-14T22:13:20.000Z"
    source: "app"
---

    滾動筆記可在集合中保留多次擷取。位置合併內置重試保護：同一擷取 ID 的重試無法重復追加同一位置。如果所選集合鍵已有不相容的使用者編寫值，Vox.md 會停止，而不會覆蓋。

    行內條目範例

    location.id:: aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee
location.coordinates:: [45.501235, -73.567890]
location.place:: "Café & Main"

Captured text

    進階 YAML 佔位符

    進階模板可使用佔位符，例如 {{coordinates}}, {{latitude}}, {{longitude}}, {{place}}, {{city}}, {{region}}, {{country}}, {{appleMapsURL}}, {{googleMapsURL}}, {{openStreetMapURL}}, {{geoURI}}, {{accuracy}}, {{timestamp}}, {{source}}，以及 {{id}}。儲存前請在路線設定中預覽配置。

    06 / 精度與標籤

    準確與城市使用同一份一致快照

    精確度座標標籤連結與欄位
    準確保留原始定位結果，顯示到小數點後六位。所選後設資料欄位需要時，可包含興趣點名稱。所有派生值都使用準確座標。
    城市在保留快照前，將經緯度四捨五入到小數點後兩位。移除興趣點名稱；城市、地區和國家可保留。所有提供商 URL、geo URI、令牌和欄位都使用捨入後的座標。

    僅在開啟寫入位置後設資料，且所選結構化欄位或進階佔位符需要地點、城市、地區或國家時，才使用 Apple 系統反向地理編碼器。僅令牌路線會跳過反向地理編碼。標籤查詢失敗時，基於座標的輸出仍可用。

    07 / 擷取來源

    快照屬於擷取發起位置

    目前位置在擷取發起的邊界時刻確定。重試和恢復會復用這一持久儲存的結果，而不會悄悄獲取更新的位置。

    擷取來源獲取邊界
    iPhone 和 iPad 快速捕捉發送
    分享表單在共享擴展中傳送
    直接入隊的文字、連結和檔案意圖意圖調用
    打開快速捕捉的捷徑、小工具、控制項和深層連結在編輯器中傳送
    捷徑、小工具、控制項、即時語音和鍵盤驅動路線錄音錄音停止時
    Apple Watch 普通擷取傳送以手錶停止錄音時為準；iPhone 不會替換為自身的位置
    Mac 擷取傳送時，或即時語音傳送的錄音停止時

    手錶僅錄音 將原始 M4A 音訊匯出到檔案，沒有 Markdown 內容，因此即使路線其他情況下使用目前位置，也不會請求位置。

    08 / 不可用與恢復

    選擇各路線如何處理不可用的定位結果

    • 詢問： 交互式擷取可重試、取消、僅本次不帶位置傳送，或為該路線選擇始終不帶位置傳送。
    • 不帶位置傳送： 不帶令牌值或後設資料輸出繼續傳送。
    • 取消擷取： 會停止傳送，而不會建立缺少所請求發起位置的筆記。
    • 重置已儲存選擇： 使用路線位置設定中的重置位置不可用選擇。

    無人值守的詢問請求儲存發起時位置不可用的結果，以供稍後檢查。重試排隊或失敗的擷取絕不會替換為稍後位置。待處理工作僅保留本地恢復所需的、按隱私權設定調整後的快照或不可用結果。

    09 / 現有路線

    升級保留原有後設資料行為

    將獲取和輸出分開可保證遷移安全：

    • 新路線： 使用目前位置和寫入位置後設資料初始均關閉。
    • 以前啟用位置的路線： 升級後兩項控制項均保持開啟，保留這些路線原有後設資料輸出。
    • 此前停用位置的路線： 兩項控制項都保持關閉；升級不會引入新的後設資料輸出。

    要將現有寫入後設資料的路線改為僅令牌行為，保持使用目前位置開啟，關閉寫入位置後設資料。現有 Markdown 不會被重寫或移除。

    10 / 隱私權與保留

    一次明確的位置快照，絕不後台跟蹤

    • Vox.md 不會持續監測位置或執行後台位置跟蹤。
    • 位置不會傳送至 Vox.md 伺服器、分析系統、廣告系統或第三方 AI 服務。
    • 令牌和提供商 URL 在本地格式化。只有打開連結時，Apple Maps、Google Maps 或 OpenStreetMap 才會收到座標。
    • 僅當所選後設資料需要地點名稱時，Apple 系統反向地理編碼器才可能發起網路請求。僅令牌位置會跳過此查詢。
    • 傳送成功後，可恢復請求會精簡為不含內容的回執，已完成擷取歷史不保留座標、標籤、提供商 URL 或位置模板。
    • 位置後設資料或令牌連結寫入 Markdown 後，便成為所選檔案的一部分。檔案同步提供商可能按其自身條款處理該檔案。
    權限可保持開啟，路線仍保持私密

    可以保持系統權限可用於獨立的目前位置操作，同時關閉所有路線的使用目前位置設定。

    請參閱 隱私權政策 瞭解完整的資料處理和保留詳情。

    11 / 故障排查

    修復常見位置和模板問題

    {location} 渲染為空

    確認實際生效的條目模板、前綴、後綴或儲存庫模板使用了完全一致的小寫令牌 {location}。然後為執行傳送的路線開啟使用目前位置。編輯器的一鍵修復可針對檢測到的行內條目格式執行此操作，而不啟用後設資料；即時儲存庫模板檔案需手動設定路線。如果權限被拒絕或定位結果不可用，請檢查路線的不可用行為及系統位置設定。

    連結有效，但未出現後設資料

    僅令牌配置下，這是預期行為。打開路線的位置設定，開啟寫入位置後設資料，再選擇筆記 frontmatter 或行內條目欄位，並選擇所需欄位。

    出現後設資料，但條目中沒有連結

    後設資料輸出不會自動插入連結。請添加 {location} 到實際生效的條目格式或儲存庫 Markdown 模板中。

    缺少地點或城市

    確認已選擇標籤欄位。座標仍可用時，Apple 反向地理編碼器仍可能失敗。城市精度會按設計移除興趣點名稱。

    frontmatter 傳送報告衝突

    配置的集合鍵， locations 預設情況下必須是相容的位置列表。在路線設定中重命名集合，或調整現有使用者編寫的 frontmatter。Vox.md 不會覆蓋不相容的值。

    重試時的位置較舊或不可用

    這是有意設計。請求保留發起時結果，避免稍後重試悄悄聲稱另一個擷取位置。需要新快照時請新建擷取。

    已允許位置權限，但路線未請求位置

    系統權限只是門檻。編輯該路線並開啟使用目前位置。僅授予權限絕不會自動為路線啟用位置。
