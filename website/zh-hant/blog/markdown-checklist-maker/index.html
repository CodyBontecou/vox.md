Markdown 清單產生器:把任意清單變成帶到期日的任務

貼上普通行、項目符號、編號條目或現有任務清單,即可複製有效的 - [ ] 任務,保留巢狀層級,可選添加到期日,並顯示已完成數量。

作者：
Cody Bontecou
更新於
2026年11月24日
需要
任何現代瀏覽器,包括 iPhone 上的 Safari。可選:用於清單的 Obsidian,以及用於語音擷取任務的 iPhone 或 Mac 版 Vox.md。
簡短回答

Markdown 任務由一個連字號、一個空格、方括號、一個空格和文字組成。寫作 - [ ] task 表示未完成的任務, - [x] done 表示已完成的任務。要把整個清單轉換為任務,請貼上到 清單產生器 如下。

- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

產生器會移除已有的項目符號、編號和核取方塊以免重複,把縮排保留為巢狀層級,並能按你的 Obsidian 外掛可讀取的格式添加到期日。它完全在本頁中運行:清單不會被上傳,頁面也不會發出任何網路請求。

2. Markdown 清單語法

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

每個任務都是一個清單項:一個連字號和一個空格,然後是 [ ] 方括號之間有一個空格,然後是文字。 Obsidian Help頁面 和 GitHub Docs頁面 都將其描述為連字號和空格,後面跟著 [ ]。要將任務標記為完成,GitHub Docs 說明應使用 [x].

空格很重要。 GitHub Flavored Markdown 規範 將核取方塊標記定義為一個左方括號、一個空白字元或字母 x,以及一個右方括號,並且其後的文字之前需要有空白字元。因此 [] (裡面什麼都沒有),或 - [ ]text (括號後沒有空格)不符合定義。連字號及其後的空格才是讓這一行成為清單項的關鍵。

任務清單不屬於核心 Markdown。同一規範將其標記為 CommonMark 的擴充,其引言也說明,原始 CommonMark 規範中沒有的功能會被標記為擴充。未實現該擴充的轉譯器會把方括號顯示為純文字,這通常就是核取方塊顯示為 [ ] 頁面上。

3. Obsidian 中的清單

Obsidian 幫助中的 基本格式語法 頁面介紹了任務清單:

  • 任務以連字號和空格開頭,後面跟著 [ ].
  • 你可以在方括號內使用任何字元來把任務標記為完成,因此 [x], [-] 和 [?] 都算。
  • 通過縮排清單項來巢狀任務清單。使用 Tab 或 Shift+Tab 來縮排或取消縮排所選條目。
  • 在閱讀檢視中,選取核取方塊即可切換任務狀態。

幫助頁面說明任何字元都能完成任務,但並未描述每個字元對應的不同外觀。如果 [-] 或 [?] 看起來不同於 [x] 在你的儲存庫中,這來自你安裝的主題或 CSS 程式碼片段,而不是 Markdown 本身。

產生器中的進度行也按同樣方式計數:方括號內除空格以外的任何字元都視為已完成,因此 [x], [X], [-] 和 [?] 均為已完成,而 [ ] 表示未完成。以「done:」或「x 」開頭的行是普通文字;該工具不會猜測它們表示已完成的任務。

4. 到期日:Tasks、Dataview 與 Reminder 的對比

Obsidian 的任務清單語法本身沒有到期日:幫助頁面中沒有相關說明。有三個外掛會讀取寫在任務文字中的日期,各自使用不同的格式。產生器會把日期寫成 ISO YYYY-MM-DD 在這三個外掛中都是如此。沒有外掛時,日期只是文字。

格式讀取者範例行
到期: 📅 YYYY-MM-DDTasks 外掛,其中說明日期必須採用 YYYY-MM-DD 格式- [ ] send invoice 📅 2026-11-25
排程日期: ⏳ YYYY-MM-DDTasks 外掛- [ ] send invoice ⏳ 2026-11-25
開始: 🛫 YYYY-MM-DDTasks 外掛- [ ] send invoice 🛫 2026-11-25
行內欄位: [due:: YYYY-MM-DD]Dataview文件,它會讀取寫在任務上的欄位,例如 [completion:: 2021-08-15]- [ ] send invoice [due:: 2026-11-25]
提醒: (@YYYY-MM-DD) 或 (@YYYY-MM-DD HH:mm)obsidian-reminder 外掛,其 README 展示了 (@2021-08-14) 和 (@2021-08-14 09:37) 於未勾選的任務- [ ] send invoice (@2026-11-25 09:30)

請選擇你使用的那一個外掛。Dataview 的頁面還列出了它自己的日期 emoji 簡寫,並說明只支援這些簡寫;產生器改用 Dataview 的方括號形式。Reminder 的 README 指出,已勾選的任務不會再發出提醒通知。

5. GitHub 與 Obsidian 的差異

GitHub Docs 將其描述為 [ ] 表示未完成的任務, [x] 來標記完成。GFM 規範將該標記定義為空白字元或字母 x 之間。Obsidian 接受任何字元。因此像這樣的任務 - [-] skipped 或 - [?] unsure 在 Obsidian 中算作已完成,但它不在規範的標記定義之內,遵循規範的轉譯器可能會將其顯示為純文字。如果該文件也會在 GitHub 上閱讀,請使用 [ ] 和 [x] 。

GitHub Docs 補充了一條規則:如果任務描述以圓括號開頭,需要用反斜線轉義,例如 - [ ] \(Optional) Open a followup issue。產生器不會為你添加反斜線;當任務以圓括號開頭時,它會給出警告。

6. 在 iPhone 和 Mac 上用 Vox.md 語音或文字擷取任務

Vox.md 的 Todo Checklist 處理模式會產生 Markdown - [ ] 會從擷取內容中提取任務項,其備援方案是確定性的清單格式化工具。語音在你的裝置上轉錄。在 Capture Bar 中, 檢查名單 套用 - [ ] 前綴,以及 兩日期設置 插入 (@yyyy-MM-dd) 或帶時間的形式。請參閱 快速捕捉 和 Routes 與處理模式 文件。

Route 可以把這些條目添加到你的每日筆記中某個標題之下,例如 ## Tasks; 追加到 Obsidian 每日筆記 介紹了設置方法,而 每日筆記範本產生器 負責編寫筆記的結構。如果是會議中的待辦事項,請參閱 會議記錄模板;關於任務清單前綴的做法,請參閱 擷取範本.

Vox.md 會寫入 (@yyyy-MM-dd) 形式。它不會寫入 Tasks 外掛的 emoji 日期或 Dataview 欄位。如果你使用其中之一,請把擷取的任務貼上到上方的產生器中並選擇該格式,或之後再編輯日期。要構建筆記頂部的屬性,請使用 屬性產生器.

在 iPhone、iPad 或 Mac 上用語音擷取任務。

Vox.md 在裝置上把你說的話變成 Markdown 清單,並添加到你的 Obsidian 筆記中。免費額度為 15 分鐘轉錄和 10 次成功的 Capture 投遞;無限使用是一次性終身解鎖,無需訂閱。

7. 常見問題

為什麼我的核取方塊顯示為 [ ] 文字?

轉譯器沒有繪製任務清單。任務清單是 CommonMark 的擴充,不支援該擴充的轉譯器會直接顯示方括號。請檢查該行是否以連字號和空格開頭,方括號之間是否有一個空格或 x 方括號之間,右括號後面還要有一個空格。在 Obsidian 中,程式碼塊或表格單元格裡的任務,可能不會像清單項那樣顯示為核取方塊。

如何巢狀任務?

縮排子任務。在 Obsidian 中,按 Tab 縮排所選條目, Shift+Tab 來取消縮排。產生器會把你清單中的 2 個或 4 個空格轉換為每層一個 Tab 字元,你也可以選擇轉換為 2 個或 4 個空格。

如何用 x 以外的字元勾選核取方塊?

Obsidian 幫助指出,方括號內的任何字元都會把任務標記為完成,因此 - [-] task 和 - [?] task 均為已完成。除非你重設清單,否則產生器會保留你貼上的字元。對於也會在 GitHub 上閱讀的文件,請使用 [x].

如何添加 Tasks 外掛能讀取的到期日?

把 📅 以及一個 YYYY-MM-DD 日期放在任務末尾,例如 - [ ] send invoice 📅 2026-11-25。在上方選擇「Tasks 外掛:到期」即可為每個任務添加。使用 ⏳ 表示排程日期, 🛫 表示開始日期。

產生器會上傳我的清單嗎?

不會。清單由本頁中的腳本在你的裝置上轉換,頁面不會發出任何網路請求。它也不會保存你的清單:關閉或重新加載頁面後內容即被清除。
