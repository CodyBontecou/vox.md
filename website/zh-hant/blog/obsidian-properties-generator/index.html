Obsidian 筆記屬性（YAML frontmatter）產生器和檢查器

按 Obsidian 期望的格式產生屬性，或檢查你已有的 frontmatter，查看某個屬性為何沒有顯示為你想要的類型。

作者：
Cody Bontecou
更新於
2026年11月22日
需要
Obsidian（任意平台）。可選：用於 iPhone、Apple Watch 或 Mac 的 Vox.md，可為擷取的筆記添加屬性。
簡短回答

Obsidian 筆記屬性是位於筆記最頂部的 YAML，夾在兩條 --- 行。每個屬性是一個 name: value 對，列表則有一個 - value 行，每項一行，內部連結必須加引號。以下示例是有效的：

---
tags:
  - journal
  - idea
aliases:
  - Weekly review
date: 2026-11-21
project: "[[Vox.md launch]]"
published: true
---

需要其他屬性，或想知道為什麼某個屬性沒有顯示為你想要的類型？下面的產生器會寫出 YAML，檢查器會列出帶行號的問題及修復方法。兩者都完全在本頁面中運行：你輸入的任何內容都不會被發送到別處。規則來自 Obsidian 幫助， 屬性 和 標籤.

    2. 檢查你已有的 frontmatter

    貼上筆記的頂部內容，包括 --- 行。檢查器逐行讀取該程式碼區塊，並列出每個問題的行號和修復方法。它使用的是一組固定的行規則，而不是完整的 YAML 剖析器，因此可能漏掉剖析器能發現的錯誤，且只檢查這裡列出的規則。

    3. 屬性類型及各自的寫法

    Obsidian 支持七種屬性類型。每種在 YAML 中的寫法如下：

    類型YAML 示例注意事項
    文字title: Weekly review請為 YAML 可能誤讀的值加引號，例如包含 : ，或以如下內容開頭的值： #。內部連結必須加引號。
    列表topics:
      - sleep
      - focus    		每個值各占一行，前面是連字號和空格。
    數字rating: 4數字不要加引號。
    核取方塊published: true該值是 true 或 false.
    日期date: 2026-11-21格式為 YYYY-MM-DD.
    日期和時間time: 2026-11-21T10:30:00格式為 YYYY-MM-DDTHH:MM:SS.
    標籤tags:
      - recipe
      - cooking    		寫成不帶 #。不含空格，且至少包含一個非數字字元。

    Obsidian 還有三個預設屬性： tags, aliases 和 cssclasses。產生器為每一種都提供了按鈕。

    4. 最容易讓屬性出錯的規則

    • 請給內部連結加引號。 project: "[[Vox.md launch]]"，而不是 project: [[Vox.md launch]]。這適用於文字屬性以及列表中的各項。
    • 每個列表項占一行。 每一項以連字號和空格開頭，並在屬性名稱下縮排。請用空格縮排，不要用Tab 字元。
    • 標籤有自己的規則。 否 # 寫在 YAML 中，不含空格，且至少包含一個非數字字元： 1984 不是有效的標籤，而 y1984 。請使用 / 用於巢狀標籤，例如 inbox/to-read。參閱 標籤 （Obsidian 說明）
    • 請用儲存的格式寫日期。 2026-11-21 表示日期， 2026-11-21T10:30:00 表示日期和時間。
    • 請使用當前的名稱。 tag, alias 和 cssclass 在 Obsidian 1.4 中已棄用，改用 tags, aliases 和 cssclasses，並且在 Obsidian 1.9 中不再支持將它們作為預設屬性。
    • 不要巢狀。 屬性不支持巢狀對象。Obsidian 建議使用原始碼模式查看巢狀屬性，因此請把它們展平為頂層名稱，例如 project_status.
    • 不要使用 Markdown。 粗體、連結和其他格式不會在屬性中渲染。Obsidian 稱這是有意為之，因為屬性是用來存放小而原子化的資訊的。

    5. 在範本中使用屬性

    開啟 範本外掛權杖 ，可在產生器中把日期欄位寫成權杖，而不是固定日期。核心範本外掛使用 {{date:YYYY-MM-DD}}；Templater 社區外掛使用 <% tp.date.now("YYYY-MM-DD") %> （見 Templater 文件）。日期和時間欄位使用 YYYY-MM-DD[T]HH:mm:ss ，在權杖中配合 T 放在方括號中，使其被寫成字母。

    連結需要留意。你在屬性介面中輸入連結時，Obsidian 會自動加上引號，但範本外掛會原樣把文字寫入文件，所以請在範本中自己寫上引號： project: "[[Vox.md launch]]".

    如需使用這些屬性的完整範本，請參閱 每日筆記範本產生器 以及 會議記錄範本產生器.

    筆記有了屬性後,你就可以用 base 查詢它們: Obsidian Bases 產生器 用於建立篩選器和檢視。

    至於筆記內文，請參閱 Markdown 表格產生器 可把試算表儲存格或 CSV 轉成表格，讓你貼到屬性區塊下方。

    6. 為你擷取的筆記添加屬性

    在 Vox.md 路線中，中繼資料欄位接受一個 key: value 鍵值對，每行一對，例如 tags: [journal, idea]. 筆記 frontmatter 會在文檔範圍寫入中繼資料。 行內條目欄位 寫入 key:: value 欄位，位於捲動筆記中每個條目旁邊。參見 路線參考中的中繼資料.

    產生器的 復制為 Vox.md 路線中繼資料 按鈕會以這種形式寫入你的屬性，列表寫為 [a, b] ，每行一個屬性。Vox.md 的文檔將該欄位描述為 key: value 行；本頁面不會測試每種屬性類型的寫法，因此請在 Obsidian 中打開第一條擷取的筆記並確認。每日筆記和收件匣的路線見 追加到 Obsidian 每日筆記, 擷取範本 和 將 iPhone 語音筆記存入 Obsidian.

    把這些屬性放到每條擷取的筆記上。

    想讓從 iPhone、Apple Watch 或 Mac 擷取的每則筆記都帶上這些屬性？把它們貼到 Vox.md 路由的中繼資料中，並選擇筆記 Frontmatter。符合資格的帳號可享 7 天免費試用。

    7. 常見問題

    為什麼 Obsidian 沒有把我的屬性顯示為我想要的類型？

    Obsidian 將屬性讀取為 YAML，不符合其類型規則的值不會顯示為該類型。常見原因有：沒有加引號的連結、沒有按每行一項寫的列表、日期不是 YYYY-MM-DD，以及帶空格的標籤。把該程式碼區塊貼上到上面的檢查器中即可找到所在行。

    屬性中的標籤需要 # 嗎？

    不需要。在 YAML 中，標籤寫成普通文字，例如 - recipe。該 # 用於筆記正文中的標籤。

    可以巢狀屬性嗎？

    不可以。屬性不支持巢狀對象。請使用扁平的名稱，或使用巢狀標籤： / 在 tags 列表。

    可以把屬性寫成 JSON 嗎？

    Obsidian 可以讀取 JSON 程式碼區塊，但會按 YAML 讀取並保存。上面的檢查器只對 YAML 應用其行規則。
