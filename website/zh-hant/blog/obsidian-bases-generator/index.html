Obsidian Bases 產生器:篩選器、檢視和公式

無需先學習結構描述,即可建立 Obsidian base 的 YAML:選擇篩選器、添加檢視、複製 .base 檔案或程式碼塊,並通過指向 Obsidian 官方文件的連結了解每個鍵的作用。

作者：
Cody Bontecou
更新於
2026年11月28日
需要
任何現代瀏覽器均可,包括 iPhone 上的 Safari。可選:啟用 Bases 核心外掛的 Obsidian,以及用於語音或文字擷取筆記的 iPhone 或 Mac 版 Vox.md。
簡短回答

base 是基於筆記的資料庫式檢視,以 YAML 編寫,最多包含五個頂層鍵: filters, formulas, properties, summaries 和 views。將 YAML 儲存為 .base 檔案,或將其貼上到筆記中的 base 程式碼塊。 產生器 下方的工具會為你產生。所需的 Obsidian 版本取決於檢視類型: 檢視頁面 列出了自 1.9 起的 Table 和 Cards、自 1.10 起的 List 和 Map,以及自 1.14 起的 Kanban。

filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

產生器完全在本頁中運行。你輸入的任何內容都不會上傳,頁面也不會發出網路請求。

    2. Bases 語法速覽

    這些是 Obsidian 的語法頁面 所說明的內容。無需學習其他結構描述。

    鍵作用範例
    filters縮小所有檢視的筆記範圍。file.hasTag("project")
    formulas定義計算屬性,用作 formula.name.total: 'price * qty'
    properties各屬性的設定。 displayName 設定列標題。displayName: "Status"
    summaries定義你自己的摘要公式,使用 values.自定義,可選
    views針對同一批筆記的檢視列表。- type: table
    type (檢視)檢視的版面配置。table, cards, list
    name (檢視)檢視的名稱。name: "Projects"
    filters (檢視)僅用於此檢視的篩選器。file.inFolder("Work")
    groupBy (檢視)按某個 property 位於 direction.direction: DESC
    order (檢視)按順序顯示的屬性。- file.name
    limit (檢視)限制行數。limit: 10
    summaries (檢視)將屬性對應到摘要。price: Sum

    產生器不會寫入所有有文件說明的鍵。語法頁面還介紹了 groupOrder,檢視還可以儲存額外狀態(例如排序列),這些由 Obsidian 自行管理。如有需要,可手動添加:YAML 由你隨意編輯。

    3. 篩選器:and、or、not

    篩選器是對每條筆記判斷真假的文字語句,或是帶有以下鍵的物件: and, or 或 not 其中包含更多篩選器的列表。全域 filters 適用於所有檢視。檢視自身的 filters 僅適用於該檢視,兩者以 AND 組合。

    filters:
  or:
    - file.hasTag("meeting")
    - file.inFolder("Meetings")

    沒有 from 或 source 鍵。沒有篩選器時,base 會包含庫中的所有檔案,因此除非你有意如此,否則請務必設定篩選器。

    語句內的文字值需要加引號,因此 YAML 需要巢狀引號: 'status == "done"'。產生器會自動為你處理。函式篩選器,例如 file.hasTag(), file.inFolder() 和 file.hasLink() 位於 函式頁面.

    4. 公式和摘要

    下的每個條目 formulas 會成為可在每個檢視中使用的屬性,寫作 formula.name。公式可以使用其他公式,但不允許循環參照,因此公式不能參照自身。結果以 YAML 字串存儲,所以運算式要放在引號內。

    formulas:
  formatted_price: 'if(price, price.toFixed(2) + " dollars")'

    檢視的 summaries 將屬性對應到摘要。語法頁面列出了以下預設值:

    • 數字: Average, Min, Max, Sum, Range, Median, Stddev
    • 日期: Earliest, Latest, Range
    • 布林值: Checked, Unchecked
    • 任一: Empty, Filled, Unique

    關於日期運算,語法頁面說明 file.mtime > now() - "1 week" 對最近一周內修改過的檔案為 true。

    5. 這意味著什麼

    在篩選器或公式中, this 是顯示該 base 的檔案。語法頁面說明:當 base 在主內容區開啟時,它就是 base 檔案本身;當 base 嵌入筆記或 Canvas 時,它是嵌入它的檔案;當 base 位於側邊欄時,它是主內容區中的當前檔案。該頁面給出了 file.hasLink(this.file) ,以此重現反向連結面板。

    6. 可複製的範例

    以下是產生器預設的純程式碼形式,無需 JavaScript 即可使用。請將資料夾、標籤和屬性名稱替換為你自己的。將文字儲存為 .base 檔案,或將其包裹在 base 程式碼塊。請參閱 建立 base 了解相關命令,並使用以下方式嵌入已儲存的檔案: ![[Name.base]] 或 ![[Name.base#View]] 來選擇預設檢視。

    閱讀清單

    filters:
  and:
    - file.inFolder("Reading")
    - 'status == "to read"'
properties:
  status:
    displayName: "Status"
views:
  - type: cards
    name: "Reading list"
    order:
      - file.name
      - status

    按狀態劃分的項目

    filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

    帶有某標籤且本周修改過的筆記

    filters:
  and:
    - file.hasTag("project")
    - 'file.mtime > now() - "1 week"'
views:
  - type: table
    name: "Modified this week"
    order:
      - file.name
      - file.mtime

    此筆記的反向連結

    filters:
  and:
    - file.hasLink(this.file)
views:
  - type: table
    name: "Backlinks"
    order:
      - file.name
      - file.folder

    用 Vox.md 擷取的語音筆記

    filters:
  and:
    - file.inFolder("Vox")
    - file.hasTag("voice")
views:
  - type: table
    name: "Voice notes"
    order:
      - file.ctime
      - file.name
      - file.tags

    該 order list 用於選擇列。排序是在 Obsidian 的檢視工具列中更改的檢視設定,因此範例中沒有寫入排序。

    7. 讓你的擷取內容顯示在 base 中

    Vox.md 會將你擷取的內容以 Markdown 筆記形式儲存到庫中的某個資料夾。其 中繼資料文件 說明路由可以將靜態中繼資料添加為 key: value 行,例如 tags: [journal, idea],並且 筆記 frontmatter 在文件範圍寫入它,還介紹了可選的位置中繼資料。按該資料夾或標籤篩選的 base(如上面最後一個範例)隨後會在一張表中列出你的擷取內容。請使用以下工具建立中繼資料: 屬性產生器,並參閱 在 iPhone 上用語音記筆記到 Obsidian 了解設定方法。

    相關工具: 每日筆記範本產生器 來建立帶日期的筆記, 標註產生器 以及 Markdown 表格產生器 用於筆記內容。

    8. 疑難排解

    • 該 base 會顯示所有筆記。 未設定來源篩選器。base 預設包含整個庫,因此請添加 file.inFolder() 或 file.hasTag() 篩選器。
    • 某個屬性列是空白的。 名稱不匹配(包括大小寫),或者筆記的 frontmatter 中沒有該屬性。請檢查筆記的屬性和列名。
    • YAML 錯誤。 請檢查縮排(使用空格)和引號。包含文字的篩選器需要巢狀引號: 'status == "done"'.
    • map 檢視為空。 根據檢視頁面,map 版面配置需要 Maps 外掛。

    9. 常見問題

    Bases 是核心外掛嗎?

    可以。 Obsidian Help 說明文件 寫道:“Bases 是一個核心外掛,可讓你建立類似資料庫的筆記檢視。”

    Bases 還是 Dataview?

    二者互相獨立。Dataview 是擁有自己查詢語言的社區外掛。base 是 Obsidian 自行讀取的 YAML,沒有 from 鍵:通過篩選器來縮小筆記範圍。本頁不會進一步比較它們的功能。

    我可以手動編輯 YAML 嗎?

    可以。 .base 檔案是 YAML 文字,各個鍵在語法頁面中有說明。你可以用任意編輯器開啟產生的檔案,也可以將程式碼塊貼上到筆記中並在那裡編輯。

    產生器會上傳我的資料嗎?

    不會。本頁中的腳本在你的設備上建立 YAML,頁面不會發出任何網路請求。重新整理頁面會清除所有內容。
