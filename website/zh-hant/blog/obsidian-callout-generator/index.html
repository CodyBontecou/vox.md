Obsidian 標註產生器：所有類型、別名和摺疊選項

選擇類型，加入標題和內文，選擇摺疊與巢狀方式，然後複製有效的 > [!type] 標註，並附有完整的類型和別名清單，以及可摺疊標註的使用方式。

作者：
Cody Bontecou
更新於
2026年11月27日
需要
任何現代瀏覽器，包括 iPhone 上的 Safari。選用：用於顯示標註的 Obsidian，以及用於透過語音或文字擷取筆記的 iPhone 或 Mac 版 Vox.md。
簡短回答

標註是一個引用區塊，其第一行為 > [!type] Optional title。之後的每一行都以 > 。加上 + 或 - 緊接在方括號之後即可使其可摺疊。如果不想手動輸入前綴，請使用 標註產生器 如下。

> [!warning]- Back up first
> Copy the vault before you change the plugin settings.
>
> Then restart Obsidian.

產生器會加上 > 前綴（巢狀時重複），保留標註內的空行，並且不會重複 > 你貼上的內容。它完全在本頁中執行：你的文字不會被上傳，頁面也不會發出任何網路請求。

2. 標註語法

> [!type] Title
> Body line one.
> Body line two.
  • 類型。 引用區塊的第一行以驚嘆號後括號中的類型開頭： > [!info]. Obsidian Help 說明文件 說明類型識別碼不區分大小寫，且不支援的類型會回退為 note.
  • 標題。 括號後的文字會取代標題。沒有它時，Obsidian 會以首字母大寫形式顯示類型識別碼，所以 > [!tip] 顯示為「Tip」。
  • 內文。 後面的每一行都以 > 。內文可以包含 Markdown、wikilink 和嵌入內容。
  • 僅標題。 內文可以省略： > [!tip] Remember to save 就是一個完整的標註。

3. 所有標註類型與別名

Obsidian 說明列出了這些內建類型。每個別名都列在其所屬類型之下，例如 tldr 配合 abstract.

類型別名典型用途
note無一般性備註。也是未知類型回退到的樣式。
abstractsummary, tldr筆記頂部的摘要。
info無背景資訊。
todo無仍待完成的事項。
tiphint, important建議或重點。
successcheck, done已完成的步驟或良好的結果。
questionhelp, faq未解決的問題或常見問題。
warningcaution, attention需要小心的事項。
failurefail, missing哪裡出了問題，或缺少什麼。
dangererror嚴重風險或錯誤訊息。
bug無一個已知的 bug。
example無一個完整範例。
quotecite附出處的引文。

類型和別名來自 Obsidian 說明。「典型用途」一欄只是建議，並非 Obsidian 的定義。在預設外觀中，每種類型都有自己的顏色和圖示；佈景主題可以更改這兩者。

4. 可摺疊標註：+ 與 -

在右括號後直接加一個加號或減號：

> [!faq]+ Open by default
> This callout is foldable and starts expanded.

> [!faq]- Closed by default
> This callout is foldable and starts collapsed.

Obsidian 說明描述了 + 為預設展開的可摺疊標註，而 - 為預設摺疊的可摺疊標註。兩者都不加時，標註不可摺疊。 + 或 - 屬於 Markdown 的一部分，因此會保留在檔案中。

5. 巢狀標註、清單、程式碼和嵌入

巢狀標註時，再加上一個 > 每一層的寫法：

> [!question] Can callouts be nested?
> > [!example] Yes
> > Add one more > for each level.

產生器的「巢狀嵌入另一個標註中」設定會寫入額外的 > 每行都加上，最多三層。把結果貼到外層標註的內文中。

清單、程式碼和其他 Markdown 放在內文中，使用 > 前綴。Obsidian 說明指出，內文可以包含 Markdown、wikilink 和嵌入內容，並且可以選取現有內容（包括清單和程式碼區塊）後執行 插入標註 指令。把清單或程式碼區塊貼到產生器的內文欄位中，它會替你加上前綴：

> [!info] Checklist
> - [ ] first
> - [ ] second
>
> ```
> code line
> ```

6. 使用 CSS 程式碼片段自訂標註類型

你自創的類型會以 note 樣式顯示。Obsidian 說明指出，自訂標註需在 CSS 程式碼片段或社群外掛程式中定義。其範例如下：

.callout[data-callout="custom-question-type"] {
  --callout-color: #000000;
  --callout-icon: lucide-alert-circle;
}

根據說明頁面， --callout-color 接受任何有效的 CSS 顏色，而 --callout-icon 接受來自 lucide.dev 的圖示 ID 或 SVG 元素。然後寫入 > [!custom-question-type] 寫在筆記裡。在產生器的自訂類型欄位中輸入相同的名稱。

7. GitHub alerts 與 Obsidian 標註

GitHub 也有類似的功能，稱為 alerts。 GitHub Docs 文件 列出了五個： NOTE, TIP, IMPORTANT, WARNING 和 CAUTION.

> [!NOTE]
> Useful information that users should know, even when skimming content.

該頁面沒有記載摺疊、自訂標題和自訂類型；而 Obsidian 標註三者都有。第一行看起來相同，所以基本的 > [!note] 或 > [!warning] 通常在兩者中都有效，但僅限 Obsidian 的類型，例如 [!bug]， +/- 摺疊或標題超出了 GitHub 文件的範圍。如果檔案要在兩處閱讀，請只使用五種 GitHub 類型，不要加額外內容。

8. 用 Vox.md 透過語音或文字擷取到 Obsidian

Vox.md 會把你擷取的內容作為 Markdown 筆記儲存到 Obsidian 儲存庫資料夾中。它是一款擷取 App，本頁並不聲稱它會替你寫標註：之後再加入，可以在這裡產生並貼上，或手動輸入上面的語法。如果要用轉錄文字作內文，把文字貼到產生器中，它會加上前綴。

9. 常見問題

為什麼我的標註沒有顯示？

檢查三件事。第一行必須以 > 然後 [!type]，驚嘆號緊接其後，括號內不留空格。內文的每一行都需要自己的 >。不帶 > 會結束引用區塊，所以它後面的行就是一般文字；請寫成 >。如果它仍顯示為一般引用區塊，請檢查以下兩者之間是否有空格或拼字錯誤： > 和 [!.

標註可以沒有標題嗎？

不完全是：省略標題後，Obsidian 會改為以首字母大寫形式顯示類型識別碼。要隱藏標題需要用 CSS；Obsidian 說明指出，隱藏標題等進一步樣式可以使用標準 CSS 選擇器。你這樣做時，產生器會讓標題留空，因此會得到預設標題。

Admonition 外掛程式還是原生標註？

原生標註無需外掛程式，使用 > [!type] 語法。Admonition 外掛程式是獨立的社群外掛程式，有自己的語法，本頁不涉及。Obsidian 說明指出，自訂標註類型也可以來自社群外掛程式。

標註能在 Obsidian 行動版和 Publish 中使用嗎？

Obsidian 說明指出，Obsidian Publish 原生支援標註。其標註頁面未提及行動版，因此本頁對此不作任何說明。

產生器會上傳我的文字嗎？

不會。本頁中的指令碼在你的裝置上產生標註，頁面不會發出任何網路請求。它也不會儲存任何內容：重新載入頁面即會清空。
