免費工具

適用於 Obsidian 的 Markdown 表格產生器：可從 Excel、Sheets 或 CSV 貼上

貼上來自 Excel、Google Sheets、Numbers、CSV 或 TSV 的列，即可複製有效的直線表格，其中 [[Note|Alias]] 與 ![[image.png|300]] 內的直線會被跳脫，換行會被處理，並可逐欄設定對齊方式。

作者：
Cody Bontecou
更新於
2026年11月26日
需要
任何現代瀏覽器皆可，包括 iPhone 上的 Safari。選用：用於表格的 Obsidian，以及用於把文字擷取成筆記的 iPhone 或 Mac 版 Vox.md。
簡短回答

Markdown 表格由一個標題列、一個由連字號組成的分隔列，以及每行一列的資料列組成，儲存格之間以 |。把你的儲存格貼到 表格產生器 取得表格，或從這個範例開始。

| Name | Owner | Status |
| --- | --- | --- |
| Draft | Ana | Done |
| Review | Lee | Open |

產生器也會處理一般產生器在 Obsidian 中忽略的問題：它會跳脫其中的直線字元，位置在 [[Note|Alias]] 和 ![[image.png|300]] 寫成 \|，並把儲存格內的換行轉成 <br> 或空格。它完全在本頁中執行：你的資料絕不會上傳，頁面也不會發出任何網路請求。

    2. Markdown 表格語法

    | Name   | Qty | Price |
| :----- | :-: | ----: |
| Apple  |   3 |  1.20 |
| Pear   |  12 |  0.80 |

    該 GitHub Flavored Markdown 規範 將表格定義為一個標題列、一個分隔標題與資料的分隔列，以及零個或多個資料列。儲存格之間以直線分隔。

    • 分隔列。 其儲存格只包含連字號，並可在左側、右側或兩端加上冒號，以設定靠左、靠右或置中對齊。 Obsidian Help 說明文件 指出，要在標題列加上冒號來對齊文字，且標題列至少要有兩個連字號。
    • 外側直線。 規範中，兩側的直線是選用的。Obsidian Help 建議加上以方便閱讀，產生器一律會寫入。
    • 對齊填充。 根據 Obsidian Help，儲存格不必完美對齊。產生器的「填充欄位」版面只是讓原始碼更易讀，「精簡」則會略過這個步驟。
    • 數量相符。 規範指出，標題列的儲存格數必須與分隔列相同。若不相同，這些行就不是表格，會被呈現為一般段落。資料列的儲存格較少時會補上空儲存格，多出的儲存格則會被忽略。
    • 在儲存格內。 規範允許行內格式，但不允許區塊層級內容，因此清單或標題不能放進儲存格。Obsidian Help 指出，你可以使用基本格式語法來設定表格內容的樣式。
    • 表格的結尾。 規範指出，表格會在第一個空行處，或另一個區塊層級結構開始處中斷。

    產生器在每個分隔儲存格中至少寫入三個連字號。這既符合 Obsidian 最少兩個的要求，也符合以下所要求的三個： GitHub Docs 文件 所要求的。

    3. Obsidian 中的表格

    • Insert Table。 Obsidian Help 指出，你可以透過 Command Palette 的 Insert Table 指令插入表格。若要用現有資料建立表格，請把資料貼到上方的產生器。
    • 別名與圖片尺寸。 Wikilink 別名，例如 [[Note|Alias]] 以及圖片尺寸，例如 ![[image.png|300]] 都含有垂直線。Obsidian Help 指出，在表格內需要加入一個 \ 在直線之前，因此請寫成 [[Note\|Alias]] 和 ![[image.png\|300]]。產生器會替你處理；你已經寫好的跳脫不會被重複加上。
    • 其他直線字元。 GFM 規範指出，儲存格內的直線必須以反斜線跳脫，即使在行內程式碼中也一樣。產生器會把每一個未跳脫的直線寫成 \|.
    • 換行。 一列必須寫在同一行，因此儲存格內的換行必須改用其他方式表示。產生器會寫入 HTML <br> 標籤，或在你選擇時以空格連接各行。Obsidian Help 的 Tables 一節與 GitHub Docs 都沒有說明儲存格內的換行，因此請確認 <br> 在你自己的保管庫中的呈現效果，如果不想在原始碼中出現標籤，請選擇空格選項。
    • 外掛程式。 也有協助編輯表格的社群外掛程式。本頁不評估也不背書其中任何一個。

    若需要核取清單，請參閱 Markdown 清單產生器；至於筆記頂端的屬性，請參閱 屬性產生器。表格很適合用來整理決議與負責人，例如來自以下的筆記： 會議記錄模板.

    4. 來自 Excel、Google Sheets 或 CSV

    選取試算表中的儲存格，複製後貼到上方的方塊。如果貼上的儲存格之間有 Tab，產生器會自動偵測。它也能偵測逗號、分號和直線，並能讀取加引號的 CSV 欄位，因此 "Lee, Sam" 仍是一個儲存格，而 "" 在引號內會變成一個引號。如果猜測有誤，請使用「分隔符號」選單。勾選或取消勾選「第一列是標題列」，以決定第一列是否成為標題列；未勾選時會加入一個空的標題列，因為 Markdown 表格需要標題列。

    • 合併儲存格。 規範與兩份說明頁面都把列描述為以直線分隔的儲存格清單，且都沒有說明合併儲存格的方法。請在複製前，把該值填入合併所涵蓋的每個儲存格。
    • 公式。 產生器只會讀取你貼上的文字。如果貼上的儲存格顯示的是公式而非結果，請在試算表 App 中複製數值後再貼上一次。
    • 列長短不一。 若某一列的儲存格數與標題列不同，產生器會提示該列的行號，並以空儲存格補齊表格。儲存格比標題列多的列會讓表格變寬，而不會遺失資料。
    • 反向轉換與修復。 貼上現有的 Markdown 表格以重新對齊，或把「輸出為」設為 CSV 或 TSV 來匯出。當分隔列缺失、儲存格數與標題列不符，或空白行會使表格中斷時，產生器會附上行號提示。

    貼上的 Markdown 表格中的對齊冒號會被保留，你也可以用「欄位對齊」選單變更每一欄。

    5. GitHub 與 Obsidian 的差異

    Obsidian Help 和 GitHub Docs 都把直線表格描述為具有標題列、連字號和選用的對齊冒號。兩份頁面所述的差異很小：

    主題Obsidian Help 說明文件GitHub Docs 與 GFM 規範
    連字號標題列至少要有兩個連字號GitHub Docs：每個標題欄至少要有三個連字號
    表格前的空白行Tables 一節沒有提到這一點GitHub Docs：表格前必須有一個空白行
    儲存格中的直線字元加入 \ 在別名與圖片尺寸的直線之前將它跳脫為 \|，即使在行內程式碼中也一樣
    外側直線選用，建議加上以方便閱讀選用

    若要在兩邊都能正常運作，請寫三個以上的連字號，在表格上方留一個空白行，並跳脫每一個直線字元。產生器正是這樣做的。Wikilink 別名是 Obsidian 語法；在 GitHub 上它只是含有直線字元的文字。核取清單產生器指南涵蓋了 工作清單的差異 也是同樣的做法。

    若要突顯表格或有關它的備註，請用標註包住它： Obsidian 標註產生器 加入 > 前綴。

    6. 用 Vox.md 把表格和筆記放進你的保管庫

    Vox.md 本身不會建立表格，上方的產生器也不需要這個 App。Vox.md 的功能是把文字擷取到 Obsidian：Quick Capture 讓你貼上現有文字，Route 則會把文字送到 Markdown 目的地。請參閱 快速捕捉 和 路線 文件。

    1. 先在上方製作你的表格，然後按下 Copy。
    2. 在 iPhone、iPad 或 Mac 上的 Vox.md 中，開啟 Quick Capture，並把表格貼到文字編輯器。
    3. 請透過保留原始文字的 Route 傳送。文件中列出了 保留原文 作為不經 AI 改寫、保留擷取文字的處理模式，並說明在以下情況下擷取的文字會原封不動送達： 使用 Apple Intelligence 處於關閉狀態，這也是預設值。處理輸入的文字是每個 Route 上的選擇性設定。
    4. Route 的目的地決定內容的去處：新筆記、像每日筆記這類持續累積的筆記，或既有筆記的底部、頂部，或指定標題之下。

    如果目的地上方已有文字，請在貼上的表格上方留一個空白行。若需要 Route 的設定範例，請參閱 擷取範本；若要先把 Zoom、Teams 或 YouTube 的字幕檔轉成逐字稿筆記，請參閱 SRT 和 VTT 轉 Markdown.

    7. 常見問題

    為什麼我的表格在 Obsidian 中沒有呈現？

    請檢查三件事。標題正下方必須有一列由連字號組成的分隔列，而且標題列與分隔列的儲存格數必須相同，否則依規範這些行會被呈現為段落。Obsidian Help 指出，標題列至少要有兩個連字號。此外，表格前要留一個空白行，GitHub Docs 有此要求，而在 Obsidian 中這樣做也沒有任何代價。把表格貼到產生器中：當分隔列缺失或數量不符時，它會附上行號提示你。

    如何在儲存格內換行？

    讓該列保持在同一行，並使用 HTML <br> 放在儲存格內，這正是產生器對多行儲存格所寫入的內容。所引用的頁面沒有說明儲存格內的換行，所以請在你的保管庫中測試。另一個選擇是以空格連接各行。

    如何在儲存格中放入直線字元或 wikilink 別名？

    在直線前加上反斜線： [[Note\|Alias]], ![[image.png\|300]] 或 a \| b。Obsidian Help 要求表格內的別名與圖片調整大小必須這樣做，而 GFM 規範則要求儲存格中的任何直線字元都要如此。

    可以合併儲存格嗎？

    規範和 Obsidian Help 中都沒有相關語法。請改為在每個儲存格中重複該值。

    表格最多可以多寬？

    所引用的頁面都沒有規定欄數或列數上限，產生器也不設限。過寬的表格在原始碼中很難閱讀，因此請使用精簡版面，或把表格拆成兩個。

    產生器會上傳我的資料嗎？

    不會。表格是由本頁中的腳本在你的裝置上建立，頁面不會發出任何網路請求，也不會儲存你的資料：關閉或重新整理頁面就會清除資料。Download 按鈕會把頁面中的檔案儲存到你的裝置。
