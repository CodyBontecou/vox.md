Generatore di Obsidian Bases: filtri, viste e formule

Crea lo YAML per una base di Obsidian senza dover prima imparare lo schema: scegli i filtri, aggiungi le viste, copia un file .base o un blocco di codice e scopri cosa fa ogni chiave, con link alla documentazione di Obsidian.

Di
Cody Bontecou
Aggiornato
28 novembre 2026
Richiede
Qualsiasi browser moderno, incluso Safari su iPhone. Facoltativo: Obsidian con il plugin principale Bases e Vox.md per iPhone o Mac per acquisire note con la voce o il testo.
La risposta breve

Una base è una vista in stile database sulle tue note, scritta in YAML con fino a cinque chiavi di primo livello: filters, formulas, properties, summaries e views. Salva lo YAML come .base file, oppure incollalo in una nota dentro un base blocco di codice. La generatore qui sotto lo scrive per te. La versione di Obsidian necessaria dipende dal tipo di vista: la pagina delle viste elenca Table e Cards dalla 1.9, List e Map dalla 1.10 e Kanban dalla 1.14.

filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

Il generatore funziona interamente in questa pagina. Nulla di ciò che scrivi viene caricato e la pagina non effettua richieste di rete.

    2. La sintassi di Bases in breve

    Queste sono le chiavi che pagina della sintassi di Obsidian documenta. Non c’è nessun altro schema da imparare.

    ChiaveCosa faEsempio
    filtersRestringe le note per ogni vista.file.hasTag("project")
    formulasDefinisce proprietà calcolate, usate come formula.name.total: 'price * qty'
    propertiesImpostazioni per proprietà. displayName imposta l’intestazione della colonna.displayName: "Status"
    summariesDefinisce formule di riepilogo personalizzate, usando values.Personalizzato, facoltativo
    viewsUn elenco di viste sulle stesse note.- type: table
    type (vista)Il layout della vista.table, cards, list
    name (vista)Il nome della vista.name: "Projects"
    filters (vista)Filtri solo per questa vista.file.inFolder("Work")
    groupBy (vista)Raggruppa le righe per property in un direction.direction: DESC
    order (vista)Le proprietà mostrate, in ordine.- file.name
    limit (vista)Limita il numero di righe.limit: 10
    summaries (vista)Associa una proprietà a un riepilogo.price: Sum

    Il generatore non scrive tutte le chiavi documentate. La pagina della sintassi descrive anche groupOrder, e le viste possono contenere uno stato aggiuntivo, come la colonna di ordinamento, che Obsidian gestisce da solo. Aggiungili a mano se ti servono: lo YAML è tuo da modificare.

    3. Filtri: and, or, not

    Un filtro è un’istruzione di testo vera o falsa per ogni nota, oppure un oggetto con and, or oppure not che contiene un elenco di altri filtri. I filters si applicano a ogni vista. I filters si applicano solo a quella vista e i due sono combinati con AND.

    filters:
  or:
    - file.hasTag("meeting")
    - file.inFolder("Meetings")

    Non c’è alcun from oppure source come in SQL o Dataview. Senza filtro, una base include tutti i file del vault, quindi impostane sempre uno a meno che tu non voglia questo.

    I valori di testo richiedono le virgolette dentro l’istruzione, quindi lo YAML richiede virgolette annidate: 'status == "done"'. Il generatore lo fa per te. I filtri funzione come file.hasTag(), file.inFolder() e file.hasLink() sono nella pagina delle funzioni.

    4. Formule e riepiloghi

    Ogni voce sotto formulas diventa una proprietà che puoi usare in ogni vista come formula.name. Una formula può usarne un’altra, ma i riferimenti circolari non sono consentiti, quindi una formula non può riferirsi a se stessa. Il risultato è memorizzato come stringa YAML, ed è per questo che l’espressione va tra virgolette.

    formulas:
  formatted_price: 'if(price, price.toFixed(2) + " dollars")'

    Il summaries associa una proprietà a un riepilogo. La pagina della sintassi elenca questi valori predefiniti:

    • Numero: Average, Min, Max, Sum, Range, Median, Stddev
    • Data: Earliest, Latest, Range
    • Booleano: Checked, Unchecked
    • Qualsiasi: Empty, Filled, Unique

    Per i calcoli sulle date, la pagina della sintassi dice file.mtime > now() - "1 week" è vero per un file modificato nell’ultima settimana.

    5. Cosa significa

    In un filtro o in una formula, this è il file in cui viene mostrata la base. La pagina della sintassi indica che è il file della base stessa quando la base si apre nell’area principale dei contenuti, il file che la incorpora quando la base è incorporata in una nota o in un Canvas, e il file attivo nell’area principale dei contenuti quando la base è nella barra laterale. La pagina fornisce file.hasLink(this.file) per replicare il pannello dei backlink.

    6. Esempi da copiare

    Questi sono i preset del generatore come semplice codice, quindi funzionano senza JavaScript. Sostituisci i nomi di cartelle, tag e proprietà con i tuoi. Salva il testo come .base file, oppure racchiudila in un base blocco di codice. Vedi Crea una base per i comandi, e incorpora un file salvato con ![[Name.base]] oppure ![[Name.base#View]] per scegliere la vista predefinita.

    Lista di lettura

    filters:
  and:
    - file.inFolder("Reading")
    - 'status == "to read"'
properties:
  status:
    displayName: "Status"
views:
  - type: cards
    name: "Reading list"
    order:
      - file.name
      - status

    Progetti per stato

    filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

    Note con un tag, modificate questa settimana

    filters:
  and:
    - file.hasTag("project")
    - 'file.mtime > now() - "1 week"'
views:
  - type: table
    name: "Modified this week"
    order:
      - file.name
      - file.mtime

    Backlink di questa nota

    filters:
  and:
    - file.hasLink(this.file)
views:
  - type: table
    name: "Backlinks"
    order:
      - file.name
      - file.folder

    Note vocali acquisite con Vox.md

    filters:
  and:
    - file.inFolder("Vox")
    - file.hasTag("voice")
views:
  - type: table
    name: "Voice notes"
    order:
      - file.ctime
      - file.name
      - file.tags

    La order list sceglie le colonne. L’ordinamento è un’impostazione della vista che cambi nella barra degli strumenti di Obsidian, quindi gli esempi non ne scrivono uno.

    7. Fai comparire le tue acquisizioni in una base

    Vox.md salva ciò che acquisisci come note Markdown in una cartella del tuo vault. La sua Documentazione sui metadati dice che una Route può aggiungere metadati statici come key: value righe, come tags: [journal, idea], e che Metadati iniziali della nota la scrive a livello di documento. Descrive anche metadati di posizione facoltativi. Una base filtrata su quella cartella o tag, come l’ultimo esempio qui sopra, elenca poi le tue acquisizioni in un’unica tabella. Crea i metadati con il generatore di proprietà, e vedi note vocali su Obsidian da iPhone per la configurazione.

    8. Risoluzione dei problemi

    • La base mostra tutte le note. Nessun filtro di origine impostato. Una base include per impostazione predefinita l’intero vault, quindi aggiungi un file.inFolder() oppure file.hasTag() filtro.
    • Una colonna di proprietà è vuota. Il nome non corrisponde, maiuscole e minuscole comprese, oppure la nota non ha quella proprietà nel frontmatter. Controlla le Properties della nota e il nome della colonna.
    • Errore YAML. Controlla l’indentazione, che usa spazi, e le virgolette. Un filtro che contiene testo richiede virgolette annidate: 'status == "done"'.
    • Una vista map è vuota. Il layout map richiede il plugin Maps, secondo la pagina delle viste.

    9. Domande

    Bases è un plugin principale?

    Sì. Guida Obsidian Help dice: “Bases è un plugin principale che permette di creare viste delle note simili a un database.”

    Bases o Dataview?

    Sono distinti. Dataview è un plugin della community con un proprio linguaggio di query. Una base è YAML che Obsidian legge da solo, senza from chiave: le note si restringono con i filtri. Questa pagina non confronta ulteriormente le loro funzionalità.

    Posso modificare lo YAML a mano?

    Sì. Un .base è un testo YAML e la pagina della sintassi documenta le chiavi. Apri il file generato in qualsiasi editor, oppure incolla il blocco di codice in una nota e modificalo lì.

    Il generatore carica i miei dati?

    No. Uno script in questa pagina crea lo YAML sul tuo dispositivo e la pagina non effettua richieste di rete. Ricaricando si cancella tutto.
