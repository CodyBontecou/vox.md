ตัวสร้าง Obsidian Bases: ตัวกรอง มุมมอง และสูตร

สร้าง YAML สำหรับ Obsidian base โดยไม่ต้องเรียนรู้สคีมาก่อน: เลือกตัวกรอง เพิ่มมุมมอง คัดลอกเป็นไฟล์ .base หรือบล็อกโค้ด และดูว่าแต่ละคีย์ทำอะไรพร้อมลิงก์ไปยังเอกสารของ Obsidian เอง

โดย
Cody Bontecou
ปรับปรุง
28 พฤศจิกายน 2026
ต้องใช้
เบราว์เซอร์ที่ทันสมัยทุกตัว รวมถึง Safari บน iPhone ไม่บังคับ: Obsidian ที่เปิดปลั๊กอินหลัก Bases และ Vox.md สำหรับ iPhone หรือ Mac เพื่อ Capture โน้ตด้วยเสียงหรือข้อความ
คำตอบสั้น ๆ

base คือมุมมองแบบฐานข้อมูลของโน้ตของคุณ เขียนเป็น YAML โดยมีคีย์ระดับบนสุดได้สูงสุดห้าคีย์: filters, formulas, properties, summaries และ views บันทึก YAML เป็น .base ไฟล์ หรือวางลงในโน้ตภายใน base บล็อกโค้ด ตัวสร้าง ด้านล่างจะเขียนให้คุณ เวอร์ชัน Obsidian ที่ต้องใช้ขึ้นอยู่กับประเภทมุมมอง: หน้ามุมมอง ระบุ Table และ Cards ตั้งแต่ 1.9, List และ Map ตั้งแต่ 1.10 และ Kanban ตั้งแต่ 1.14

filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

ตัวสร้างทำงานทั้งหมดในหน้านี้ ไม่มีสิ่งที่คุณพิมพ์ถูกอัปโหลด และหน้านี้ไม่ส่งคำขอเครือข่ายใด ๆ

1. สร้าง base ของคุณ

ตัวสร้างต้องใช้ JavaScript หากไม่มี ตาราง syntax และตัวอย่างพร้อมคัดลอกด้านล่างยังใช้งานได้

พรีเซ็ต

พรีเซ็ตจะกรอกแบบฟอร์มให้ แล้วแก้ไขอะไรก็ได้ภายหลัง

ตัวกรองต้นทาง (ใช้กับทุกมุมมอง)
สูตร (ไม่บังคับ)

อ้างอิงสูตรเป็น formula.name ใน order, groupBy และ summaries

base ของคุณ

การตรวจสอบ

    คัดลอกไปยังคลิปบอร์ดแล้ว คัดลอกไม่สำเร็จ เลือกข้อความแล้วคัดลอกเอง ดาวน์โหลด {file} แล้ว โหลดพรีเซ็ตแล้ว: {name} ลบ ลบมุมมอง มุมมอง {n} ประเภทตัวกรอง การเปรียบเทียบพร็อพเพอร์ตี้ พร็อพเพอร์ตี้ ตัวดำเนินการ ค่า อาร์กิวเมนต์ ชื่อสูตร นิพจน์ พร็อพเพอร์ตี้ ชื่อที่แสดง ชนิด ชื่อ พร็อพเพอร์ตี้ที่จะแสดง (ลำดับ) หนึ่งรายการต่อบรรทัด จำกัดจำนวน (ไม่บังคับ) จัดกลุ่มตามพร็อพเพอร์ตี้ (ไม่บังคับ) ทิศทาง ตัวกรองของมุมมอง หนึ่งนิพจน์ต่อบรรทัด (ต้องเป็นจริงทั้งหมด) สรุปผล พร็อพเพอร์ตี้สรุปผล สรุป เพิ่มสรุปผล มุมมอง {n} ไม่มีชื่อ ตั้งชื่อให้ทุกมุมมอง เพิ่มอย่างน้อยหนึ่งมุมมอง ไม่เช่นนั้น base จะไม่แสดงอะไร สูตร {name} อ้างอิงตัวเอง Obsidian ไม่อนุญาตให้อ้างอิงวนกลับ ชื่อสูตร {name} ควรขึ้นต้นด้วยตัวอักษรหรือขีดล่าง และใช้เฉพาะตัวอักษร ตัวเลข และขีดล่าง สูตร {name} ไม่มีนิพจน์ จึงถูกข้ามไป มีสองสูตรที่ใช้ชื่อ {name} ข้อความ {value} มีช่องว่าง จึงเขียนเป็นสตริงที่มีเครื่องหมายคำพูด ค่าข้อความต้องมีเครื่องหมายคำพูด แถวตัวกรองมีค่าว่าง จึงถูกข้ามไป พร็อพเพอร์ตี้ groupBy {name} ไม่อยู่ในรายการ order ของมุมมอง {n} base ยังทำงานได้ แต่จะไม่แสดงคอลัมน์นั้น {name} ไม่ใช่สรุปผลที่มีเอกสารรองรับ เลือกจากรายการ ยังไม่ได้ตั้งตัวกรองต้นทาง base นี้จึงรวมโน้ตทุกรายการใน vault เพิ่มตัวกรองโฟลเดอร์หรือแท็กเพื่อจำกัดขอบเขต ประเภทมุมมอง map ต้องใช้ปลั๊กอิน Maps ประเภทมุมมอง kanban ระบุไว้ในหน้ามุมมองว่าใช้ได้ตั้งแต่ Obsidian 1.14 ชื่อพร็อพเพอร์ตี้ {name} มีช่องว่าง ตรวจสอบว่า Obsidian ตั้งชื่อพร็อพเพอร์ตี้นั้นอย่างไรก่อนใช้งาน ไม่พบปัญหา

    2. ภาพรวมไวยากรณ์ Bases

    นี่คือคีย์ที่ หน้า syntax ของ Obsidian อธิบายไว้ ไม่มีสคีมาอื่นให้ต้องเรียนรู้

    คีย์ทำหน้าที่อะไรตัวอย่าง
    filtersจำกัดโน้ตสำหรับทุกมุมมองfile.hasTag("project")
    formulasกำหนดพร็อพเพอร์ตี้ที่คำนวณได้ ซึ่งใช้เป็น formula.name.total: 'price * qty'
    propertiesการตั้งค่าต่อพร็อพเพอร์ตี้ displayName ตั้งหัวคอลัมน์displayName: "Status"
    summariesกำหนดสูตรสรุปผลของคุณเอง โดยใช้ values.กำหนดเอง ไม่บังคับ
    viewsรายการมุมมองของโน้ตชุดเดียวกัน- type: table
    type (มุมมอง)เลย์เอาต์ของมุมมองtable, cards, list
    name (มุมมอง)ชื่อของมุมมองname: "Projects"
    filters (มุมมอง)ตัวกรองสำหรับมุมมองนี้เท่านั้นfile.inFolder("Work")
    groupBy (มุมมอง)จัดกลุ่มแถวตาม property ใน direction.direction: DESC
    order (มุมมอง)พร็อพเพอร์ตี้ที่แสดง ตามลำดับ- file.name
    limit (มุมมอง)จำกัดจำนวนแถวlimit: 10
    summaries (มุมมอง)จับคู่พร็อพเพอร์ตี้กับสรุปผลprice: Sum

    ตัวสร้างไม่ได้เขียนทุกคีย์ที่มีเอกสาร หน้า syntax ยังอธิบายถึง groupOrder และมุมมองอาจมีสถานะเพิ่มเติม เช่น คอลัมน์เรียงลำดับ ซึ่ง Obsidian จัดการเอง เพิ่มด้วยตนเองได้หากต้องการ: YAML เป็นของคุณที่จะแก้ไข

    3. ตัวกรอง: and, or, not

    ตัวกรองคือคำสั่งข้อความที่เป็นจริงหรือเท็จสำหรับแต่ละโน้ต หรือออบเจ็กต์ที่มี and, or หรือ not ที่เก็บรายการตัวกรองเพิ่มเติม ตัวกรองส่วนกลาง filters ใช้กับทุกมุมมอง ส่วนของมุมมองเอง filters ใช้กับมุมมองนั้นเท่านั้น และทั้งสองรวมกันด้วย AND

    filters:
  or:
    - file.hasTag("meeting")
    - file.inFolder("Meetings")

    ไม่มี from หรือ source ไม่เหมือน SQL หรือ Dataview หากไม่มีตัวกรอง base จะรวมไฟล์ทั้งหมดใน vault ดังนั้นควรตั้งตัวกรองเสมอ เว้นแต่ต้องการเช่นนั้น

    ค่าข้อความต้องมีเครื่องหมายคำพูดภายในคำสั่ง ดังนั้น YAML จึงต้องใช้เครื่องหมายคำพูดซ้อน: 'status == "done"' ตัวสร้างทำให้โดยอัตโนมัติ ตัวกรองแบบฟังก์ชัน เช่น file.hasTag(), file.inFolder() และ file.hasLink() อยู่ใน หน้าฟังก์ชัน.

    4. สูตรและสรุปผล

    แต่ละรายการใต้ formulas จะกลายเป็นพร็อพเพอร์ตี้ที่ใช้ได้ในทุกมุมมองเป็น formula.name สูตรหนึ่งใช้อีกสูตรหนึ่งได้ แต่ไม่อนุญาตให้อ้างอิงวนกลับ ดังนั้นสูตรจึงอ้างอิงตัวเองไม่ได้ ผลลัพธ์ถูกเก็บเป็นสตริง YAML จึงต้องใส่นิพจน์ไว้ในเครื่องหมายคำพูด

    formulas:
  formatted_price: 'if(price, price.toFixed(2) + " dollars")'

    ของมุมมอง summaries จับคู่พร็อพเพอร์ตี้กับสรุปผล หน้า syntax ระบุค่าเริ่มต้นเหล่านี้:

    • ตัวเลข: Average, Min, Max, Sum, Range, Median, Stddev
    • วันที่: Earliest, Latest, Range
    • บูลีน: Checked, Unchecked
    • ใด ๆ: Empty, Filled, Unique

    สำหรับการคำนวณวันที่ หน้า syntax ระบุว่า file.mtime > now() - "1 week" เป็นจริงสำหรับไฟล์ที่แก้ไขในช่วงสัปดาห์ที่ผ่านมา

    5. สิ่งนี้หมายความว่าอย่างไร

    ในตัวกรองหรือสูตร this คือไฟล์ที่แสดง base อยู่ หน้า syntax ระบุว่าเป็นไฟล์ base เองเมื่อเปิดในพื้นที่เนื้อหาหลัก เป็นไฟล์ที่ฝังเมื่อ base ถูกฝังในโน้ตหรือ Canvas และเป็นไฟล์ที่ใช้งานอยู่ในพื้นที่เนื้อหาหลักเมื่อ base อยู่ในแถบด้านข้าง หน้านั้นให้ file.hasLink(this.file) เป็นวิธีเลียนแบบแผง backlinks

    6. ตัวอย่างที่คัดลอกได้

    นี่คือพรีเซ็ตของตัวสร้างในรูปแบบโค้ดธรรมดา จึงใช้งานได้โดยไม่ต้องมี JavaScript แทนที่ชื่อโฟลเดอร์ แท็ก และพร็อพเพอร์ตี้ด้วยของคุณ บันทึกข้อความเป็น .base ไฟล์ หรือใส่ไว้ใน base บล็อกโค้ด ดู สร้าง base สำหรับคำสั่ง และฝังไฟล์ที่บันทึกด้วย ![[Name.base]] หรือ ![[Name.base#View]] เพื่อเลือกมุมมองเริ่มต้น

    รายการอ่าน

    filters:
  and:
    - file.inFolder("Reading")
    - 'status == "to read"'
properties:
  status:
    displayName: "Status"
views:
  - type: cards
    name: "Reading list"
    order:
      - file.name
      - status

    โปรเจกต์ตามสถานะ

    filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

    โน้ตที่มีแท็ก แก้ไขในสัปดาห์นี้

    filters:
  and:
    - file.hasTag("project")
    - 'file.mtime > now() - "1 week"'
views:
  - type: table
    name: "Modified this week"
    order:
      - file.name
      - file.mtime

    Backlinks ของโน้ตนี้

    filters:
  and:
    - file.hasLink(this.file)
views:
  - type: table
    name: "Backlinks"
    order:
      - file.name
      - file.folder

    โน้ตเสียงที่บันทึกด้วย Vox.md

    filters:
  and:
    - file.inFolder("Vox")
    - file.hasTag("voice")
views:
  - type: table
    name: "Voice notes"
    order:
      - file.ctime
      - file.name
      - file.tags

    ส่วน order list เลือกคอลัมน์ การเรียงลำดับเป็นการตั้งค่ามุมมองที่คุณเปลี่ยนในแถบเครื่องมือมุมมองของ Obsidian ตัวอย่างจึงไม่เขียนไว้

    7. ทำให้ Capture ของคุณปรากฏใน base

    Vox.md บันทึกสิ่งที่คุณ Capture เป็นโน้ต Markdown ในโฟลเดอร์ใน vault ของคุณ เอกสารเมทาดาทา ระบุว่า Route เพิ่มเมทาดาทาแบบคงที่ได้เป็น key: value บรรทัด เช่น tags: [journal, idea] และ Frontmatter ของโน้ต เขียนไว้ในระดับเอกสาร และยังอธิบายเมทาดาทาตำแหน่งที่ไม่บังคับ base ที่กรองตามโฟลเดอร์หรือแท็กนั้น เหมือนตัวอย่างสุดท้ายด้านบน จะแสดง Capture ของคุณในตารางเดียว สร้างเมทาดาทาด้วย ตัวสร้างคุณสมบัติ และดู โน้ตเสียงไปยัง Obsidian บน iPhone สำหรับการตั้งค่า

    เครื่องมือที่เกี่ยวข้อง: เครื่องมือสร้างเทมเพลตบันทึกประจำวัน เพื่อสร้างโน้ตที่มีวันที่ ตัวสร้าง callout และ ตัวสร้างตาราง Markdown สำหรับเนื้อหาของโน้ต

    อยากได้โน้ตที่คุ้มค่าแก่การสืบค้นไหม

    Vox.md บันทึกเสียงและข้อความบน iPhone และ Mac ลงใน vault ของคุณโดยตรงเป็น Markdown พร้อมพร็อพเพอร์ตี้ที่คุณเลือก การบันทึกเสียง Transcription และ Capture ต้องใช้ Vox.md Unlimited บัญชีที่มีสิทธิ์จะได้ Free trial 7 วัน

    บันทึกโน้ตด้วยเสียง

    ตัวสร้างด้านบนทำงานได้เต็มที่โดยไม่ต้องมีแอป

    8. การแก้ไขปัญหา

    • base แสดงโน้ตทุกรายการ ยังไม่ได้ตั้งตัวกรองต้นทาง ตามค่าเริ่มต้น base จะรวมทั้ง vault ดังนั้นให้เพิ่ม file.inFolder() หรือ file.hasTag() ตัวกรอง
    • คอลัมน์พร็อพเพอร์ตี้ว่างเปล่า ชื่อไม่ตรงกัน (รวมถึงตัวพิมพ์เล็กใหญ่) หรือโน้ตไม่มีพร็อพเพอร์ตี้นั้นใน frontmatter ตรวจสอบ Properties ของโน้ตและชื่อคอลัมน์
    • ข้อผิดพลาด YAML ตรวจสอบการเยื้องซึ่งใช้ช่องว่าง และเครื่องหมายคำพูด ตัวกรองที่มีข้อความต้องใช้เครื่องหมายคำพูดซ้อน: 'status == "done"'.
    • มุมมอง map ว่างเปล่า ตามหน้ามุมมอง เลย์เอาต์ map ต้องใช้ปลั๊กอิน Maps

    9. คำถาม

    Bases เป็นปลั๊กอินหลักหรือไม่

    ได้ ความช่วยเหลือของ Obsidian ระบุว่า “Bases เป็นปลั๊กอินหลักที่ให้คุณสร้างมุมมองแบบฐานข้อมูลของโน้ตได้”

    Bases หรือ Dataview

    ทั้งสองแยกจากกัน Dataview เป็นปลั๊กอินชุมชนที่มีภาษาสืบค้นของตัวเอง ส่วน base คือ YAML ที่ Obsidian อ่านเอง โดยไม่มี from คีย์: คุณจำกัดโน้ตด้วยตัวกรอง หน้านี้ไม่ได้เปรียบเทียบฟีเจอร์ของทั้งสองเพิ่มเติม

    แก้ไข YAML ด้วยตนเองได้ไหม

    ได้ .base ไฟล์เป็นข้อความ YAML และหน้า syntax อธิบายคีย์ต่าง ๆ เปิดไฟล์ที่สร้างในโปรแกรมแก้ไขใดก็ได้ หรือวางบล็อกโค้ดลงในโน้ตแล้วแก้ไขที่นั่น

    ตัวสร้างอัปโหลดข้อมูลของฉันไหม

    ไม่ สคริปต์ในหน้านี้สร้าง YAML บนอุปกรณ์ของคุณ และหน้านี้ไม่ส่งคำขอเครือข่ายใด ๆ การโหลดหน้าใหม่จะล้างทุกอย่าง
