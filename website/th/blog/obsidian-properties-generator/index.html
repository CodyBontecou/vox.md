  6. เพิ่มคุณสมบัติให้โน้ตที่คุณบันทึก
  7. คำถาม

    2. ตรวจสอบ frontmatter ที่คุณมีอยู่แล้ว

    วางส่วนบนของโน้ต รวมถึง --- บรรทัด ตัวตรวจสอบอ่านบล็อกทีละบรรทัดและแสดงแต่ละปัญหาพร้อมเลขบรรทัดและวิธีแก้ โดยใช้ชุดกฎระดับบรรทัดที่กำหนดไว้ ไม่ใช่ตัวแยกวิเคราะห์ YAML เต็มรูปแบบ จึงอาจพลาดข้อผิดพลาดที่ตัวแยกวิเคราะห์จะพบ และตรวจเฉพาะกฎที่ระบุไว้ที่นี่

    ตัวตรวจสอบจะมองหา: การใช้แท็บเป็นการย่อหน้า การขาดบรรทัดเปิดหรือปิด --- ลิงก์ภายในที่ไม่มีเครื่องหมายคำพูด แท็กที่มีช่องว่าง # คำนำหน้า อักขระอื่นที่แท็กห้ามมี หรือแท็กที่เป็นตัวเลขล้วน ชื่อที่เลิกใช้แล้ว tag, alias และ cssclass อ็อบเจ็กต์ซ้อน การจัดรูปแบบ Markdown ในค่า ชื่อซ้ำ และค่าบางอย่างที่ YAML อ่านต่างจากที่คุณตั้งใจ โทเคนเทมเพลต เช่น {{date}} และ <% %> จะถูกข้าม

    ชื่อคุณสมบัติ ชนิด ค่า ลบ ลบคุณสมบัติ {name} หนึ่งค่าต่อบรรทัด หนึ่งแท็กต่อบรรทัด จะมี # หรือไม่ก็ได้ ทำเครื่องหมายแล้ว เติมโดยปลั๊กอินเทมเพลต ข้อความ รายการ ตัวเลข ช่องทำเครื่องหมาย วันที่ วันที่และเวลา แท็ก คัดลอกไปยังคลิปบอร์ดแล้ว คัดลอกแล้ว วางลงในฟิลด์ Metadata ของ Route คัดลอกไม่สำเร็จ เลือกข้อความแล้วคัดลอกเอง ดาวน์โหลด properties.md แล้ว เพิ่ม {name} แล้ว {name} อยู่ในรายการแล้ว คุณสมบัติที่ไม่มีชื่อจะถูกละไว้ {name} ปรากฏมากกว่าหนึ่งครั้ง ให้เก็บไว้หนึ่งแถวต่อคุณสมบัติ {name} ไม่ใช่ตัวเลข จึงเว้นว่างไว้ แท็ก “{from}” ถูกเขียนเป็น {to} เพราะแท็กห้ามมีช่องว่างหรือคำนำหน้า # และต้องมีอักขระที่ไม่ใช่ตัวเลข แท็กที่ทำให้ถูกต้องไม่ได้ถูกละไว้: {from} {name} ต้องมีทั้งวันที่และเวลา จึงเว้นว่างไว้ ไม่พบปัญหา วาง frontmatter ที่ต้องการตรวจสอบ ดูเหมือน JSON Obsidian อ่านและบันทึกเป็น YAML กฎระดับบรรทัดที่นี่ใช้กับ YAML ดังนั้นให้วางเวอร์ชัน YAML เพื่อตรวจสอบ พบปัญหา: {n} บรรทัด {line} วิธีแก้: บล็อกไม่ได้ขึ้นต้นด้วยบรรทัด --- คุณสมบัติอยู่ระหว่างสองบรรทัด --- ที่ด้านบนของโน้ต เพิ่ม --- ในบรรทัดของตัวเองก่อนคุณสมบัติแรก ไม่มีบรรทัด --- ปิดท้ายหลังคุณสมบัติ เพิ่ม --- ในบรรทัดของตัวเองหลังคุณสมบัติสุดท้าย บรรทัดนี้ย่อหน้าด้วยแท็บ YAML ไม่อนุญาตให้ใช้แท็บย่อหน้า แทนที่แท็บนำหน้าแต่ละตัวด้วยช่องว่าง เช่นสองช่อง บรรทัดนี้ไม่ใช่คู่ name: value เขียนเป็น name: value โดยมีช่องว่างหลังโคลอน คุณสมบัติ {key} ถูกตั้งค่าไว้แล้วที่บรรทัด {first} เก็บบรรทัด {key} ไว้เพียงบรรทัดเดียว แล้วรวมค่าเข้าไว้ในบรรทัดนั้น {key} เป็นชื่อคุณสมบัติที่เลิกใช้แล้ว เลิกใช้ใน Obsidian 1.4 และเลิกรองรับในฐานะคุณสมบัติเริ่มต้นใน 1.9 เปลี่ยนชื่อเป็น {fixed} ลิงก์ภายในในคุณสมบัติต้องอยู่ในเครื่องหมายคำพูด เขียนเป็น {fixed} แท็กในคุณสมบัติเขียนโดยไม่มีคำนำหน้า # เขียนเป็น {fixed} แท็ก {tag} มีช่องว่าง แท็กห้ามมีช่องว่าง ใช้ขีดกลาง เช่น {fixed} หรือใส่แต่ละแท็กในบรรทัดของตัวเอง แท็ก {tag} ไม่มีอักขระที่ไม่ใช่ตัวเลข แท็กต้องมีอย่างน้อยหนึ่งตัว เพิ่มตัวอักษร เช่น {fixed} แท็ก {tag} มีอักขระที่แท็กห้ามมี แท็กใช้ได้เฉพาะตัวอักษร ตัวเลข ขีดล่าง ขีดกลาง และ / สำหรับการซ้อน ลบหรือแทนที่ เช่น {fixed} {key} เก็บอ็อบเจ็กต์ซ้อน คุณสมบัติไม่รองรับอ็อบเจ็กต์ซ้อน ทำให้แบนเป็นคุณสมบัติระดับบนแยกกัน หรือแก้ไขในโหมดซอร์ส ค่ามีการจัดรูปแบบ Markdown ({sample}) คุณสมบัติไม่แสดงผล Markdown ซึ่งเป็นการออกแบบ ลบอักขระจัดรูปแบบและเก็บข้อความธรรมดา ค่าที่ไม่มีเครื่องหมายคำพูดนี้มีโคลอนตามด้วยช่องว่าง ซึ่ง YAML จะอ่านเป็นจุดเริ่มต้นของชื่ออีกชื่อหนึ่ง ใส่ค่าในเครื่องหมายคำพูด: {fixed} ค่าที่ไม่มีเครื่องหมายคำพูดนี้ขึ้นต้นด้วย {char} ซึ่ง YAML ถือเป็นกรณีพิเศษ ใส่ค่าในเครื่องหมายคำพูด: {fixed} บรรทัดนี้เปิดเครื่องหมายคำพูดแต่ไม่ได้ปิด เพิ่มเครื่องหมายคำพูดปิด ใน YAML ช่องว่างตามด้วย # คือจุดเริ่มต้นของคอมเมนต์ ดังนั้นส่วนที่เหลือของบรรทัดจึงไม่ใช่ส่วนของค่า หาก # เป็นส่วนของค่า ให้ใส่ค่าในเครื่องหมายคำพูด: {fixed} โหลดตัวอย่างที่มีข้อผิดพลาดแล้ว

    4. กฎที่ทำให้คุณสมบัติพังบ่อยที่สุด

    • ใส่ลิงก์ภายในในเครื่องหมายคำพูด project: "[[Vox.md launch]]" ไม่ใช่ project: [[Vox.md launch]] ใช้กับคุณสมบัติแบบข้อความและรายการในลิสต์
    • หนึ่งรายการต่อบรรทัด แต่ละรายการขึ้นต้นด้วยขีดกลางและช่องว่าง ย่อหน้าไว้ใต้ชื่อคุณสมบัติ ใช้ช่องว่างในการย่อหน้า ไม่ใช่แท็บ
    • แท็กมีกฎของตัวเอง ไม่ # ใน YAML ไม่มีช่องว่าง และมีอักขระที่ไม่ใช่ตัวเลขอย่างน้อยหนึ่งตัว: 1984 ไม่ใช่แท็กที่ถูกต้อง แต่ y1984 ให้ใช้ / สำหรับแท็กซ้อน เช่น inbox/to-read ดู แท็ก ในวิธีใช้ Obsidian
    • เขียนวันที่ในรูปแบบที่จัดเก็บ 2026-11-21 สำหรับวันที่ และ 2026-11-21T10:30:00 สำหรับวันที่และเวลา
    • ใช้ชื่อปัจจุบัน tag, alias และ cssclass เลิกใช้ใน Obsidian 1.4 และให้ใช้ tags, aliases และ cssclasses และเลิกรองรับในฐานะคุณสมบัติเริ่มต้นใน Obsidian 1.9
    • อย่าซ้อนกัน คุณสมบัติไม่รองรับอ็อบเจ็กต์ซ้อน Obsidian แนะนำให้ดูคุณสมบัติซ้อนในโหมดซอร์ส ดังนั้นให้ทำให้แบนเป็นชื่อระดับบน เช่น project_status.
    • อย่าใช้ Markdown ตัวหนา ลิงก์ และการจัดรูปแบบอื่นจะไม่แสดงผลในคุณสมบัติ Obsidian ระบุว่าเป็นความตั้งใจ เพราะคุณสมบัติมีไว้สำหรับข้อมูลชิ้นเล็กๆ ที่แยกเป็นหน่วยเดียว

    5. การใช้คุณสมบัติในเทมเพลต

    เปิด โทเคนของปลั๊กอินเทมเพลต ในตัวสร้างเพื่อเขียนฟิลด์วันที่เป็นโทเคนแทนวันที่คงที่ ปลั๊กอิน Templates หลักใช้ {{date:YYYY-MM-DD}} ส่วนปลั๊กอินชุมชน Templater ใช้ <% tp.date.now("YYYY-MM-DD") %> (ดู Templater เอกสาร) ฟิลด์วันที่และเวลาใช้ YYYY-MM-DD[T]HH:mm:ss ในโทเคน พร้อมกับ T ในวงเล็บเหลี่ยม เพื่อให้เขียนเป็นตัวอักษร

    ลิงก์ต้องระวังเป็นพิเศษ Obsidian จะเติมเครื่องหมายคำพูดให้ลิงก์ที่คุณพิมพ์ใน UI ของคุณสมบัติ แต่ปลั๊กอินเทมเพลตเขียนข้อความลงไฟล์ตามที่เป็น ดังนั้นให้เขียนเครื่องหมายคำพูดเองในเทมเพลต: project: "[[Vox.md launch]]".

    สำหรับเทมเพลตทั้งชุดที่ใช้คุณสมบัติเหล่านี้ ดู เครื่องมือสร้างเทมเพลตบันทึกประจำวัน และ ตัวสร้างเทมเพลตบันทึกการประชุม.

    เมื่อโน้ตมีพร็อพเพอร์ตี้แล้ว คุณสืบค้นด้วย base ได้: ตัวสร้าง Obsidian Bases สร้างตัวกรองและมุมมอง

    เมื่อโน้ตมีพร็อพเพอร์ตี้แล้ว คุณสืบค้นด้วย base ได้: ตัวสร้าง Obsidian Bases สร้างตัวกรองและมุมมอง

    สำหรับเนื้อหาของโน้ต ตัวสร้างตาราง Markdown เปลี่ยนเซลล์สเปรดชีตหรือ CSV เป็นตารางที่คุณวางใต้บล็อกพร็อพเพอร์ตีได้

    6. เพิ่มคุณสมบัติให้โน้ตที่คุณบันทึก

    ในฟิลด์ Metadata ของ Route ใน Vox.md รับได้หนึ่ง key: value หนึ่งคู่ต่อบรรทัด เช่น tags: [journal, idea]. Frontmatter ของโน้ต เขียน metadata ในระดับเอกสาร ฟิลด์รายการในบรรทัด เขียน key:: value ฟิลด์ข้างแต่ละรายการในโน้ตแบบต่อเนื่อง ดู Metadata ในเอกสารอ้างอิง Routes.

    ของตัวสร้าง คัดลอกเป็น metadata ของ Route ใน Vox.md ปุ่มจะเขียนคุณสมบัติของคุณในรูปแบบนั้น โดยรายการจะเขียนเป็น [a, b] และหนึ่งคุณสมบัติต่อบรรทัด เอกสารของ Vox.md อธิบายฟิลด์นี้ว่า key: value บรรทัด หน้านี้ไม่ได้ทดสอบว่าคุณสมบัติแต่ละชนิดถูกเขียนอย่างไร ดังนั้นให้เปิดโน้ตแรกที่บันทึกใน Obsidian แล้วตรวจสอบ ส่วน Route สำหรับโน้ตประจำวันและกล่องข้อความเข้าอยู่ใน ต่อท้ายลงโน้ตรายวัน Obsidian, เทมเพลตการจับข้อมูล และ โน้ตเสียง iPhone ไปยัง Obsidian.

    ใส่คุณสมบัติเหล่านี้ในทุกโน้ตที่บันทึก

    อยากให้คุณสมบัติเหล่านี้อยู่ในทุกโน้ตที่คุณจดจาก iPhone, Apple Watch หรือ Mac ใช่ไหม วางลงในเมทาดาทาของเส้นทาง Vox.md แล้วเลือก Frontmatter ของโน้ต บัญชีที่มีสิทธิ์ทดลองใช้ฟรีได้ 7 วัน

    7. คำถาม

    ทำไม Obsidian จึงไม่แสดงคุณสมบัติของฉันเป็นชนิดที่ตั้งใจไว้

    Obsidian อ่านคุณสมบัติเป็น YAML และค่าที่ไม่เป็นไปตามกฎของชนิดนั้นจะไม่แสดงเป็นชนิดนั้น สาเหตุที่พบบ่อยคือลิงก์ที่ไม่มีเครื่องหมายคำพูด รายการที่ไม่ได้เขียนหนึ่งรายการต่อบรรทัด วันที่ที่ไม่อยู่ในรูปแบบ YYYY-MM-DD และแท็กที่มีช่องว่าง วางบล็อกลงในตัวตรวจสอบด้านบนเพื่อหาบรรทัดที่ผิด

    แท็กในคุณสมบัติต้องมี # ไหม

    ไม่ต้อง ใน YAML แท็กเขียนเป็นคำธรรมดา เช่น - recipe ส่วน # ใช้สำหรับแท็กในเนื้อหาของโน้ต

    ซ้อนคุณสมบัติได้ไหม

    ไม่ได้ คุณสมบัติไม่รองรับอ็อบเจ็กต์ซ้อน ให้ใช้ชื่อแบบแบน หรือใช้แท็กซ้อนด้วย / ภายใน tags ลิสต์

    เขียนคุณสมบัติเป็น JSON ได้ไหม

    Obsidian อ่านบล็อก JSON ได้ แต่จะอ่านและบันทึกเป็น YAML ตัวตรวจสอบด้านบนใช้กฎระดับบรรทัดกับ YAML เท่านั้น
