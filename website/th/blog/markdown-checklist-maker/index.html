งาน Markdown คือขีดกลาง ช่องว่าง วงเล็บเหลี่ยม ช่องว่าง แล้วจึงข้อความ เขียน - [ ] task สำหรับงานที่ยังไม่เสร็จ และ - [x] done สำหรับงานที่เสร็จแล้ว หากต้องการเปลี่ยนทั้งลิสต์เป็นงาน ให้วางลงใน ตัวสร้างเช็กลิสต์ ด้านล่าง

- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

ตัวสร้างจะลบสัญลักษณ์หัวข้อย่อย ตัวเลข และช่องทำเครื่องหมายที่มีอยู่เพื่อไม่ให้ซ้ำซ้อน คงการเยื้องไว้เป็นการซ้อน และเพิ่มวันครบกำหนดในรูปแบบที่ปลั๊กอิน Obsidian ของคุณอ่านได้ ทำงานทั้งหมดในหน้านี้ ลิสต์จะไม่ถูกอัปโหลด และหน้านี้ไม่ส่งคำขอผ่านเครือข่าย

1. สร้างเช็กลิสต์ของคุณ

ตัวสร้างเช็กลิสต์ต้องใช้ JavaScript หากไม่มี ไวยากรณ์ด้านล่างก็ยังใช้เป็นข้อมูลอ้างอิงได้

ลิสต์ของคุณ
สิ่งที่ต้องทำ
การซ้อน

แท็บในลิสต์ของคุณนับเป็นหนึ่งระดับเสมอ หัวข้อยังคงเป็นหัวข้อ

วันครบกำหนดสำหรับทุกงาน

เช็กลิสต์ของคุณ

ตัวอย่าง

วางลิสต์เพื่อดูผลลัพธ์ เสร็จแล้ว {done} จาก {total} ไม่มีงานในลิสต์นี้ คัดลอกไปยังคลิปบอร์ดแล้ว คัดลอกไม่สำเร็จ เลือกข้อความแล้วคัดลอกเอง โหลดตัวอย่างแล้ว ล้างแล้ว เช็กลิสต์ของคุณ ลิสต์ของคุณที่ไม่มีช่องทำเครื่องหมาย เลือกวันที่ที่ถูกต้องเพื่อเพิ่มวันครบกำหนด ยังไม่ได้เพิ่มวันที่ ป้อนเวลา เช่น 09:30 วันที่ถูกเพิ่มโดยไม่มีเวลา งานที่มีวันที่ลักษณะนี้อยู่แล้วจะไม่ถูกแก้ไข บน GitHub คำอธิบายงานที่ขึ้นต้นด้วยวงเล็บต้องมีแบ็กสแลชนำหน้า

2. ไวยากรณ์เช็กลิสต์ Markdown

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

แต่ละงานคือรายการในลิสต์: ขีดกลางหนึ่งตัวและช่องว่างหนึ่งช่อง ตามด้วย [ ] โดยมีช่องว่างหนึ่งช่องระหว่างวงเล็บเหลี่ยม แล้วตามด้วยข้อความ Obsidian Help หน้า และ GitHub Docs หน้า ทั้งสองอธิบายว่าเป็นขีดกลางและช่องว่าง ตามด้วย [ ] หากต้องการทำเครื่องหมายว่างานเสร็จ GitHub Docs บอกให้ใช้ [x].

ช่องว่างมีความสำคัญ สเปก GitHub Flavored Markdown นิยามเครื่องหมายช่องทำเครื่องหมายว่าเป็นวงเล็บเหลี่ยมเปิด อักขระช่องว่าง หรือตัวอักษร x และวงเล็บปิด และต้องมีช่องว่างก่อนข้อความที่ตามหลัง ดังนั้น [] ที่ไม่มีอะไรอยู่ข้างใน หรือ - [ ]text โดยไม่มีช่องว่างหลังวงเล็บ จะไม่ตรงกับนิยาม ขีดกลางและช่องว่างหลังมันคือสิ่งที่ทำให้บรรทัดนั้นเป็นรายการในลิสต์

รายการงานไม่ได้เป็นส่วนหนึ่งของ Markdown หลัก สเปกเดียวกันนี้ระบุว่าเป็นส่วนขยายของ CommonMark และคำนำของสเปกบอกว่าฟีเจอร์ที่ไม่มีในสเปก CommonMark ดั้งเดิมจะถูกระบุเป็นส่วนขยาย ตัวแสดงผลที่ไม่ได้ติดตั้งส่วนขยายนี้จะแสดงวงเล็บเหลี่ยมเป็นข้อความธรรมดา ซึ่งเป็นสาเหตุทั่วไปที่ช่องทำเครื่องหมายแสดงเป็น [ ] บนหน้า

3. เช็กลิสต์ใน Obsidian

ในวิธีใช้ Obsidian หน้า ไวยากรณ์การจัดรูปแบบพื้นฐาน อธิบายเรื่องรายการงาน:

  • งานขึ้นต้นด้วยขีดกลางและช่องว่าง ตามด้วย [ ].
  • คุณใช้อักขระใดก็ได้ในวงเล็บเหลี่ยมเพื่อทำเครื่องหมายว่างานเสร็จ ดังนั้น [x], [-] และ [?] ล้วนนับว่าเสร็จแล้ว
  • คุณซ้อนรายการงานได้ด้วยการเยื้องรายการ ใช้ Tab หรือ Shift+Tab เพื่อเยื้องเข้าหรือเยื้องออกรายการที่เลือก
  • คุณสลับสถานะของงานในมุมมองการอ่านได้โดยเลือกช่องทำเครื่องหมายของงานนั้น

หน้า Help ระบุว่าอักขระใดก็ได้ทำให้งานเสร็จ แต่ไม่ได้อธิบายว่าแต่ละอักขระมีหน้าตาต่างกัน หาก [-] หรือ [?] ดูต่างจาก [x] ใน vault ของคุณ นั่นมาจากธีมหรือ CSS snippet ที่คุณติดตั้งไว้ ไม่ได้มาจาก Markdown เอง

บรรทัดความคืบหน้าในตัวสร้างนับแบบเดียวกัน อักขระใดก็ตามในวงเล็บเหลี่ยมที่ไม่ใช่ช่องว่างถือว่างานเสร็จแล้ว ดังนั้น [x], [X], [-] และ [?] เสร็จแล้ว และ [ ] คืองานที่ยังไม่เสร็จ บรรทัดที่ขึ้นต้นด้วย “done:” หรือ “x ” เป็นข้อความธรรมดา เครื่องมือจะไม่เดาว่าหมายถึงงานที่เสร็จแล้ว

4. วันครบกำหนด: Tasks, Dataview และ Reminder

ไวยากรณ์รายการงานของ Obsidian ไม่มีวันครบกำหนดของตัวเอง หน้า Help ไม่ได้ระบุไว้ มีปลั๊กอินสามตัวที่อ่านวันที่ซึ่งเขียนไว้ในข้อความของงาน โดยแต่ละตัวใช้รูปแบบของตัวเอง ตัวสร้างจะเขียนวันที่ในรูปแบบ ISO YYYY-MM-DD ในทุกตัว หากไม่มีปลั๊กอิน วันที่ก็เป็นเพียงข้อความ

รูปแบบอ่านโดยบรรทัดตัวอย่าง
ครบกำหนด: 📅 YYYY-MM-DDปลั๊กอิน Tasks ซึ่งระบุว่าวันที่ต้องเขียนเป็น YYYY-MM-DD (รูปแบบ ISO)- [ ] send invoice 📅 2026-11-25
กำหนดการ: ⏳ YYYY-MM-DDปลั๊กอิน Tasks- [ ] send invoice ⏳ 2026-11-25
เริ่ม: 🛫 YYYY-MM-DDปลั๊กอิน Tasks- [ ] send invoice 🛫 2026-11-25
ฟิลด์อินไลน์: [due:: YYYY-MM-DD]Dataview เอกสาร ซึ่งอ่านฟิลด์ที่เขียนไว้ในงาน เช่น [completion:: 2021-08-15]- [ ] send invoice [due:: 2026-11-25]
การเตือน: (@YYYY-MM-DD) หรือ (@YYYY-MM-DD HH:mm)obsidian-reminder ปลั๊กอิน ซึ่ง README แสดงตัวอย่าง (@2021-08-14) และ (@2021-08-14 09:37) บนงานที่ยังไม่ติ๊ก- [ ] send invoice (@2026-11-25 09:30)

เลือกปลั๊กอินที่คุณใช้เพียงตัวเดียว หน้าของ Dataview ยังระบุทางลัดอีโมจิสำหรับวันที่ของตัวเองด้วย และบอกว่านั่นเป็นทางลัดเดียวที่รองรับ ตัวสร้างจึงเขียนรูปแบบวงเล็บของ Dataview แทน README ของ Reminder บอกว่าคุณจะไม่ได้รับการแจ้งเตือนสำหรับงานที่ติ๊กไปแล้ว

5. ความแตกต่างระหว่าง GitHub กับ Obsidian

GitHub Docs อธิบายว่า [ ] สำหรับงานที่ยังไม่เสร็จ และ [x] เพื่อทำเครื่องหมายว่างานเสร็จ สเปก GFM นิยามเครื่องหมายว่าเป็นช่องว่างหรือตัวอักษร x ระหว่างวงเล็บเหลี่ยม Obsidian ยอมรับอักขระใดก็ได้ ดังนั้นงานอย่าง - [-] skipped หรือ - [?] unsure ถือว่าเสร็จแล้วใน Obsidian แต่อยู่นอกนิยามของเครื่องหมายในสเปก และตัวแสดงผลที่ทำตามสเปกอาจแสดงเป็นข้อความธรรมดา หากไฟล์ถูกอ่านบน GitHub ด้วย ให้ใช้ [ ] และ [x] เท่านั้น

GitHub Docs เพิ่มอีกหนึ่งกฎ หากคำอธิบายงานขึ้นต้นด้วยวงเล็บ ให้ใส่แบ็กสแลชนำหน้า เช่น - [ ] \(Optional) Open a followup issue ตัวสร้างไม่ได้เติมแบ็กสแลชให้คุณ แต่จะเตือนเมื่องานขึ้นต้นด้วยวงเล็บ

6. บันทึกงานด้วยเสียงหรือข้อความบน iPhone และ Mac ด้วย Vox.md

โหมดประมวลผล Todo Checklist ของ Vox.md สร้างงานในรูปแบบ Markdown - [ ] จากสิ่งที่บันทึก และตัวสำรองคือตัวจัดรูปแบบเช็กลิสต์ที่ให้ผลคงที่ เสียงจะถูกถอดเป็นข้อความบนอุปกรณ์ของคุณ ใน Capture Bar รายการตรวจสอบ ใส่คำนำหน้า - [ ] คำนำหน้า และ วางสองวันที่ แทรก (@yyyy-MM-dd) หรือรูปแบบที่มีเวลา ดู การจับภาพอย่างรวดเร็ว และ Routes และโหมดประมวลผล ในเอกสาร

Route สามารถเพิ่มรายการลงในโน้ตประจำวันของคุณใต้หัวข้อ เช่น ## Tasks; ต่อท้ายลงโน้ตรายวัน Obsidian อธิบายขั้นตอนการตั้งค่า และ เครื่องมือสร้างเทมเพลตบันทึกประจำวัน เขียนโครงสร้างของโน้ต สำหรับรายการสิ่งที่ต้องทำจากการประชุม ดู เทมเพลตบันทึกการประชุม สำหรับสูตรคำนำหน้ารายการงาน ดู เทมเพลตการจับข้อมูล.

Vox.md เขียนรูปแบบ (@yyyy-MM-dd) ที่แสดงในเอกสาร ไม่ได้เขียนวันที่อีโมจิของปลั๊กอิน Tasks หรือฟิลด์ของ Dataview หากคุณใช้แบบใดแบบหนึ่ง ให้วางงานที่บันทึกลงในตัวสร้างด้านบนแล้วเลือกรูปแบบนั้น หรือแก้วันที่ภายหลัง หากต้องการสร้างคุณสมบัติที่ด้านบนของโน้ต ให้ใช้ ตัวสร้างคุณสมบัติ.

บันทึกงานด้วยเสียงบน iPhone, iPad หรือ Mac

Vox.md เปลี่ยนสิ่งที่คุณพูดเป็นเช็กลิสต์ Markdown บนอุปกรณ์ แล้วเพิ่มลงในโน้ต Obsidian ของคุณ สิทธิ์ใช้ฟรีคือถอดเสียงเป็นข้อความ 15 นาที และส่ง Capture สำเร็จ 10 ครั้ง ส่วนการใช้ไม่จำกัดคือปลดล็อกตลอดชีพครั้งเดียว ไม่มีค่าสมาชิก

บันทึกงานด้วยเสียง

ตัวสร้างเช็กลิสต์ด้านบนใช้งานได้เต็มที่โดยไม่ต้องมีแอป

7. คำถาม

ทำไมช่องทำเครื่องหมายของฉันแสดงเป็นข้อความ [ ]

ตัวแสดงผลไม่ได้แสดงรายการงาน รายการงานเป็นส่วนขยายของ CommonMark ตัวแสดงผลที่ไม่มีส่วนขยายนี้จึงแสดงวงเล็บเหลี่ยมตามที่เป็น ตรวจสอบว่าบรรทัดขึ้นต้นด้วยขีดกลางและช่องว่าง มีช่องว่างหรือ x อยู่ระหว่างวงเล็บเหลี่ยม และมีช่องว่างตามหลังวงเล็บปิด ใน Obsidian งานที่อยู่ในบล็อกโค้ดหรือเซลล์ตารางอาจไม่แสดงเป็นช่องทำเครื่องหมายเหมือนรายการในลิสต์

จะซ้อนงานได้อย่างไร

เยื้องงานย่อยเข้าไป ใน Obsidian ให้กด Tab เพื่อเยื้องรายการที่เลือก และ Shift+Tab เพื่อเลื่อนเข้า-ออกกลับ ตัวสร้างจะเปลี่ยนช่องว่าง 2 หรือ 4 ช่องในลิสต์ของคุณเป็นแท็บหนึ่งอันต่อระดับ หรือเป็นช่องว่าง 2 หรือ 4 ช่องหากคุณต้องการ

จะติ๊กช่องด้วยอักขระอื่นที่ไม่ใช่ x ได้อย่างไร

Obsidian Help ระบุว่าอักขระใดก็ได้ในวงเล็บเหลี่ยมทำให้งานเสร็จ ดังนั้น - [-] task และ - [?] task เสร็จแล้ว ตัวสร้างจะเก็บอักขระที่คุณวางไว้ เว้นแต่คุณรีเซ็ตลิสต์ สำหรับไฟล์ที่ถูกอ่านบน GitHub ด้วย ให้ใช้ [x].

จะเพิ่มวันครบกำหนดที่ปลั๊กอิน Tasks อ่านได้อย่างไร

ใส่ 📅 และวันที่รูปแบบ YYYY-MM-DD ที่ท้ายงาน เช่น - [ ] send invoice 📅 2026-11-25 เลือก “ปลั๊กอิน Tasks: ครบกำหนด” ด้านบนเพื่อเพิ่มลงในทุกงาน ใช้ ⏳ สำหรับวันกำหนดการ และ 🛫 สำหรับวันเริ่ม

ตัวสร้างอัปโหลดลิสต์ของฉันไหม
