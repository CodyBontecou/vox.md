Markdown-Checklisten-Generator: jede Liste in Aufgaben umwandeln, mit Fälligkeitsdatum

Füge einfache Zeilen, Aufzählungen, nummerierte Einträge oder eine vorhandene Aufgabenliste ein und kopiere gültige - [ ]-Aufgaben, mit erhaltener Verschachtelung, optionalem Fälligkeitsdatum und einer Zählung der erledigten Aufgaben.

Die kurze Antwort

Eine Markdown-Aufgabe besteht aus einem Bindestrich, einem Leerzeichen, Klammern, einem Leerzeichen und dem Text. Schreibe - [ ] task für eine offene Aufgabe und - [x] done für eine erledigte. Um eine ganze Liste in Aufgaben umzuwandeln, füge sie in den Checklisten-Generator unten.

- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

Der Generator entfernt vorhandene Aufzählungszeichen, Nummern und Kontrollkästchen, damit nichts doppelt vorkommt, behält Einrückungen als Verschachtelung bei und kann ein Fälligkeitsdatum in dem Format hinzufügen, das dein Obsidian-Plugin liest. Er läuft vollständig auf dieser Seite: Die Liste wird nie hochgeladen, und die Seite stellt keine Netzwerkanfragen.

2. Markdown-Checklisten-Syntax

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

Jede Aufgabe ist ein Listenelement: ein Bindestrich und ein Leerzeichen, dann [ ] mit einem Leerzeichen zwischen den Klammern, dann der Text. Obsidian Help Seite und GitHub Docs Seite beschreiben es beide als Bindestrich und Leerzeichen, gefolgt von [ ]. Zum Abschließen einer Aufgabe nennen die GitHub Docs [x].

Auf die Leerzeichen kommt es an. Die GitHub-Flavored-Markdown-Spezifikation definiert die Kontrollkästchen-Markierung als eine linke Klammer, ein Leerraumzeichen oder den Buchstaben x, dann eine rechte Klammer; vor dem Text danach ist Leerraum nötig. Also [] ohne Inhalt oder - [ ]text ohne Leerzeichen nach der Klammer, entspricht nicht der Definition. Der Bindestrich mit seinem Leerzeichen macht die Zeile überhaupt erst zu einem Listenelement.

Aufgabenlisten gehören nicht zum Kern-Markdown. Dieselbe Spezifikation kennzeichnet sie als Erweiterung von CommonMark, und ihre Einleitung sagt, dass Funktionen, die nicht in der ursprünglichen CommonMark-Spezifikation stehen, als Erweiterungen markiert sind. Ein Renderer, der die Erweiterung nicht umsetzt, zeigt die Klammern als Rohtext an. Das ist der übliche Grund, warum ein Kontrollkästchen als [ ] auf der Seite angezeigt wird.

3. Checklisten in Obsidian

In Obsidian Help behandelt die Seite Grundlegende Formatierungssyntax Aufgabenlisten:

  • Eine Aufgabe beginnt mit einem Bindestrich und einem Leerzeichen, gefolgt von [ ].
  • Du kannst jedes Zeichen in den Klammern verwenden, um die Aufgabe als erledigt zu markieren, also gelten [x], [-] und [?] zählen alle.
  • Du verschachtelst eine Aufgabenliste, indem du Listenelemente einrückst. Verwende Tab oder Shift+Tab zum Ein- oder Ausrücken der ausgewählten Einträge.
  • In der Leseansicht kannst du eine Aufgabe umschalten, indem du ihr Kontrollkästchen auswählst.

Die Hilfeseite dokumentiert, dass jedes Zeichen eine Aufgabe abschließt. Sie beschreibt kein unterschiedliches Aussehen für jedes Zeichen. Wenn [-] oder [?] anders aussieht als [x] liegt das in deinem Vault an einem Theme oder CSS-Snippet, das du installiert hast, nicht am Markdown selbst.

Die Fortschrittszeile im Generator zählt genauso: Jedes Zeichen in den Klammern außer einem Leerzeichen gilt als erledigt, also sind [x], [X], [-] und [?] erledigt und [ ] offen. Zeilen, die mit „done:“ oder „x “ beginnen, sind normaler Text; das Tool nimmt nicht an, dass sie eine erledigte Aufgabe meinen.

4. Fälligkeitsdaten: Tasks, Dataview und Reminder im Vergleich

Die Aufgabenlisten-Syntax von Obsidian kennt kein eigenes Fälligkeitsdatum: Die Hilfeseite dokumentiert keines. Drei Plugins lesen ein im Aufgabentext geschriebenes Datum, jedes in seinem eigenen Format. Der Generator schreibt das Datum als ISO YYYY-MM-DD in allen drei. Ohne das Plugin ist das Datum nur Text.

DatumsformatGelesen vonBeispielzeile
Fällig: 📅 YYYY-MM-DDTasks-Plugins, die sagen, dass das Datum im Format YYYY-MM-DD stehen muss- [ ] send invoice 📅 2026-11-25
Geplant: ⏳ YYYY-MM-DDTasks-Plugins- [ ] send invoice ⏳ 2026-11-25
Beginn: 🛫 YYYY-MM-DDTasks-Plugins- [ ] send invoice 🛫 2026-11-25
Inline-Feld: [due:: YYYY-MM-DD]Dataview Dokumentation, das an einer Aufgabe geschriebene Felder liest, etwa [completion:: 2021-08-15]- [ ] send invoice [due:: 2026-11-25]
Erinnerung: (@YYYY-MM-DD) oder (@YYYY-MM-DD HH:mm)obsidian-reminder Plugin, deren README (@2021-08-14) und (@2021-08-14 09:37) bei nicht abgehakten Aufgaben zeigt- [ ] send invoice (@2026-11-25 09:30)

Wähle das eine Plugin, das du nutzt. Die Seite von Dataview nennt außerdem eigene Emoji-Kürzel für Datumsangaben und sagt, dass dies die einzigen Kürzel sind, die es unterstützt; der Generator schreibt stattdessen die Klammerform von Dataview. Die Reminder-README sagt, dass du für Erinnerungen an bereits abgehakte Aufgaben nicht benachrichtigt wirst.

5. Unterschiede zwischen GitHub und Obsidian

Die GitHub Docs beschreiben [ ] für eine offene Aufgabe und [x] um eine als erledigt zu markieren. Die GFM-Spezifikation definiert die Markierung als Leerraum oder den Buchstaben x zwischen den Klammern. Obsidian akzeptiert jedes Zeichen. Eine Aufgabe wie - [-] skipped oder - [?] unsure ist in Obsidian erledigt, liegt aber außerhalb der Markierungsdefinition der Spezifikation, und ein Renderer, der der Spezifikation folgt, zeigt es möglicherweise als Rohtext an. Wird die Datei auch auf GitHub gelesen, verwende [ ] und [x] , mehr nicht.

Die GitHub Docs nennen eine zusätzliche Regel: Beginnt eine Aufgabenbeschreibung mit einer Klammer, maskiere sie mit einem Backslash, wie in - [ ] \(Optional) Open a followup issue. Der Generator fügt den Backslash nicht für dich ein; er warnt, wenn eine Aufgabe mit einer Klammer beginnt.

6. Aufgaben auf iPhone und Mac per Sprache oder Text mit Vox.md erfassen

Der Verarbeitungsmodus Todo Checklist von Vox.md erzeugt aus einer Erfassung Markdown-Aufgabenelemente mit dem Präfix - [ ] und fällt auf einen deterministischen Checklisten-Formatierer zurück. Sprache wird auf deinem Gerät transkribiert. In der Capture Bar Checkliste wendet das Präfix - [ ] an, und Fälligkeitsdatum festlegen fügt (@yyyy-MM-dd) oder eine Variante mit Uhrzeit ein. Siehe die Schnelle Erfassung und Routen und Verarbeitungsmodi Dokumentation.

Eine Route kann die Einträge in deine Tagesnotiz einfügen, und zwar unter einer Überschrift wie ## Tasks; An eine Obsidian-Tagesnotiz anhängen führt durch die Einrichtung, und der Generator für Tagesnotiz-Vorlagen schreibt die Struktur der Notiz. Für Aufgaben aus einer Besprechung siehe die Vorlage für Besprechungsnotizen; ein Rezept für das Aufgabenlisten-Präfix findest du unter Capture-Vorlagen.

Vox.md schreibt die (@yyyy-MM-dd) -Form aus der Dokumentation. Emoji-Daten des Tasks-Plugins oder Dataview-Felder schreibt es nicht. Wenn du eines davon nutzt, füge die erfassten Aufgaben in den Generator oben ein und wähle dieses Format, oder bearbeite das Datum nachträglich. Um die Properties am Anfang einer Notiz zu erstellen, verwende den Properties-Generator.

7. Fragen

Warum wird mein Kontrollkästchen als Text [ ] angezeigt?

Der Renderer stellt keine Aufgabenlisten dar. Aufgabenlisten sind eine Erweiterung von CommonMark, daher zeigt ein Renderer ohne diese Erweiterung die Klammern an. Prüfe, ob die Zeile mit einem Bindestrich und einem Leerzeichen beginnt, ob ein Leerzeichen oder x zwischen den Klammern steht und dass nach der schließenden Klammer ein Leerzeichen folgt. In Obsidian wird eine Aufgabe in einem Codeblock oder einer Tabellenzelle unter Umständen nicht als Kontrollkästchen dargestellt, wie es bei einem Listenelement der Fall ist.

Wie verschachtele ich Aufgaben?

Rücke die untergeordnete Aufgabe ein. Drücke in Obsidian Tab zum Einrücken der ausgewählten Einträge und Shift+Tab zum Ausrücken. Der Generator wandelt 2 oder 4 Leerzeichen in deiner Liste in einen Tabulator pro Ebene um, oder auf Wunsch in 2 oder 4 Leerzeichen.

Wie hake ich ein Kästchen mit einem anderen Zeichen als x ab?

Laut Obsidian Help markiert jedes Zeichen in den Klammern die Aufgabe als erledigt, also sind - [-] task und - [?] task erledigt. Der Generator behält das eingefügte Zeichen bei, solange du die Liste nicht zurücksetzt. Für Dateien, die auch auf GitHub gelesen werden, verwende [x].

Wie füge ich ein Fälligkeitsdatum hinzu, das das Tasks-Plugin liest?

Setze 📅 und ein YYYY-MM-DD -Datum am Ende der Aufgabe, zum Beispiel - [ ] send invoice 📅 2026-11-25. Wähle oben „Tasks-Plugin: fällig“, um es zu jeder Aufgabe hinzuzufügen. Verwende ⏳ für ein geplantes Datum und 🛫 für ein Startdatum.

Lädt der Generator meine Liste hoch?

Nein. Die Liste wird von einem Skript auf dieser Seite auf deinem Gerät umgewandelt, und die Seite stellt keine Netzwerkanfragen. Deine Liste wird nicht gespeichert: Beim Schließen oder Neuladen der Seite wird sie gelöscht.
