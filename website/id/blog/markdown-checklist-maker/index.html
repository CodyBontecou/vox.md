Tempel baris biasa, butir, item bernomor, atau daftar tugas yang ada dan salin tugas - [ ] yang valid, dengan sarang dipertahankan, tenggat opsional, dan hitungan yang selesai.

Jawaban singkat

Tugas Markdown adalah tanda hubung, spasi, tanda kurung siku, spasi, lalu teks. Tulis - [ ] task untuk tugas yang belum selesai dan - [x] done untuk tugas yang selesai. Untuk mengubah seluruh daftar menjadi tugas, tempelkan ke pembuat daftar periksa di bawah.

- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

Pembuat daftar menghapus butir, nomor, dan kotak centang yang ada agar tidak ganda, mempertahankan indentasi sebagai sarang, dan dapat menambahkan tenggat dalam format yang dibaca plugin Obsidian Anda. Semuanya berjalan di halaman ini: daftar tidak pernah diunggah, dan halaman tidak membuat permintaan jaringan.

2. Sintaks daftar periksa Markdown

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

Setiap tugas adalah item daftar: tanda hubung dan spasi, lalu [ ] dengan spasi di antara tanda kurung siku, lalu teksnya. Obsidian Help halaman dan GitHub Docs halaman keduanya menjelaskannya sebagai tanda hubung dan spasi diikuti [ ]. Untuk menandai tugas selesai, GitHub Docs menyarankan menggunakan [x].

Spasi itu penting. spesifikasi GitHub Flavored Markdown mendefinisikan penanda kotak centang sebagai tanda kurung siku kiri, karakter spasi putih, atau huruf x, dan tanda kurung siku penutup, serta memerlukan spasi putih sebelum teks setelahnya. Jadi [] tanpa isi, atau - [ ]text tanpa spasi setelah tanda kurung, tidak sesuai definisi. Tanda hubung dan spasinya yang membuat baris menjadi item daftar.

Daftar tugas bukan bagian dari Markdown inti. Spesifikasi yang sama menandainya sebagai ekstensi CommonMark, dan pendahuluannya menyebut fitur yang tidak ada di spesifikasi CommonMark asli ditandai sebagai ekstensi. Renderer yang tidak mengimplementasikan ekstensi itu menampilkan tanda kurung sebagai teks biasa, yang biasanya menjadi alasan kotak centang tampil sebagai [ ] di halaman.

3. Daftar periksa di Obsidian

Panduan Obsidian tentang sintaks pemformatan dasar membahas daftar tugas:

  • Sebuah tugas diawali tanda hubung dan spasi, diikuti [ ].
  • Anda bisa memakai karakter apa pun di dalam tanda kurung siku untuk menandai tugas selesai, jadi [x], [-] dan [?] semuanya dihitung.
  • Anda membuat daftar tugas bersarang dengan mengindentasi item daftar. Gunakan Tab atau Shift+Tab untuk mengindentasi atau membatalkan indentasi item terpilih.
  • Anda bisa mencentang tugas di tampilan Baca dengan memilih kotak centangnya.

Halaman Help mendokumentasikan bahwa karakter apa pun menyelesaikan tugas. Halaman itu tidak menjelaskan tampilan berbeda untuk tiap karakter. Jika [-] atau [?] tampak berbeda dari [x] di vault Anda, itu berasal dari tema atau snippet CSS yang Anda pasang, bukan dari Markdown itu sendiri.

Baris kemajuan di pembuat daftar menghitung dengan cara yang sama: karakter apa pun di dalam tanda kurung selain spasi berarti selesai, jadi [x], [X], [-] dan [?] selesai dan [ ] belum selesai. Baris yang diawali “done:” atau “x ” adalah teks biasa; alat ini tidak menebak bahwa itu berarti tugas selesai.

4. Tenggat: Tasks vs Dataview vs Reminder

Sintaks daftar tugas Obsidian tidak punya tanggal jatuh tempo sendiri: halaman Help tidak mendokumentasikannya. Tiga plugin membaca tanggal yang ditulis di teks tugas, masing-masing dengan formatnya sendiri. Pembuat daftar menulis tanggal sebagai ISO YYYY-MM-DD di semuanya. Tanpa plugin, tanggal hanyalah teks.

FormatDibaca olehContoh baris
Tenggat: 📅 YYYY-MM-DDTasks, yang menyebut tanggal harus ditulis dalam YYYY-MM-DD dengan format ini- [ ] send invoice 📅 2026-11-25
Dijadwalkan: ⏳ YYYY-MM-DDTasks- [ ] send invoice ⏳ 2026-11-25
Mulai: 🛫 YYYY-MM-DDTasks- [ ] send invoice 🛫 2026-11-25
Field sebaris: [due:: YYYY-MM-DD]Dataview dokumentasi, yang membaca field yang ditulis pada tugas, seperti [completion:: 2021-08-15]- [ ] send invoice [due:: 2026-11-25]
Pengingat: (@YYYY-MM-DD) atau (@YYYY-MM-DD HH:mm)plugin obsidian-reminder, yang README-nya menunjukkan (@2021-08-14) dan (@2021-08-14 09:37) pada tugas yang belum dicentang- [ ] send invoice (@2026-11-25 09:30)

Pilih satu plugin yang Anda pakai. Halaman Dataview juga mencantumkan pintasan emoji sendiri untuk tanggal dan menyebut hanya itu yang didukung; pembuat daftar menulis bentuk tanda kurung siku milik Dataview. README Reminder menyebut Anda tidak diberi notifikasi untuk pengingat pada tugas yang sudah dicentang.

5. Perbedaan GitHub dan Obsidian

GitHub Docs menjelaskan [ ] untuk tugas yang belum selesai dan [x] untuk menandai tugas selesai. Spesifikasi GFM mendefinisikan penanda sebagai spasi putih atau huruf x di antara tanda kurung siku. Obsidian menerima karakter apa pun. Jadi tugas seperti - [-] skipped atau - [?] unsure selesai di Obsidian, tetapi di luar definisi penanda dalam spesifikasi, dan renderer yang mengikuti spesifikasi bisa menampilkannya sebagai teks biasa. Jika file juga dibaca di GitHub, gunakan [ ] dan [x] saja.

GitHub Docs menambahkan satu aturan: jika deskripsi tugas diawali tanda kurung, beri garis miring terbalik di depannya, seperti pada - [ ] \(Optional) Open a followup issue. Pembuat daftar tidak menambahkan garis miring terbalik untuk Anda; ia memberi peringatan saat tugas diawali tanda kurung.

6. Tangkap tugas dengan suara atau teks di iPhone dan Mac dengan Vox.md

Mode pemrosesan Todo Checklist milik Vox.md menghasilkan Markdown - [ ] item tugas dari sebuah capture, dan cadangannya adalah pemformat daftar periksa deterministik. Suara ditranskripsi di perangkat Anda. Di Capture Bar, Checklistnya menerapkan - [ ] awalan, dan Dua Tanggal yang menyisipkan (@yyyy-MM-dd) atau bentuk dengan waktu. Lihat Cepat menangkap dan Route dan mode pemrosesan dokumentasi.

Sebuah Route dapat menambahkan item ke catatan harian Anda di bawah judul seperti ## Tasks; Tambahkan ke catatan harian Obsidian menjelaskan pengaturannya, dan generator templat catatan harian menulis struktur catatan. Untuk item tindakan dari rapat, lihat templat catatan rapat; untuk resep awalan daftar tugas, lihat templat capture.

Vox.md menulis (@yyyy-MM-dd) bentuk yang ditunjukkan di dokumentasinya. Ia tidak menulis tanggal emoji plugin Tasks atau field Dataview. Jika Anda memakai salah satunya, tempel tugas hasil capture ke pembuat daftar di atas dan pilih format itu, atau ubah tanggalnya kemudian. Untuk membuat properti di bagian atas catatan, gunakan generator properti.

7. Pertanyaan

Mengapa kotak centang saya tampil sebagai teks [ ]?

Renderer tidak menggambar daftar tugas. Daftar tugas adalah ekstensi CommonMark, jadi renderer tanpa ekstensi itu menampilkan tanda kurung. Pastikan baris diawali tanda hubung dan spasi, ada spasi atau x di antara tanda kurung siku, dan bahwa ada spasi setelah tanda kurung penutup. Di Obsidian, tugas di dalam blok kode atau sel tabel mungkin tidak digambar sebagai kotak centang seperti item daftar.

Bagaimana membuat tugas bersarang?

Indentasikan tugas anak. Di Obsidian, tekan Tab untuk mengindentasi item terpilih dan Shift+Tab untuk membatalkan indentasi. Pembuat daftar mengubah 2 atau 4 spasi dalam daftar Anda menjadi satu tab per tingkat, atau menjadi 2 atau 4 spasi jika Anda mau.

Bagaimana mencentang kotak dengan karakter selain x?

Obsidian Help menyebut karakter apa pun di dalam tanda kurung siku menandai tugas selesai, jadi - [-] task dan - [?] task selesai. Pembuat daftar mempertahankan karakter yang Anda tempel kecuali Anda mengatur ulang daftar. Untuk file yang juga dibaca di GitHub, gunakan [x].

Bagaimana menambahkan tenggat yang dibaca plugin Tasks?

Tulis 📅 dan YYYY-MM-DD tanggal di akhir tugas, misalnya - [ ] send invoice 📅 2026-11-25. Pilih “Plugin Tasks: tenggat” di atas untuk menambahkannya ke setiap tugas. Gunakan ⏳ untuk tanggal terjadwal dan 🛫 untuk tanggal mulai.

Apakah pembuat daftar mengunggah daftar saya?

Tidak. Daftar dikonversi oleh skrip di halaman ini, di perangkat Anda, dan halaman tidak membuat permintaan jaringan. Daftar Anda tidak disimpan: menutup atau memuat ulang halaman menghapusnya.
