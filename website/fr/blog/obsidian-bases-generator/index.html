Générateur Obsidian Bases : filtres, vues et formules

Générez le YAML d’une base Obsidian sans apprendre d’abord le schéma : choisissez des filtres, ajoutez des vues, copiez un fichier .base ou un bloc de code, et découvrez le rôle de chaque clé avec des liens vers la documentation d’Obsidian.

Par
Cody Bontecou
Mis à jour
28 novembre 2026
Nécessite
N’importe quel navigateur moderne, y compris Safari sur iPhone. Facultatif : Obsidian avec le plugin principal Bases, et Vox.md pour iPhone ou Mac afin de capturer des notes par la voix ou le texte.
La réponse courte

Une base est une vue de vos notes de type base de données, écrite en YAML avec jusqu’à cinq clés de premier niveau : filters, formulas, properties, summaries et views. Enregistrez le YAML dans un .base fichier, ou collez-le dans une note à l’intérieur d’un base bloc de code. Le générateur ci-dessous l’écrit pour vous. La version d’Obsidian requise dépend du type de vue : la page des vues indique Table et Cards depuis la 1.9, List et Map depuis la 1.10, et Kanban depuis la 1.14.

filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

Le générateur fonctionne entièrement dans cette page. Rien de ce que vous saisissez n’est envoyé, et la page n’effectue aucune requête réseau.

    2. La syntaxe de Bases en bref

    Voici les clés page de syntaxe d’Obsidian documente. Il n’y a pas d’autre schéma à apprendre.

    CléCe qu’il faitExemple
    filtersRestreint les notes pour toutes les vues.file.hasTag("project")
    formulasDéfinit des propriétés calculées, utilisées comme formula.name.total: 'price * qty'
    propertiesRéglages par propriété. displayName définit l’en-tête de colonne.displayName: "Status"
    summariesDéfinit vos propres formules de résumé, avec values.Personnalisé, facultatif
    viewsUne liste de vues sur les mêmes notes.- type: table
    type (vue)La disposition de la vue.table, cards, list
    name (vue)Le nom de la vue.name: "Projects"
    filters (vue)Filtres pour cette vue uniquement.file.inFolder("Work")
    groupBy (vue)Regroupe les lignes par une property dans un direction.direction: DESC
    order (vue)Les propriétés affichées, dans l’ordre.- file.name
    limit (vue)Limite le nombre de lignes.limit: 10
    summaries (vue)Associe une propriété à un résumé.price: Sum

    Le générateur n’écrit pas toutes les clés documentées. La page de syntaxe décrit aussi groupOrder, et les vues peuvent contenir un état supplémentaire, comme la colonne de tri, qu’Obsidian gère lui-même. Ajoutez-les à la main si besoin : le YAML est à vous.

    3. Filtres : and, or, not

    Un filtre est une instruction textuelle vraie ou fausse pour chaque note, ou un objet avec and, or ou not contenant une liste d’autres filtres. Les filtres globaux filters s’appliquent à chaque vue. Les filters s’appliquent à cette vue uniquement, et les deux sont combinés avec AND.

    filters:
  or:
    - file.hasTag("meeting")
    - file.inFolder("Meetings")

    Il n’y a pas de from ou source clé comme dans SQL ou Dataview. Sans filtre, une base inclut tous les fichiers du vault ; définissez-en donc toujours un, sauf si c’est ce que vous voulez.

    Les valeurs textuelles doivent être entre guillemets dans l’instruction, le YAML nécessite donc des guillemets imbriqués : 'status == "done"'. Le générateur s’en charge pour vous. Les filtres de fonction tels que file.hasTag(), file.inFolder() et file.hasLink() se trouvent sur la page des fonctions.

    4. Formules et résumés

    Chaque entrée sous formulas devient une propriété utilisable dans chaque vue sous la forme formula.name. Une formule peut en utiliser une autre, mais les références circulaires sont interdites : une formule ne peut donc pas se référencer elle-même. Le résultat est stocké sous forme de chaîne YAML, d’où les guillemets autour de l’expression.

    formulas:
  formatted_price: 'if(price, price.toFixed(2) + " dollars")'

    Le summaries associe une propriété à un résumé. La page de syntaxe liste ces valeurs par défaut :

    • Nombre : Average, Min, Max, Sum, Range, Median, Stddev
    • Date : Earliest, Latest, Range
    • Booléen : Checked, Unchecked
    • Any : Empty, Filled, Unique

    Pour le calcul de dates, la page de syntaxe indique file.mtime > now() - "1 week" est vrai pour un fichier modifié durant la dernière semaine.

    5. Ce que cela signifie

    Dans un filtre ou une formule, this est le fichier dans lequel la base s’affiche. La page de syntaxe précise qu’il s’agit du fichier de la base elle-même lorsque la base s’ouvre dans la zone de contenu principale, du fichier d’intégration lorsque la base est intégrée dans une note ou un Canvas, et du fichier actif de la zone de contenu principale lorsque la base est dans la barre latérale. La page donne file.hasLink(this.file) pour reproduire le volet des rétroliens.

    6. Exemples à copier

    Voici les préréglages du générateur sous forme de code brut, ils fonctionnent donc sans JavaScript. Remplacez les noms de dossier, de tag et de propriété par les vôtres. Enregistrez le texte dans un .base fichier, ou placez-le dans un base bloc de code. Voir Créer une base pour les commandes, et intégrez un fichier enregistré avec ![[Name.base]] ou ![[Name.base#View]] pour choisir la vue par défaut.

    Liste de lecture

    filters:
  and:
    - file.inFolder("Reading")
    - 'status == "to read"'
properties:
  status:
    displayName: "Status"
views:
  - type: cards
    name: "Reading list"
    order:
      - file.name
      - status

    Projets par statut

    filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

    Notes avec un tag, modifiées cette semaine

    filters:
  and:
    - file.hasTag("project")
    - 'file.mtime > now() - "1 week"'
views:
  - type: table
    name: "Modified this week"
    order:
      - file.name
      - file.mtime

    Rétroliens de cette note

    filters:
  and:
    - file.hasLink(this.file)
views:
  - type: table
    name: "Backlinks"
    order:
      - file.name
      - file.folder

    Notes vocales capturées avec Vox.md

    filters:
  and:
    - file.inFolder("Vox")
    - file.hasTag("voice")
views:
  - type: table
    name: "Voice notes"
    order:
      - file.ctime
      - file.name
      - file.tags

    Le order list choisit les colonnes. L’ordre de tri est un réglage de vue que vous modifiez dans la barre d’outils de vue d’Obsidian, les exemples n’en écrivent donc pas.

    7. Faire apparaître vos captures dans une base

    Vox.md enregistre ce que vous capturez sous forme de notes Markdown dans un dossier de votre vault. Son Documentation des métadonnées indique qu’une Route peut ajouter des métadonnées statiques sous la forme key: value lignes, comme tags: [journal, idea], et que Métadonnées d’en-tête de note l’écrit à l’échelle du document. Il décrit aussi des métadonnées d’emplacement facultatives. Une base filtrée sur ce dossier ou ce tag, comme le dernier exemple ci-dessus, liste alors vos captures dans un seul tableau. Construisez les métadonnées avec le générateur de propriétés, et consultez notes vocales vers Obsidian sur iPhone pour la configuration.

    Outils associés : le générateur de modèle de note quotidienne pour créer des notes datées, le générateur de callouts et le Créateur de tableaux Markdown pour le contenu des notes.

    Des notes qui valent la peine d’être interrogées ?

    Vox.md capture la voix et le texte sur iPhone et Mac directement dans votre vault en Markdown, avec les propriétés de votre choix. L’enregistrement, la transcription et la Capture nécessitent Vox.md Unlimited ; les comptes éligibles bénéficient d’un essai gratuit de 7 jours.

    8. Dépannage

    • La base affiche toutes les notes. Aucun filtre source n’est défini. Une base inclut tout le vault par défaut, ajoutez donc un file.inFolder() ou file.hasTag() filtre.
    • Une colonne de propriété est vide. Le nom ne correspond pas, majuscules et minuscules comprises, ou la note n’a pas cette propriété dans son frontmatter. Vérifiez les Propriétés de la note et le nom de la colonne.
    • Erreur YAML. Vérifiez l’indentation, qui utilise des espaces, et les guillemets. Un filtre contenant du texte nécessite des guillemets imbriqués : 'status == "done"'.
    • Une vue map est vide. D’après la page des vues, la disposition map nécessite le plugin Maps.

    9. Questions fréquentes

    Bases est-il un plugin principal ?

    Oui. Aide d’Obsidian indique : « Bases est un plugin principal qui permet de créer des vues de vos notes semblables à une base de données. »

    Bases ou Dataview ?

    Ils sont distincts. Dataview est un plugin communautaire avec son propre langage de requête. Une base est du YAML qu’Obsidian lit lui-même, sans from clé : vous restreignez les notes avec des filtres. Cette page ne compare pas davantage leurs fonctionnalités.

    Puis-je modifier le YAML à la main ?

    Oui. Un .base est un texte YAML, et la page de syntaxe documente les clés. Ouvrez le fichier généré dans n’importe quel éditeur, ou collez le bloc de code dans une note et modifiez-le là.

    Le générateur envoie-t-il mes données ?

    Non. Un script de cette page construit le YAML sur votre appareil, et la page n’effectue aucune requête réseau. Recharger la page efface tout.
