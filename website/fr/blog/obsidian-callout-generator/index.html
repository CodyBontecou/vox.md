Générateur de callouts Obsidian : tous les types, alias et options de repli

Choisissez un type, ajoutez un titre et un corps, choisissez le repli et l’imbrication, puis copiez un callout > [!type] valide, avec la liste complète des types et alias et le fonctionnement des callouts repliables.

Par
Cody Bontecou
Mis à jour
27 novembre 2026
Nécessite
Tout navigateur moderne, y compris Safari sur iPhone. Facultatif : Obsidian pour les callouts, et Vox.md pour iPhone ou Mac pour capturer des notes à la voix ou au clavier.
La réponse courte

Un callout est une citation dont la première ligne est > [!type] Optional title. Chaque ligne suivante commence par > . Ajoutez + ou - juste après les crochets pour le rendre repliable. Pour en créer un sans saisir les préfixes, utilisez le générateur de callouts ci-dessous.

> [!warning]- Back up first
> Copy the vault before you change the plugin settings.
>
> Then restart Obsidian.

Le générateur ajoute le > préfixe à chaque ligne (répété pour l’imbrication), conserve les lignes vides dans le callout et ne double pas un > que vous avez collé. Il s’exécute entièrement dans cette page : votre texte n’est jamais envoyé, et la page n’effectue aucune requête réseau.

2. Syntaxe des callouts

> [!type] Title
> Body line one.
> Body line two.
  • Type : La première ligne d’une citation commence par le type entre crochets après un point d’exclamation : > [!info]. Aide d’Obsidian indique que l’identifiant du type n’est pas sensible à la casse, et qu’un type non pris en charge revient à note.
  • Titre. Le texte après les crochets remplace le titre. Sans lui, Obsidian affiche l’identifiant du type en casse de titre, donc > [!tip] affiche « Tip ».
  • Corps. Chaque ligne suivante commence par > . Le corps peut contenir du Markdown, des wikilinks et des intégrations.
  • Titre seul. Vous pouvez omettre le corps : > [!tip] Remember to save est un callout complet.

3. Tous les types de callout et leurs alias

L’aide d’Obsidian répertorie ces types intégrés. Chaque alias est indiqué avec le type auquel il appartient, par exemple tldr avec abstract.

FormatAliasUsage typique
noteaucunUne remarque générale. C’est aussi le style auquel revient un type inconnu.
abstractsummary, tldrUn résumé en haut d’une note.
infoaucunInformations de contexte.
todoaucunQuelque chose reste à faire.
tiphint, importantUn conseil ou un point clé.
successcheck, doneUne étape terminée ou un bon résultat.
questionhelp, faqUne question ouverte ou fréquemment posée.
warningcaution, attentionQuelque chose qui demande de la prudence.
failurefail, missingCe qui a mal tourné ou ce qui manque.
dangererrorUn risque sérieux ou un message d’erreur.
bugaucunUn bogue connu.
exampleaucunUn exemple concret.
quoteciteUne citation avec sa source.

Les types et alias proviennent de l’aide d’Obsidian. La colonne « Usage typique » est une suggestion, pas une définition d’Obsidian. Chaque type a sa propre couleur et son icône dans l’apparence par défaut ; les thèmes peuvent modifier les deux.

4. Callouts repliables : + ou -

Ajoutez un plus ou un moins juste après le crochet fermant :

> [!faq]+ Open by default
> This callout is foldable and starts expanded.

> [!faq]- Closed by default
> This callout is foldable and starts collapsed.

L’aide d’Obsidian décrit + comme repliable et déplié par défaut, et - comme repliable et replié par défaut. Sans l’un ni l’autre, le callout n’est pas repliable. Le + ou - fait partie du Markdown, donc il reste dans le fichier.

5. Callouts imbriqués, listes, code et intégrations

Pour un callout imbriqué, ajoutez un autre > pour chaque niveau :

> [!question] Can callouts be nested?
> > [!example] Yes
> > Add one more > for each level.

Le réglage « Imbriquer dans un autre callout » du générateur écrit le > sur chaque ligne, jusqu’à trois niveaux. Collez le résultat dans le corps du callout extérieur.

Les listes, le code et le reste du Markdown vont dans le corps, avec le > préfixe sur chaque ligne. L’aide d’Obsidian indique que le corps peut contenir du Markdown, des wikilinks et des intégrations, et que vous pouvez envelopper du contenu existant, y compris des listes et des blocs de code, en le sélectionnant et en exécutant la Insérer le callout commande. Collez une liste ou un bloc de code dans le champ de corps du générateur et il ajoute les préfixes à votre place :

> [!info] Checklist
> - [ ] first
> - [ ] second
>
> ```
> code line
> ```

6. Types de callout personnalisés avec un extrait CSS

Un type que vous inventez s’affiche avec le style note. L’aide d’Obsidian indique que les callouts personnalisés se définissent dans un extrait CSS ou un plugin communautaire. Son exemple :

.callout[data-callout="custom-question-type"] {
  --callout-color: #000000;
  --callout-icon: lucide-alert-circle;
}

Selon la page d’aide, --callout-color accepte n’importe quelle couleur CSS valide, et --callout-icon prend un ID d’icône de lucide.dev ou un élément SVG. Écrivez ensuite > [!custom-question-type] dans une note. Saisissez le même nom dans le champ de type personnalisé du générateur.

7. Alertes GitHub et callouts Obsidian

GitHub a une fonction similaire appelée alertes. Documentation GitHub en répertorie cinq : NOTE, TIP, IMPORTANT, WARNING et CAUTION.

> [!NOTE]
> Useful information that users should know, even when skimming content.

Cette page ne documente ni repli, ni titre personnalisé, ni types personnalisés ; les callouts Obsidian offrent les trois. La première ligne est identique, donc un > [!note] ou > [!warning] fonctionne souvent dans les deux, mais un type propre à Obsidian comme [!bug], un +/- repli ou un titre sort de ce que GitHub documente. Si un fichier est lu sur les deux, restez sur les cinq types GitHub sans extras.

9. Questions fréquentes

Pourquoi mon callout ne s’affiche-t-il pas ?

Vérifiez trois points. La première ligne doit commencer par > puis [!type], avec le point d’exclamation et sans espace dans les crochets. Chaque ligne du corps a besoin de son propre >. Une ligne vide sans > met fin à la citation, donc les lignes suivantes sont du texte ordinaire ; écrivez-le ainsi : >. S’il s’affiche toujours comme une simple citation, vérifiez qu’il n’y a ni espace ni faute de frappe entre > et [!.

Un callout peut-il ne pas avoir de titre ?

Pas tout à fait : sans titre, Obsidian affiche à la place l’identifiant du type en casse de titre. Pour masquer le titre, il faut du CSS ; l’aide d’Obsidian indique qu’une mise en forme supplémentaire, comme masquer le titre, peut utiliser des sélecteurs CSS standard. Le générateur laisse le titre vide si vous le faites, vous obtenez donc le titre par défaut.

Plugin Admonition ou callouts natifs ?

Les callouts natifs n’ont besoin d’aucun plugin et utilisent la > [!type] syntaxe de cette page. Le plugin Admonition est un plugin communautaire distinct, avec sa propre syntaxe, que cette page ne couvre pas. L’aide d’Obsidian indique que des types de callout personnalisés peuvent aussi provenir d’un plugin communautaire.

Les callouts fonctionnent-ils sur Obsidian mobile et dans Publish ?

L’aide d’Obsidian indique que les callouts sont pris en charge nativement dans Obsidian Publish. Sa page sur les callouts ne mentionne pas le mobile, dans un sens ou dans l’autre, donc cette page ne prétend rien à ce sujet.

Le générateur envoie-t-il mon texte ?

Non. Un script de cette page construit le callout sur votre appareil, et la page n’effectue aucune requête réseau. Rien n’est enregistré : recharger la page efface tout.
