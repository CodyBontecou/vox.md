Créateur de tableaux Markdown pour Obsidian : collez depuis Excel, Sheets ou CSV

Collez des lignes depuis Excel, Google Sheets, Numbers, CSV ou TSV et copiez un tableau à barres verticales valide, avec la barre échappée dans [[Note|Alias]] et ![[image.png|300]], les sauts de ligne gérés et l’alignement par colonne.

Par
Cody Bontecou
Mis à jour
26 novembre 2026
Nécessite
Tout navigateur moderne, y compris Safari sur iPhone. Facultatif : Obsidian pour les tableaux, et Vox.md pour iPhone ou Mac pour capturer le texte dans une note.
La réponse courte

Un tableau Markdown se compose d’une ligne d’en-tête, d’une ligne de délimitation de traits d’union, puis d’une ligne par rangée, avec des cellules séparées par |. Collez vos cellules dans le créateur de tableaux ci-dessous pour en obtenir un, ou partez de cet exemple.

| Name | Owner | Status |
| --- | --- | --- |
| Draft | Ana | Done |
| Review | Lee | Open |

Le créateur corrige aussi ce que les générateurs génériques ignorent dans Obsidian : il échappe la barre verticale dans [[Note|Alias]] et ![[image.png|300]] s’écrit \|, et transforme un saut de ligne dans une cellule en <br> ou une espace. Il s’exécute entièrement dans cette page : vos données ne sont jamais envoyées, et la page n’effectue aucune requête réseau.

    2. Syntaxe des tableaux Markdown

    | Name   | Qty | Price |
| :----- | :-: | ----: |
| Apple  |   3 |  1.20 |
| Pear   |  12 |  0.80 |

    Le spécification GitHub Flavored Markdown définit un tableau comme une ligne d’en-tête, une ligne de délimitation qui sépare l’en-tête des données, et zéro ligne de données ou plus. Les cellules sont séparées par des barres verticales.

    • Ligne de délimitation. Ses cellules ne contiennent que des traits d’union, avec un deux-points facultatif à gauche, à droite ou aux deux extrémités pour définir un alignement à gauche, à droite ou centré. Aide d’Obsidian indique qu’on ajoute des deux-points à la ligne d’en-tête pour aligner le texte, et que la ligne d’en-tête doit contenir au moins deux traits d’union.
    • Barres verticales extérieures. Les barres verticales de chaque côté sont facultatives dans la spécification. Obsidian Help recommande de les inclure pour la lisibilité, et le créateur les écrit toujours.
    • Remplissage. Les cellules n’ont pas besoin d’un alignement parfait, selon Obsidian Help. La disposition « Pad columns » du créateur aligne la source uniquement pour faciliter la lecture ; « Compact » ne le fait pas.
    • Nombres identiques. La spécification exige que la ligne d’en-tête ait le même nombre de cellules que la ligne de délimitation. Sinon, les lignes ne forment pas un tableau et s’affichent comme un paragraphe. Une ligne de données avec moins de cellules reçoit des cellules vides, et les cellules en trop sont ignorées.
    • Dans une cellule. La spécification autorise la mise en forme en ligne mais pas le contenu de niveau bloc : une liste ou un titre ne peut donc pas se trouver dans une cellule. Obsidian Help indique que vous pouvez utiliser sa syntaxe de mise en forme de base pour styliser le contenu d’un tableau.
    • La fin d’un tableau. La spécification indique que le tableau est interrompu à la première ligne vide, ou au début d’une autre structure de niveau bloc.

    Le créateur écrit au moins trois traits d’union dans chaque cellule de délimitation. Cela satisfait le minimum de deux d’Obsidian et les trois que Documentation GitHub le demande.

    3. Les tableaux dans Obsidian

    • La commande Insert Table. Obsidian Help indique que vous pouvez insérer un tableau avec la commande Insert Table depuis la Command Palette. Pour en construire un à partir de données que vous avez déjà, collez-les dans le créateur ci-dessus.
    • Alias et tailles d’image. Un alias de wikilink comme [[Note|Alias]] et une taille d’image comme ![[image.png|300]] contiennent tous deux une barre verticale. Obsidian Help indique qu’à l’intérieur d’un tableau, vous devez ajouter un \ avant la barre, donc écrivez [[Note\|Alias]] et ![[image.png\|300]]. Le créateur le fait pour vous ; un échappement que vous avez déjà écrit n’est pas doublé.
    • Toute autre barre verticale. La spécification GFM indique qu’une barre verticale dans une cellule doit être échappée par une barre oblique inverse, même dans un extrait de code. Le créateur échappe chaque barre non échappée sous la forme \|.
    • Sauts de ligne. Une ligne s’écrit sur une seule ligne ; un saut de ligne dans une cellule doit donc devenir autre chose. Le créateur écrit un HTML <br> , ou joint les lignes avec une espace si vous le choisissez. Ni la section Tables d’Obsidian Help ni GitHub Docs ne décrivent les sauts de ligne dans les cellules ; vérifiez donc que <br> s’affiche dans votre propre coffre, et choisissez l’option espace si vous ne voulez pas de balises dans la source.
    • Extensions. Il existe des plugins communautaires qui aident à modifier les tableaux. Cette page n’en évalue ni n’en recommande aucun.

    Pour les listes de tâches, consultez le Générateur de checklist Markdown ; pour les propriétés en haut d’une note, le générateur de propriétés. Un tableau convient bien pour une liste de décisions et de responsables dans une note issue du modèle de notes de réunion.

    4. Depuis Excel, Google Sheets ou CSV

    Sélectionnez les cellules dans votre tableur, copiez-les et collez-les dans la zone ci-dessus. Si les cellules sont collées avec des tabulations entre elles, le créateur le détecte. Il détecte aussi les virgules, les points-virgules et les barres verticales, et il lit les champs CSV entre guillemets, donc "Lee, Sam" reste une seule cellule et "" entre guillemets devient un guillemet. Utilisez le menu Separator si la détection est erronée. Cochez ou décochez « La première ligne est l’en-tête » pour décider si la première ligne devient la ligne d’en-tête ; sans cela, une ligne d’en-tête vide est ajoutée, car un tableau Markdown en a besoin.

    • Cellules fusionnées. La spécification et les deux pages d’aide décrivent une ligne comme une liste de cellules séparées par des barres verticales, et aucune ne décrit de moyen de fusionner des cellules. Placez la valeur dans chaque cellule couverte par la fusion avant de copier.
    • Formules. Le créateur ne lit que le texte que vous collez. Si les cellules collées affichent des formules au lieu de leurs résultats, copiez les valeurs dans votre application de tableur et collez à nouveau.
    • Lignes inégales. Si une ligne a un nombre de cellules différent de l’en-tête, le créateur affiche un avertissement avec le numéro de cette ligne et complète le tableau avec des cellules vides. Une ligne avec plus de cellules que l’en-tête élargit le tableau au lieu de supprimer des données.
    • Inverser et réparer. Collez un tableau Markdown existant pour le réaligner, ou réglez Output as sur CSV ou TSV pour l’exporter. Le créateur avertit, avec un numéro de ligne, lorsque la ligne de délimitation est absente, que son nombre de cellules ne correspond pas à l’en-tête, ou qu’une ligne vide mettrait fin au tableau.

    Les deux-points d’alignement d’un tableau Markdown collé sont conservés, et vous pouvez modifier chaque colonne avec les menus Column alignment.

    5. Différences entre GitHub et Obsidian

    Obsidian Help et GitHub Docs décrivent tous deux les tableaux à barres verticales avec une ligne d’en-tête, des traits d’union et des deux-points d’alignement facultatifs. Les différences indiquées par les pages sont minimes :

    SujetAide d’ObsidianGitHub Docs et spécification GFM
    Traits d’unionLa ligne d’en-tête doit contenir au moins deux traits d’unionGitHub Docs : au moins trois traits d’union dans chaque colonne d’en-tête
    Ligne vide avant le tableauLa section Tables n’en mentionne aucunGitHub Docs : vous devez laisser une ligne vide avant votre tableau
    Barre verticale littérale dans une celluleAjoutez un \ avant la barre dans les alias et les tailles d’imageÉchappez-la en \|, même dans un extrait de code
    Barres verticales extérieuresFacultatif, recommandé pour la lisibilitéFacultatif

    Pour fonctionner aux deux endroits, écrivez trois traits d’union ou plus, laissez une ligne vide au-dessus du tableau et échappez chaque barre verticale. C’est ce que fait le créateur. Un alias de wikilink est une syntaxe d’Obsidian ; sur GitHub, ce n’est que du texte contenant une barre verticale. Le guide du créateur de listes de tâches traite des différences des listes de tâches de la même manière.

    Pour mettre en valeur un tableau ou une remarque à son sujet, enveloppez-le dans un callout : le Générateur de callouts Obsidian ajoute le > les préfixes à votre place.

    6. Placez tableaux et notes dans votre coffre avec Vox.md

    Vox.md ne construit pas de tableaux lui-même, et le créateur ci-dessus fonctionne sans l’app. Ce que fait Vox.md, c’est capturer du texte dans Obsidian : Quick Capture vous permet de coller du texte existant, et une Route le livre vers une destination Markdown. Consultez le Capture rapide et Parcours documentation.

    1. Créez votre tableau ci-dessus et appuyez sur Copy.
    2. Dans Vox.md sur iPhone, iPad ou Mac, ouvrez Quick Capture et collez le tableau dans l’éditeur de texte.
    3. Envoyez-le avec une Route qui conserve le texte d’origine. La documentation mentionne Conserver l’original comme mode de traitement qui conserve le texte capturé sans réécriture par IA, et indiquent que le texte capturé est livré tel quel lorsque Utiliser Apple Intelligence est désactivé, ce qui est son réglage par défaut. Le traitement du texte saisi est un réglage facultatif sur chaque Route.
    4. La destination de la Route décide où le texte arrive : une nouvelle note, une note continue comme votre note quotidienne, ou une note existante, en bas, en haut ou sous un titre choisi.

    Laissez une ligne vide au-dessus du tableau collé si la destination contient déjà du texte au-dessus. Pour une recette de Route, consultez modèles de capture, et pour transformer d’abord un fichier de sous-titres Zoom, Teams ou YouTube en note de transcription, consultez SRT et VTT vers Markdown.

    7. Questions fréquentes

    Pourquoi mon tableau ne s’affiche-t-il pas dans Obsidian ?

    Vérifiez trois choses. Il doit y avoir une ligne de délimitation de traits d’union juste sous l’en-tête, et les lignes d’en-tête et de délimitation doivent avoir le même nombre de cellules, sinon la spécification affiche les lignes comme un paragraphe. Obsidian Help indique que la ligne d’en-tête doit contenir au moins deux traits d’union. Et laissez une ligne vide avant le tableau, ce qu’exige GitHub Docs et qui ne coûte rien dans Obsidian. Collez le tableau dans le créateur : il avertit, avec un numéro de ligne, lorsque la ligne de délimitation est absente ou que les nombres diffèrent.

    Comment ajouter un saut de ligne dans une cellule ?

    Gardez la ligne sur une seule ligne et utilisez une balise HTML <br> dans la cellule, ce que le créateur écrit pour une cellule multiligne. Les pages citées ne décrivent pas les sauts de ligne dans les cellules ; testez donc dans votre coffre. L’autre choix est de joindre les lignes avec une espace.

    Comment mettre une barre verticale ou un alias de wikilink dans une cellule ?

    Placez une barre oblique inverse avant la barre verticale : [[Note\|Alias]], ![[image.png\|300]] ou a \| b. Obsidian Help l’exige pour les alias et le redimensionnement d’images dans les tableaux, et la spécification GFM l’exige pour toute barre verticale dans une cellule.

    Puis-je fusionner des cellules ?

    Aucune syntaxe n’apparaît pour cela dans la spécification ni dans Obsidian Help. Répétez plutôt la valeur dans chaque cellule.

    Quelle peut être la largeur d’un tableau ?

    Aucune des pages citées ne donne de nombre maximal de colonnes ou de lignes, et le créateur n’impose aucune limite. Un tableau très large est difficile à lire dans la source ; utilisez donc la disposition Compact, ou scindez-le en deux tableaux.

    Le créateur envoie-t-il mes données ?

    Non. Le tableau est construit par un script dans cette page, sur votre appareil, et la page n’effectue aucune requête réseau. Elle n’enregistre pas vos données : fermer ou recharger la page les efface. Le bouton Download enregistre un fichier de la page sur votre appareil.
