2. Ajouter le modèle à Obsidian

Plugin Core Templates. Activez Templates dans Paramètres → Plugins principaux, puis réglez Template folder location, par exemple Templates. Enregistrez-y le modèle sous forme de fichier .md . Dans une nouvelle note, exécutez Templates: Insert template depuis la palette de commandes et choisissez-le. Obsidian remplace {{title}}, {{date}} et {{time}} lorsque vous insérez le modèle. Un format après deux-points, comme {{date:YYYY-MM-DD}}, utilise les jetons Moment.js. Consultez l’aide du plugin Templates et le tableau des jetons de format Moment.js.

Plugin Templater. Installez Templater depuis les plugins de la communauté et réglez son paramètre Template folder location. Insérez le modèle avec Templater: Open insert template modal. Pour appliquer ce modèle à chaque nouvelle note de Meetings/ , activez Trigger Templater on new file creation, réglez Template matching mode sur les modèles de dossier et associez le dossier Meetings au fichier. La documentation des réglages de Templater explique les modèles de dossier, et le module de date documente tp.date.now.

Propriétés. Les métadonnées d’en-tête entre les lignes --- deviennent des propriétés de la note. Un lien dans une propriété doit être entre guillemets, c’est pourquoi le champ projet s’écrit "[[Project name]]". Consultez Propriétés dans l’aide d’Obsidian. Pour vérifier un frontmatter existant, utilisez le générateur et vérificateur de propriétés. Une fois les notes dotées de propriétés, vous pouvez les interroger avec une base : le Générateur Obsidian Bases construit les filtres et les vues.

3. Une note par réunion

Rangez les réunions dans un seul dossier, comme Meetings/, et mettez la date et l’heure de début dans le nom du fichier : Meetings/2026-11-19 1430 Design review.md. Les noms dans cet ordre se trient par date, et deux réunions du même jour ne partagent jamais un fichier.

Activez Lien vers la note quotidienne dans le générateur pour ajouter une ligne Daily note: qui renvoie à la note de ce jour. Le lien utilise YYYY-MM-DD ; si vos notes quotidiennes utilisent un autre format de date, modifiez-le pour qu’il corresponde ; le générateur de modèle de note quotidienne prévisualise le nom de fichier produit par un format. Pour lister aussi les réunions du jour dans la note quotidienne, faites-y un lien ; ajouter à une note quotidienne Obsidian montre comment Vox.md peut y ajouter des entrées.

4. Actions à mener et suivi

Écrivez chaque action à mener sous forme de tâche Obsidian, - [ ] Send the release notes, puis cochez-la sous la forme - [x] une fois terminée ; consultez Syntaxe de mise en forme de base. Placez le responsable en premier pour que chaque ligne indique qui fait quoi.

Si vos actions sont déjà une simple liste, le Générateur de checklist Markdown les transforme en tâches et ajoute une échéance au format Tasks, Dataview ou Reminder.

Pour un tableau de décisions et de responsables plutôt qu’une liste de tâches, collez les lignes d’un tableur dans le Créateur de tableaux Markdown et copiez le résultat dans la note.

Mettez en valeur un résumé ou un avertissement dans la note avec un callout : le Générateur de callouts Obsidian écrit la > [!type] syntaxe, avec repli facultatif.

Le style facultatif ajoute une date d’échéance au format d’un plugin de la communauté, le plugin Tasks: 📅 suivi de YYYY-MM-DD. Le générateur indique la date de la réunion ; remplacez-la par la vraie date d’échéance. Sans le plugin Tasks, l’emoji et la date restent du texte brut et la tâche fonctionne quand même.

Pour rassembler les points ouverts de toutes les réunions au même endroit, ajoutez une requête Tasks à une note :

```tasks
not done
path includes Meetings
```

La requête liste les tâches non terminées des notes dont le chemin contient Meetings. Dataview peut créer des listes similaires si vous l’utilisez déjà.

5. Remplir la note à partir d’un enregistrement

Un modèle vous donne les titres. Vox.md peut écrire la note lui-même : il enregistre la réunion, la transcrit sur votre appareil et enregistre un fichier Markdown dans votre coffre via un Parcours.

  1. Enregistrez. Sur Mac, Vox.md peut enregistrer une app d’appel et votre micro sur des pistes séparées ; suivez Transcrire localement les réunions sur Mac dans Obsidian. Pour une réunion en présentiel, enregistrez avec le micro de l’iPhone ou de l’iPad ; consultez enregistrer les notes vocales iPhone dans Obsidian.
  2. Choisissez la destination. Dans le Parcours, choisissez votre coffre, sélectionnez Nouvelle note, puis saisissez un chemin comme Meetings/{date}-{hour}{minute}.md. {date} s’écrit 2026-11-19 et {hour}{minute} s’écrit 1430. Ce sont des jetons Vox.md, pas des formats Moment.js. Consultez Modèles de capture Obsidian pour d’autres recettes de chemins.
  3. Choisissez le mode. Réglez le mode de traitement du Parcours sur Notes de réunion. Il produit une section ## Notes et, si la transcription contient des actions à mener, une liste de contrôle ## Action Items à cocher. Il utilise Apple Intelligence sur le matériel compatible avec macOS 26 ou iOS 26 ; sinon, un outil de mise en forme déterministe construit la structure.

Notes de réunion ne remplit pas l’ordre du jour, les participants ni les décisions à votre place. Si vous voulez ces titres au-dessus des notes, choisissez Markdown simple dans le générateur, décochez « Compte rendu » et « Actions à mener en tâches », puis enregistrez le résultat dans votre coffre. Sélectionnez ensuite ce fichier comme modèle de coffre du Parcours. Vox.md remplit ses jetons à accolades simples dans le modèle et écrit la transcription traitée en dessous. Vérifiez la première note avant de vous fier à la mise en page ; la documentation des Parcours couvre les destinations et les modèles.

Si la réunion avait lieu sur Zoom ou Teams et que vous avez téléchargé sa transcription en fichier .srt ou .vtt, convertissez-la en Markdown avec les tours de parole grâce au Convertisseur SRT et VTT, puis collez-le sous le ## Transcript titre de ce modèle.

Dites à toutes les personnes présentes que vous enregistrez et transcrivez la réunion, et obtenez d’abord leur consentement. Les règles varient selon le lieu et l’entreprise ; consultez comment prévenir les participants que vous enregistrez.

6. Questions fréquentes

Faut-il utiliser Core Templates ou Templater ?

Core Templates est fourni avec Obsidian et gère le titre, la date et l’heure. Templater est un plugin de la communauté qui ajoute des scripts, des décalages de date et des modèles de dossier, si bien qu’une nouvelle note dans Meetings/ peut recevoir le modèle automatiquement. Si vous n’avez besoin que des champs de cette page, Core Templates suffit.

Pourquoi {{date}} ne change-t-il pas ensuite ?

Obsidian remplace les variables de modèle une seule fois, lorsque vous insérez le modèle. La note contient ensuite du texte brut, par exemple 2026-11-19, et la conserve. C’est ce qu’il faut pour un compte rendu de réunion.

Vox.md peut-il utiliser mon modèle Obsidian ?

En partie. Un Parcours peut utiliser un fichier Markdown de votre coffre comme modèle. Vox.md remplit ses propres jetons à accolades simples, comme {date}, ainsi que les commandes de date Templater tp.date.now et tp.file.creation_date. Il n’exécute pas les autres commandes Templater, comme tp.file.title, et ne développe pas les variables du plugin principal Templates comme {{title}}. Laissez-les donc hors du modèle d’un Parcours. Utilisez la sortie Markdown simple pour un Parcours Vox.md.

Le générateur envoie-t-il mes choix quelque part ?

Non. Le modèle est construit par un script de cette page. Il enregistre vos derniers choix dans le stockage local de votre navigateur, pour les retrouver la prochaine fois, et Réinitialiser les efface.
