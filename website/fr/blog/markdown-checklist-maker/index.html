Générateur de checklist Markdown : transformez n’importe quelle liste en tâches, avec échéances

Collez des lignes simples, des puces, des éléments numérotés ou une liste de tâches existante et copiez des tâches - [ ] valides, avec l’imbrication conservée, une échéance facultative et le nombre de tâches terminées.

Nécessite
N’importe quel navigateur moderne, y compris Safari sur iPhone. Facultatif : Obsidian pour les checklists, et Vox.md pour iPhone ou Mac pour capturer des tâches à la voix.
La réponse courte

Une tâche Markdown est un trait d’union, une espace, des crochets, une espace et le texte. Écrivez - [ ] task pour une tâche ouverte et - [x] done pour une tâche terminée. Pour transformer toute une liste en tâches, collez-la dans le générateur de checklist ci-dessous.

- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

Le générateur retire les puces, numéros et cases existants pour que rien ne soit doublé, conserve l’indentation comme imbrication et peut ajouter une échéance au format lu par votre plugin Obsidian. Il s’exécute entièrement dans cette page : la liste n’est jamais envoyée, et la page n’effectue aucune requête réseau.

2. Syntaxe d’une checklist Markdown

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

Chaque tâche est un élément de liste : un trait d’union et une espace, puis [ ] avec une espace entre les crochets, puis le texte. page Obsidian Help et page GitHub Docs les décrivent tous deux comme un trait d’union et une espace suivis de [ ]. Pour marquer une tâche comme terminée, GitHub Docs indique d’utiliser [x].

Les espaces comptent. Le spécification GitHub Flavored Markdown définit le marqueur de case comme un crochet gauche, un espace blanc ou la lettre x, et un crochet droit, et elle exige un espace blanc avant le texte qui suit. Donc [] sans rien à l’intérieur, ou - [ ]text sans espace après le crochet, ne correspond pas à la définition. Le trait d’union et son espace sont ce qui fait de la ligne un élément de liste.

Les listes de tâches ne font pas partie du Markdown de base. La même spécification les présente comme une extension de CommonMark, et son introduction indique que les fonctionnalités absentes de la spécification CommonMark d’origine sont signalées comme extensions. Un moteur qui n’implémente pas l’extension affiche les crochets comme texte brut, ce qui explique en général qu’une case s’affiche comme [ ] sur la page.

3. Checklists dans Obsidian

La documentation Obsidian Help sur la mise en forme de base couvre les listes de tâches :

  • Une tâche commence par un trait d’union et une espace suivis de [ ].
  • Vous pouvez utiliser n’importe quel caractère entre les crochets pour marquer la tâche comme terminée, donc [x], [-] et [?] comptent toutes.
  • Pour imbriquer une liste de tâches, indentez les éléments de liste. Utilisez Tab ou Shift+Tab pour indenter ou désindenter les éléments sélectionnés.
  • Vous pouvez cocher ou décocher une tâche en mode Lecture en sélectionnant sa case.

La page d’aide indique que n’importe quel caractère termine une tâche. Elle ne décrit pas d’apparence différente pour chaque caractère. Si [-] ou [?] est différent de [x] dans votre vault, cela vient d’un thème ou d’un extrait CSS que vous avez installé, pas du Markdown lui-même.

La ligne de progression du générateur compte de la même façon : tout caractère entre les crochets autre qu’une espace signifie terminé, donc [x], [X], [-] et [?] sont terminées et [ ] est ouverte. Les lignes qui commencent par « done: » ou « x » sont du texte ordinaire ; l’outil ne devine pas qu’elles désignent une tâche terminée.

4. Échéances : Tasks, Dataview ou Reminder

La syntaxe des listes de tâches d’Obsidian n’a pas de date d’échéance propre : la page d’aide n’en documente aucune. Trois plugins lisent une date écrite dans le texte de la tâche, chacun dans son propre format. Le générateur écrit la date au format ISO YYYY-MM-DD dans tous. Sans le plugin, la date n’est que du texte.

FormatLu parLigne d’exemple
Échéance : 📅 YYYY-MM-DDplugin Tasks, qui indique que la date doit s’écrire YYYY-MM-DD en respectant ce format- [ ] send invoice 📅 2026-11-25
Planifiée : ⏳ YYYY-MM-DDplugin Tasks- [ ] send invoice ⏳ 2026-11-25
Début : 🛫 YYYY-MM-DDplugin Tasks- [ ] send invoice 🛫 2026-11-25
Champ en ligne : [due:: YYYY-MM-DD]documentation de Dataview, qui lit les champs écrits sur une tâche, comme [completion:: 2021-08-15]- [ ] send invoice [due:: 2026-11-25]
Reminder : (@YYYY-MM-DD) ou (@YYYY-MM-DD HH:mm)obsidian-reminder extension, dont le README montre (@2021-08-14) et (@2021-08-14 09:37) sur les tâches non cochées- [ ] send invoice (@2026-11-25 09:30)

Choisissez le seul plugin que vous utilisez. La page de Dataview liste aussi ses propres raccourcis emoji pour les dates et indique que ce sont les seuls raccourcis pris en charge ; le générateur écrit plutôt la forme à crochets de Dataview. Le README de Reminder indique que vous n’êtes pas notifié des rappels sur des tâches déjà cochées.

5. Différences entre GitHub et Obsidian

GitHub Docs décrit [ ] pour une tâche ouverte et [x] pour en marquer une comme terminée. La spécification GFM définit le marqueur comme un espace blanc ou la lettre x entre les crochets. Obsidian accepte n’importe quel caractère. Ainsi, une tâche telle que - [-] skipped ou - [?] unsure est terminée dans Obsidian, mais sort de la définition du marqueur de la spécification, et un moteur conforme peut l’afficher comme texte brut. Si le fichier est aussi lu sur GitHub, utilisez [ ] et [x] uniquement.

GitHub Docs ajoute une règle : si la description d’une tâche commence par une parenthèse, échappez-la avec une barre oblique inverse, comme dans - [ ] \(Optional) Open a followup issue. Le générateur n’ajoute pas la barre oblique inverse à votre place ; il avertit quand une tâche commence par une parenthèse.

Voir la Capture rapide et Routes et modes de traitement documentation.

Une Route peut ajouter les éléments à votre note quotidienne sous un titre tel que ## Tasks; Ajouter à une note quotidienne Obsidian explique la configuration, et le générateur de modèle de note quotidienne écrit la structure de la note. 7. Questions fréquentes

Pourquoi ma case à cocher s’affiche-t-elle comme du texte [ ] ?

Le moteur de rendu n’affiche pas les listes de tâches. Elles sont une extension de CommonMark ; un moteur sans cette extension affiche les crochets. Vérifiez que la ligne commence par un trait d’union et une espace, qu’il y a une espace ou x entre les crochets, et qu’une espace suit le crochet fermant. Dans Obsidian, une tâche placée dans un bloc de code ou une cellule de tableau peut ne pas s’afficher comme case à cocher, contrairement à un élément de liste.

Comment imbriquer des tâches ?

Indentez la tâche enfant. Dans Obsidian, appuyez sur Tab pour indenter les éléments sélectionnés et Shift+Tab pour les désindenter. Le générateur transforme 2 ou 4 espaces de votre liste en une tabulation par niveau, ou en 2 ou 4 espaces si vous préférez.

Comment cocher une case avec un autre caractère que x ?

L’aide d’Obsidian indique que n’importe quel caractère entre les crochets marque la tâche comme terminée, donc - [-] task et - [?] task sont terminées. Le générateur conserve le caractère que vous avez collé, sauf si vous réinitialisez la liste. Pour les fichiers lus aussi sur GitHub, utilisez [x].

Comment ajouter une échéance lue par le plugin Tasks ?

Mettez 📅 et une YYYY-MM-DD date à la fin de la tâche, par exemple - [ ] send invoice 📅 2026-11-25. Choisissez « Plugin Tasks : échéance » ci-dessus pour l’ajouter à chaque tâche. Utilisez ⏳ pour une date planifiée et 🛫 pour une date de début.

Le générateur envoie-t-il ma liste ?

Non. La liste est convertie par un script de cette page, sur votre appareil, et la page n’effectue aucune requête réseau. Elle n’enregistre pas votre liste : fermer ou recharger la page l’efface.
