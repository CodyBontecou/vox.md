    現在の位置、 {location}、およびメタデータ

    YAML やインラインフィールドを自動追加せず、発生時点で1回取得した位置をエントリーの書式で使います。位置の取得とメタデータの出力は、すべてのルートで別々に明示的に選ぶ設定です。

    2026年8月21日更新 1回限りの取得 バックグラウンド追跡なし 全機能のガイド
    01 / 概要

    位置の取得とメタデータの出力は別

    各ルートには、位置情報の設定が2つに分かれてあります。 現在地を使用 で、そのルートがキャプチャ発生時に位置を1回取得するかを決めます。 位置情報メタデータを書き込む で、取得した位置をフロントマターやインラインフィールドにも書き込むかを決めます。

    コントロール意味すること意味しないこと
    システムの位置情報へのアクセス許可アプリや対応するキャプチャ画面を使用中に、Vox.md が位置を取得できるようにします。この操作でルートの位置取得が有効になることはありません。
    現在地を使用このルート用に位置情報を1回取得し、次で利用できるようにします。 {location}.YAML やインラインのメタデータを自動的に書き込むことはありません。
    位置情報メタデータを書き込む取得した位置情報から、選択した構造化フィールド、または検証済みの高度な YAML を書き込みます。これは次の動作の有無は制御しません。 {location} として出力できます。
    利用意思を示すのは権限ではなくルート

    「使用中のみ」の許可は、OS 側の利用条件を満たすだけです。Vox.md が位置を取得するのは、独立した「現在の位置」キャプチャバーアクション、または「現在地を使用」をオンにしたルートに限ります。

    02 / 設定

    1つのルートに現在の位置を設定する

    1. ルートを開く。iPhone または iPad では「設定」→「ルート」を開きます。Mac では設定を開き、ルートを選びます。
    2. ルートを編集する。発生時点の位置を使うルートを選びます。設定はそのルートに属し、ほかのルートには影響しません。
    3. 位置情報を開く。オンにする項目は、 現在地を使用。次はそのままにします。 位置情報メタデータを書き込む をオフにすると、トークンだけの動作になります。
    4. 精度を選ぶ。取得時の位置を使う場合は「正確な」を、座標を小数点以下2桁に丸め、施設名を含めない場合は「都市」を選択します。
    5. 取得できない場合の動作を選ぶ。発生時点の位置を取得できない場合の動作は、「確認」「位置なしで送信」「キャプチャをキャンセル」で決まります。
    6. 追加 {location} は必要に応じて指定します。トークンは、入り口 寺、独自のエントリー接頭辞・接尾辞、保管庫内の Markdown テンプレートに置けます。

    初回は、OS の位置情報の許可画面が表示される場合があります。以前に拒否した場合は、iOS、iPadOS、macOS のシステム設定で Vox.md の位置情報アクセスを有効にしてください。

    03 / よく使う設定

    必要最小限の位置情報の出し方を選ぶ

    期待する結果現在地を使用位置情報メタデータを書き込む寺
    ルートの位置情報なしオフオフ次は使わないでください。 {location}、または空で出力されます。
    クリックできるリンクのみオンオフ追加 {location}。位置情報のフィールドは書き込みません。
    メタデータのみオンオン省略 {location}。設定したフィールドだけを書き込みます。
    リンクとメタデータオンオン追加 {location} を選び、メタデータのフィールドを設定します。

    「現在地を使用」をオフにすると、そのルートのトークン展開とメタデータ出力の両方を無効にします。後で使うために以前のメタデータ書式の設定が残っていても同様です。

    04 / テンプレートトークン

    使用 {location} ノートのメタデータを変えずに

    「現在地を使用」がオンで、発生時点の取得結果を使える場合、 {location} は、検証済みの Google Maps 用 Markdown リンクを出力します。

    [Location](https://www.google.com/maps/search/?api=1&query=45.501235%2C-73.567890)

    トークンは、再利用可能な入り口 寺、独自のエントリー接頭辞・接尾辞、保管庫内の Markdown テンプレートで使えます。ルートで選んだ「正確な」または「都市」の座標を使います。

    トークンのみの例

    接尾辞を次のようにする場合：

    Captured from {location}

    Vox.md では次の出力を作れます。

    Captured from [Location](https://www.google.com/maps/search/?api=1&query=45.501235%2C-73.567890)

    「位置情報メタデータを書き込む」がオフの場合、ルートが追加する位置情報はこのリンクだけです。次は追加しません。 locations: コレクションも、次も追加しません。 location.*:: のフィールドを書き込みます。

    入力画面のワンタップ修正

    有効なエントリー接頭辞、接尾辞、または再利用できる入り口 寺で次を使う場合、 {location} を使い、選択したルートの現在の位置がオフの場合、入力画面はトークンが空になることを説明し、次を提案します。 [Route] で現在地を使用。この操作は、意図的に「位置情報メタデータを書き込む」をオフにしたまま、ルートの現在の位置をオンにします。次の送信で、ノートのメタデータを変えずにトークンを解決できます。保管庫のテンプレートファイルは配信時にしか読まないため、その内容から入力画面のヒントを出すことはできません。保管庫テンプレートでトークンを使う場合、現在の位置は手動で有効にしてください。

    トークンが空になる場合

    {location} は、現在の位置がオフ、位置を取得できない、位置なしでキャプチャを続行する場合に、空文字列になります。任意のテンプレート行を作る際は、周囲の句読点やラベルに注意してください。

    独立したキャプチャバーアクション

    速い捕獲の 現在の位置 アクションは、1回取得した位置の Google Maps リンクを現在のドラフトに直接挿入します。ルートとは独立しており、「現在地を使用」と「位置情報メタデータを書き込む」のどちらも変更しません。

    05 / メタデータの出力

    構造化フィールドは選んだときだけ書き込む

    次のリンクに加えて、または代わりに、機械可読な位置フィールドをノートに出力したい場合は、「位置情報メタデータを書き込む」をオンにします。 {location} リンクです。

    ノートのフロントマター

    各位置を、次の名前のコレクションに追加します。 locations が既定で、キャプチャ ID をキーにします。関係のない既存のフロントマターは保持されます。

    エントリーのインラインフィールド

    Dataview 形式で次を書き込みます。 location.key:: value 行をキャプチャした項目の横に書き込みます。フロントマターのコレクションは追加されません。

    構造化フィールド

    座標、緯度、経度、場所、市区町村、地域、国、プロバイダのリンク、geo URI、精度、タイムスタンプ、ソース、ID を選択して名前を変更できます。

    高度な YAML

    ノートのフロントマターには、検証済みで範囲を制限した YAML テンプレートを使います。高度な YAML は、エントリーのインラインフィールドでは使えません。

    構造化フロントマターの例

    ---
title: Field Notes
locations:
  - id: "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee"
    coordinates: [45.501235, -73.567890]
    place: "Café & Main"
    appleMapsURL: "https://maps.apple.com/?ll=45.501235%2C-73.567890&q=Caf%C3%A9%20%26%20Main"
    timestamp: "2023-11-14T22:13:20.000Z"
    source: "app"
---

    ローリングノートのコレクションには、複数のキャプチャを残せます。位置のマージには再試行の保護が組み込まれており、同じキャプチャ ID で再試行しても、同じ位置を重複して追加できません。選んだコレクションキーに、利用者が記述した互換性のない値がすでにある場合、Vox.md は上書きせず停止します。

    インラインエントリーの例

    location.id:: aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee
location.coordinates:: [45.501235, -73.567890]
location.place:: "Café & Main"

Captured text

    高度な YAML プレースホルダ

    高度なテンプレートでは、次のようなプレースホルダを使えます。 {{coordinates}}, {{latitude}}, {{longitude}}, {{place}}, {{city}}, {{region}}, {{country}}, {{appleMapsURL}}, {{googleMapsURL}}, {{openStreetMapURL}}, {{geoURI}}, {{accuracy}}, {{timestamp}}, {{source}}、および {{id}}。保存する前にルート設定で構成をプレビューしてください。

    06 / 精度とラベル

    「正確な」と「都市」は一貫した同じ取得結果を使う

    精度座標ラベルリンクとフィールド
    正確な取得時の位置を小数点以下6桁で表示します。選択したメタデータフィールドで必要な場合、施設名のラベルを含められます。すべての派生値に正確な座標を使います。
    都市取得結果を保持する前に、緯度と経度を小数点以下2桁に丸めます。施設名のラベルを削除します。市区町村、地域、国は残る場合があります。すべてのプロバイダ URL、geo URI、トークン、フィールドが、丸めた座標を使います。

    Apple のシステム逆ジオコーダを使うのは、「位置情報メタデータを書き込む」がオンで、選択した構造化フィールドや高度なプレースホルダに、場所、市区町村、地域、国が必要な場合だけです。トークンのみのルートでは逆ジオコーディングを行いません。ラベルの取得に失敗しても、座標に基づく出力は使えます。

    07 / キャプチャ元

    取得結果はキャプチャの発生地点に属する

    現在の位置は、キャプチャが発生した時点で取得されます。再試行や復元では、その保存済みの結果を再利用し、通知なく新しい位置を取得することはありません。

    キャプチャ元取得のタイミング
    iPhone と iPad の速い捕獲送る
    共有シート共有拡張機能から送信
    直接キューに入れるテキスト、リンク、ファイルのインテントインテントの呼び出し
    速い捕獲を開くショートカット、ウィジェット、コントロール、ディープリンク入力画面から送信
    ショートカット、ウィジェット、コントロール、即時音声、キーボード経由のルート録音録音の停止時
    Apple Watch の通常のキャプチャ配信Watch での録音停止時。iPhone 自身の位置に置き換えることはありません
    Mac のキャプチャ送信時、または音声を即時配信する場合の録音停止時

    Watch の「録音のみ」 は、Markdown への出力面なしで未処理の M4A 音声を Files に書き出すため、ルートの他の用途で現在の位置を使っていても、位置を取得しません。

    08 / 取得不能と復元

    位置を取得できない場合の動作をルートごとに選ぶ

    • 確認： 操作可能なキャプチャでは、再試行、キャンセル、今回だけ位置なしで送信、そのルートで常に位置なしで送信、を選べます。
    • 位置なしで送信： は、トークン値やメタデータを出力せず、配信を続行します。
    • キャプチャをキャンセル： は、要求した発生時点の位置なしでノートを作るのではなく、配信を停止します。
    • 保存した選択をリセット： ルートの位置設定で「位置取得不能時の選択をリセット」を使ってください。

    無人実行の「確認」リクエストでは、発生時に位置を取得できなかった結果を、後で確認できるよう保存します。待機中や失敗したキャプチャを再試行しても、後の位置に置き換えることはありません。保留中の作業には、ローカル復元に必要な、プライバシー処理済みの取得結果または取得不能の結果だけを保持します。

    09 / 既存のルート

    更新後も従来のメタデータ動作を保持

    取得と出力を分けているため、移行時の動作も安全に保てます。

    • 新しいルート： 「現在地を使用」と「位置情報メタデータを書き込む」は、どちらも初めはオフです。
    • 以前から位置情報を有効にしていたルート： は、更新後も両方をオンに保ち、それらのルートがすでに書き込んでいたメタデータを維持します。
    • 以前は位置情報が無効だったルート： では、両方の設定をオフのままにします。更新によって新しいメタデータ出力が有効になることはありません。

    メタデータを書き込む既存のルートをトークンだけの動作に変えるには、「現在地を使用」はオンのまま、「位置情報メタデータを書き込む」をオフにします。既存の Markdown を書き換えたり削除したりすることはありません。

    10 / プライバシーと保持期間

    明示的な取得は1回だけ。バックグラウンド追跡はしません

    • Vox.md は継続的に位置を監視したり、バックグラウンドで位置を追跡したりしません。
    • 位置情報は Vox.md のサーバー、分析システム、広告システム、サードパーティの AI サービスには送信されません。
    • トークンとプロバイダの URL はローカルで整形します。Apple Maps、Google Maps、OpenStreetMap に座標が渡るのは、そのリンクを開いたときだけです。
    • 選択したメタデータに場所のラベルが必要な場合に限り、Apple のシステム逆ジオコーダがネットワークリクエストを行うことがあります。トークンだけで位置を使う場合、この照会は行いません。
    • 配信成功後、復元可能なリクエストは内容を含まない受領記録に縮小され、完了したキャプチャ履歴には座標、ラベル、プロバイダ URL、位置テンプレートを保持しません。
    • 位置メタデータやトークンのリンクを Markdown に書き込むと、選択したファイルの一部になります。ファイル同期プロバイダは、そのファイルを自身の規約に基づいて処理する場合があります。
    権限を許可したままでも、ルートごとの位置取得は無効にできます

    独立した「現在の位置」アクションのためにシステム権限を許可したままでも、すべてのルートの「現在地を使用」はオフにしておけます。

    次を参照してください。 プライバシーポリシー で、データの取り扱いと保持期間の詳細を確認してください。

    11 / トラブルシューティング

    位置情報とテンプレートのよくある問題を解決

    {location} は空で出力されます

    有効な入り口 寺、接頭辞、接尾辞、保管庫テンプレートに、正確に次の小文字トークンが使われているか確認します。 {location}。次に、配信するルートで「現在地を使用」をオンにします。検出したインラインのエントリー書式は、入力画面のワンタップ修正で、メタデータを有効にせず設定できます。保管庫のテンプレートファイルには、手動のルート設定が必要です。権限が拒否されている場合や修正が使えない場合は、ルートの取得不能時の動作と、システムの位置情報設定を確認してください。

    リンクは使えるが、メタデータが出ない

    トークンのみの設定では、その動作が正しい状態です。ルートの位置設定で「位置情報メタデータを書き込む」をオンにし、ノートのフロントマターまたはエントリーのインラインフィールドを選んで、必要なフィールドを指定します。

    メタデータはあるが、エントリーにリンクがない

    メタデータ出力でリンクが自動挿入されることはありません。次を追加してください。 {location} を、有効なエントリー書式や保管庫の Markdown テンプレートに追加します。

    場所や市区町村が表示されない

    ラベルのフィールドが選択されているか確認してください。座標は取得できても、Apple の逆ジオコーダが失敗する場合があります。「都市」の精度では、施設名を意図的に削除します。

    フロントマターへの配信で衝突が報告される

    設定したコレクションのキー、 locations が既定で、互換性のある位置リストである必要があります。ルート設定でコレクション名を変更するか、利用者が記述した既存のフロントマターを調整してください。Vox.md は、互換性のない値を上書きしません。

    再試行で位置情報が古い、または取得できない

    これは意図した動作です。リクエストは発生時点の結果を保持するため、後の再試行が通知なく別の場所をキャプチャ位置として扱うことはありません。新しい位置が必要なら、新しいキャプチャを始めてください。

    位置情報へのアクセスは許可されているが、ルートが取得しない

    システムの許可は、利用の前提にすぎません。そのルートを編集し、「現在地を使用」をオンにしてください。権限を許可しただけでは、ルートの位置取得は有効になりません。
