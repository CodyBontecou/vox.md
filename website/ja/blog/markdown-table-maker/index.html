Obsidian 用 Markdown 表メーカー: Excel、Sheets、CSV から貼り付け

Excel、Google Sheets、Numbers、CSV、TSV の行を貼り付けると、[[Note|Alias]] や ![[image.png|300]] 内の縦線をエスケープし、改行を処理し、列ごとの配置を設定した、有効なパイプ表をコピーできます。

作成者
Cody Bontecou
更新日
2026年11月26日
必要条件
最新のブラウザであれば使えます。iPhone の Safari も含みます。オプション: 表を使う Obsidian と、テキストをノートに Capture する iPhone または Mac 用の Vox.md。
短く答えると

Markdown 表は、ヘッダー行、ハイフンの区切り行、そして 1 行につき 1 行のデータ行からなり、セルは次で区切ります: |。セルを次に貼り付けます: 表メーカー を使って作成するか、この例から始めてください。

| Name | Owner | Status |
| --- | --- | --- |
| Draft | Ana | Done |
| Review | Lee | Open |

このメーカーは、一般的なジェネレーターが対応しない Obsidian 特有の問題にも対応します。次の中の縦線をエスケープします: [[Note|Alias]] と ![[image.png|300]] は \|、またセル内の改行を次に変換します: <br> またはスペースです。すべてこのページ内で動作し、データがアップロードされることはなく、ページはネットワークリクエストを行いません。

    2. Markdown 表の構文

    | Name   | Qty | Price |
| :----- | :-: | ----: |
| Apple  |   3 |  1.20 |
| Pear   |  12 |  0.80 |

    この GitHub Flavored Markdown 仕様 は、表を 1 行のヘッダー行、ヘッダーとデータを区切る区切り行、0 行以上のデータ行として定義しています。セルはパイプで区切ります。

    • 区切り行。 セルにはハイフンだけを入れ、左端、右端、または両端にコロンを付けると、左揃え、右揃え、中央揃えになります。 Obsidian ヘルプ では、テキストを揃えるにはヘッダー行にコロンを付け、ヘッダー行にはハイフンが 2 つ以上必要とされています。
    • 外側のパイプ。 両端のパイプは、仕様では省略できます。Obsidian Help では読みやすさのために付けることを勧めており、このメーカーは常にパイプを付けて出力します。
    • パディング。 Obsidian Help によると、セルをきれいにそろえる必要はありません。メーカーの「Pad columns」レイアウトは、ソースを読みやすくするためだけに位置をそろえるもので、「Compact」はそれを行いません。
    • セル数を一致させる。 仕様では、ヘッダー行の セル数は区切り行と同じでなければなりません。異なる場合、その行は表ではなく段落として表示されます。セル数が足りないデータ行には空のセルが追加され、余分なセルは無視されます。
    • セルの中。 仕様ではインライン書式は使えますが、ブロックレベルの内容は使えないため、リストや見出しをセルに入れることはできません。Obsidian Help によると、基本的な書式構文で表の内容にスタイルを付けられます。
    • 表の終わり。 仕様では、表は最初の空行、または別のブロックレベル構造の先頭で終わります。

    メーカーは、区切り行のすべてのセルにハイフンを 3 つ以上書きます。これは Obsidian の最小値である 2 つと、次が求める 3 つの両方を満たします: GitHub ドキュメント が求めるとおりです。

    3. Obsidian の表

    • Insert Table。 Obsidian Help によると、Command Palette の Insert Table コマンドで表を挿入できます。すでにあるデータから作るには、上のメーカーに貼り付けてください。
    • エイリアスと画像サイズ。 ウィキリンクのエイリアス、たとえば [[Note|Alias]] と、次のような画像サイズ: ![[image.png|300]] はどちらも縦線を含みます。Obsidian Help によると、表の中では次を追加する必要があります: \ 縦線の前に付けるため、次のように書きます: [[Note\|Alias]] と ![[image.png\|300]]。メーカーが自動で行います。すでに書いたエスケープが二重になることはありません。
    • その他のパイプ。 GFM 仕様では、セル内のパイプはコードスパンの中でもバックスラッシュでエスケープする必要があります。メーカーは、エスケープされていないパイプをすべて次のようにエスケープします: \|.
    • 改行。 行は 1 行で書くため、セル内の改行は別のものに置き換える必要があります。メーカーは HTML を書き出します: <br> タグを書き出すか、そちらを選んだ場合は行をスペースでつなぎます。Obsidian Help の Tables セクションにも GitHub Docs にもセル内の改行の説明はないため、次を確認してください: <br> が自分の Vault でどう表示されるか確認してください。ソースにタグを入れたくない場合は、スペースを選んでください。
    • プラグイン。 表の編集を助けるコミュニティプラグインがあります。このページでは、それらの評価や推奨は行いません。

    チェックリストについては、次をご覧ください: Markdown チェックリストメーカー。ノート冒頭のプロパティには、次を使います: プロパティジェネレーター。決定事項と担当者の一覧には表が便利です。次のノートで使えます: 会議メモのテンプレート.

    4. Excel、Google Sheets、CSV から

    スプレッドシートのセルを選択してコピーし、上のボックスに貼り付けます。セルの間にタブが入って貼り付けられた場合、メーカーはそれを検出します。カンマ、セミコロン、パイプも検出し、引用符で囲まれた CSV フィールドも読み取るため、 "Lee, Sam" は 1 つのセルのままで、 "" は、引用符の中では引用符に変わります。推測が違っていたら Separator メニューを使ってください。「最初の行をヘッダーにする」にチェックを入れるか外すかで、最初の行をヘッダー行にするか決まります。外した場合は、Markdown 表には必ずヘッダーが必要なため、空のヘッダー行が追加されます。

    • セルの結合。 仕様と両方のヘルプページは、行をパイプで区切ったセルの並びとして説明しており、セルを結合する方法はどこにも書かれていません。コピーする前に、結合範囲のすべてのセルに値を入れてください。
    • 数式。 メーカーは貼り付けたテキストを読むだけです。貼り付けたセルに計算結果ではなく数式が表示される場合は、スプレッドシートアプリで値をコピーして、もう一度貼り付けてください。
    • 行ごとのセル数の不一致。 行のセル数がヘッダーと異なる場合、メーカーはその行の行番号付きで警告し、空のセルで表を補います。ヘッダーよりセルが多い行がある場合は、データを捨てずに表を広げます。
    • 逆変換と修復。 既存の Markdown 表を貼り付けて整え直したり、Output as を CSV か TSV にしてエクスポートしたりできます。区切り行がない場合、セル数がヘッダーと一致しない場合、空行で表が途切れる場合には、行番号付きで警告します。

    貼り付けた Markdown 表の配置用コロンは保持され、Column alignment メニューで列ごとに変更できます。

    5. GitHub と Obsidian の違い

    Obsidian Help と GitHub Docs はどちらも、ヘッダー行、ハイフン、省略可能な配置用コロンを使うパイプ表を説明しています。各ページに書かれている違いはわずかです:

    トピックObsidian ヘルプGitHub Docs と GFM 仕様
    ハイフンヘッダー行にはハイフンが 2 つ以上必要ですGitHub Docs: ヘッダーの各列にハイフンが 3 つ以上必要です
    表の前に空行を入れるTables セクションには記載がありませんGitHub Docs: 表の前に空行を入れる必要があります
    セル内のパイプ文字追加: \ エイリアスと画像サイズの縦線の前に次のようにエスケープします: \|、コードスパンの中でも同様です
    外側のパイプ省略可、読みやすさのために推奨省略可

    どちらでも問題なく表示するには、ハイフンを 3 つ以上書き、表の上に空行を入れ、すべてのパイプをエスケープします。メーカーはそのとおりに出力します。ウィキリンクのエイリアスは Obsidian の構文で、GitHub ではパイプを含むただのテキストです。チェックリストメーカーのガイドで説明しています: タスクリストの違い 同じ方法で指定します。

    表やその補足を目立たせるには、コールアウトで囲みます。 Obsidian コールアウトジェネレーター を追加します: > の接頭辞を自動で付けます。

    6. Vox.md で表とノートを Vault に取り込む

    Vox.md 自体は表を作成しません。上のメーカーはアプリなしで使えます。Vox.md が行うのは Obsidian へのテキストの Capture です。Quick Capture で既存のテキストを貼り付け、Route で Markdown の宛先に届けます。次をご覧ください: 速い捕獲 と ルート のドキュメント。

    1. 上で表を作り、Copy を押してください。
    2. iPhone、iPad、Mac の Vox.md で Quick Capture を開き、表をテキストエディタに貼り付けます。
    3. 元のテキストを保持する Route で送信します。ドキュメントには次が載っています: オリジナルを保持 を、AI による書き換えなしで取り込んだテキストを保持する処理モードとして挙げており、次の場合に取り込んだテキストはそのまま届けられると記載しています: Apple Intelligenceを使用 がオフのときです。これが既定値です。入力したテキストの処理は、各 Route でオプトインする設定です。
    4. Route の宛先によって、書き込み先が決まります。新規ノート、デイリーノートのような追記用ノート、または既存ノートの末尾、先頭、選んだ見出しの下のいずれかです。

    貼り付け先の上にすでにテキストがある場合は、貼り付ける表の上に空行を入れてください。Route のレシピについては、次をご覧ください: キャプチャテンプレート。Zoom、Teams、YouTube の字幕ファイルをまず文字起こしノートにするには、次をご覧ください: SRT と VTT から Markdown へ.

    iPhone、iPad、Mac から Vox.md で Obsidian に Capture する

    Vox.md は音声とテキストを Obsidian のノートに取り込みます。録音、文字起こし、Capture には Vox.md Unlimited が必要です。対象のアカウントでは 7 日間の無料トライアル付きの週額または年額のサブスクリプション、または買い切りのライフタイム購入からお選びいただけます。App Store には現地の価格が表示されます。

    7. よくある質問

    Obsidian で表が表示されないのはなぜですか?

    次の 3 点を確認してください。ヘッダーの直下にハイフンの区切り行があること、ヘッダー行と区切り行のセル数が同じであること(そうでないと、仕様では段落として表示されます)。Obsidian Help では、ヘッダー行にハイフンが 2 つ以上必要とされています。そして表の前に空行を入れてください。GitHub Docs では必須で、Obsidian では入れても支障ありません。表をメーカーに貼り付けると、区切り行がない場合やセル数が一致しない場合に、行番号付きで警告します。

    セル内で改行するにはどうすればよいですか?

    行を 1 行に保ち、HTML を使います: <br> をセル内に入れます。複数行のセルにはメーカーがこれを書き出します。参照したページにはセル内の改行の説明がないため、ご自分の Vault で試してください。もう一つの方法は、行をスペースでつなぐことです。

    セルにパイプやウィキリンクのエイリアスを入れるにはどうすればよいですか?

    パイプの前にバックスラッシュを付けます: [[Note\|Alias]], ![[image.png\|300]] または a \| b。Obsidian Help は表内のエイリアスと画像のサイズ指定にこれを求めており、GFM 仕様はセル内のあらゆるパイプに求めています。

    セルを結合できますか?

    仕様にも Obsidian Help にも、そのための構文はありません。代わりに、各セルに同じ値を繰り返してください。

    表の幅はどこまで大きくできますか?

    参照したどのページにも列数や行数の上限は書かれておらず、メーカーも制限を設けていません。とても幅の広い表はソースで読みにくいため、Compact レイアウトを使うか、表を 2 つに分けてください。

    メーカーはデータをアップロードしますか?

    いいえ。表はこのページ内のスクリプトがお使いのデバイス上で作成し、ページはネットワークリクエストを一切行いません。データは保存されず、ページを閉じるか再読み込みすると消去されます。Download ボタンは、ページ上のファイルをお使いのデバイスに保存します。
