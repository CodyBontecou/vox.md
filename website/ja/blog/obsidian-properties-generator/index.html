Obsidian ノートプロパティ（YAML フロントマター）のジェネレーターとチェッカー

Obsidian が想定する形式でプロパティを作成するか、手元のフロントマターをチェックして、プロパティが意図した種類で表示されない理由を確認します。

作成者
Cody Bontecou
更新日
2026年11月22日
必要条件
Obsidian（任意のプラットフォーム）。任意: キャプチャしたノートにプロパティを追加するための iPhone、Apple Watch、Mac 向け Vox.md。
短く答えると

Obsidian のノートプロパティは、ノートの先頭にある YAML で、次の2つの行の間に置かれます: --- 行。各プロパティは次のとおりです: name: value のペアで、リストには次があります: - value 行に1項目ずつ書き、内部リンクは引用符で囲む必要があります。次の例は有効です:

---
tags:
  - journal
  - idea
aliases:
  - Weekly review
date: 2026-11-21
project: "[[Vox.md launch]]"
published: true
---

ほかのプロパティが必要ですか？ 意図した種類で表示されない理由を知りたいですか？ 下のジェネレーターが YAML を書き、チェッカーが行番号付きで問題と修正案を示します。どちらもこのページ内だけで動作し、入力内容はどこにも送信されません。ルールの出典は Obsidian ヘルプです: プロパティ と タグ.

    2. 手元のフロントマターをチェック

    3. プロパティの種類と書き方

    Obsidian は7種類のプロパティをサポートしています。YAML では次のように書きます:

    種類YAML の例落とし穴
    テキストtitle: Weekly reviewYAML が誤解する値は引用符で囲んでください。たとえば次を含む値: : を含む値、または次で始まる値: #。内部リンクは引用符で囲む必要があります。
    リストtopics:
      - sleep
      - focus    		各値は1行ずつで、先頭にハイフンとスペースが付きます。
    数値rating: 4数値は引用符なしで書いてください。
    チェックボックスpublished: true値は次のとおりです: true または false.
    日付date: 2026-11-21形式は次のとおりです: YYYY-MM-DD.
    日付と時刻time: 2026-11-21T10:30:00形式は次のとおりです: YYYY-MM-DDTHH:MM:SS.
    タグtags:
      - recipe
      - cooking    		次なしで書く: #。スペースを含めず、数字以外の文字を1文字以上含めます。

    Obsidian にはデフォルトのプロパティが3つもあります: tags, aliases と cssclasses。ジェネレーターにはそれぞれのボタンがあります。

    4. プロパティが壊れやすい主なルール

    • 内部リンクは引用符で囲んでください。 project: "[[Vox.md launch]]"、次ではありません: project: [[Vox.md launch]]。これはテキストのプロパティと、リスト内の項目に適用されます。
    • リストの項目は1行に1つ。 各項目は、プロパティ名の下にインデントして、ハイフンとスペースで始めます。インデントにはタブではなくスペースを使ってください。
    • タグには独自のルールがあります。 いいえ # YAML 内で、スペースを含めず、数字以外の文字を1文字以上含めます: 1984 は有効なタグではありませんが、次は有効です: y1984 です。代わりに次を使ってください: / 。次のようなネストしたタグ用: inbox/to-read。参照先： タグ （Obsidian ヘルプ）
    • 日付は保存形式で書いてください。 2026-11-21 （日付用）および 2026-11-21T10:30:00 （日付と時刻用）。
    • 現在の名前を使ってください。 tag, alias と cssclass は Obsidian 1.4 で非推奨となり、次に置き換えられました: tags, aliases と cssclasses。デフォルトプロパティとしてのサポートは Obsidian 1.9 で終了しました。
    • ネストしないでください。 プロパティはネストされたオブジェクトをサポートしません。Obsidian はネストしたプロパティの表示にソースモードを勧めています。次のようなトップレベルの名前に平坦化してください: project_status.
    • Markdown は使わないでください。 太字、リンクなどの書式はプロパティでは表示されません。Obsidian はこれを意図的な仕様とし、プロパティは小さく独立した情報のためのものだと説明しています。

    5. テンプレートでプロパティを使う

    オンにする項目は、 テンプレートプラグインのトークン をジェネレーターで使うと、日付フィールドを固定の日付ではなくトークンとして書き込めます。コアの Templates プラグインは次を使います: {{date:YYYY-MM-DD}}。Templater コミュニティプラグインは次を使います: <% tp.date.now("YYYY-MM-DD") %> （次の Templater を参照: ドキュメント本文）。日付と時刻のフィールドは次を使います: YYYY-MM-DD[T]HH:mm:ss をトークンに指定し、次を併用します: T を角括弧で囲むと、文字として書き込まれます。

    リンクには注意が必要です。Obsidian はプロパティ UI で入力したリンクには引用符を付けますが、テンプレートプラグインはテキストをそのままファイルに書き込むため、テンプレートでは自分で引用符を書いてください: project: "[[Vox.md launch]]".

    これらのプロパティを使うテンプレート全体については、次を参照してください: デイリーノートテンプレートジェネレーター および 会議メモテンプレートジェネレーター.

    ノート本文には、次を使います: Markdown 表メーカー は、スプレッドシートのセルや CSV を、プロパティブロックの下に貼り付けられる表に変換します。

    6. キャプチャするノートにプロパティを追加

    Vox.md のルートでは、メタデータのフィールドに次を1つ指定します: key: value の組を1行ずつ指定します。例： tags: [journal, idea]. ノートのフロントマター はメタデータをドキュメント単位で書き込みます。 エントリーのインラインフィールド 書き込む内容は、 key:: value ローリングノートの各エントリーの横にあるフィールド。次を参照してください: ルートのリファレンスにあるメタデータ.

    ジェネレーターの Vox.md ルートのメタデータとしてコピー ボタンは、リストを次の形式にして、プロパティをその形で書き込みます: [a, b] と、1行につき1つのプロパティで構成されます。Vox.md のドキュメントではこのフィールドを次のように説明しています: key: value 行。このページは各プロパティの種類がどう書かれるかをテストしないため、最初にキャプチャしたノートを Obsidian で開いて確認してください。デイリーノートとインボックス用のルートについては次で説明しています: Obsidian のデイリーノートに追記, キャプチャテンプレート と iPhone の音声メモを Obsidian へ.

    キャプチャするすべてのノートにこれらのプロパティを付けます。

    7. よくある質問

    Obsidian でプロパティが意図した種類として表示されないのはなぜですか？

    Obsidian はプロパティを YAML として読み取り、その種類のルールに従っていない値はその種類として表示されません。よくある原因は、引用符のない内部リンク、1行に1項目で書かれていないリスト、次の形式でない日付です: YYYY-MM-DD、スペースを含むタグ。ブロックを上のチェッカーに貼り付けると該当行がわかります。

    プロパティのタグに # は必要ですか？

    いいえ。YAML ではタグは次のように通常の単語として書きます: - recipe。この # はノート本文中のタグ用です。

    プロパティをネストできますか？

    いいえ。プロパティはネストされたオブジェクトをサポートしません。フラットな名前を使うか、次のようなネストしたタグを使ってください: / 内の tags リスト。

    プロパティを JSON で書けますか？

    Obsidian は JSON ブロックを読み取れますが、YAML として読み取り保存します。上のチェッカーは行ルールを YAML にのみ適用します。
