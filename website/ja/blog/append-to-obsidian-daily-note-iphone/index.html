iPhone でテキストと音声を Obsidian のデイリーノートに追加

デイリーファイルと見出しを一度選べば、後の考えもキャプチャプレスで同じ場所に送れます。

作成者
Cody Bontecou
更新日
2026年10月26日
必要条件
iPhone · 書き込み可能な保管庫フォルダ
短く答えると

Vox.md のキャプチャプレスを保管庫に接続し、日単位のローリングノートを選んで、既存のデイリーノートのファイル名にパスを合わせます。ノート末尾への追加には「末尾」、指定セクションの下への挿入には「見出し」を使います。同じ保存先で、テキストと音声のキャプチャを受け取れます。

このガイドは振り分けと書式を扱います。録音とモデルの設定は、次から始めてください。 iPhone の音声メモを Obsidian へ。Obsidian 自体にもデイリーノートのキャプチャ機能があります。すべての追記手順に Vox.md が必要なわけではありません。

このガイドの内容
  1. デイリーノートのパスを合わせる
  2. 挿入位置と見出しを選ぶ
  3. 連続した2件のキャプチャを確認する
  4. タスクリストを整形する
  5. ファイルの重複や誤った位置への挿入を防ぐ
  6. Obsidian の標準キャプチャを検討する

1. デイリーノートのパスを合わせる

保管庫の既存のデイリーノートで、フォルダとファイル名を確認します。この例では、次を想定しています。 Journal/2026-10-26.md。規則が異なる場合は、ご自身のものを使ってください。

  1. よくある 設定 → キャプチャプリセット を Vox.md で開きます。Journal など、有効なプリセットを作成または編集します。
  2. Files を使って保存先を保管庫のフォルダに接続します。そのフォルダは、Vox.md から参照でき、書き込み可能である必要があります。
  3. 選択 ローリングノート および 毎日 期間です。
  4. 例の命名規則に合わせる場合、パスのパターンを次に設定します。 Journal/{period}.md。送信前に、解決された保存先を確認します。

日単位の期間では、 {period} は、次のような日付に置き換わります。 2026-10-26。デイリーファイルを保管庫のルートに置く場合は、代わりに次を使います。 {period}.md。これは Vox.md のパストークンであり、Obsidian のテンプレート式ではありません。

Vox.md は Daily Notes プラグインの設定を自動的に読みません。別のフォルダやファイル名を選ぶと、別の対象になります。パスは Files で選択したフォルダからの相対パスです。実際のサブフォルダでない限り、保管庫自体の名前をパスに重ねて入れないでください。

Vox.md を無料でダウンロード

10回の成功したキャプチャ配信と15分の文字起こしを無料で試せます。無制限利用は1回限りの永久ライセンス購入で、価格は地域によって異なります。

2. 挿入位置と見出しを選ぶ

選択 底 でデイリーノートの末尾に追加するか、次を使います。 TOP で先頭に追加します。セクション内にキャプチャをまとめるには、次を選択します。 ヘッドで、見出しの名前とレベルを設定します。

以下の例では、次の名前のレベル2見出しを使います。 受信箱。その見出しのセクション末尾への挿入を選ぶと、新しい項目が既存の項目の後に並びます。見出しがない場合の動作には次を設定します。 創出ヘッド で Vox.md に追加させるか、次を選びます。 エラー表示 は、自分でノートを修正したい場合に選びます。

プレーンな項目には、次を選択します。 オリジナルを保持 処理を使います。エントリーの書式には、次のような箇条書きの接頭辞を指定します。 - で、短いキャプチャをそれぞれリスト項目にできます。接頭辞は書式の選択です。その動作を設定しない限り、プレーンな文字起こしがチェックリストになることはありません。

3. 連続する2件のキャプチャを確認

まず速い捕獲で「登山道のガイドを読む」と入力し、Journal プリセットで送信します。次に「レインジャケットを詰める」と入力し、同じプリセットで再送します。Obsidian で解決されたデイリーノートを開き、両方が Inbox の下に表示されていることを確認してください。

上記の日付パス、見出し、箇条書きの接頭辞を使うと、次のファイルの該当部分は、 Journal/2026-10-26.md は、次のようになります。

## Inbox
- Read the trail guide
- Pack a rain jacket

これは、その設定での出力例です。エントリーテンプレート、処理、既存ノートの内容によって結果は変わります。音声認識を加える前に、短いテキストを2回キャプチャして、振り分けを確認してください。

音声には、同じプリセットを使って速い捕獲から録音します。文字起こしをドラフトに追加して送信前に確認するか、ルートに慣れたら「すぐに送信」を選んでください。キーボードは、2件目の Markdown キャプチャを書き出す代わりに、ホストアプリに文字を挿入します。

タスクリストを整形する

Tasks セクションには、次の名前のレベル2見出しを選びます。 タスク と、統一したチェックリストの方法を使います。テキスト処理なしの入力キャプチャでは、「オリジナルを保持」と次のエントリー接頭辞を使います。 - [ ] は、AI による書き換えをせずに、短い項目をタスクにします。

## Tasks
- [ ] Read the trail guide
- [ ] Pack a rain jacket

代わりに タスクチェックリスト処理を有効にする場合は、チェックボックスの接頭辞を重ねて追加せず、処理側にタスク記号を任せます。入力テキストと混在テキストの処理は、別途有効化する必要があります。長いノートやリストにプリセットを適用する前に、まず1件の結果を確認してください。次を参照してください。 処理のモード と エントリーの書式.

再利用できる入り口 寺で、タイムスタンプやソースのフィールドを追加できます。問題が保存先、処理、書式のどこにあるかを切り分けられるよう、最初の設定はシンプルに保ちます。

ファイルの重複や誤った位置への挿入を防ぐ

2つ目のデイリーノートができた

解決されたフォルダとファイル名を、Obsidian の既存ファイルと比較します。選択した保管庫のルート、日単位の期間、日付の規則、パスのパターンを確認してください。新しいノートを対象にすると個別ファイルを作成し、ローリングのデイリーノートにまとめることはありません。

項目が違う見出しの下に入った

見出しのテキストとレベルを確認します。レベル2の Inbox と、レベル3の Inbox は別の対象です。セクションの先頭・末尾のどちらに挿入するか、見出しがない場合に作成するかも確認してください。

書き込みが失敗、または保留中

選択したフォルダへのアクセスを復元し、既存の保留中キャプチャを再試行します。配信が未解決の間は、同じ内容を手動で再送しないでください。任意の 保護回復 は、同じリクエストの繰り返しを識別するため、表示可能な HTML コメントを書き込みます。既定ではオフです。たまたま同じ言葉になった、別々に作成された2件のキャプチャは検出しません。

1つのドラフトだけ保存先を変えた

入力画面では、プリセットを変更せず、そのキャプチャに限って保存先を上書きできます。次に戻してください。 デフォルトの予想 は、プレビューが設定したルートと一致しない場合に使います。

フォルダにネットワークが必要

キャプチャと文字起こしがローカルでも、すべてのファイルプロバイダをオフラインで使えるわけではありません。デイリーファイルとフォルダがローカルで利用できるか確認し、同期は選んだ同期プロバイダに任せてください。

Obsidian の標準キャプチャを検討する

Obsidian の 公式 iOS ガイド で、デイリーノートの末尾や先頭にテキストを追加する速い捕獲の保存先を説明しています。標準の速い捕獲には Obsidian 1.14 以降と iOS 26 以降が必要です。目的を果たせるなら、まず標準機能から始めてください。

Vox.md は、Markdown の保存先を軸に、独自のプリセット処理、エントリー書式、メディアキャプチャ、ローカル音声バックエンドの選択を提供します。デイリーノートへの追加には別のアプリが必須だと考えるのではなく、必要な手順全体に合うかで選んでください。
