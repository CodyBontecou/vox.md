Markdown チェックリストメーカー: どんなリストも期限付きのタスクに

行、箇条書き、番号付き項目、既存のタスクリストを貼り付けて、入れ子を保ったまま、任意の期限付きで、完了数も確認できる正しい - [ ] タスクをコピーできます。

作成者
Cody Bontecou
更新日
2026年11月24日
必要条件
最近のブラウザならどれでも使えます (iPhone の Safari も含みます)。任意: チェックリスト用の Obsidian と、音声でタスクをキャプチャするための iPhone または Mac 版の Vox.md。
短く答えると

Markdown のタスクは、ハイフン、スペース、括弧、スペース、テキストの順です。次のように書きます: - [ ] task は未完了のタスク、 - [x] done は完了したタスクです。リスト全体をタスクにするには、次に貼り付けます: チェックリストメーカー 以下を参照してください。

- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

メーカーは、既存の箇条書き、番号、チェックボックスを取り除いて二重にならないようにし、インデントを入れ子として保ち、お使いの Obsidian プラグインが読み取る形式で期限を追加できます。処理はすべてこのページ内で行われ、リストがアップロードされることも、ページがネットワークリクエストを行うこともありません。

2. Markdown チェックリストの書き方

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

各タスクはリスト項目で、ハイフンとスペースに続けて [ ] 括弧の間にスペースを入れ、その後にテキストを続けます。 Obsidian Helpページ と GitHub Docsページ どちらも、ハイフンとスペースに続けて次のように書くと説明しています: [ ]。タスクを完了にするには、GitHub Docs では次を使うとされています: [x].

スペースは重要です。 GitHub Flavored Markdown 仕様 は、チェックボックスのマーカーを次のように定義しています。左括弧、空白文字または文字 x、右括弧。さらに、後ろのテキストの前に空白が必要です。したがって、 [] のように中身が空のものや、 - [ ]text のように括弧の後ろにスペースがないものは、定義に一致しません。ハイフンとそのスペースがあって初めて、その行がリスト項目になります。

タスクリストはコアの Markdown には含まれません。同じ仕様で CommonMark の拡張機能と位置づけられており、冒頭でも、元の CommonMark 仕様にない機能は拡張として示すと説明されています。この拡張に対応していないレンダラーでは角括弧がそのまま表示され、これがチェックボックスが [ ] という文字で表示される主な原因です。

3. Obsidian のチェックリスト

Obsidian ヘルプの 基本的な書式設定 のページにタスクリストの説明があります:

  • タスクは、ハイフンとスペースに続けて [ ].
  • 括弧の中にどんな文字を入れても、タスクを完了にできます。したがって、 [x], [-] と [?] はすべて完了として数えられます。
  • タスクリストを入れ子にするには、リスト項目をインデントします。 Tab または Shift+Tab を使うと、選択した項目をインデントまたはインデント解除できます。
  • 閲覧ビューでは、チェックボックスを選択してタスクを切り替えられます。

ヘルプページには、任意の文字でタスクが完了になると書かれています。文字ごとに見た目が異なるとは書かれていません。もし [-] または [?] の見た目が [x] と、お使いの Vault で異なって見えるなら、それはインストール済みのテーマや CSS スニペットによるもので、Markdown 自体の機能ではありません。

メーカーの進捗行も同じ数え方です。括弧の中にスペース以外の文字があれば完了とみなすため、 [x], [X], [-] と [?] は完了で、 [ ] は未完了です。「done:」や「x 」で始まる行は通常のテキストとして扱われ、完了済みのタスクを意味するとは推測しません。

4. 期限: Tasks、Dataview、Reminder の違い

Obsidian のタスクリスト記法には、期限を表す独自の書き方がありません。ヘルプページにも記載はありません。3 つのプラグインが、タスクのテキスト中に書かれた日付を、それぞれ独自の形式で読み取ります。メーカーは、日付を ISO 形式の YYYY-MM-DD で、すべてのプラグインに書き出します。プラグインがなければ、日付は単なるテキストです。

形式対応入力例
期限: 📅 YYYY-MM-DDTasks プラグインが読み取り、日付は YYYY-MM-DD 形式にする必要があるとされています- [ ] send invoice 📅 2026-11-25
予定日: ⏳ YYYY-MM-DDTasks プラグイン- [ ] send invoice ⏳ 2026-11-25
開始日: 🛫 YYYY-MM-DDTasks プラグイン- [ ] send invoice 🛫 2026-11-25
インラインフィールド: [due:: YYYY-MM-DD]Dataviewドキュメント。タスクに書かれたフィールドを読み取ります。例: [completion:: 2021-08-15]- [ ] send invoice [due:: 2026-11-25]
Reminder プラグイン: (@YYYY-MM-DD) または (@YYYY-MM-DD HH:mm)obsidian-reminder プラグイン。README では (@2021-08-14) と (@2021-08-14 09:37) が未完了のタスクに付いた例が示されています- [ ] send invoice (@2026-11-25 09:30)

お使いのプラグインを 1 つ選んでください。Dataview のページには日付用の絵文字ショートカットも載っており、対応するショートカットはそれだけだと書かれていますが、メーカーは代わりに Dataview の角括弧形式で書き出します。Reminder の README によると、すでにチェック済みのタスクのリマインダーは通知されません。

5. GitHub と Obsidian の違い

GitHub Docs では、 [ ] は未完了のタスク、 [x] は完了のタスクを表すとされています。GFM 仕様では、マーカーを括弧の間の空白または文字 x のいずれかと定めています。Obsidian は任意の文字を受け付けるため、次のようなタスクは - [-] skipped または - [?] unsure は Obsidian では完了ですが、仕様のマーカー定義の範囲外であり、仕様に従うレンダラーではそのままの文字として表示されることがあります。ファイルを GitHub でも読む場合は、 [ ] と [x] だけを使ってください。

GitHub Docs には、もう 1 つルールがあります。タスクの説明が括弧で始まる場合は、バックスラッシュでエスケープします。例: - [ ] \(Optional) Open a followup issue。メーカーはバックスラッシュを自動では追加しません。タスクが括弧で始まる場合は警告が出ます。

6. Vox.md で iPhone と Mac から音声やテキストでタスクをキャプチャ

Vox.md のタスクチェックリスト処理モードは、キャプチャから Markdown の - [ ] タスク項目を作成し、代替手段として決まった形式に整えるチェックリスト整形機能があります。音声はデバイス上で文字起こしされます。キャプチャバーでは、 チェックリスト は - [ ] 接頭辞を付け、 二日目設定 は (@yyyy-MM-dd) 、または時刻付きの形式を挿入します。次を参照してください: 速い捕獲 と Route と処理モード のドキュメント。

Route を使えば、次のような見出しの下にデイリーノートへ項目を追加できます: ## Tasks; Obsidian のデイリーノートに追記 で手順を説明しています。また、 デイリーノートテンプレートジェネレーター がノートの構成を書き出します。会議の行動項目については、次を参照してください: 会議メモのテンプレート。タスクリスト用の接頭辞レシピは次を参照してください: キャプチャテンプレート.

Vox.md が書き込むのは、次の (@yyyy-MM-dd) 形式です。Tasks プラグインの絵文字の日付や Dataview のフィールドは書き込みません。それらを使う場合は、キャプチャしたタスクを上のメーカーに貼り付けてその形式を選ぶか、あとで日付を編集してください。ノート先頭のプロパティを作るには、次を使います: プロパティジェネレーター.

7. よくある質問

チェックボックスが [ ] という文字で表示されるのはなぜですか？

レンダラーがタスクリストを描画していません。タスクリストは CommonMark の拡張機能なので、対応していないレンダラーでは角括弧がそのまま表示されます。行がハイフンとスペースで始まっていること、括弧の間にスペースか x があること、閉じ括弧の後ろにスペースが続いていることを確認してください。Obsidian では、コードブロックや表のセル内のタスクは、リスト項目のようにチェックボックスとして表示されないことがあります。

タスクを入れ子にするには？

子タスクをインデントします。Obsidian では、 Tab で選択した項目をインデントし、 Shift+Tab でインデントを解除します。メーカーは、リストの 2 つまたは 4 つのスペースを、レベルごとに 1 つのタブに変換します。お好みで 2 つまたは 4 つのスペースにもできます。

x 以外の文字でチェックを付けるには？

Obsidian ヘルプでは、括弧の中のどんな文字でもタスクが完了になるとされています。したがって、 - [-] task と - [?] task は完了です。リストをリセットしない限り、メーカーは貼り付けた文字をそのまま保持します。GitHub でも読むファイルには、次を使ってください: [x].

Tasks プラグインが読み取る期限はどう追加しますか？

タスクの末尾に 📅 と、 YYYY-MM-DD の日付を付けます。例: - [ ] send invoice 📅 2026-11-25。すべてのタスクに追加するには、上の「Tasks プラグイン: 期限」を選びます。予定日には ⏳ 、開始日には 🛫 を使います。

メーカーはリストをアップロードしますか？

いいえ。リストはこのページ内のスクリプトでお使いのデバイス上で変換され、ページはネットワークリクエストを行いません。リストは保存されず、ページを閉じるか再読み込みすると消えます。
