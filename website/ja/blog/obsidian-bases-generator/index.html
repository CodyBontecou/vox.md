Obsidian Bases ジェネレーター: フィルター、ビュー、数式

スキーマを先に覚えなくても、Obsidian の base 用 YAML を作成できます。フィルターを選び、ビューを追加し、.base ファイルまたはコードブロックをコピーできます。各キーの役割は、Obsidian 公式ドキュメントへのリンク付きで確認できます。

作成者
Cody Bontecou
更新日
2026年11月28日
必要条件
最新のブラウザ(iPhone の Safari を含む)で使えます。任意: Bases コアプラグインを有効にした Obsidian と、音声やテキストでノートをキャプチャするための iPhone または Mac 用 Vox.md。
短く答えると

base は、ノートに対するデータベース形式のビューで、最大 5 つのトップレベルキーを持つ YAML で記述します: filters, formulas, properties, summaries と views。YAML を次の名前で保存します: .base ファイルにするか、ノート内の次のブロックに貼り付けます: base コードブロック。 ジェネレーター が作成します。必要な Obsidian のバージョンはビュータイプによって異なります。 ビューのページ には、1.9 から Table と Cards、1.10 から List と Map、1.14 から Kanban が挙げられています。

filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

ジェネレーターはすべてこのページ内で動作します。入力した内容はアップロードされず、ネットワークリクエストも行われません。

1. base を作成

ジェネレーターには JavaScript が必要です。無効の場合でも、構文の表と下のコピーして使える例は利用できます。

プリセット

プリセットはフォームに入力されます。その後は自由に編集できます。

ソースフィルター(すべてのビューに適用)
数式(任意)

数式は次のように参照します: formula.name (order、groupBy、サマリー内)。

表示名(任意)
出力

あなたの base

    2. Bases 構文の概要

    次がキーです: Obsidian の構文ページ が説明しています。ほかに覚えるスキーマはありません。

    キー動作例
    filtersすべてのビューのノートを絞り込みます。file.hasTag("project")
    formulas計算プロパティを定義します。使い方: formula.name.total: 'price * qty'
    propertiesプロパティごとの設定です。 displayName は列ヘッダーを設定します。displayName: "Status"
    summaries独自のサマリー数式を定義します。使用するもの: values.カスタム、任意
    views同じノートに対するビューのリストです。- type: table
    type (ビュー)ビューのレイアウトです。table, cards, list
    name (ビュー)ビューの名前です。name: "Projects"
    filters (ビュー)このビューだけのフィルターです。file.inFolder("Work")
    groupBy (ビュー)行をグループ化します。基準: property (次の中): direction.direction: DESC
    order (ビュー)表示するプロパティを順番に指定します。- file.name
    limit (ビュー)行数の上限を指定します。limit: 10
    summaries (ビュー)プロパティをサマリーに対応付けます。price: Sum

    ジェネレーターは、ドキュメントにあるすべてのキーを書き出すわけではありません。構文ページには次も記載されています: groupOrder。ビューには、並べ替えの列など、Obsidian が自動で管理する追加の状態を持たせることもできます。必要なら手動で追加してください。YAML は自由に編集できます。

    3. フィルター: and、or、not

    フィルターは、ノートごとに true か false になるテキストのステートメント、または次を持つオブジェクトです: and, or または not (さらに多くのフィルターのリストを保持します)。グローバルな filters はすべてのビューに適用されます。ビュー固有の filters はそのビューにのみ適用され、両者は AND で組み合わされます。

    filters:
  or:
    - file.hasTag("meeting")
    - file.inFolder("Meetings")

    次は存在しません: from または source キーのようなものは、SQL や Dataview とは異なります。フィルターがない base は vault 内のすべてのファイルを含むので、意図しない限り必ずフィルターを設定してください。

    テキスト値はステートメント内で引用符が必要なため、YAML では引用符を入れ子にします: 'status == "done"'。ジェネレーターが自動で行います。関数フィルター(例: file.hasTag(), file.inFolder() と file.hasLink() は次にあります: 関数のページ.

    4. 数式とサマリー

    次の下の各エントリ: formulas は、すべてのビューで次のように使えるプロパティになります: formula.name。数式は別の数式を使えますが、循環参照は使えないため、数式が自分自身を参照することはできません。結果は YAML の文字列として保存されるため、式を引用符で囲みます。

    formulas:
  formatted_price: 'if(price, price.toFixed(2) + " dollars")'

    ビューの summaries は、プロパティをサマリーに対応付けます。構文ページには次の既定値が挙げられています:

    • 数値: Average, Min, Max, Sum, Range, Median, Stddev
    • 日付: Earliest, Latest, Range
    • 真偽値: Checked, Unchecked
    • いずれか: Empty, Filled, Unique

    日付計算については、構文ページに次のようにあります: file.mtime > now() - "1 week" は、直近 1 週間に変更されたファイルで true になります。

    5. このツールでできること

    フィルターや数式では、 this は、base が表示されているファイルです。構文ページによると、base がメインのコンテンツ領域で開かれている場合は base ファイル自体、ノートや Canvas に埋め込まれている場合は埋め込み元のファイル、サイドバーにある場合はメインのコンテンツ領域でアクティブなファイルを指します。このページでは次の例が示されています: file.hasLink(this.file) (バックリンクペインを再現する方法として)。

    6. コピーして使える例

    ジェネレーターのプリセットをそのままコードにしたものです。JavaScript なしでも使えます。フォルダ、タグ、プロパティの名前はご自身のものに置き換えてください。テキストを次の名前で保存します: .base ファイルにするか、次で囲みます: base コードブロック。参照: base を作成 (コマンドについて)。保存したファイルは次で埋め込めます: ![[Name.base]] または ![[Name.base#View]] (既定のビューを選ぶ)。

    読むものリスト

    filters:
  and:
    - file.inFolder("Reading")
    - 'status == "to read"'
properties:
  status:
    displayName: "Status"
views:
  - type: cards
    name: "Reading list"
    order:
      - file.name
      - status

    ステータス別のプロジェクト

    filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

    タグ付きで今週変更したノート

    filters:
  and:
    - file.hasTag("project")
    - 'file.mtime > now() - "1 week"'
views:
  - type: table
    name: "Modified this week"
    order:
      - file.name
      - file.mtime

    このノートのバックリンク

    filters:
  and:
    - file.hasLink(this.file)
views:
  - type: table
    name: "Backlinks"
    order:
      - file.name
      - file.folder

    Vox.md でキャプチャした音声ノート

    filters:
  and:
    - file.inFolder("Vox")
    - file.hasTag("voice")
views:
  - type: table
    name: "Voice notes"
    order:
      - file.ctime
      - file.name
      - file.tags

    この order list で列を選びます。並べ替え順は、Obsidian のビューツールバーで変更するビューの設定なので、例には含めていません。

    7. キャプチャを base に表示する

    Vox.md は、キャプチャした内容を vault 内のフォルダに Markdown ノートとして保存します。その メタデータのドキュメント には、Route で静的メタデータを次のように追加できるとあります: key: value 行(例: tags: [journal, idea]。また、その ノートのフロントマター はそれをドキュメント全体のスコープに書き込みます。任意の位置情報メタデータも記載されています。上の最後の例のように、そのフォルダまたはタグでフィルターした base なら、キャプチャを 1 つの表に一覧できます。メタデータは次で作成します: プロパティジェネレーター。次も参照してください: iPhone で Obsidian に音声ノートを送る (セットアップについて)。

    関連ツール: デイリーノートテンプレートジェネレーター 日付付きノートを作成するための コールアウトジェネレーター および Markdown 表メーカー (ノートの内容用)。

    検索しがいのあるノートが欲しいですか?

    Vox.md は、iPhone と Mac で音声とテキストを、選んだプロパティ付きの Markdown として vault に直接キャプチャします。録音、文字起こし、Capture には Vox.md Unlimited が必要です。対象のアカウントには 7 日間の無料トライアルがあります。

    8. トラブルシューティング

    • base にはすべてのノートが表示されます。 ソースフィルターが設定されていません。base は既定で vault 全体を含むため、次を追加してください: file.inFolder() または file.hasTag() フィルター。
    • プロパティの列が空白です。 大文字小文字を含めて名前が一致していないか、ノートのフロントマターにそのプロパティがありません。ノートのプロパティと列名を確認してください。
    • YAML エラー。 スペースによるインデントと引用符を確認してください。テキストを含むフィルターには、入れ子の引用符が必要です: 'status == "done"'.
    • map ビューが空です。 ビューのページによると、map レイアウトには Maps プラグインが必要です。

    9. よくある質問

    Bases はコアプラグインですか?

    はい。 Obsidian ヘルプ には次のようにあります。「Bases は、ノートのデータベースのようなビューを作成できるコアプラグインです。」

    Bases と Dataview、どちらを使う?

    両者は別物です。Dataview は独自のクエリ言語を持つコミュニティプラグインです。base は Obsidian 自身が読み込む YAML で、次は不要です: from キー: フィルターでノートを絞り込みます。このページでは、機能の詳しい比較は行いません。

    YAML を手動で編集できますか?

    はい。 .base ファイルは YAML テキストで、各キーは構文ページに記載されています。生成したファイルは任意のエディターで開くか、コードブロックをノートに貼り付けて編集できます。

    ジェネレーターはデータをアップロードしますか?

    いいえ。このページ内のスクリプトがお使いのデバイス上で YAML を作成し、ネットワークリクエストは行いません。再読み込みすると、すべて消去されます。
