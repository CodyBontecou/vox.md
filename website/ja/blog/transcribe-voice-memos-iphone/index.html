iPhone のボイスメモを Markdown に文字起こし

Apple の文字起こしで十分なら、まずそれを使います。Vox.md のローカル文字起こしと Markdown 保存先が必要なら、音声を読み込んでください。

作成者
Cody Bontecou
更新日
2026年10月30日
必要条件
保存済みの録音 · 準備済みのバックエンド
短く答えると

iPhone のボイスメモをテキストにするには、まずボイスメモに文字起こしがあるか確認します。目的を果たせるなら、それをコピーしてください。Vox.md のデバイス上の文字起こしと Markdown の振り分けを使う場合は、録音を Files に書き出し、その音声を Vox.md に読み込み、文字起こしを確認して選んだフォルダに保存します。

このガイドは、Apple のボイスメモにある既存の録音から始めます。Vox.md で直接新しく録音する場合は、次を使ってください。 音声メモを Obsidian に送るガイド。この手順は、ドキュメントとソースの確認に基づくもので、新たに実機で書き出しを行ったものではありません。

このガイドの内容
  1. Apple の文字起こしを試す
  2. 録音を書き出す
  3. Vox.md を準備する
  4. 読み込んで確認する
  5. Markdown ファイルを確認する
  6. 上限と復元を確認

1. ボイスメモにすでに文字起こしがあるか確認

Apple は、対応する iPhone、言語、地域での文字起こしを案内しています。ボイスメモで録音を選択し、次を開きます。 その他 メニューで次を探します。 文字起こしを見る または 文字起こしをコピー。必要なのがそれだけなら、文字起こし全体または選択したテキストをコピーし、ノートに貼り付けます。

Apple がすでに作成した文字起こしをコピーするだけなら、別のアプリは不要です。次を確認してください。 Apple の文字起こしガイド で現在の対応状況を確認してください。項目が表示されない理由は、デバイス、システム、言語、地域の対応状況による場合があります。音声の破損を意味するものではありません。

2. Vox.md で文字起こしする場合は音声を書き出す

Apple の ボイスメモの書き出し手順 で、録音を選んで次を開く手順を説明しています。 その他 → 共有、さらに次を選ぶと、 Files に保存。再び見つけられるフォルダを選び、保存します。

通常の書き出し形式は、 .m4a 録音を書き出します。設定によっては、編集可能なレイヤーやエフェクトを別の表現で保持できます。この手順では、まず通常の単一音声ファイルへの書き出しを使ってください。このガイドは、すべてのレイヤー付き・編集可能な書き出しが、すべての文字起こしバックエンドで動くことを保証するものではありません。元の Voice Memo は残してください。

音声ファイルの共有は、Apple の文字起こしのコピーとは異なります。音声を Vox.md に読み込むと、選択した文字起こしバックエンドでもう一度処理します。Apple の文字起こしを読み込むわけではなく、同じ表現になる保証もありません。

3. バックエンドと Markdown の保存先を準備

iPhone 用 Vox.md を入手

  1. Vox.md で、デバイスと録音言語に対応する文字起こしバックエンドを選びます。必要なモデルのダウンロードは、接続中に完了してください。
  2. 書き込み可能な Markdown フォルダを持つキャプチャプレスを作成または選択します。次を使ってください。 新しいノート を初回の読み込みに使うと、出力ファイルを見分けやすくなります。
  3. 選択 オリジナルを保持 処理を使うと、任意の AI による書き換えをせず、認識したテキストを使えます。
  4. 速い捕獲の音声コントロールで、次を選びます。 下書きに追加 を読み込み前に選ぶと、最初の文字起こしを確認できます。

「オリジナルを保持」は認識テキストを保持するものであり、認識を逐語的・無誤りにするものではありません。「自動」、Apple Speech、ダウンロードしたモデルでは、デバイスと言語の要件が異なります。次を確認してください。 モデルのリファレンス と、インストール済みアプリで現在必要な購入またはアクセス条件を確認してから、長い録音を読み込んでください。

Obsidian には、Files が公開する実際の保管庫フォルダを選んでください。Vox.md は Obsidian Sync サービスに直接接続しません。通常の書き込み可能な Markdown フォルダでも使えます。

4. 保存した録音を読み込み、ドラフトを確認

  1. よくある オーディオまたはビデオを読み込む を、速い捕獲の音声コントロールで選びます。
  2. Files から書き出した録音を選び、読み込みと文字起こしの完了を待ちます。
  3. 「下書きに追加」を選んだ場合、入力画面で文字起こしを確認します。氏名、日付、数字、その他の重要な表現を元音声と照合して修正してください。
  4. 選択したプリセットと保存先を確認し、次をタップします。 送る.

一般的な Files 添付アクションでファイルを付けるのではなく、文字起こしの読み込みコントロールを使ってください。ノートの音声添付ファイルそのものは、文字起こしではありません。

次を使って、 すぐに送信 を代わりに選ぶと、完成した文字起こしは、同じドラフト確認を経ずに、選択したプリセットで処理を続けられます。最初の確認では、先に「下書きに追加」を設定してください。読み込みを始める前に、進行中の録音を終了します。

5. 実際の Markdown ファイルを確認

配信が完了するまで待ちます。Files または Obsidian で保存先を開き、ファイル、テキスト、ファイル名を確認してください。入力画面に文字起こしが見えていれば認識でテキストができたことは分かりますが、フォルダへの書き込み成功までは証明できません。

合成した録音から、たとえば次の本文になります。

Review the garden plan on Saturday.
Bring the updated measurements.

これは出力例であり、実際の録音や精度テストではありません。ファイル名、メタデータ、書式はプリセットで決まります。新しく読み込んだ項目の日付やファイル名が、元のボイスメモの録音日になるとは限りません。必要な場合は、その情報を明示的に加えてください。

新しいノートへの読み込みが1件成功したら、次に進みます。 デイリーノートのガイド をローリング保存先に使うか、次を選びます。 テンプレートのレシピ を受信ノートやタスク項目に使います。古い録音を日記に送る前に、対象ノートの日付とパスを確認してください。

上限、プライバシー、読み込みの失敗

  • 読み込みを使えない場合： 現在の録音を終了し、アプリのアクセス条件を確認して、選択したプリセットが有効であることを確かめます。
  • 認識に失敗する場合： バックエンドの準備、言語、ローカルストレージ、ファイルの音声をデコードできるかを確認してください。原本を残し、長いファイルや特殊なファイルを試す前に、小さな通常の音声書き出しで試します。
  • 配信が保留中の場合： フォルダへのアクセスを復元し、保持されている失敗済みの配信を再試行してください。同じメモを再度読み込むと、キャプチャが重複する場合があります。
  • 元の音声も必要な場合： 音声の保持は、別途設定して確認してください。テキストができたからといって、すべてのプリセットが音声も添付保存するとは限りません。

Vox.md はデバイス上で文字起こしを行います。バックエンドの初回準備にはダウンロードが必要な場合があり、Files プロバイダによっては、元ファイルの取得や保存先への書き込みに接続が必要です。音声や Markdown を同期フォルダに保存すると、そのプロバイダが同期を行います。完全に接続を切って使う手順は、次に沿って確認してください。 オフラインで使うための準備と確認ガイド.

このルートは、ボイスメモライブラリの自動同期、一括アーカイブ読み込み、Apple の編集、レイヤー、文字起こしのタイミング、録音メタデータの保持を約束するものではありません。まず録音を1件使い、原本を保持して、保存したテキストを確認してから手順を広げてください。
