Markdown चेकलिस्ट मेकर: किसी भी सूची को नियत तिथि सहित टास्क में बदलें

सादी पंक्तियाँ, बुलेट, क्रमांकित आइटम या मौजूदा टास्क सूची पेस्ट करें और मान्य - [ ] टास्क कॉपी करें, नेस्टिंग बरकरार, वैकल्पिक नियत तिथि और पूरे हुए टास्क की गिनती के साथ।

लेखक:
Cody Bontecou
अपडेट किया गया
24 नवंबर 2026
आवश्यक है
कोई भी आधुनिक ब्राउज़र, iPhone पर Safari सहित। वैकल्पिक: चेकलिस्ट के लिए Obsidian, और आवाज़ से टास्क कैप्चर करने के लिए iPhone या Mac पर Vox.md।
छोटा जवाब

Markdown टास्क एक हाइफ़न, एक स्पेस, ब्रैकेट, एक स्पेस और फिर टेक्स्ट होता है। लिखें - [ ] task खुले टास्क के लिए और - [x] done पूरे हो चुके टास्क के लिए। पूरी सूची को टास्क में बदलने के लिए उसे इसमें पेस्ट करें: चेकलिस्ट मेकर नीचे।

- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

मेकर मौजूदा बुलेट, क्रमांक और चेकबॉक्स हटाता है ताकि कुछ दोहराया न जाए, इंडेंटेशन को नेस्टिंग के रूप में रखता है, और आपके Obsidian प्लगइन के पढ़े जाने वाले फ़ॉर्मैट में नियत तिथि जोड़ सकता है। यह पूरी तरह इसी पेज में चलता है: सूची कभी अपलोड नहीं होती, और पेज कोई नेटवर्क अनुरोध नहीं करता।

1. अपनी चेकलिस्ट बनाएँ

चेकलिस्ट मेकर को JavaScript चाहिए। इसके बिना भी नीचे दिया सिंटैक्स संदर्भ के रूप में काम करता है।

आपकी सूची
क्या करें
नेस्टिंग

आपकी सूची में एक टैब हमेशा एक स्तर गिना जाता है। शीर्षक शीर्षक ही रहते हैं।

हर टास्क के लिए नियत तिथि

आपकी चेकलिस्ट

पूर्वावलोकन

नतीजा देखने के लिए सूची पेस्ट करें। {total} में से {done} पूरे इस सूची में कोई टास्क नहीं। क्लिपबोर्ड पर कॉपी हो गया। कॉपी नहीं हो सकी। टेक्स्ट चुनकर खुद कॉपी करें। उदाहरण लोड हो गया। साफ़ कर दिया। आपकी चेकलिस्ट चेकबॉक्स के बिना आपकी सूची नियत तिथि जोड़ने के लिए मान्य तारीख चुनें। कोई तारीख नहीं जोड़ी गई। 09:30 जैसा समय दर्ज करें। तारीख बिना समय के जोड़ी गई। जिन टास्क में पहले से इस तरह की तारीख थी, उन्हें जैसा था वैसा छोड़ा गया। GitHub पर, कोष्ठक से शुरू होने वाले टास्क विवरण के आगे बैकस्लैश चाहिए।

2. Markdown चेकलिस्ट सिंटैक्स

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

हर टास्क एक सूची आइटम है: एक हाइफ़न और एक स्पेस, फिर [ ] ब्रैकेट के बीच एक स्पेस के साथ, फिर टेक्स्ट। Obsidian Help पृष्ठ और GitHub Docs पृष्ठ दोनों इसे हाइफ़न और स्पेस के बाद आने वाला बताते हैं [ ]। टास्क को पूरा चिह्नित करने के लिए GitHub Docs उपयोग करने को कहता है [x].

स्पेस मायने रखते हैं। GitHub Flavored Markdown स्पेक चेकबॉक्स मार्कर को एक बायाँ ब्रैकेट, एक व्हाइटस्पेस वर्ण या अक्षर x, और एक दायाँ ब्रैकेट, और उसके बाद के टेक्स्ट से पहले व्हाइटस्पेस चाहिए। इसलिए [] जिसके अंदर कुछ नहीं है, या - [ ]text ब्रैकेट के बाद स्पेस के बिना, परिभाषा से मेल नहीं खाता। हाइफ़न और उसका स्पेस ही पंक्ति को सूची आइटम बनाते हैं।

टास्क सूचियाँ कोर Markdown का हिस्सा नहीं हैं। वही स्पेक इन्हें CommonMark का एक्सटेंशन बताता है, और उसकी प्रस्तावना कहती है कि मूल CommonMark स्पेक में न मौजूद सुविधाओं को एक्सटेंशन के रूप में चिह्नित किया गया है। जो रेंडरर एक्सटेंशन लागू नहीं करता, वह ब्रैकेट को सादे टेक्स्ट में दिखाता है, जो आमतौर पर चेकबॉक्स के इस रूप में दिखने का कारण होता है: [ ] पेज पर।

3. Obsidian में चेकलिस्ट

Obsidian Help का बुनियादी फ़ॉर्मैटिंग सिंटैक्स पेज टास्क सूचियों को कवर करता है:

  • टास्क एक हाइफ़न और एक स्पेस से शुरू होता है, उसके बाद [ ].
  • टास्क को पूरा चिह्नित करने के लिए आप ब्रैकेट के भीतर कोई भी वर्ण उपयोग कर सकते हैं, इसलिए [x], [-] और [?] सब गिने जाते हैं।
  • आप सूची आइटम को इंडेंट करके टास्क सूची नेस्ट करते हैं। उपयोग करें Tab या Shift+Tab चुने हुए आइटम को इंडेंट या अन-इंडेंट करने के लिए।
  • आप Reading व्यू में टास्क के चेकबॉक्स को चुनकर उसे टॉगल कर सकते हैं।

Help पेज बताता है कि कोई भी वर्ण टास्क को पूरा करता है। यह हर वर्ण के लिए अलग रूप का वर्णन नहीं करता। अगर [-] या [?] इससे अलग दिखता है [x] आपके वॉल्ट में, तो यह आपके इंस्टॉल किए थीम या CSS स्निपेट से आता है, Markdown से नहीं।

मेकर में प्रगति पंक्ति भी उसी तरह गिनती है: ब्रैकेट के भीतर स्पेस के अलावा कोई भी वर्ण पूरा माना जाता है, इसलिए [x], [X], [-] और [?] पूरे हैं और [ ] खुला है। जो पंक्तियाँ “done:” या “x ” से शुरू होती हैं, वे सामान्य टेक्स्ट हैं; टूल अनुमान नहीं लगाता कि वे पूरे टास्क हैं।

4. नियत तिथियाँ: Tasks बनाम Dataview बनाम Reminder

Obsidian की टास्क सूची सिंटैक्स में अपनी कोई नियत तिथि नहीं है: Help पेज में ऐसा कुछ दर्ज नहीं है। तीन प्लगइन टास्क के टेक्स्ट में लिखी तारीख पढ़ते हैं, हर एक अपने फ़ॉर्मैट में। मेकर तारीख को ISO रूप में लिखता है YYYY-MM-DD सभी में। प्लगइन के बिना तारीख सिर्फ़ टेक्स्ट है।

फ़ॉर्मैटइनके द्वारा पढ़ा जाता हैउदाहरण पंक्ति
नियत: 📅 YYYY-MM-DDTasks प्लगइन, जो कहता है कि तारीख इस रूप में होनी चाहिए YYYY-MM-DD इस रूप में- [ ] send invoice 📅 2026-11-25
निर्धारित: ⏳ YYYY-MM-DDTasks प्लगइन- [ ] send invoice ⏳ 2026-11-25
शुरू: 🛫 YYYY-MM-DDTasks प्लगइन- [ ] send invoice 🛫 2026-11-25
इनलाइन फ़ील्ड: [due:: YYYY-MM-DD]Dataview दस्तावेज़ीकरण, जो टास्क पर लिखे फ़ील्ड पढ़ता है, जैसे [completion:: 2021-08-15]- [ ] send invoice [due:: 2026-11-25]
Reminder प्लगइन: (@YYYY-MM-DD) या (@YYYY-MM-DD HH:mm)obsidian-reminder प्लगइन, जिसका README दिखाता है (@2021-08-14) और (@2021-08-14 09:37) बिना चेक किए टास्क पर- [ ] send invoice (@2026-11-25 09:30)

वही एक प्लगइन चुनें जिसका आप उपयोग करते हैं। Dataview का पेज तारीखों के लिए अपने इमोजी शॉर्टहैंड भी सूचीबद्ध करता है और कहता है कि केवल वही समर्थित हैं; मेकर इसके बजाय Dataview का ब्रैकेट रूप लिखता है। Reminder के README के अनुसार, पहले से चेक किए गए टास्क के रिमाइंडर की सूचना आपको नहीं मिलती।

5. GitHub और Obsidian में अंतर

GitHub Docs बताता है [ ] खुले टास्क के लिए और [x] किसी को पूरा चिह्नित करने के लिए। GFM स्पेक मार्कर को व्हाइटस्पेस या अक्षर x ब्रैकेट के बीच। Obsidian कोई भी वर्ण स्वीकार करता है। इसलिए ऐसा टास्क - [-] skipped या - [?] unsure Obsidian में पूरा माना जाता है, लेकिन यह स्पेक की मार्कर परिभाषा से बाहर है, और स्पेक का पालन करने वाला रेंडरर इसे सादे टेक्स्ट के रूप में दिखा सकता है। अगर फ़ाइल GitHub पर भी पढ़ी जाती है, तो उपयोग करें [ ] और [x] ही।

GitHub Docs एक और नियम जोड़ता है: अगर टास्क का विवरण कोष्ठक से शुरू होता है, तो उसके आगे बैकस्लैश लगाएँ, जैसे - [ ] \(Optional) Open a followup issue। मेकर आपके लिए बैकस्लैश नहीं जोड़ता; टास्क कोष्ठक से शुरू हो तो यह चेतावनी देता है।

तालिकाएँ वह दूसरा सिंटैक्स हैं जहाँ Obsidian और GitHub के ब्योरे मायने रखते हैं। स्प्रेडशीट सेल या CSV को ऐसी तालिका में बदलने के लिए जो Obsidian और GitHub दोनों पर काम करे, इसका उपयोग करें: Markdown टेबल मेकर.

टास्क सूची के ऊपर किसी सारांश या चेतावनी को callout से हाइलाइट करें: Obsidian callout जनरेटर बनाता है > [!type] Markdown, जिनमें फ़ोल्ड होने वाले भी शामिल हैं।

6. Vox.md से iPhone और Mac पर आवाज़ या टेक्स्ट से टास्क कैप्चर करें

Vox.md का Todo Checklist प्रोसेसिंग मोड Markdown बनाता है - [ ] कैप्चर से टास्क आइटम बनाता है, और इसका फ़ॉलबैक एक निर्धारक चेकलिस्ट फ़ॉर्मैटर है। आवाज़ आपके डिवाइस पर ट्रांसक्राइब होती है। Capture Bar में, चेकलिस्ट लागू करता है - [ ] प्रीफ़िक्स, और दो तारीखें डालता है (@yyyy-MM-dd) या समय वाला रूप। देखें तेजी से पकड़ और Routes और प्रोसेसिंग मोड दस्तावेज़।

एक Route आइटम को आपके डेली नोट में इस जैसे शीर्षक के नीचे जोड़ सकता है: ## Tasks; Obsidian के दैनिक नोट में जोड़ें सेटअप समझाता है, और डेली नोट टेम्पलेट जनरेटर नोट का ढाँचा लिखता है। मीटिंग के एक्शन आइटम के लिए देखें मीटिंग नोट्स टेम्पलेट; टास्क सूची के प्रीफ़िक्स की विधि के लिए देखें कैप्चर टेम्पलेट.

Vox.md लिखता है (@yyyy-MM-dd) रूप, जो इसके दस्तावेज़ में दिखाया गया है। यह Tasks प्लगइन की इमोजी तारीखें या Dataview फ़ील्ड नहीं लिखता। अगर आप इनमें से कोई उपयोग करते हैं, तो कैप्चर किए टास्क को ऊपर के मेकर में पेस्ट करें और वही फ़ॉर्मैट चुनें, या बाद में तारीख बदलें। नोट के ऊपर प्रॉपर्टीज़ बनाने के लिए इसका उपयोग करें प्रॉपर्टी जनरेटर.

iPhone, iPad या Mac पर आवाज़ से टास्क कैप्चर करें।

Vox.md आपकी कही बात को डिवाइस पर ही Markdown चेकलिस्ट में बदलकर आपके Obsidian नोट में जोड़ देता है। रिकॉर्डिंग, ट्रांसक्रिप्शन और Capture के लिए Vox.md Unlimited चाहिए: पात्र खातों के लिए 7 दिन के मुफ़्त ट्रायल वाला साप्ताहिक या सालाना सब्सक्रिप्शन, या एक बार की आजीवन खरीद। App Store आपकी स्थानीय कीमत दिखाता है।

7. सवाल

मेरा चेकबॉक्स [ ] टेक्स्ट क्यों दिखता है?

रेंडरर टास्क सूचियाँ नहीं दिखा रहा। टास्क सूचियाँ CommonMark का एक्सटेंशन हैं, इसलिए इसके बिना रेंडरर ब्रैकेट ही दिखाता है। जाँचें कि पंक्ति हाइफ़न और स्पेस से शुरू होती है, कि ब्रैकेट के बीच स्पेस या x के बीच है, और बंद करने वाले ब्रैकेट के बाद एक स्पेस है। Obsidian में कोड ब्लॉक या टेबल सेल के भीतर का टास्क सूची आइटम की तरह चेकबॉक्स के रूप में नहीं दिख सकता।

टास्क को नेस्ट कैसे करूँ?

चाइल्ड टास्क को इंडेंट करें। Obsidian में दबाएँ Tab चुने हुए आइटम को इंडेंट करने के लिए और Shift+Tab इंडेंट हटाने के लिए। मेकर आपकी सूची के 2 या 4 स्पेस को प्रति स्तर एक टैब में बदलता है, या पसंद हो तो 2 या 4 स्पेस में।

x के अलावा किसी और वर्ण से बॉक्स कैसे चेक करूँ?

Obsidian Help कहता है कि ब्रैकेट के भीतर कोई भी वर्ण टास्क को पूरा चिह्नित करता है, इसलिए - [-] task और - [?] task पूरे हैं। मेकर आपका पेस्ट किया हुआ वर्ण तब तक रखता है जब तक आप सूची रीसेट न करें। जिन फ़ाइलों को GitHub पर भी पढ़ा जाता है, उनके लिए उपयोग करें [x].

Tasks प्लगइन जो नियत तिथि पढ़ सके, उसे कैसे जोड़ूँ?

लिखें 📅 और एक YYYY-MM-DD टास्क के अंत में तारीख, उदाहरण के लिए - [ ] send invoice 📅 2026-11-25। हर टास्क में जोड़ने के लिए ऊपर “Tasks प्लगइन: नियत तिथि” चुनें। उपयोग करें ⏳ निर्धारित तारीख के लिए और 🛫 शुरुआती तारीख के लिए।

क्या मेकर मेरी सूची अपलोड करता है?

नहीं। सूची इसी पेज की एक स्क्रिप्ट से आपके डिवाइस पर बदली जाती है, और पेज कोई नेटवर्क अनुरोध नहीं करता। यह आपकी सूची सहेजता नहीं: पेज बंद या रीलोड करने पर वह मिट जाती है।
