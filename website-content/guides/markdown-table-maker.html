The short answer

A Markdown table is a header row, a delimiter row of hyphens, then one row per line, with cells separated by |. Paste your cells into the table maker below to get one, or start from this example.

| Name | Owner | Status |
| --- | --- | --- |
| Draft | Ana | Done |
| Review | Lee | Open |

The maker also fixes what generic generators skip in Obsidian: it escapes the bar inside [[Note|Alias]] and ![[image.png|300]] as \|, and turns a line break inside a cell into <br> or a space. It runs entirely in this page: your data is never uploaded, and the page makes no network requests.

    2. Markdown table syntax

    | Name   | Qty | Price |
| :----- | :-: | ----: |
| Apple  |   3 |  1.20 |
| Pear   |  12 |  0.80 |

    The GitHub Flavored Markdown spec defines a table as one header row, a delimiter row that separates the header from the data, and zero or more data rows. Cells are separated by pipes.

    • Delimiter row. Its cells contain only hyphens, with an optional colon on the left, the right or both ends to set left, right or center alignment. Obsidian Help says you add colons to the header row to align text, and that the header row must contain at least two hyphens.
    • Outer pipes. The pipes on either side are optional in the spec. Obsidian Help says including them is recommended for readability, and the maker always writes them.
    • Padding. Cells do not need perfect alignment, according to Obsidian Help. The maker’s “Pad columns” layout lines the source up only to make it easier to read; “Compact” skips it.
    • Matching counts. The spec says the header row must have the same number of cells as the delimiter row. If it does not, the lines are not a table and render as a paragraph. A data row with fewer cells gets empty cells added, and extra cells are ignored.
    • Inside a cell. The spec allows inline formatting but not block-level content, so a list or heading cannot go in a cell. Obsidian Help says you can use its basic formatting syntax to style content in a table.
    • The end of a table. The spec says the table is broken at the first empty line, or at the beginning of another block-level structure.

    The maker writes at least three hyphens in every delimiter cell. That satisfies Obsidian’s minimum of two and the three that GitHub Docs asks for.

    3. Tables in Obsidian

    • Insert Table. Obsidian Help says you can insert a table with the Insert Table command from the Command Palette. To build one from data you already have, paste it into the maker above.
    • Aliases and image sizes. A wikilink alias such as [[Note|Alias]] and an image size such as ![[image.png|300]] both contain a vertical bar. Obsidian Help says that inside a table you need to add a \ before the bar, so write [[Note\|Alias]] and ![[image.png\|300]]. The maker does this for you; an escape you already wrote is not doubled.
    • Any other pipe. The GFM spec says a pipe inside a cell must be escaped with a backslash, even inside a code span. The maker escapes every unescaped pipe as \|.
    • Line breaks. A row is written on one line, so a line break inside a cell has to become something else. The maker writes an HTML <br> tag, or joins the lines with a space if you choose that. Neither Obsidian Help’s Tables section nor GitHub Docs describes line breaks in cells, so check that <br> renders in your own vault, and pick the space option if you do not want tags in the source.
    • Plugins. Community plugins that help edit tables exist. This page does not evaluate or endorse any of them.

    For checklists see the Markdown checklist maker; for the properties at the top of a note, the properties generator. A table works well for a list of decisions and owners in a note from the meeting notes template.

    4. From Excel, Google Sheets or CSV

    Select the cells in your spreadsheet, copy, and paste them into the box above. If the cells paste with tabs between them, the maker detects that. It also detects commas, semicolons and pipes, and it reads quoted CSV fields, so "Lee, Sam" stays one cell and "" inside quotes becomes a quote. Use the Separator menu if the guess is wrong. Tick or untick “The first row is the header” to decide whether the first row becomes the header row; without it, an empty header row is added, because a Markdown table needs one.

    • Merged cells. The spec and both help pages describe a row as a list of cells separated by pipes, and none of them describes a way to merge cells. Put the value in every cell the merge covered before you copy.
    • Formulas. The maker only reads the text you paste. If the pasted cells show formulas instead of their results, copy the values in your spreadsheet app and paste again.
    • Uneven rows. If a row has a different number of cells from the header, the maker warns with the line number of that row and pads the table with empty cells. A row with more cells than the header widens the table instead of dropping data.
    • Reverse and repair. Paste an existing Markdown table to re-align it, or set Output as to CSV or TSV to export it. The maker warns, with a line number, when the delimiter row is missing, when its cell count does not match the header, or when a blank line would end the table.

    Alignment colons from a pasted Markdown table are kept, and you can change each column with the Column alignment menus.

    5. GitHub vs Obsidian differences

    Obsidian Help and GitHub Docs both describe pipe tables with a header row, hyphens and optional alignment colons. The differences the pages state are small:

    TopicObsidian HelpGitHub Docs and GFM spec
    HyphensThe header row must contain at least two hyphensGitHub Docs: at least three hyphens in each header column
    Blank line before the tableThe Tables section does not mention oneGitHub Docs: you must include a blank line before your table
    Literal pipe in a cellAdd a \ before the bar in aliases and image sizesEscape it as \|, even inside a code span
    Outer pipesOptional, recommended for readabilityOptional

    To be safe in both places, write three or more hyphens, leave a blank line above the table, and escape every pipe. That is what the maker does. A wikilink alias is Obsidian syntax; on GitHub it is just text with a pipe in it. The checklist maker guide covers the task list differences in the same way.

    To highlight a table or a note about it, wrap it in a callout: the Obsidian callout generator adds the > prefixes for you.

    7. Questions

    Why is my table not rendering in Obsidian?

    Check three things. There must be a delimiter row of hyphens straight under the header, and the header and delimiter rows must have the same number of cells, otherwise the spec renders the lines as a paragraph. Obsidian Help says the header row must contain at least two hyphens. And leave a blank line before the table, which GitHub Docs requires and which costs nothing in Obsidian. Paste the table into the maker: it warns, with a line number, when the delimiter row is missing or the counts differ.

    How do I add a line break in a cell?

    Keep the row on one line and use an HTML <br> inside the cell, which is what the maker writes for a multi-line cell. The cited pages do not describe line breaks in cells, so test it in your vault. The other choice is to join the lines with a space.

    How do I put a pipe or a wikilink alias in a cell?

    Put a backslash before the pipe: [[Note\|Alias]], ![[image.png\|300]] or a \| b. Obsidian Help requires this for aliases and image resizing inside tables, and the GFM spec requires it for any pipe in a cell.

    Can I merge cells?

    No syntax for it appears in the spec or in Obsidian Help. Repeat the value in each cell instead.

    How wide can a table be?

    None of the cited pages gives a maximum number of columns or rows, and the maker sets no limit. A very wide table is hard to read in source, so use the Compact layout, or split it into two tables.

    Does the maker upload my data?

    No. The table is built by a script in this page, on your device, and the page makes no network requests. It does not save your data: closing or reloading the page clears it. The Download button saves a file from the page to your device.
