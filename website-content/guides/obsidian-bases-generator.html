The short answer

A base is a database-style view over your notes, written as YAML with up to five top-level keys: filters, formulas, properties, summaries and views. Save the YAML as a .base file, or paste it into a note inside a base code block. The generator below writes it for you. Which Obsidian version you need depends on the view type: the views page lists Table and Cards from 1.9, List and Map from 1.10, and Kanban from 1.14.

filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

The generator runs entirely in this page. Nothing you type is uploaded, and the page makes no network requests.

    2. Bases syntax at a glance

    These are the keys Obsidian’s syntax page documents. There is no other schema to learn.

    KeyWhat it doesExample
    filtersNarrows the notes for every view.file.hasTag("project")
    formulasDefines computed properties, used as formula.name.total: 'price * qty'
    propertiesPer-property settings. displayName sets the column header.displayName: "Status"
    summariesDefines your own summary formulas, using values.Custom, optional
    viewsA list of views over the same notes.- type: table
    type (view)The layout of the view.table, cards, list
    name (view)The view’s name.name: "Projects"
    filters (view)Filters for this view only.file.inFolder("Work")
    groupBy (view)Groups rows by a property in a direction.direction: DESC
    order (view)The properties shown, in order.- file.name
    limit (view)Caps the number of rows.limit: 10
    summaries (view)Maps a property to a summary.price: Sum

    The generator does not write every documented key. The syntax page also describes groupOrder, and views can hold extra state such as the sort column, which Obsidian manages itself. Add those by hand if you need them: the YAML is yours to edit.

    3. Filters: and, or, not

    A filter is a text statement that is true or false for each note, or an object with and, or or not holding a list of more filters. Global filters apply to every view. A view’s own filters apply to that view only, and the two are combined with AND.

    filters:
  or:
    - file.hasTag("meeting")
    - file.inFolder("Meetings")

    There is no from or source key like in SQL or Dataview. With no filter, a base includes every file in the vault, so always set one unless you want that.

    Text values need quotes inside the statement, so the YAML needs nested quotes: 'status == "done"'. The generator does this for you. Function filters such as file.hasTag(), file.inFolder() and file.hasLink() are on the functions page.

    4. Formulas and summaries

    Each entry under formulas becomes a property you can use in every view as formula.name. A formula can use another formula, but circular references are not allowed, so a formula cannot refer to itself. The result is stored as a YAML string, which is why the expression goes inside quotes.

    formulas:
  formatted_price: 'if(price, price.toFixed(2) + " dollars")'

    A view’s summaries maps a property to a summary. The syntax page lists these defaults:

    • Number: Average, Min, Max, Sum, Range, Median, Stddev
    • Date: Earliest, Latest, Range
    • Boolean: Checked, Unchecked
    • Any: Empty, Filled, Unique

    For date maths, the syntax page says file.mtime > now() - "1 week" is true for a file modified in the last week.

    5. What this means

    In a filter or formula, this is the file the base is shown in. The syntax page says it is the base file itself when the base opens in the main content area, the embedding file when the base is embedded in a note or Canvas, and the active file in the main content area when the base is in the sidebar. The page gives file.hasLink(this.file) as a way to replicate the backlinks pane.

    6. Examples you can copy

    These are the generator’s presets as plain code, so they work without JavaScript. Replace folder, tag and property names with yours. Save the text as a .base file, or wrap it in a base code block. See Create a base for the commands, and embed a saved file with ![[Name.base]] or ![[Name.base#View]] to choose the default view.

    Reading list

    filters:
  and:
    - file.inFolder("Reading")
    - 'status == "to read"'
properties:
  status:
    displayName: "Status"
views:
  - type: cards
    name: "Reading list"
    order:
      - file.name
      - status

    Projects by status

    filters:
  and:
    - file.hasTag("project")
properties:
  status:
    displayName: "Status"
views:
  - type: table
    name: "Projects by status"
    groupBy:
      property: status
      direction: ASC
    order:
      - file.name
      - status
      - file.mtime

    Notes with a tag, modified this week

    filters:
  and:
    - file.hasTag("project")
    - 'file.mtime > now() - "1 week"'
views:
  - type: table
    name: "Modified this week"
    order:
      - file.name
      - file.mtime

    Backlinks of this note

    filters:
  and:
    - file.hasLink(this.file)
views:
  - type: table
    name: "Backlinks"
    order:
      - file.name
      - file.folder

    Voice notes captured with Vox.md

    filters:
  and:
    - file.inFolder("Vox")
    - file.hasTag("voice")
views:
  - type: table
    name: "Voice notes"
    order:
      - file.ctime
      - file.name
      - file.tags

    The order list picks the columns. Sort order is a view setting you change in Obsidian’s view toolbar, so the examples do not write one.

    8. Troubleshooting

    • The base shows every note. No source filter is set. A base includes the whole vault by default, so add a file.inFolder() or file.hasTag() filter.
    • A property column is blank. The name does not match, including case, or the note does not have that property in its frontmatter. Check the note’s Properties and the column name.
    • YAML error. Check indentation, which uses spaces, and quotes. A filter that holds text needs nested quotes: 'status == "done"'.
    • A map view is empty. The map layout needs the Maps plugin, according to the views page.

    9. Questions

    Is Bases a core plugin?

    Yes. Obsidian Help says: “Bases is a core plugin that lets you create database-like views of your notes.”

    Bases or Dataview?

    They are separate. Dataview is a community plugin with its own query language. A base is YAML that Obsidian reads itself, with no from key: you narrow notes with filters. This page does not compare their features further.

    Can I edit the YAML by hand?

    Yes. A .base file is YAML text, and the syntax page documents the keys. Open the generated file in any editor, or paste the code block into a note and edit it there.

    Does the generator upload my data?

    No. A script in this page builds the YAML on your device, and the page makes no network requests. Reloading clears everything.
