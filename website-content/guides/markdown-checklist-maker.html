The short answer

A Markdown task is a hyphen, a space, brackets, a space and the text. Write - [ ] task for an open task and - [x] done for a finished one. To turn a whole list into tasks, paste it into the checklist maker below.

- [ ] buy milk
	- [ ] oat
- [ ] call Sam
- [x] send invoice

The maker strips existing bullets, numbers and checkboxes so nothing is doubled, keeps indentation as nesting, and can add a due date in the format your Obsidian plugin reads. It runs entirely in this page: the list is never uploaded, and the page makes no network requests.

2. Markdown checklist syntax

- [ ] unchecked task
- [x] checked task
- [ ] parent task
	- [ ] nested task

Each task is a list item: a hyphen and a space, then [ ] with a space between the brackets, then the text. Obsidian Help page and GitHub Docs page both describe it as a hyphen and a space followed by [ ]. To mark a task complete, GitHub Docs says to use [x].

The spaces matter. The GitHub Flavored Markdown spec defines the checkbox marker as a left bracket, a whitespace character or the letter x, and a right bracket, and it needs whitespace before the text after it. So [] with nothing inside, or - [ ]text with no space after the bracket, does not match the definition. The hyphen and its space are what make the line a list item at all.

Task lists are not part of core Markdown. The same spec marks them as an extension to CommonMark, and its introduction says features that are not in the original CommonMark spec are marked as extensions. A renderer that does not implement the extension shows the brackets as literal text, which is the usual reason a checkbox shows as [ ] on the page.

3. Checklists in Obsidian

Obsidian Help’s basic formatting syntax page covers task lists:

  • A task starts with a hyphen and a space followed by [ ].
  • You can use any character inside the brackets to mark the task as complete, so [x], [-] and [?] all count.
  • You nest a task list by indenting list items. Use Tab or Shift+Tab to indent or unindent the selected items.
  • You can toggle a task in Reading view by selecting its checkbox.

The Help page documents that any character completes a task. It does not describe a different look for each character. If [-] or [?] looks different from [x] in your vault, that comes from a theme or CSS snippet you have installed, not from the Markdown itself.

The progress line in the maker counts the same way: any character inside the brackets other than a space is done, so [x], [X], [-] and [?] are done and [ ] is open. Lines that start with “done:” or “x ” are ordinary text; the tool does not guess that they mean a finished task.

4. Due dates: Tasks vs Dataview vs Reminder

Obsidian’s task list syntax has no due date of its own: the Help page documents none. Three plugins read a date written in the task text, each in its own format. The maker writes the date as ISO YYYY-MM-DD in all of them. Without the plugin, the date is just text.

5. GitHub vs Obsidian differences

GitHub Docs describes [ ] for an open task and [x] to mark one complete. The GFM spec defines the marker as whitespace or the letter x between the brackets. Obsidian accepts any character. So a task such as - [-] skipped or - [?] unsure is complete in Obsidian, but it is outside the spec’s marker definition, and a renderer that follows the spec may show it as literal text. If the file is also read on GitHub, use [ ] and [x] only.

GitHub Docs adds one rule: if a task description begins with a parenthesis, escape it with a backslash, as in - [ ] \(Optional) Open a followup issue. The maker does not add the backslash for you; it warns when a task starts with a parenthesis.

7. Questions

Why does my checkbox show as [ ] text?

The renderer is not drawing task lists. Task lists are an extension to CommonMark, so a renderer without it shows the brackets. Check that the line starts with a hyphen and a space, that there is a space or x between the brackets, and that a space follows the closing bracket. In Obsidian, a task in a code block or a table cell may not draw as a checkbox the way a list item does.

How do I nest tasks?

Indent the child task. In Obsidian, press Tab to indent the selected items and Shift+Tab to unindent them. The maker turns 2 or 4 spaces in your list into one tab per level, or into 2 or 4 spaces if you prefer.

How do I check a box with a character other than x?

Obsidian Help says any character inside the brackets marks the task complete, so - [-] task and - [?] task are done. The maker keeps the character you pasted unless you reset the list. For files that are also read on GitHub, use [x].

How do I add a due date the Tasks plugin reads?

Put 📅 and a YYYY-MM-DD date at the end of the task, for example - [ ] send invoice 📅 2026-11-25. Choose “Tasks plugin: due” above to add it to every task. Use ⏳ for a scheduled date and 🛫 for a start date.

Does the maker upload my list?

No. The list is converted by a script in this page, on your device, and the page makes no network requests. It does not save your list: closing or reloading the page clears it.
